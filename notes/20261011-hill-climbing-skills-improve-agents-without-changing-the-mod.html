모델은 그대로, 스킬을 키운다

브라우저 에이전트는 똑똑하지만 매번 처음부터 시작해서 같은 곳에서 계속 넘어진다. 발표자는 실행 에이전트와 교사 에이전트가 번갈아 돌며 요령을 찾아 스킬 파일로 남기는 루프로, 모델을 바꾸지 않고 에이전트를 개선하는 방법을 보여 준다.

원본 영상: Hill-Climbing Skills: Improve Agents Without Changing the Model 발표: Shubhankar Srivastava (Browserbase 세일즈 엔지니어링 팀)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 말하거나 데모 화면에서 읽어 준 것이고 원 출처를 따로 확인하지는 않았다. 발표자는 Browserbase 소속이라 자사 인프라와 제품 이야기가 섞여 있다. 자막에서 뭉개진 이름은 확실한 것만 바로잡았고, 나머지는 들린 대로 적고 (추정)을 붙였다. mm:ss는 영상 위치다.

3분 요약
  1. 브라우저 에이전트의 가장 큰 문제는 신뢰성이다. 발표자는 이것을 모델 문제가 아니라 엔지니어링 문제로 본다.
  2. 근본 원인은 매 실행이 0에서 시작한다는 것이다. 사이트마다 통하는 요령이 쌓이지 않는다.
  3. 해법은 Karpathy의 autoresearch를 브라우저에 옮긴 autobrowse 루프다. 실행 에이전트가 해 보고, 교사 에이전트가 기록을 읽어 strategy.md를 고친다.
  4. 루프가 수렴하면 요령을 SKILL.md로 졸업시킨다. 다음 에이전트는 이 파일을 읽고 바로 지름길로 간다.
  5. 데모 수치: Google Flights 비용 12달러 → 3달러, OpenTable 비용 6.22달러 → 0.51달러, 시간 189초 → 27초.
  6. 다른 분야에 쓰려면 두 조건이 필요하다. 다시 돌려 볼 수 있는 환경과 성공을 판정할 수 있는 결과다.
  7. 사이트는 계속 바뀐다. 실패를 계기로 루프를 다시 돌려 스킬을 고친다. 프롬프트 인젝션은 입력, 스킬, 인프라 세 층에서 막는다.
01

브라우저 에이전트와 신뢰성 01:40

브라우저를 도구로 쓰는 에이전트를 브라우저 에이전트 browser agent라고 부른다.

에이전트는 CLI나 MCP 같은 통로로 브라우저를 조작한다. 쓰는 도구는 낮은 수준의 동작이다.

  • 빨간 버튼 누르기, 새로고침 누르기
  • 스크린샷 찍기
  • 페이지의 접근성 트리 accessibility tree 읽기. 화면의 버튼과 글을 구조로 정리한 것이다

Browserbase는 이런 에이전트를 만들고 돌리는 플랫폼이다. 원격 브라우저 인프라, SDK, 스킬, CLI를 제공한다.

가장 큰 문제는 신뢰성 02:40

사용자들은 에이전트가 멈추거나, 안티봇 anti-bot과 CAPTCHA에 막히거나, 일을 잊고 대충 끝내는 데 답답해한다.

발표자는 신뢰성 reliability을 엔지니어링 문제로 본다. 최근 Opus나 Fable 같은 모델은 충분히 똑똑하다. 신뢰성을 올리는 일 대부분은 모델 바깥에서 일어난다. 하네스 harness, 에이전트에게 주는 도구, 스킬이 그 자리다.

Google Flights 03:30

출발 시간 필터를 마우스로 끌어야 한다. 드래그는 에이전트에게 까다로운 동작이다.

결과: 어떤 HTML 요소와 JavaScript를 건드려야 할지 몰라 헤맨다. 결국 항공권을 못 찾는다.

OpenTable 04:00

OpenClaw나 Hermes 같은 개인 에이전트에게 데이트 저녁 식당 예약을 시켰다.

결과: 사이트의 안티봇에 걸려 "Access Denied" 화면만 본다.

02

매번 처음부터 시작하는 천재 04:40

Opus 같은 범용 모델이나 Codex의 컴퓨터 사용 기능은 일반적인 일을 잘한다. 하지만 오래 걸리고 까다로운 사이트에서는 프로덕션으로 돌리기 어렵다.

  • 사이트마다 통하는 요령이나 실행해야 할 JavaScript를 에이전트가 모른다.
  • 가장 중요한 원인: 실행마다 0에서 시작한다. 이전 실행에서 배운 것이 남지 않는다.
  • 프로덕션의 실행 기록 trace에서 배우지 않는다.

발표자는 Darkh(추정. Dwarkesh를 말한 것으로 보인다)가 며칠 전 던진 질문을 꺼낸다. 컴퓨터 사용은 결과를 검증할 수 있는 문제처럼 보이는데 왜 아직 진전이 느린가. 발표자의 답은 학습이 일어나지 않기 때문이라는 것이다.

브라우저 에이전트는 배우지 못하는 천재다.발표자의 표현을 옮김 05:50

사이트별로 파인튜닝 fine-tuning하자는 의견도 있다. 발표자는 이 방법이 확장되지 않는다고 본다. 새 과제가 나올 때마다 모델을 다시 학습시킬 수는 없다. 필요한 것은 프로덕션 기록에서 배우며 점점 나아지는 방식이다.

지금매 실행이 처음부터같은 사이트에서 같은 실수를 반복한다
→
원하는 것실행할수록 나아진다배운 요령이 다음 실행으로 넘어간다
03

autobrowse 루프 06:10

4~6개월 전 Andrej Karpathy가 autoresearch라는 방식을 내놓았다. 검증할 수 있는 문제를 주면 에이전트가 계속 다시 시도한다. 자기 실행 기록을 보고 스스로 나아진다.

Browserbase는 이걸 브라우저 에이전트에 옮겼다. 웹사이트는 매번 똑같이 동작하지 않는다. 매일 바뀌고, 매번 다른 CAPTCHA를 낸다. 이런 환경에서도 배울 수 있는지가 질문이었다.

그 결과가 autobrowse다. autoresearch에 browsing을 붙인 이름이다. 08:10

구성 요소하는 일
실행자 doerbrowse CLI로 브라우저를 직접 조작한다. 버튼을 누르고, 스크린샷을 보고, 정보를 가져온다
교사 teacher실행자의 기록(스크린샷, 로그)을 읽고 무엇이 잘됐고 무엇이 틀렸는지 찾는다
strategy.md교사가 회차마다 배운 점을 적는 파일. 다음 회차의 실행자에게 넘어간다
SKILL.md루프가 수렴한 뒤 남기는 최종 결과물. 앞으로 쓸 에이전트에게 준다

실행자와 교사 모두 Claude Agent SDK로 만든 에이전트다.

루프가 도는 순서 09:30

  1. 실행자가 과제를 해 본다.
  2. 교사가 스크린샷과 로그를 보고 놓친 점을 찾는다. 예: "이 버튼이 아니라 저 버튼을 눌러야 한다."
  3. 교사가 배운 점을 strategy.md에 적는다.
  4. 다음 회차의 실행자는 고친 strategy.md를 받아 다시 한다.
  5. 더 짜낼 요령이 없다고 판단되면 멈춘다. 이것을 수렴 converge이라 부른다.
  6. 수렴한 결과를 SKILL.md로 정리한다. 발표자는 이것을 스킬이 졸업 graduate한다고 표현한다.
일부러 정하지 않는 것 반복 횟수, 목표 성공률, 토큰이나 시간 한도를 정하지 않는다. 넓은 지시만 주고 실행자와 교사가 알아서 하게 둔다. 발표자는 이것을 쓴 교훈 bitter lesson을 받아들이는 방식이라고 부른다. 사람이 규칙을 짜 넣기보다 계산을 많이 쓰게 두는 편이 결국 낫다는 생각이다.
04

라이브 데모: Google Flights 07:00

발표자가 무대에서 과제를 넣었다. "이번 토요일 샌프란시스코에서 뉴욕 가는 비즈니스석 항공편을 찾아라. 기내 수하물 1개, 오전 출발."

Browserbase에서 원격 브라우저가 뜨고 Google Flights로 이동한다. 에이전트의 추론 과정이 실시간으로 보인다.

회차결과내용
1회차 10:00실패배운 점: 달력 입력 위젯을 건너뛴다. 조건을 URL 쿼리 파라미터 query parameter로 넣으면 클릭할 필요가 없다
2회차 12:10성공비용이 12달러에서 3달러로 줄었다
3회차 12:40실패턴 수와 지연 시간은 줄었다. 하지만 무언가를 지나치게 고쳐서 overcorrect 실패했다
졸업 16:50성공스킬을 처음부터 끝까지 적용했고, 더 배울 것이 없었다

1회차의 요령은 지나고 보면 당연하다. 발표자는 사람이라면 이런 복잡한 URL을 직접 짜 볼 생각을 못 했을 것이라고 말한다.

데모에서 실행자와 교사는 같은 모델을 썼다. 자막에는 'Opus 48'로 나온다(추정). Opus 계열의 특정 버전을 말한 것으로 보이지만 정확한 이름은 확인하지 못했다.

졸업한 스킬에 담긴 것 11:20

  • 미리 채운 URL은 필수다. 버튼을 눌러 가며 클릭과 토큰을 낭비하지 않는다.
  • 달력이 다시 열리는 버그가 있다. 그 경로를 피한다.
  • 시간 필터를 끌어야 하면 마우스 대신 JavaScript 주입으로 처리한다.

이 요령들은 이후 모든 실행에 그대로 남는다. 발표자는 성능, 신뢰성, 비용이 모두 좋아진다고 말한다.

최종 결과는 편도 비즈니스석, 7월 4일 오전 8시 출발, 기내 수하물 1개 포함, 649달러였다. 스킬이 찾은 지름길은 "검색 조건 전체를 URL에 담는다"였다. Browserbase의 리플레이로 전 과정을 다시 보며 결과가 맞는지 확인할 수 있다.

05

이전 실행에서 나온 스킬 13:00

데모가 도는 동안 발표자는 미리 돌려 둔 실행 두 개를 보여 줬다.

AI Engineer 행사 웹사이트 13:00

과제는 "AI Engineer 웹사이트에서 힐클라이밍을 다루는 발표와 워크숍을 찾아라"였다.

모든 회차가 성공했다. 그래도 회차가 갈수록 비용은 줄었다. 발표자는 화면에서 7.4배, 4배 같은 개선 배수를 짚었다.

스킬에 남은 요령은 이렇다.

  1. 일정 페이지로 바로 간다.
  2. 열린 오류가 있으면 무작정 다시 시도하지 않는다.
  3. 세션 검색창에 키워드를 넣는다.
  4. 잠깐 기다린다. 사이트 로딩이 느릴 때가 있다.
  5. 그다음 결과를 읽는다.

회차마다 Browserbase의 리플레이 영상이 남는다. 에이전트가 실제로 무엇을 했는지 확인하는 관측 observability 용도로 쓴다.

OpenTable: 막힌 길 대신 열린 길 14:10

1회차는 처음에 본 "Access Denied" 화면에서 끝났다.

교사는 이 차단이 에이전트 실력 문제가 아니라 환경 탓이라고 판단했다. 사이트가 특정 동작을 막고 있었다.

2회차에서 길을 찾았다. 쿼리 파라미터에 위도, 경도, metro ID를 넣으면 제대로 된 화면이 바로 열린다.

차단이 걸리는 지점도 찾았다. /r 경로를 열지 않는다. /s 페이지를 새로고침하지 않는다.

최종 스킬은 이런 순서다. 검색 URL을 만든다. 날짜를 정해진 방식으로 계산한다. 샌프란시스코의 알려진 metro 값을 쓴다. /r은 절대 부르지 않는다. 부르면 Access Denied가 돌아온다.

발표자는 사람이라면 찾기 어려운 요령이라고 강조했다. 규칙을 짜 주지 않고 에이전트에게 맡기면 이런 요령을 찾아낸다는 주장이다.

06

고객 현장과 browse.sh 15:40

발표자는 세일즈 엔지니어다. 고객의 브라우저 에이전트가 프로덕션에서 성공해야 계약이 끝난다. 그래서 발표자에게 신뢰성이 가장 중요하다.

작업마다 병목이 달라서 편차가 크다. 발표자가 말하려는 점은 이런 기법으로 계속 올라갈 hill climb 수 있다는 것이다.

고객이 만든 파이프라인 17:40

예전에는 고객이 사이트마다 스크립트를 직접 썼다. 사이트를 뜯어보는 데 엔지니어 시간을 많이 썼다. 사이트가 100개, 1,000개로 늘면 감당할 수 없었다.

지금은 고객들이 이런 파이프라인을 만들었다고 한다.

  • 스킬을 필요할 때 바로 생성한다.
  • 스킬 변경을 PR로 자동으로 올린다.
  • 프로덕션에서 실패하면 에이전트가 스킬을 고친다.

browse.sh: 브라우저 에이전트용 전화번호부 18:20

한 사이트에 되면 500개 사이트에도 할 수 있다는 생각으로 만든 서비스다. 발표자는 인터넷 이전의 전화번호부 yellow pages에 비유한다. 웹사이트마다 어떤 일을 어떻게 하는지가 적혀 있다는 뜻이다.

  • browse CLI를 설치하면 스킬을 무료로 쓸 수 있다. 토큰 비용은 Browserbase가 부담한다고 했다.
  • 예: Amazon 상품 검색 스킬. 언제 쓰는지, 가격과 재고를 어떻게 보는지, 스크린샷이 들어 있다.
  • 발표자는 OpenClaw에 browse CLI를 준다. 에이전트가 상황에 따라 alltrails.com이나 weather.gov 스킬을 알아서 불러온다.
  • 뒤에서는 같은 autoresearch 루프가 돈다. 원하는 스킬을 요청하면 만들어서 이메일로 알려 준다. 예: 이번 주 샌프란시스코 행사 찾기.

발표자는 Browserbase 소속이다. 고객 수치와 browse.sh는 자사 제품 이야기이니 그 점을 감안해 읽자.

07

다른 분야로 옮기기 20:20

같은 문제는 브라우저 밖에도 있다. 에이전트가 같은 일을 매번 0에서 다시 배운다.

핵심 정리

  1. 브라우저 에이전트의 가장 큰 문제는 신뢰성이다. 발표자는 이를 모델이 아닌 엔지니어링 문제로 본다.
  2. 근본 원인은 매 실행이 0에서 시작한다는 것이다. 사이트별 요령이 쌓이지 않는다.
  3. 사이트마다 파인튜닝하는 방법은 확장되지 않는다. 실행 기록에서 배워야 한다.
  4. autobrowse는 실행자가 해 보고, 교사가 기록을 읽어 strategy.md를 고치는 루프다.
  5. 반복 횟수, 성공률, 예산을 정하지 않고 수렴할 때까지 둔다. 수렴하면 SKILL.md로 졸업한다.
  6. 루프가 찾는 요령은 대개 클릭을 건너뛰는 지름길이다. URL 쿼리 파라미터, JavaScript 주입, 차단 경로 피하기가 그 예다.
  7. 데모 수치: Google Flights 12달러 → 3달러, OpenTable 6.22달러 → 0.51달러.
  8. 다른 분야에 쓰려면 재현 가능한 환경과 검증 가능한 결과가 있어야 한다.
  9. 사이트는 바뀐다. 프로덕션 실패나 정기 점검을 계기로 루프를 다시 돌려 스킬을 고친다.
  10. 웹에서 배우는 만큼 프롬프트 인젝션에 노출된다. 입력, 스킬, 인프라 세 층에서 막는다.

strategy.md는 회차마다 교사가 고치며 다음 회차로 넘기는 작업 파일이다. SKILL.md는 루프가 수렴한 뒤 남기는 최종 결과물로, 앞으로 쓸 에이전트에게 준다.
Q5루프에 일부러 정해 주지 않는 것 세 가지와 그 이유는?
반복 횟수, 목표 성공률, 토큰이나 시간 한도. 사람이 규칙을 짜 넣기보다 계산을 많이 쓰게 두는 편이 낫다는 쓴 교훈을 따른 것이다.
Q6Google Flights 데모 1회차에서 교사가 찾은 요령은?
달력 입력 위젯을 건너뛰고 조건을 URL 쿼리 파라미터로 넣는다. 클릭과 토큰을 아낀다.
Q7OpenTable에서 차단을 피한 방법과 그 결과는?
위도, 경도, metro ID를 쿼리 파라미터로 넣어 바로 결과 화면을 연다. /r을 열지 않고 /s를 새로고침하지 않는다. 비용은 6.22달러에서 0.51달러로, 시간은 189초에서 27초로 줄었다.
Q8이 방법을 다른 분야에 쓰기 위한 두 조건은?
같은 조건으로 다시 돌려 볼 수 있는 환경, 그리고 성공을 판정하거나 숫자로 잴 수 있는 결과.
Q93회차처럼 성공 뒤에 실패가 다시 나오면 어떻게 봐야 하나?
흔히 있는 일이다. 루프가 한 번의 실패에 지나치게 반응하지 않고 스스로 회복하도록 설계해야 한다. 루프 구조 자체도 실험 대상이다.
Q10지연 시간을 목표로 주면 루프가 찾아내기도 하는 극단적인 해법은?
브라우저를 아예 빼고 사이트의 API를 역공학해 직접 부른다. 0.5초 만에 끝나는 해법을 찾은 적도 있다.
Q11사이트가 바뀌어도 스킬을 최신으로 유지하는 방법 두 가지는?
프로덕션 실패를 계기로 루프를 돌려 스킬을 고치고 PR로 사람에게 보낸다. 또는 cron으로 정기 샘플 실행을 돌려 실패하면 치유 루프를 시작한다.
Q12프롬프트 인젝션을 막는 세 층은?
입력 층(하네스에 닿기 전에 거르기), 스킬 층(보안 리뷰 에이전트 검사), 인프라 층(갈 수 있는 URL과 동작 제한, 네트워크 방화벽).

용어 정리

용어뜻
브라우저 에이전트Browser agent. 브라우저를 도구로 써서 클릭, 입력, 화면 읽기를 하며 일하는 AI 에이전트
힐클라이밍Hill climbing. 조금씩 바꿔 보고 결과가 나아지는 쪽으로 계속 나아가는 개선 방식
하네스Harness. 모델을 감싸 도구, 프롬프트, 스킬, 실행 순서를 정해 주는 틀
접근성 트리Accessibility tree. 화면의 버튼, 글, 입력창을 구조로 정리한 것. 에이전트가 페이지를 글로 읽을 때 쓴다
안티봇 / CAPTCHA사람이 아닌 접근을 가려내 막는 사이트의 장치
autoresearchKarpathy가 내놓은 방식. 검증 가능한 문제를 두고 에이전트가 반복해 시도하며 자기 기록을 보고 나아진다
autobrowseautoresearch를 브라우저 작업에 옮긴 Browserbase의 루프
실행자 / 교사Doer / Teacher. 실행자는 과제를 직접 하고, 교사는 그 기록을 읽어 전략을 고친다
strategy.md교사가 회차마다 배운 점을 적는 파일. 다음 회차로 넘어간다
SKILL.md루프가 수렴한 뒤 남기는 요령 모음. 다른 에이전트에 그대로 줄 수 있는 마크다운 파일
수렴 / 졸업더 나아질 점이 없어 루프를 멈추는 것 / 그 결과를 스킬로 확정하는 것
실행 기록Trace. 에이전트가 단계마다 실행한 명령, 받은 출력, 스크린샷을 남긴 것
쿼리 파라미터Query parameter. URL 뒤에 붙는 조건값. 예: 날짜, 좌석 등급
JavaScript 주입페이지에 스크립트를 직접 실행시켜 조작하는 방법. 마우스 드래그처럼 까다로운 동작을 대신한다
쓴 교훈Bitter lesson. 사람이 짜 넣은 규칙보다 계산을 많이 쓰는 일반적인 방법이 결국 더 잘된다는 주장. Rich Sutton의 글에서 나왔다
재현 가능한 환경Replayable environment. 같은 조건에서 여러 번 다시 돌려 볼 수 있는 실행 환경
검증 가능한 결과Verifiable outcome. 성공했는지 판정하거나 숫자로 잴 수 있는 결과
log loss신경망 학습에서 예측이 얼마나 틀렸는지 재는 값. 낮을수록 좋다
검증기Verifier. 에이전트의 결과가 맞는지 판정하는 장치나 모델
평가 (eval)여러 전략이나 모델의 결과 품질을 비교해 재는 테스트 묶음
상각Amortize. 한 번 든 비용을 여러 번 쓰며 나눠 갚는 것
cron정해진 시간마다 작업을 자동으로 실행하는 예약 장치
프롬프트 인젝션Prompt injection. 입력 안에 지시문을 숨겨 AI가 원래 지시 대신 그걸 따르게 만드는 공격
WebMCP웹사이트가 자기 기능을 에이전트용 도구로 알려 주는 방식. 브라우저 안의 API와 비슷하다
