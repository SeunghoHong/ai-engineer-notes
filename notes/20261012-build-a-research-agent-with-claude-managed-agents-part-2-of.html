Claude Managed Agents로 리서치 에이전트 만들기

Anthropic의 관리형 에이전트 서비스로 SEC 공시를 분석하는 리서치 앱을 단계별로 키우는 실습이다. 핵심은 에이전트가 일을 나누고, 기억을 나누고, 자기 결과를 스스로 채점하게 만드는 것이다.

원본 영상: Build a Research Agent with Claude Managed Agents (Part 2 of 4) 발표: Gabe, Priyanka(추정) · Anthropic

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 영상은 앞선 발표의 질의응답 도중에 시작하고, 여러 세션 오케스트레이션 시연 직전에 끝난다. 제품 기능과 계획은 모두 발표진이 말한 것이고 공식 문서와 대조하지는 않았다. 발표진은 이 제품을 만든 Anthropic 사람들이다. 자막에서 뭉개진 이름은 확실한 것만 바로잡고, 불확실한 것은 들린 대로 쓰고 (추정)을 붙였다. mm:ss는 영상 위치다.

3분 요약
  1. Claude Managed Agents는 에이전트를 Anthropic 클라우드에서 대신 돌려 준다. 개발자는 세션을 열고 이벤트를 주고받기만 하면 된다.
  2. 재료는 세 가지다. 에이전트(프롬프트·모델·도구), 환경(샌드박스 템플릿), 세션(실제 실행)이다.
  3. 채팅 앱은 이벤트 스트림 하나로 끝난다. 메시지 이벤트를 올리고, 받은 이벤트를 화면에 흘려보낸다.
  4. 에이전트에 스킬, 서브에이전트, 자기 참조, 커스텀 도구, 메모리 스토어를 붙여 리서치 데스크로 키운다.
  5. Outcomes는 할 일과 채점 기준을 받아 일한 뒤, 별도 서브에이전트가 채점하게 한다. 기준에 못 미치면 다시 한다.
  6. 비밀값은 볼트에 둔다. 샌드박스에는 가짜 값만 있고, 허용한 도메인으로 나갈 때만 진짜 값으로 바뀐다.
  7. 아직 없는 것도 분명하다. 세션당 예산 상한, 되감기와 포킹, 서브에이전트 단위 채점은 지금 없다.
01

세 가지 재료: 에이전트, 환경, 세션 01:20

Claude Managed Agents(줄여서 CMA)는 에이전트를 Anthropic 클라우드에서 대신 돌려 주는 서비스다. 첫 발표자 Priyanka(추정)가 콘솔Console에서 농담하는 에이전트를 만들며 기본 구조를 보여 줬다.

재료뜻시연에서 한 일
에이전트 agent무엇을 어떻게 할지 정한 설정. 시스템 프롬프트, 이름, 설명, 모델, 도구를 담는다"주제를 주면 농담하는 에이전트를 만들어 줘"라고 입력했다. Claude가 프롬프트와 이름을 쓰고 모델을 골랐다. 만들기를 누르면 /v1/agents 엔드포인트가 호출된다
환경 environment샌드박스의 템플릿. 접속할 수 있는 도메인과 설치할 패키지를 정한다 02:00네트워크를 제한 없이 열었다. 실제 서비스라면 접속할 도메인이나 MCP 서버를 좁혀야 한다고 했다
세션 session에이전트를 환경 위에서 실제로 한 번 돌리는 단위 02:40"고양이 농담 해 줘"를 보냈다. 모델이 생각한 뒤 고양이 농담을 돌려줬다

샌드박스sandbox는 에이전트가 명령과 코드를 실행하는 격리된 컴퓨터다. MCPModel Context Protocol는 에이전트가 외부 도구와 데이터에 접속하는 표준 방식이다.

개발자가 맡는 일, Anthropic이 맡는 일 03:10

개발자
  • 세션을 시작한다
  • 이벤트를 보낸다
  • 이벤트를 받는다
  • 그 위에 제품을 만든다
Anthropic (발표자 설명)
  • 인프라와 호스팅
  • 하네스harness: 모델을 감싸 도구 호출과 실행 순서를 처리하는 틀
  • 샌드박스 관리
  • 규모 확장
  • 이벤트 기록 저장

자사 제품을 소개하는 자리다. "나머지는 우리가 다 관리한다"는 설명은 그 점을 감안해 읽자.

환경의 패키지는 언제 설치되나 34:20 질의응답에서 나온 내용이다. 패키지는 환경을 만들 때 설치된다. 그 뒤로는 캐시해 두고, 환경을 다시 띄울 때 재사용한다. 패키지는 npm, cargo, pip처럼 공개 저장소에서 받을 수 있어야 한다. 사내 패키지는 파일이나 GitHub 저장소를 세션에 직접 올려 설치하면 된다.
02

워크숍 준비와 전체 흐름 03:30

여기서부터 Gabe가 실습을 이끈다. 만들 것은 SEC 공시를 분석하는 리서치 앱이다. SEC는 미국 증권거래위원회다. 공시는 상장사가 SEC에 내는 보고서다.

이번 워크숍에서 만드는 것 04:40

발표자는 워크숍을 6막으로 나눴다고 했다. 소개한 흐름은 다음과 같다.

  1. 채팅 화면: 에이전트와 대화하는 화면을 직접 만든다.
  2. 멀티 에이전트와 스킬: 에이전트가 서브에이전트에게 일을 나눈다. 종목별 SEC 공시를 가져와 분석하는 스킬을 준다.
  3. 오래 걸리는 비동기 작업: 강화한 에이전트에게 긴 분석을 맡긴다.
  4. 맵리듀스형 오케스트레이션: 한 에이전트가 여러 세션에 일을 나눠 주고 결과를 모은다. CMA 위에 직접 만든 하네스와 커스텀 도구로 조율한다.
  5. 정기 실행: deployments API로 세션을 정해진 주기마다 돌린다. 스스로 갱신되는 장기 분석을 만든다.
이 영상의 범위 이 영상은 3번(비동기 작업)과 스킬 수정까지 보여 준다. 4번과 5번은 계획만 소개됐다. 시연은 영상이 끝난 뒤로 넘어갔다.

준비 단계 06:10

코드는 손으로 쓰지 않는다. 발표자는 Claude Code를 썼고, 다른 코딩 에이전트를 써도 된다고 했다.

  1. 워크숍 저장소를 클론하고 research desk 디렉터리로 들어간다.
  2. bun i로 의존성을 설치한다. bun run dev로 서버를 띄운다.
  3. 웹 페이지의 Setup 화면을 연다.
  4. Claude Code에서 workshop start를 입력한다. 저장소에 든 워크숍 스킬이 단계별로 진행한다. 07:40
  5. .env.example을 .env.local로 복사하고 API 키를 넣는다. 08:20
  6. 같은 파일에 이름과 이메일을 넣는다. SEC는 API를 부르는 사람이 누구인지 알고 싶어 한다. 이 값이 EDGAR 식별자EDGAR identity다.

다음 단계로 넘어갈 때는 workshop next를 입력한다. 지금 몇 막인지는 Claude가 기억한다. 발표자는 Claude에게 "하는 일을 가르쳐 가며 진행해 달라"고 부탁했다. 워크숍 스킬이 저장소에 있으니 집에서 혼자 다시 돌려 볼 수 있다.

03

첫 단계: 채팅 화면 붙이기 11:00

Setup 화면의 버튼을 누르면 두 가지가 만들어진다.

  • 환경: SEC를 중심으로 몇몇 사이트에만 접속할 수 있다. SEC를 부를 때 쓸 Python 패키지를 미리 깐다.
  • 에이전트: 프롬프트와 기본 도구만 있다. 스킬도 없고, 서브에이전트 조율도 없다.

대화는 이벤트 스트림 하나로 12:00

세션과의 소통은 이벤트 스트림event stream으로 한다. 에이전트가 보내는 이벤트는 스트림을 듣고 받는다. 내 쪽 이벤트는 엔드포인트로 올린다. 채팅형 앱에서 오가는 모든 것이 이 스트림 위에서 일어난다.

  1. 사용자가 채팅창에서 Enter를 누른다.
  2. 백엔드가 입력 내용을 사용자 메시지 이벤트user message event로 세션에 보낸다.
  3. 백엔드는 API와 연결한 SSE 스트림을 듣는다. SSEServer-Sent Events는 서버가 이벤트를 계속 밀어 보내는 연결 방식이다.
  4. 받은 이벤트를 브라우저로 다시 흘려보낸다. 프론트엔드가 이를 보기 좋게 그린다.

Desk 탭에서 인사를 보내면 에이전트가 답한다. 13:00

발표자는 여기서 CMA의 진짜 목적을 짚었다. 13:20

04

에이전트 강화: 스킬, 서브에이전트, 메모리 13:40

발표자는 다음 목표를 "지능의 사다리를 올라가는 것"이라고 표현했다. workshop next를 입력하면 Claude가 에이전트를 업그레이드하는 코드를 쓴다. 필요한 자원을 미리 만들어 두는 이 작업을 프로비저닝provisioning이라고 한다.

붙이는 것역할이 데모에서
스킬 skill특정 작업을 하는 방법을 적어 둔 묶음SEC를 부르는 법. Python 패키지 사용법과, EDGAR 식별자를 써야 한다는 점까지 적었다
서브에이전트 sub-agent메인 에이전트가 일을 맡기는 전문 에이전트. 각자 프롬프트, 도구, 권한을 따로 가진다뒤의 실행 기록에서는 재무 분석 서브에이전트와 위험 평가 서브에이전트가 쓰였다
자기 참조 self-reference메인 에이전트가 자기와 같은 프롬프트의 복제본을 서브에이전트로 띄운다 15:10아래 두 상자에서 설명한다
커스텀 도구 custom tool개발자가 입력 스키마를 정하고, 호출되면 내 서버가 처리하는 도구 14:40dispatch analysis(이름은 들린 대로). 나중에 "리서치 총괄" 에이전트가 여러 세션을 띄울 때 쓴다
메모리 스토어 memory store여러 세션이 함께 쓰는 오래가는 기억 저장소 16:40세션마다 다른 종목을 공부한다. 알게 된 것은 메모리에 남겨 서로 나눈다

에이전트의 설정을 바꾸면 그 에이전트의 새 버전이 만들어진다. 15:00

자기 참조를 두는 이유 세션이 어떤 일을 하게 될지 미리 다 알기는 어렵다. 그래도 일을 나눠 맡길 서브에이전트는 있었으면 한다. 이럴 때 자기 복제본을 열어 두면 Claude가 필요할 때 띄워 쓴다.
복제본은 대화 기록을 물려받지 않는다 15:40 자주 나온 질문이라고 했다. 복사되는 것은 프롬프트, 도구 설명, 스키마뿐이다. 지금 세션의 대화 기록transcript은 넘어가지 않는다. 서브에이전트에게 필요한 맥락은 따로 전해야 한다는 점을 기억하자.

Setup 화면의 "Staff the desk" 버튼을 누르면 이 자원들이 한꺼번에 만들어진다. 16:10 결과 화면에서 에이전트는 스킬, 서브에이전트, 프롬프트, 모델을 모두 갖췄다. 17:10

발표자는 워크숍 끝에 이 메모리로 에이전트를 며칠, 몇 달, 몇 년에 걸쳐 개선하는 법을 보여 주겠다고 했다. 질의응답에서 나온 설명은 공유 기억과 dreaming에 정리했다.

05

Outcomes: 스스로 채점하는 장시간 작업 17:40

이번에는 채팅이 아니다. "이 종목을 조사해서 내가 정한 형식으로 보고서를 줘" 같은 비동기 작업이다.

여기에 아웃컴outcomes을 쓴다. 발표자는 이것을 Anthropic이 만든 자기 감독self-supervision 방식이라고 소개했다.

  1. 할 일과, 그 일을 평가할 루브릭rubric을 준다. 루브릭은 채점 기준표다.
  2. Claude가 일을 한다.
  3. 끝났다고 판단하면 서브에이전트에게 채점을 맡긴다. 이 서브에이전트는 루브릭과 결과물을 함께 본다.
  4. 채점 질문은 두 가지다. 제대로 했는가, 끝까지 했는가.
  5. 통과하면 끝난다. 통과하지 못하면 다시 시도한다.

앱은 종목 하나로 세션을 시작할 때마다 outcome을 정의하는 사용자 이벤트를 보낸다. 18:20 이 이벤트에는 작업 설명, 루브릭, 최대 반복 횟수max iterations가 들어간다.

이벤트 이름은 자막에 "user defined outcome"으로 들렸다. 정확한 API 이름은 추정이다.

Scorecard 화면에서 Nvidia 분석을 요청하자 세션이 시작됐다. 18:50 발표자에 따르면 10분 정도 걸린다.

서브에이전트의 일도 따로 채점하나 31:20 질의응답에서 나온 질문이다. outcome은 세션 전체 단위로 정의한다. 메인 에이전트가 서브에이전트들과 협업해 일을 하고, 마지막에 "끝났다"고 말한다. 서브에이전트 단위의 outcome은 지금은 없다. 발표자 설명으로는 서브에이전트는 세션의 맥락을 넓히고 능력을 키우는 협업 수단이다.
06

한 세션을 처음부터 끝까지 19:10

분석이 오래 걸려서 발표자는 전날 돌려 둔 세션을 대신 보여 줬다.

핵심 정리

  1. CMA는 에이전트, 환경, 세션 세 재료로 이루어진다. 개발자는 세션을 열고 이벤트를 주고받는다.
  2. 환경은 샌드박스 템플릿이다. 실제 서비스에서는 접속 도메인을 좁힌다. 패키지는 만들 때 설치되고 캐시된다.
  3. 채팅 앱은 이벤트 스트림 하나면 된다. 사용자 메시지 이벤트를 올리고, SSE로 받은 이벤트를 화면에 다시 흘린다.
  4. 에이전트를 키우는 재료는 스킬, 서브에이전트, 자기 참조, 커스텀 도구, 메모리 스토어다. 설정을 바꾸면 새 버전이 생긴다.
  5. 자기 복제 서브에이전트는 프롬프트, 도구 설명, 스키마만 받는다. 대화 기록은 받지 않는다.
  6. Outcomes = 작업 설명 + 루브릭 + 최대 반복 횟수. 별도 서브에이전트가 채점하고, 미달이면 다시 한다. 단위는 세션 전체다.
  7. 콘솔에서 스레드 단위로 서브에이전트의 작업을 끝까지 볼 수 있다.
  8. 스킬은 언제든 고칠 수 있다. 고친 뒤 시작하는 세션이 새 내용을 쓴다. 종목이 많으면 커스텀 도구와 내 서버의 하네스로 세션을 나눠 돌린다.
  9. 비밀값은 볼트에 둔다. 사내 데이터는 MCP(필요하면 터널)나 자체 호스팅 샌드박스로 연결한다.
  10. 아직 없는 것: 세션당 예산 상한, 되감기와 포킹, 서브에이전트 단위 outcome, 메모리 밖으로 넓힌 dreaming.

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1CMA의 세 재료인 에이전트, 환경, 세션은 각각 무엇인가?
에이전트는 프롬프트, 모델, 도구 등을 담은 설정이다. 환경은 접속 도메인과 패키지를 정한 샌드박스 템플릿이다. 세션은 에이전트를 환경 위에서 실제로 한 번 돌리는 단위다.
Q2채팅 화면에서 메시지는 어떤 경로로 오가나?
사용자가 Enter를 누르면 백엔드가 사용자 메시지 이벤트로 세션에 보낸다. 응답은 백엔드가 SSE 스트림으로 듣고, 브라우저로 다시 흘려보낸다.
Q3자기 참조로 띄운 서브에이전트가 물려받는 것과 물려받지 않는 것은?
프롬프트, 도구 설명, 스키마는 물려받는다. 지금 세션의 대화 기록은 물려받지 않는다.
Q4자기 참조는 왜 두나?
세션이 어떤 일을 하게 될지 미리 다 모를 때가 많다. 자기 복제본을 열어 두면 필요할 때 Claude가 띄워 일을 나눌 수 있다.
Q5outcome 정의에 담는 세 가지와 채점 방식은?
작업 설명, 루브릭, 최대 반복 횟수다. Claude가 끝났다고 판단하면 서브에이전트가 루브릭과 결과물을 보고 제대로, 끝까지 했는지 판정한다. 미달이면 다시 시도한다.
Q6Nvidia 분석 outcome이 요구한 결과물 두 가지는?
메모리에 남기는 회사 노트, 그리고 정해진 파일 위치에 저장하는 구조화된 스코어카드(JSON)다.
Q7outcome에 "메모리부터 확인하라"를 넣은 이유는?
이미 분석한 내용을 다시 조사하지 않고 재사용하기 위해서다.
Q8스킬을 고치면 어느 세션에 반영되나?
고친 뒤 새로 시작하는 세션 중, 그 스킬을 참조하는 세션이다.
Q9볼트에서 진짜 비밀값이 붙는 시점과 조건은?
요청이 밖으로 나가는 지점(egress)에서 붙는다. 그 비밀값에 허용한 도메인으로 갈 때만 바뀐다. 다른 도메인으로는 자리표시자가 그대로 나간다.
Q10MCP 서버를 인터넷에 열기 싫을 때, 그것도 부담일 때 각각 어떤 길을 쓰나?
열기 싫으면 MCP 터널을 쓴다. 터널도 부담이면 내 네트워크와 연결된 자체 호스팅 샌드박스를 쓴다.
Q11Agent SDK와 CMA는 어떻게 다른가?
Agent SDK는 화면 없이 쓰는 Claude Code 바이너리로, 직접 돌린다. CMA는 Anthropic 클라우드에서 돌아가는 완전 호스팅 서비스이고, 범용으로 새로 만든 하네스를 쓴다.
Q12발표 시점에 아직 없는 기능 네 가지는?
세션당 비용·토큰 상한, 되감기와 세션 포킹, 서브에이전트 단위 outcome, 메모리 스토어 밖으로 넓힌 dreaming.

용어 정리

용어뜻
Claude Managed Agents (CMA)에이전트 실행에 필요한 인프라를 Anthropic이 대신 운영하는 서비스
에이전트 agent시스템 프롬프트, 모델, 도구, 스킬, 서브에이전트를 묶은 설정. 바꾸면 새 버전이 생긴다
환경 environment샌드박스의 템플릿. 접속할 수 있는 도메인과 설치할 패키지를 정한다
샌드박스 sandbox에이전트가 명령과 코드를 실행하는 격리된 컴퓨터
세션 session에이전트를 환경 위에서 실제로 한 번 돌리는 단위. 이벤트를 주고받으며 진행된다
이벤트 스트림 event stream세션과 앱이 이벤트를 주고받는 통로
SSEServer-Sent Events. 서버가 브라우저나 클라이언트로 이벤트를 계속 밀어 보내는 연결 방식
하네스 harness모델을 감싸 도구 호출, 실행 순서, 규칙을 처리하는 실행 틀
서브에이전트 sub-agent메인 에이전트가 일을 맡기는 전문 에이전트. 각자 프롬프트, 도구, 권한을 가진다
자기 참조 self-reference메인 에이전트가 자기와 같은 정의의 복제본을 서브에이전트로 띄우게 하는 설정
스킬 skill특정 작업을 하는 방법을 적어 둔 묶음. 고치면 이후 새 세션이 바로 쓴다
커스텀 도구 custom tool개발자가 입력 스키마를 정하고, 호출되면 내 서버가 처리하는 도구
메모리 스토어 memory store여러 세션이 함께 읽고 쓰는 오래가는 기억 저장소
아웃컴 outcome할 일, 루브릭, 최대 반복 횟수를 정해 두고 결과를 스스로 채점하게 하는 기능
루브릭 rubric결과물을 평가하는 채점 기준표
스레드 thread콘솔에서 서브에이전트 하나가 한 일을 보여 주는 단위
볼트 vault자격 증명을 묶어 두는 곳. 샌드박스엔 자리표시자만 두고, 허용한 도메인으로 나갈 때만 진짜 값으로 바꾼다
egress요청이 샌드박스에서 바깥으로 나가는 지점
MCPModel Context Protocol. 에이전트가 외부 도구와 데이터에 접속하는 표준 방식
MCP 터널 MCP tunnelMCP 서버를 인터넷에 열지 않고 내 네트워크와 Anthropic 네트워크를 잇는 통로
자체 호스팅 샌드박스Self-hosted sandbox. 샌드박스만 내 인프라나 내가 고른 업체에서 돌리는 방식
dreaming여러 세션의 기록과 메모리를 분석해 메모리를 고쳐 쓰는 기능. 발표 시점에는 메모리 스토어에만 적용된다
방향 바꾸기 steering실행 중인 세션에 새 메시지를 보내 진행 방향을 바꾸는 것
세션 포킹 session forking세션을 특정 시점에서 갈라 다른 지시로 다시 진행하는 기능. 발표 시점에는 로드맵 항목이다
맵리듀스 map-reduce일을 여러 곳에 나눠 처리하고(map) 결과를 모으는(reduce) 구조
Agent SDK화면 없이 쓰는 Claude Code. 바이너리로 받아 직접 돌린다
deployments API세션을 정해진 주기로 돌리게 하는 기능. 이 영상에서는 예고만 했다
EDGARSEC의 전자 공시 시스템. API를 부를 때 이름과 이메일로 신원을 밝혀야 한다
티커 ticker증권 시장에서 종목을 가리키는 짧은 코드
OAuth비밀번호를 넘기지 않고 권한 토큰으로 다른 서비스에 접근하게 하는 표준
잠금 lock-in한 업체의 서비스에 묶여 다른 곳으로 옮기기 어려운 상태
