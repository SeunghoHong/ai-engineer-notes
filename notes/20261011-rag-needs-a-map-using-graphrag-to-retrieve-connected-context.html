RAG에는 지도가 필요하다

벡터 검색만으로는 "이것과 저것이 어떻게 이어지는가"를 답하기 어렵다. 그래프 RAG는 검색 경로에 지식 그래프를 넣어 연결된 맥락을 꺼내고, 에이전트가 어떤 길로 답에 도달했는지 추적할 수 있게 한다. 이 워크숍은 개념 설명과 Neo4j 실습을 함께 담은 입문 과정이다.

원본 영상: RAG Needs a Map: Using GraphRAG to Retrieve Connected Context 발표: Nyah Macklin (Neo4j 시니어 소프트웨어 엔지니어 · 시니어 개발자 애드보킷)

영어 워크숍의 자동 자막을 바탕으로 한글로 정리했다. 수치와 주장은 모두 발표자가 말한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 이름이 뭉개진 곳은 확실한 것만 알려진 이름으로 바로잡았고, 나머지는 "(추정)"을 붙였다. mm:ss는 영상 위치다.

발표자는 그래프 데이터베이스 회사 Neo4j 소속이다. 그래프 RAG의 장점과 Neo4j 제품(Aura, Graph Academy, GraphRAG for Python)에 대한 설명은 그 점을 감안해 읽자.

3분 요약
  1. 데이터는 표, 벡터, 지식 그래프로 표현할 수 있다. 표는 조인이 많아 느리고, 벡터는 사람이 읽을 수 없다. 지식 그래프는 사람과 기계가 모두 읽을 수 있다.
  2. 그래프 RAG는 RAG의 한 종류다. 검색 경로에 지식 그래프가 포함된다는 점만 다르다.
  3. 검색 엔진으로 풀리는 질문은 벡터 RAG로 충분하다. 세 단계 이상 건너뛰어야 하는 질문, 여러 문서를 모아 세거나 합쳐야 하는 질문은 그래프 RAG가 필요하다.
  4. 발표자의 결론은 둘 다 쓰라는 것이다. 그래프가 벡터를 대체하는 게 아니라 벡터 위에 더해진다.
  5. 지식 그래프는 LLM으로 만들 수 있다. 문서를 모으고, 자르고, 임베딩하고, LLM에게 개체와 관계를 JSON으로 뽑게 한 뒤 Cypher로 그래프를 만든다.
  6. 실습에서는 GraphRAG for Python 패키지로 Graph Academy 강의 PDF를 그래프로 만들고, Aura 에이전트에 유사도 검색 도구와 자연어→Cypher 도구를 붙여 질문했다.
  7. 에이전트는 "강의가 몇 개냐"는 집계 질문에 30이라고 답했지만 실제는 15였다. 빌더를 두 번 돌려 데이터가 중복됐기 때문이다. 그래프를 직접 조회하면 바로 드러난다.
01

사과 하나, 세 가지 표현 07:10

발표자는 AI의 블랙박스 문제를 넘으려면 지식과 데이터 자체가 투명해야 한다고 말한다. 같은 사과를 세 가지로 표현해 보면 차이가 보인다.

표현모습누가 읽나
사람의 눈빨갛고 둥근 과일 사진사람
벡터 vector소수점 숫자가 길게 늘어선 배열기계. 사람은 외우지 않는 한 읽을 수 없다
지식 그래프 knowledge graph사과 → 나무에서 난다, 둥글다, 빨갛다, 과일이다 (회사가 아니다)사람과 기계 모두

세상의 모든 것은 벡터로도 표현할 수 있다. 하지만 지식 그래프는 사람이 이해하는 것을 기계도 이해하게 만들고, 둘의 읽기 방식을 하나로 합친다.

02

표와 벡터가 놓치는 것 09:10

지금 대부분의 데이터는 표(행과 열)이거나 벡터다. 표로 저장하면 행과 행이 어떻게 이어지는지 알아내려고 조인을 여러 번 해야 하고, 조인이 쌓이면 애플리케이션이 느려진다.

같은 데이터를 지식 그래프로 두면 관계와 묶음이 바로 드러난다. 에이전트는 노드(동그라미)에서 관계(선)를 따라 다음 노드로 한 칸씩 건너뛰며 과거에 무슨 일이 있었는지 추적하고 설명할 수 있다.

규제가 있는 분야에서 더 중요하다 금융, 의료, 법률처럼 규제가 있는 분야에서는 에이전트가 왜 그 결정을 내렸는지 맥락과 이력이 꼭 필요하다. 발표자는 "아무도 바이브 뱅킹을 원하지 않는다"고 농담했다. 에이전트가 내 돈에 접근해 마음대로 쓰는 상황은 실제로 본 적이 있다고 한다.

에이전트 메모리는 이 발표에서 다루지 않았다. 발표자는 별도의 발표에서 다룬다고 했다.

03

RAG와 그래프 RAG의 구조 11:40

RAG Retrieval-Augmented Generation는 질문에 답하기 전에 외부 자료를 찾아 LLM에 함께 넣어 주는 방식이다. 보통의 RAG와 그래프 RAG는 한 가지만 다르다.

보통 RAG벡터 저장소만 검색한다PDF → 조각내기 → 임베딩 모델로 색인 → 질문도 같은 모델로 임베딩 → 가장 비슷한 조각 k개 → LLM → 답
→
그래프 RAG검색 경로에 지식 그래프가 들어간다나머지 흐름은 같다. 조각과 함께 그래프에서 연결된 노드와 관계를 꺼내 LLM에 준다
그래프 RAG는 근본적으로 RAG다. 다만 검색 경로에 지식 그래프가 포함된다.발표자의 정의를 옮김 12:30
04

언제 그래프 RAG를 쓰나 12:50

벡터 RAG로 충분한 경우
  • 검색 엔진으로 풀 수 있는 질문
  • 비슷한 문단 하나를 찾으면 끝나는 질문

발표자도 대부분의 쓰임새에서 벡터 RAG가 충분히 강력하다고 인정한다.

그래프 RAG가 필요한 경우
  • 여러 단계를 건너뛰어야 하는 질문. 발표자 기준은 세 단계 이상
  • 소스 코드 분석
  • 공급망 질문
  • 여러 문서의 내용을 모아 세거나 합쳐야 하는 질문

에이전트가 어디를 거쳐 답에 도달했는지 볼 수 있다는 점이 핵심이다.

결론: 둘 다 쓴다 그래프가 벡터 계층을 완전히 대체한다는 뜻이 아니다. 둘을 함께 쓰면 양쪽의 장점을 다 얻는다. 발표자의 표현으로는 "덧붙이자"다.
05

리트리버와 데이터 소스 16:10

리트리버 retriever는 RAG의 핵심 부품이다. 외부 데이터에서 관련 정보를 찾아오는 일을 맡는다. 발표자는 공을 물어오는 골든 리트리버에 빗댄다. 질문이나 프롬프트 같은 비정형 입력을 받아, 구조화된 데이터를 뒤져 답의 맥락을 가져온다.

Neo4j가 지원하는 리트리버하는 일
전문 검색 full-text단어가 들어 있는 텍스트를 찾는다
벡터 검색 vector뜻이 비슷한 텍스트 조각을 찾는다
텍스트→Cypher text-to-Cypher자연어 질문을 그래프 질의어로 바꿔 그래프를 직접 조회한다

데이터 소스는 하나가 아니다 17:20

문서, API, 지식 그래프가 모두 데이터 소스가 될 수 있다. 발표자는 뉴스 챗봇을 예로 들었다.

  • 뉴스 API: 최신 기사와 헤드라인을 가져온다
  • 지식 그래프: 주제들이 서로 어떻게 이어지는지, 역사적 맥락에서 어떤 관계인지 이해한다
  • 문서 데이터베이스: 기사, 보고서 같은 본문을 저장하고 꺼낸다

그래프 RAG의 장점으로 발표자는 더 풍부한 맥락, 정확도 향상, 설명 가능성을 꼽는다. 그래프 탐색에 에이전트 메모리를 더하면 역사적 맥락까지 얻을 수 있다.

06

지식 그래프란 18:40

지식 그래프는 현실 세계의 개체 entity와 그 사이 관계 relationship를 정리한 표현이다. 발표자는 자신과 동료를 예로 든다.

  • 발표자는 노드다. 동료 Jeremy도 노드다.
  • 두 노드 사이에 관계가 둘 있다. "동료다", "친구다".
  • Zach, Ryan 같은 다른 동료 노드로 계속 이어진다.

이것이 지식 그래프의 가장 단순한 형태다. 데이터를 가장 단순하게 표현한 것일 뿐이다.

07

LLM으로 지식 그래프 만들기 19:50

비정형 텍스트에서 지식 그래프를 만드는 과정은 다섯 단계다. 예시는 Neo4j 위키백과 문서다.

  1. 모으기: 문서에서 텍스트를 전부 가져온다.
  2. 자르기: 텍스트를 조각 chunk으로 나눈다.
  3. 임베딩: 조각마다 벡터를 만든다.
  4. 추출: LLM에게 개체와 관계를 뽑게 한다. 손으로 해도 되지만 LLM이 시간을 크게 줄인다.
  5. 그래프 생성: 추출 결과를 파싱해 Cypher로 그래프를 만든다.
추출 프롬프트의 뼈대 21:00 "주어진 텍스트에서 요청한 개체와 관계를 찾아라. 출력은 JSON 객체 목록을 담은 JSON 형식으로 만들어라." 이 출력을 파싱해 그래프를 만든다.

생성된 그래프 예시는 이렇다. 그래프 데이터베이스 Neo4j는 회사 Neo4j가 개발했고, Java로 구현됐다. 발표자는 회사가 그래프 데이터베이스 전체를 만든 게 아니라 Neo4j라는 제품을 만든 것이라고 덧붙였다.

여담: Neo4j라는 이름은 영화 매트릭스의 Neo와 "for Java"에서 왔다고 발표자가 소개했다.

Cypher Cypher는 그래프에 최적화된 질의 언어다. 관계형 데이터베이스의 SQL에 해당한다.

그래프 생성과 확인 28:40

저장소에는 원본 데이터, 풀이 코드, 에이전트, 그리고 지식 그래프 빌더 두 개가 들어 있다. 이 중 구조화된 지식 그래프 빌더를 실행하면 Aura 인스턴스에 그래프가 실시간으로 쌓인다. 시간이 꽤 걸린다.

Aura 콘솔의 Query 화면에서 아래 질의를 실행하면 노드와 관계가 전부 그려진다. 빌더가 돌고 있는 동안 다시 실행하면 그래프가 커지는 게 보인다.

MATCH p = ()-[]->()
RETURN p

위 질의는 자막에서 "match p equals 빈 노드, 화살표, 빈 노드, return p"로 들린 것을 복원한 것이다. 뜻은 "모든 노드와 관계를 보여 달라"다.

이 화면은 그림만 보여 주는 도구가 아니다. 노드를 눌러 데이터를 살펴볼 수 있는 조회 도구다. 발표자는 미리 그래프를 채워 두었기 때문에, 다시 돌리면 중복 제거가 일어난다고 했다.

발표자의 설명을 정리하면 이렇다. 처음 실행에서 강의 15개가 들어갔고, 빌더를 다시 돌리면서 15개가 더 생겨 30개가 됐다. 에이전트를 업데이트하지 않은 상태라는 말도 있었지만, 정확한 원인 설명은 자막에서 다소 흐릿하다. 분명한 것은 Aura 콘솔에서 Lesson 노드 타입을 직접 눌러 보면 15개가 맞게 나온다는 점이다.

배울 점 그래프 RAG의 집계 능력은 그래프가 깨끗할 때 믿을 수 있다. 빌더를 다시 돌릴 때는 중복 제거가 제대로 되는지 확인하고, 에이전트의 숫자 답은 그래프를 직접 조회해 맞춰 본다. 그래프의 장점은 바로 이 확인이 쉽다는 데 있다.

핵심 정리

  1. 같은 데이터도 표, 벡터, 지식 그래프로 표현할 수 있다. 지식 그래프만 사람과 기계가 함께 읽는다.
  2. 표는 조인이 쌓여 느려지고, 벡터는 사람이 읽을 수 없다. 그래프는 관계를 따라 한 칸씩 건너뛰며 추적하고 설명할 수 있다.
  3. 그래프 RAG는 RAG다. 검색 경로에 지식 그래프가 들어간다는 점만 다르다.
  4. 검색 엔진으로 풀리는 질문은 벡터 RAG로 충분하다. 세 단계 이상 건너뛰는 질문, 소스 코드 분석, 공급망, 여러 문서를 모아 세는 질문은 그래프 RAG가 필요하다.
  5. 그래프는 벡터를 대체하지 않는다. 둘 다 쓴다.
  6. 리트리버는 정보를 물어오는 부품이다. Neo4j는 전문 검색, 벡터 검색, 텍스트→Cypher 세 가지를 지원한다.
  7. 지식 그래프 구축: 모으기 → 자르기 → 임베딩 → LLM으로 개체와 관계를 JSON 추출 → Cypher로 생성.
  8. 스키마(노드 타입, 관계 타입, 패턴)를 정해 두면 LLM이 타입을 지어내지 않는다.
  9. Aura 에이전트의 유사도 검색 도구에는 벡터 인덱스가 먼저 필요하고, Cypher는 nodes와 scores를 반환해야 한다.
  10. 에이전트가 집계 질문에 30이라 답했지만 실제는 15였다. 빌더 재실행으로 생긴 중복 때문이다. 숫자 답은 그래프를 직접 조회해 확인한다.

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1사과를 벡터로 표현한 것과 지식 그래프로 표현한 것의 가장 큰 차이는?
벡터는 숫자 배열이라 사람이 읽을 수 없다. 지식 그래프는 "나무에서 난다, 둥글다, 과일이다" 같은 관계로 돼 있어 사람과 기계가 모두 읽는다.
Q2데이터를 표로 저장했을 때 관계를 알아내려면 무엇이 필요하고, 그 비용은?
조인을 여러 번 해야 한다. 조인이 쌓이면 애플리케이션 성능이 크게 떨어진다.
Q3그래프 RAG를 한 문장으로 정의하면?
검색 경로에 지식 그래프가 포함된 RAG. 나머지 흐름은 보통 RAG와 같다.
Q4발표자가 "그래프 RAG가 꼭 필요하다"고 보는 질문의 기준은?
세 단계 이상 건너뛰어야 하는 다중 홉 질문. 그 밖에 소스 코드 분석, 공급망 질문, 여러 문서를 모아 세거나 합쳐야 하는 질문.
Q5발표자는 벡터 RAG와 그래프 RAG 중 무엇을 고르라고 했나?
둘 다. 그래프가 벡터 계층을 대체하는 게 아니라 그 위에 더해져 양쪽 장점을 다 얻는다.
Q6리트리버가 하는 일과, Neo4j가 지원하는 세 종류는?
질문 같은 비정형 입력을 받아 구조화된 데이터에서 관련 정보를 찾아온다. 전문 검색, 벡터 검색, 텍스트→Cypher.
Q7LLM으로 지식 그래프를 만드는 다섯 단계는?
모으기, 자르기(조각내기), 임베딩, LLM으로 개체와 관계를 JSON으로 추출, 파싱해서 Cypher로 그래프 생성.
Q8빌더 코드에서 스키마(노드 타입, 관계 타입, 패턴)를 미리 정하는 이유는?
LLM이 추출할 때 새 노드 타입이나 관계 타입을 지어내지 않고 정해진 스키마 안에서만 뽑게 하기 위해서다.
Q9유사도 검색 도구를 붙이기 전에 해야 할 일과, 도구의 Cypher가 반드시 반환해야 하는 것은?
Aura 콘솔의 Query 창에서 벡터 인덱스를 먼저 만든다. Cypher는 nodes와 scores(유사도 점수)를 반환해야 한다.
Q10에이전트가 강의 수를 30이라고 답한 이유와, 실제 수를 확인한 방법은?
빌더를 두 번 실행해 강의 노드가 중복으로 들어갔다. Aura 콘솔에서 그래프를 직접 조회하거나 Lesson 노드 타입을 눌러 보면 15개가 나온다.
Q11그래프 RAG의 설명 가능성이 규제 분야에서 특히 중요한 이유는?
금융, 의료, 법률에서는 에이전트가 왜 그 결정을 내렸는지 맥락과 이력을 추적할 수 있어야 한다. 그래프는 어떤 노드를 거쳐 답에 도달했는지 보여 준다.
