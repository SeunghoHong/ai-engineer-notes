Codex와 일하는 새로운 방법

Codex는 코드를 짜는 도구를 넘어, 회사 곳곳의 맥락을 읽고 노트북을 닫아도 일하며 말과 메시지로 일을 넘겨받는 쪽으로 넓어졌다. OpenAI 개발자 경험팀 두 사람이 7~11월에 나온 기능을 맥락, 반복, 어디서나, 내보내기, 위임의 다섯 갈래로 보여 준다.

원본 영상: New Ways of Working with Codex 발표: Dominik Kundel, Charlie Guo (OpenAI 개발자 경험팀)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치와 주장은 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 뭉개진 이름 중 확실한 것(Codex, ChatGPT, AGENTS.md, Tailscale, YubiKey 등)은 바로잡았다. 모델 이름(Soul, Astra, Luna)과 제품 이름은 들린 대로 적었고, 확실하지 않은 곳에는 (추정)을 붙였다. mm:ss는 영상 위치다.

두 발표자는 OpenAI 직원이고, 발표 전체가 자사 제품 Codex와 ChatGPT 기능 소개다. 성능 수치, 사용자 증가, "가장 강력한 기능" 같은 평가는 그 점을 감안해 읽자.

3분 요약
  1. Codex는 죽지 않았다는 게 발표자의 주장이다. 같은 Codex 하네스가 데스크톱 앱, CLI, ChatGPT, Slack, dot, Agents API를 모두 움직인다.
  2. 맥락: 모든 걸 불러 주는 대신 동료에게 말하듯 막연하게 말한다. 그러려면 저장소 안 기준은 AGENTS.md와 린터로, 저장소 밖 맥락은 플러그인, 앱샷, 컴퓨터 사용, 컴퓨터 기록으로 채워 둔다.
  3. 반복: Ultra Fast는 8배 빠르고 6배 비싸다. 핫 리로딩 서버를 띄우고 추론 강도를 낮춰 UI를 다듬을 때 값을 한다. 빌드가 긴 일에는 이득이 작다.
  4. 어디서나: 책상 밑 Mac mini 대신 Codex Cloud v2를 쓴다. 여러 저장소, 자동 환경 설정, 스냅샷, Tailscale 접속을 지원한다.
  5. 내보내기: Sites는 DB, 저장소, ChatGPT 로그인을 갖춘 웹앱 플랫폼이다. 코드 리뷰 탭에서는 버튼 하나로 PR 리뷰를 맡긴다.
  6. 위임: 음성 모드는 받아쓰기가 아니라 앱 전체를 모는 조종간이다. dot은 안전망이자 일을 던져 두는 곳이다.
  7. 팁: 추론 강도를 낮춘다. 새 모델이 나오면 기존 습관을 버려 보고 필요한 것만 되살린다.
01

Codex는 죽지 않았다, 넓어지는 중이다 00:40

온라인에는 "Codex는 끝났다"는 주장이 돌았다. Charlie의 답은 반대다. Codex를 쓰는 방법, 쓰는 곳, 기능이 모두 어느 때보다 많다고 말한다. 그저 커지는 게 아니라 모양이 바뀌고 있다는 것이다.

  • ChatGPT와 합쳐졌다 01:10: 올해 Codex가 ChatGPT의 업무 기능(자막에 "ChatGPT work"로 들림, 추정)과 합쳐졌다. 발표자는 이 덕분에 수천만 명이 더 Codex로 오래 도는 에이전트를 쓰게 됐다고 말했다.
  • 다시 클라우드로 01:40: 첫 Codex는 클라우드 에이전트였다. 자기 환경에서 저장소를 받아 원격으로 일했다. 지금은 내 기기의 Codex를 원격으로 모는 도구와, 더 강한 클라우드 환경으로 다시 그쪽에 다가가고 있다.
  • 하네스 하나가 여러 곳을 움직인다 02:10: 같은 Codex 하네스가 ChatGPT의 업무 기능, CLI, Slack의 @ChatGPT 태그, dot, 새 Agents API를 움직인다.

하네스harness는 모델에 도구, 권한, 실행 환경을 붙여 실제로 일하게 하는 실행 틀이다. 하네스가 하나라는 점이 이 발표 전체에 깔려 있다. 한 곳에서 연결한 맥락과 도구가 다른 곳에서도 그대로 통하기 때문이다.

Charlie는 7월 AI Engineer World's Fair 워크숍에서 1~7월에 나온 기능을 정리했다. 이번 7~11월 목록은 너무 길어 화면에 맞게 덜어 내야 했다. 발표는 다섯 주제와 팁으로 나뉜다.

"Codex는 죽지 않았다"는 평가와 사용자 증가는 OpenAI 직원이 자사 제품을 두고 한 말이다. 슬라이드에 ChatGPT와 합친 날 이후의 사용자 수 그래프가 있었지만, 자막에 숫자가 남지 않아 옮기지 않았다.

02

막연하게 말해도 알아듣게 만들기 03:50

여기서부터 Dominik이 이어받는다. 코딩 에이전트에서 무언가를 얻으려면 맞는 맥락이 먼저다. 지금 무슨 작업을 하는지뿐 아니라, 그 작업으로 이루려는 목표까지 알아야 한다.

지난 2년컨텍스트 엔지니어링필요한 정보를 빠짐없이 골라 프롬프트에 정확히 조합한다

지금막연한 프롬프트맥락을 이미 아는 동료나 친구에게 말하듯 짧게 말한다

"막연한 프롬프트vague prompting"는 Dominik이 붙인 이름이다. 모든 걸 일일이 불러 줘야 하는 동료와는 아무도 일하고 싶지 않다. 그 정도면 직접 하는 편이 낫다. 에이전트도 마찬가지다.

Codex가 맥락 모으기에 강한 이유 04:50

OpenAI는 거대한 모노레포monorepo에서 일한다. 여러 프로젝트를 한 저장소에 모아 둔 구조다. Codex가 그 안에서 쓸모 있으려면, 큰 저장소를 돌아다니며 필요한 한 조각을 찾아내야 했다. 그래서 모델과 Codex 모두 이 일을 잘하도록 다듬어졌다고 Dominik은 설명한다.

첫 단계: 기준은 저장소 안에 05:30

코딩 표준은 늘 저장소 안에 둔다. AGENTS.md 파일이든, 린터linter 같은 도구든 상관없다.

점검 기준 실력 좋은 엔지니어를 처음 이 코드베이스에 넣었을 때, 실수 없이 바로 기여할 수 있어야 한다. 에이전트에게도 같은 기준이 적용된다.

하지만 맥락은 코드에만 있지 않다. 많은 맥락이 저장소 밖에 있다. 다음 네 섹션은 그 맥락을 끌어오는 방법이다.

03

플러그인: 저장소 밖 맥락 연결하기 06:00

플러그인plugin은 특정 용도에 필요한 것을 한데 묶은 꾸러미다.

  • MCP 서버: 에이전트가 외부 서비스에 접속하는 통로
  • 스킬skill: 특정 작업을 하는 절차와 지시
  • 그 밖의 자료: 해당 용도에 필요한 추가 자원

OpenAI는 플러그인 마켓플레이스를 열었고 계속 늘리고 있다. 직접 만든 플러그인도 제출할 수 있다. 회사 안에서만 공유하거나, GitHub에 오픈소스 마켓플레이스로 공개할 수도 있다.

한 번 연결하면 모든 곳에서 06:30

대부분의 플러그인은 원격 MCPremote MCP를 쓴다. 내 기기 한 대에 묶이지 않는다는 뜻이다. 그리고 모든 화면이 같은 Codex 하네스로 돈다. 그래서 연결 하나를 모든 화면이 함께 쓴다.

예 웹의 ChatGPT에서 Slack 플러그인을 한 번 연결한다. 그러면 개발 서버dev box에서 도는 Codex도 같은 Slack 메시지를 읽는다. Slack에서 @ChatGPT로 태그해 부르는 경우도 같은 자원을 쓴다.

막연한 요청이 통하는 장면 07:30

Dominik이 예전에 Codex에게 보낸 메시지를 보여 줬다. 처음 읽는 사람은 무슨 일인지 짐작만 할 수 있다. Slack 어디서 태그됐는지도, 어느 Katya를 말하는지도 적지 않았다. 그래도 Codex는 알아들었다. Slack에 연결돼 있어 그 대화를 찾았고, Google Drive에 연결돼 있어 대화에 공유된 스프레드시트를 열었다.

자정 배포를 맡긴 사례 08:20

6월에 문서 사이트를 일요일 자정에 업데이트해야 했다. Dominik은 그 시간까지 깨어 지켜보고 싶지 않았다. 그래서 Codex에게 이렇게 맡겼다.

  1. Codex와 함께 PR을 준비하고 검토를 마쳤다.
  2. 제때 승인을 받도록 계속 챙기라고 했다.
  3. 막판 변경이 있는지 Slack 채널을 지켜보라고 했다.
  4. 당시 배포에 20분이 걸렸으니, 20분 먼저 배포를 시작하라고 했다.
  5. 실제로 반영됐는지 확인하라고 했다.

자정 4분 뒤 Codex가 "반영됐고 문제없다"고 알렸다. Dominik은 손댈 일이 없었다.

더 재밌는 일은 전날인 토요일에 있었다. 동료가 변경 사항과 미리보기 URL 건으로 Dominik을 태그했는데, Codex가 대신 답했다. 동료는 "좋아 보인다"고 했다. Dominik은 나중에야 알았다. Codex는 엉뚱한 대화로 새지 않고, 출시를 끝까지 밀고 가는 일만 했다.

04

플러그인 확장: 앱 화면까지 바꾸기 09:50

지금까지 본 플러그인은 에이전트에게 맥락을 주는 수단이었다. 최근 나온 플러그인 확장plugin extensions은 그 맥락을 다루는 화면 자체를 바꾼다. Codex 데스크톱 앱과 웹·모바일 ChatGPT의 거의 모든 곳을 확장할 수 있다.

  • 사이드바 항목 추가
  • 사이드 패널
  • 전체 페이지 화면
  • 파일 뷰어 변경
  • 컴포저composer 변경: 에이전트에게 요청을 쓰는 입력창

OpenAI도 같은 부품으로 만든다. Codex 데스크톱 앱의 여러 페이지(Sites, 코드 리뷰, 보안, 클라우드)가 OpenAI가 만들어 함께 내보내는 플러그인이다.

데모: 디자인 시스템 플러그인 11:10

Dominik은 회사 디자인 시스템을 둘러보는 플러그인을 만들었다. 데스크톱 앱 안에서 어떤 컴포넌트가 있는지 보고 바로 쓸 수 있다. 원래는 디자인 시스템 탭을 따로 열어 두고, 모델에게 원하는 모양을 설명할 때 참고했다. 이제 그 화면이 앱 안에 있다.

  • 만든 방법: Codex에게 "여기 우리 디자인 시스템이 있다, 이런 플러그인을 만들어 달라"고 한 번 요청했다.
  • 컴포저에 추가: 버튼을 누르면 고른 컴포넌트(데모에서는 actions 드롭다운)의 정보가 입력창에 들어간다. 내가 타이핑할 필요도, Codex가 찾으러 갈 필요도 없다.

컴포저 확장 12:20

입력창에서 디자인 시스템을 멘션하고 Tab을 누르면 컴포넌트 목록이 자동완성으로 뜬다. Figma 플러그인을 설치하면 내 Figma 파일이 같은 방식으로 자동완성된다. 사내 도구에도 붙일 수 있다.

정리 회사마다 고유한 작업 방식이 있다. 그걸 플러그인으로 만들어 두면 나와 에이전트 모두 같은 맥락에 쉽게 닿는다.
05

화면 밖 맥락 모으기 13:00

플러그인이 없는 곳의 맥락은 화면과 컴퓨터에서 직접 가져온다. 도구가 네 가지 있다.

컴퓨터 사용에이전트가 자기 커서로 앱을 직접 조작macOS플러그인이 없을 때, 앱을 테스트할 때

앱샷: 스크린샷 대신 13:00

청중 중 앱샷appshot을 써 본 사람은 몇 명뿐이었다. Dominik은 아주 저평가된 기능이라며, 스크린샷을 찍어 Codex에 보내고 있다면 앱샷으로 바꾸라고 권한다.

  • 단축키: Mac은 왼쪽과 오른쪽 Command 키를 함께 누른다. Windows는 양쪽 Alt 키다. 데스크톱 앱이 깔려 있어야 하고, 처음에는 권한을 물을 수 있다.
  • 다른 점: 화면 이미지와 함께 접근성 트리accessibility tree를 보낸다. 화면 요소의 구조와 글자를 정리한 정보다.
  • 이득: 웹 페이지나 Slack 대화처럼 화면 아래로 이어지는 내용까지 넘어간다. "텍스트 보기"를 누르면 변수, 숫자 같은 정보가 함께 담긴 걸 볼 수 있다.

컴퓨터 사용과 Chrome 확장 14:30

컴퓨터 사용computer use은 macOS에서 백그라운드로 돈다. 내 화면을 빼앗지 않고, 커서를 따로 가지고 앱을 조작한다. 정보를 가져오는 데도, 앱을 테스트하는 데도 쓴다. 데모에서는 iOS 시뮬레이터를 조작했다.

데스크톱 전체를 맡기기 싫다면 Chrome 확장을 쓴다. 웹사이트의 맥락만 가져온다. Windows, Linux, macOS에서 백그라운드로 돈다. 나는 여러 탭에서 계속 일하고, Codex는 내 탭을 빼앗지 않으면서 같은 로그인 상태를 쓴다.

Q4컴퓨터 기록이 스크린샷 대신 쓰는 것과, 개인정보를 지키는 장치는?
Mac의 이벤트 스트림을 쓴다. 그래서 토큰을 덜 쓰고 빠르다. 일시정지, 최근 기록 지우기, 특정 사이트·앱 제외가 있고 비공개 모드는 처음부터 기록하지 않는다.
Q5ChatGPT Space에서 문서가 낡지 않게 하는 두 장치는?
assistant instructions(에이전트가 페이지를 고칠 때 따를 지시)와 auto update(정해진 주기로 갱신하는 지시). Dominik은 이를 페이지별 AGENTS.md라고 불렀다.
Q6Ultra Fast의 이득이 작은 일과 잘 맞는 일은?
빌드와 테스트 시간이 긴 일(iOS 앱, 게임)은 이득이 작다. 핫 리로딩 개발 서버를 띄우고 추론 강도를 light로 낮춰 UI를 빠르게 다듬을 때 잘 맞는다.
Q7주석 API는 무엇을 정하나? 예를 하나 들면?
페이지에서 무엇을 고를 수 있게 할지 정한다. 디자인 시스템이라면 개별 컴포넌트는 고를 수 있고 Storybook 틀은 고를 수 없게 한다. ModRetro 플러그인은 게임 속 요소에만 주석을 달게 했다.
Q8Codex Cloud v2 환경이 스스로 알아내는 것과, 빠르게 유지하는 방법은?
필요한 API 키, 설치할 의존성, 개발 서버와 테스트를 띄우는 명령을 알아낸다. 스냅샷과 백그라운드 지속 갱신으로 빠르게 유지한다.
Q9Sites가 정적 호스팅 이상이라고 하는 이유는?
데이터베이스(D1), 파일·객체 저장소(R2), Sign in with ChatGPT 인증, 플러그인, 분석, 비밀값을 갖춰 웹앱을 온전히 만들 수 있기 때문이다.
Q10Charlie가 말한 음성 모드에 대한 흔한 오해와 실제 쓰는 법은?
흔히 타이핑 대신 말하는 입력 수단으로만 쓴다. Charlie는 스레드 관리, 진행 확인, 다른 앱 데이터 가져오기, 새 스레드 만들기까지 앱 전체를 모는 조종간으로 쓴다.
Q11Charlie가 dot을 쓰는 세 가지 방식은?
안전망(버그, 머지 충돌, 일정 충돌, 화재 소식을 먼저 짚어 줌), 위임함(Slack 메시지를 넘겨 조사·할 일 만들기), 어디에나(Slack, Teams, 전화, 문자).
Q12모델과 추론 강도를 고르는 Dominik의 팁은?
슬라이더를 끝까지 올리지 말고 high에서 시작한다. 새 세대가 나오면 extra high에서 high로 낮춰 본다. 주 에이전트는 Soul medium으로 두고, 어려운 일은 Astra, 단순 반복은 Luna 서브에이전트에게 맡기는 스킬을 만든다. 다만 늘 더 좋거나 싸지는 않다.

용어뜻
하네스Harness. 모델에 도구, 권한, 실행 환경을 붙여 실제로 일하게 하는 실행 틀

모노레포Monorepo. 여러 프로젝트를 한 저장소에 모아 관리하는 방식
AGENTS.md저장소에 두는 에이전트용 지시 파일
린터Linter. 코드 스타일과 흔한 실수를 자동으로 검사하는 도구
MCPModel Context Protocol. 에이전트가 외부 도구와 데이터에 접속하는 표준 방식. 원격 MCP는 내 기기 밖 서버에서 돈다
스킬Skill. 특정 작업 절차를 에이전트가 불러 쓸 수 있게 묶은 지시와 자료
플러그인 확장Plugin extensions. 플러그인으로 앱 화면의 일부(사이드바, 패널, 컴포저 등)를 바꾸는 기능
컴포저Composer. 에이전트에게 요청을 쓰는 입력창
앱샷Appshot. 스크린샷과 접근성 트리 텍스트를 함께 보내는 화면 캡처
접근성 트리Accessibility tree. 화면 요소의 구조와 글자를 보조 기술이 읽을 수 있게 정리한 정보
컴퓨터 사용Computer use. 에이전트가 커서를 따로 가지고 앱을 직접 조작하는 기능
컴퓨터 기록Computer history. 사용자가 어떤 앱을 어떻게 쓰는지 기록해 기억으로 쓰는 기능
추론 강도Reasoning effort. 답하기 전에 얼마나 오래 생각할지 정하는 설정. light, medium, high, extra high
핫 리로딩Hot reloading. 코드를 고치면 앱을 다시 켜지 않고 화면에 바로 반영하는 개발 서버 기능
DOM웹 페이지의 구조를 이루는 요소 트리
주석Annotations. 앱 안 브라우저에서 페이지의 특정 부분을 찍어 피드백하는 기능
E2E 테스트End-to-end test. 사용자가 쓰는 흐름을 처음부터 끝까지 실제로 돌려 보는 테스트
VMVirtual machine. 물리 컴퓨터 위에 소프트웨어로 만든 가상 컴퓨터
스냅샷Snapshot. 환경 상태를 저장해 두었다가 빠르게 되살리는 것
비밀값Secrets. API 키처럼 코드에 직접 넣으면 안 되는 값
OIDCOpenID Connect. 신원을 증명하는 표준 인증 방식. 클라우드 자원 접근에 쓴다
Tailscale여러 기기를 하나의 사설 네트워크로 묶어 주는 서비스
앱 서버App server. 발표자 설명으로는 모든 Codex 화면을 움직이는 하네스 프로세스
서브에이전트Sub-agent. 주 에이전트가 일부 작업을 맡기려고 띄우는 보조 에이전트. 주 세션에 묶인다

리믹스Remix. 다른 사람의 Site를 복사해 필요에 맞게 고치는 기능
위키 레이싱Wiki racing. 링크만 따라 한 위키백과 문서에서 다른 문서로 누가 빨리 가는지 겨루는 놀이
