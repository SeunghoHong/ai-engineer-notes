Codex로 요리하기: 여섯 단계

OpenAI 개발자 경험 팀이 Codex 사용법을 요리에 빗대어 여섯 단계로 정리했다. 컨텍스트를 주고, 만들고, 컴퓨터를 대신 조작하게 하고, 긴 작업을 함께 하고, 시간을 두고 자동으로 돌리고, 마지막으로 자기 제품 안에 심는다. 핵심 메시지는 "한 번 묻기"에서 "스스로 도는 루프 만들기"로 옮겨 가라는 것이다.

원본 영상: Cooking with Codex 발표: Charlie Guo, Gabriel Chua (OpenAI 개발자 경험 팀)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 기능 설명과 수치는 모두 발표자가 말한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 이름이 뭉개진 곳은 확실한 경우에만 알려진 이름으로 바로잡았다. mm:ss는 영상 위치다. 두 번째 시간은 현장 실습이라 자막에 없다.

두 발표자는 Codex를 만드는 OpenAI 소속이다. 기능의 장점과 사용자 반응 인용은 제품을 만든 쪽의 시각이라는 점을 감안해 읽자.

3분 요약
  1. 컨텍스트가 첫 재료다. 앱샷(화면과 글자를 함께 캡처), 플러그인, 받아쓰기, 메모리로 머릿속과 Slack과 문서에 있는 맥락을 Codex에 넘긴다.
  2. 만든 것은 Sites로 나눈다. 코드뿐 아니라 요약 사이트, 코드 리뷰, 이미지, 문서를 결과물로 만들 수 있다.
  3. 컴퓨터 조작은 세 가지 길이 있다. 컴퓨터 사용은 API가 없는 프로그램에, Chrome 확장은 로그인 상태가 필요할 때, 앱 안 브라우저는 로컬 웹앱을 깊게 테스트할 때 쓴다.
  4. 긴 작업은 목표와 서브스레드로 다룬다. 15시간 넘게 도는 작업에 목표 파일, 진행 대시보드, 코드 리뷰 스레드, 목표 감사 스레드, Slack 보고를 붙인다.
  5. 바탕에는 네 가지가 있다. 컨텍스트 압축, 검증 가능한 종료 조건을 가진 목표, 역할별 서브에이전트, 정해진 시점에 반드시 도는 훅.
  6. 자동화는 두 종류다. 한 스레드 안에서 타이머로 도는 하트비트와, 예약 시각에 새 스레드를 여는 예약 작업.
  7. 앱 서버로 Codex를 어디에나 심을 수 있다. 사용자는 자기 ChatGPT 구독과 토큰 예산으로 그 제품을 쓴다.
01

사람들이 Codex로 만든 것 00:50

발표는 사용자들이 올린 사례를 훑으며 시작한다. 코딩 도구라는 이름에 갇히지 않은 쓰임이 많다.

  • 한 세션에서 서브에이전트 sub agent를 300개 가까이 띄운 사례
  • Ableton용 신시사이저 플러그인 제작
  • OpenAI 팀원 Brent가 Codex로 Premiere를 움직여 영상을 편집하는 일
  • 게임 제작. 발표자는 오디오, 아트, 게임 규칙, 난이도 조정을 스레드마다 나눠 맡기기 좋다고 본다
  • 스스로 달리는 골프 카트

어디서 쓰느냐도 넓어졌다. 회의 사이에 노트북을 들고 다니는 모습이 밈이 됐고, 모바일 앱으로 기차 안이나 산책 중에도 이어서 일한다. Codex가 오픈소스이고 앱 서버 app server가 있어서 전자잉크 기기에 넣은 사람도 있다. 다른 에이전트용 설정 파일이 있으면 그대로 가져와 시작할 수 있다고 한다.

02

2026년 상반기 새 기능 04:10

발표 시점은 2026년 6월 말이다. 발표자는 반년 동안 나온 것을 한 장에 다 적기 어렵다며 몇 가지만 짚었다.

기능무엇을 하나
기록과 재생 record and replay버튼 순서를 말로 설명하는 대신 직접 해 보이며 가르친다. 컴퓨터 사용 기술 위에 만들었다
스레드 넘기기 thread handoff클라우드, 원격 서버, 내 컴퓨터 사이에서 작업을 밀고 당긴다
모바일 앱 정식 출시기기와 1대1로 짝지어 쓴다. 발표자는 더 안전한 방식이라고 설명한다
플러그인, 컴퓨터 사용, 멀티모달, 앱샷이 발표의 재료다. 아래 단계에서 하나씩 다룬다
03

여섯 단계 한눈에 05:20

누구나 요리할 수 있다. 하지만 두려움 없는 사람만 위대해진다.영화 라따뚜이의 대사. 발표자가 인용했다
단계내용대상
1. 컨텍스트 주기문서, 머릿속, 대화, 이메일, Notion, Linear에 있는 맥락을 넘긴다처음 쓰는 사람
2. 만들기맥락을 받은 Codex가 바로 결과물을 만든다처음 쓰는 사람
3. 행동하기브라우저와 데스크톱 프로그램을 Codex가 대신 조작한다숙련자
4. 긴 작업 협업몇 시간씩 도는 작업을 스레드와 목표로 관리한다숙련자
5. 시간을 두고 일하기반복 가능하고 일관된 루프를 만든다숙련자
6. 어디에나 심기내 제품이나 사내 플랫폼 안에 Codex를 넣는다숙련자

발표 내내 Chrome 위에 "Codex가 이 브라우저를 디버깅하기 시작했습니다"라는 띠가 떠 있었다. 발표자가 말하는 동안 Codex가 슬라이드를 읽고 있었다는 뜻이다. 정체는 5단계에서 밝혀진다.

04

1단계: 컨텍스트 주기 06:30

금요일 오후 4시 44분, 발표자 세 사람은 아직 데모 아이디어가 없었다. Slack에서 "실시간 번역기를 만들자", "GPT 실시간 모델을 쓰자"는 대화가 오갔다. Gabriel Chua는 그 Slack 창을 그대로 Codex에 넘겨 macOS 앱을 만들게 했다. macOS 앱을 만들어 본 적은 없다고 한다.

앱샷: 화면과 글자를 함께 넘기기 07:20

앱샷 appshot은 스크린샷과 비슷하지만 화면 속 글자가 텍스트로 함께 들어간다. 양쪽 엄지로 Command 키를 누르면 지금 보고 있는 앱이 그대로 Codex에 붙는다. Slack 대화, 브레인스토밍, 개인 맥락을 다시 타이핑할 필요가 없다. Charlie Guo는 이제 Slack이나 브라우저에서 복사해 붙이는 일을 하지 않고, 앱샷으로 보낸 뒤 "알아서 해"라고 한다. 발표자 기준으로 열에 아홉은 맞게 알아듣는다고 한다.

Sites와 Codex 원격 08:00

  • Sites: 2026년 6월에 기업과 비즈니스 요금제용 미리보기로 나온 기능이다. 공유할 수 있는 간단한 사이트를 만든다. 발표자는 Agents SDK 저장소의 커밋 기록을 읽혀 "새로 바뀐 것" 사이트를 만들었다. 샌드박스 에이전트, 도구로서의 Codex, 도구 검색, 실시간 에이전트 같은 항목이 코드 예시와 함께 정리됐다.
  • Codex 원격 Codex remote 09:20: ChatGPT 모바일 앱에서 내 노트북이나 원격 서버에 명령을 보낸다. Charlie Guo는 전화기로 "이 저장소를 IKEA 조립 설명서 스타일로 그려 달라"고 보냈다. 노트북은 켜 두면 Codex가 잠들지 않게 유지한다.

발표자는 요즘 모두가 주말에 노트북을 두고 나가서 "Codex, 막힌 건 없어?"라고 묻는 관리자가 됐다고 농담했다.

플러그인: 기술, 앱, MCP 서버 묶음 11:10

플러그인 plugin은 세 가지를 하나로 묶은 것이다.

  • 기술 skill: 모범 사례와 팀 고유의 작업 절차를 적은 프롬프트
  • 앱: 외부 서비스에 연결하는 설정
  • MCP 서버: 필요한 도구를 제공하는 서버

번역기 데모에는 두 플러그인을 썼다. macOS 앱 빌드 플러그인은 AppKit, 리퀴드 글래스 디자인, 앱 서명과 검사 방법을 담고 있다. OpenAI 개발자 플러그인은 API 키를 직접 만들어 준다. 발표자는 개발자 포털에 가서 키를 만들고 어딘가 저장했기를 기도하던 시절은 끝났다고 말한다. Gmail, Outlook, Teams, Slack 플러그인도 있다.

어려운 작업을 끝낸 뒤 "이걸 기술로 만들어" Charlie Guo의 습관이다. 어떻게 시켜야 할지 몰랐던 작업을 대화로 겨우 해내면, 마지막에 "이걸 기술로, 더 좋게는 플러그인으로 만들어"라고 한다. 다음에는 플러그인 하나만 부르면 같은 일이 끝난다. Codex 앱에는 플러그인을 만드는 기술이 들어 있다.

번역 앱은 4분 2초 만에 만들어졌고 무대에서 독일어 번역을 시도했다. 마이크 설정이 꼬여 몇 번 다시 시도했다. 발표자 말대로 "진짜 라이브 데모"였다.

메모리, Chronicle, 사용자 지침 15:30

기능내용주의
메모리대화에서 사용자 취향을 배운다. 예: Python 패키지 관리에 uv를 선호한다는 것기본은 꺼져 있다. 설정의 개인화 항목에서 켠다
ChroniclePro 구독자용 연구 미리보기. 화면에서 무엇을 보고 있었는지 기억한다. GitHub 파이프라인 실패 화면을 보다가 "왜 실패했어?"라고만 물어도 맥락을 안다발표자는 비즈니스 요금제라 데모하지 못했다
도구 사용 대화 제외도구가 돌려준 결과 중 오래 남기고 싶지 않은 정보가 있을 수 있다도구를 쓴 대화에서는 메모리를 만들지 않는 옵션이 있다
사용자 지침홈 디렉터리의 AGENTS.md와 같다. 모든 대화에 적용된다예시는 "항상 해적처럼 답해"였다

메모리와 Chronicle은 토큰을 조금 더 쓴다고 발표자가 밝혔다. 대신 과거 대화를 바탕으로 할 일을 알아채는 경험이 "진짜 동료 같다"고 평한다.

받아쓰기를 더 많이 쓰라 17:50

Charlie Guo는 받아쓰기 dictation가 가장 덜 쓰이는 기능이라고 본다. 말하는 속도가 타이핑보다 훨씬 빠르다. 단어 하나하나를 정확히 쓸 필요도 없다. 두서없이 길게 말해도 모델이 대개 맞는 일을 찾아낸다. 말하면서 생각이 정리되는 효과도 있다.

05

2단계: 만들고 나누기 19:30

재료가 모이면 만든다. 발표자는 결과물이 코드만은 아니라고 강조한다.

  • Sites로 공유: OpenAI 안에서는 행사 뒤 "오늘 있었던 일을 요약해 사이트로 만들어"라고 시켜 조직에 공유한다. 팀원 Cory는 워크숍 장소 후보를 비교하는 사이트를 만들어 결정에 썼다.
  • 코드 리뷰 20:10: /code-review를 치면 커밋하지 않은 변경을 대상으로 리뷰 작업이 뜬다. 요리를 내보내기 전 맛보는 보조 요리사에 비유했다.
  • 이미지 생성: IKEA 설명서 요청은 SVG로 나왔다. 이미지 생성 기술을 쓰면 그림으로 다시 만들 수 있다.
  • 스프레드시트, 문서, 슬라이드: 이 발표에서는 다루지 않았다. 같은 행사에서 Jason이 따로 발표한다고 했다.
06

3단계: 컴퓨터를 대신 조작하기 21:20

Gabriel Chua는 OpenAI 전에 큰 조직에 있었다. 모든 것에 API가 있지는 않았다. 오래된 대시보드에서 날짜 범위를 월요일부터 일요일까지 하나씩 눌러 내려받던 일이 있었다.

데모 1: 대시보드에서 데이터 내려받기 22:20

앱샷으로 대시보드를 넘기고 두 가지를 시켰다. 최근 7일 커밋 수를 CSV로, 이달 1일부터 오늘(6월 29일)까지 풀 리퀘스트 데이터를 JSON으로 받아 달라고 했다. Codex가 컴퓨터 사용 computer use 기술을 골라 쓰고, 화면을 본 뒤 두 번째 커서가 나타나 버튼을 눌렀다. 발표자 두 사람의 손은 키보드에서 떨어져 있었다.

내 커서를 뺏기지 않는다 macOS에서는 Codex가 별도의 커서로 움직인다. 발표자는 그동안 다른 탭을 열고 스크롤할 수 있었다. 화면 주도권을 두고 에이전트와 씨름하지 않아도 된다.

데모 2: Google 폼 만들기 24:10

피드백 폼은 질문을 만들고 선택지를 채우고 필수 표시를 하는 반복 작업이다. 발표자는 질문을 적어 둔 Google 문서를 앱샷으로 넘기고 "모든 질문을 필수로 표시해 폼을 만들어"라고 했다. 이번에는 Chrome 확장 Chrome extension을 썼다. 파란 커서가 Chrome 안에서 버튼을 누르는 동안, 발표자는 다른 스레드에서 Codex 저장소에 메모리용 모델 설정 항목을 물어봤다.

세 가지 길 중 무엇을 쓰나 26:20

방식잘 맞는 상황이유

마무리: 스스로에게 묻는 질문 62:10

Charlie Guo는 Codex의 한계를 넓히려 할 때 반복해서 묻는 질문을 공유했다. 순서대로 깊어진다.

  1. Codex에게 시켜 봤나? 사무실에서 가장 자주 하는 말이 "Codex한테 물어봤어?"가 됐다.
  2. 한 번 묻기에서 루프로 갈 수 있나? 루프가 매 턴 무엇을 확인해야 하는지 생각한다.
  3. 무엇이 Codex를 막았나? 부족한 컨텍스트였나, 권한이었나. 그것을 기술이나 플러그인으로 만들어 다음에는 막히지 않게 할 수 있나.
  4. 하나에서 여럿으로 갈 수 있나? 구조를 암묵적으로 나누게 하거나, 여러 스레드가 서로 대화하게 할 수 있나.
  5. 이 과정에 사람이 왜 필요한가? API 키를 포털에서 복사해 붙이는 일은 이제 플러그인이 한다. 사람이 꼭 있어야 하는 곳은 남기고, 나머지는 빼서 스스로를 막힘에서 풀어 준다.
소프트웨어 하나를 만드는 일과, 소프트웨어를 조립 라인처럼 찍어 내는 공장을 만드는 일은 다르다.Charlie Guo의 말을 옮김. 발표자는 이를 "기계를 만드는 기계"라고 불렀다

발표 뒤에는 같은 자리에서 미니 해커톤이 이어졌다. 참가자에게 Codex 크레딧과 API 크레딧이 각각 100달러씩 제공됐다.

12

핵심 정리

  1. Codex 사용은 여섯 단계다. 컨텍스트 주기, 만들기, 행동하기, 긴 작업 협업, 시간을 두고 돌리기, 어디에나 심기.
  2. 앱샷은 화면과 글자를 함께 넘긴다. 복사해 붙이는 대신 창을 통째로 보내고 "알아서 해"라고 한다.
  3. 플러그인은 기술, 앱, MCP 서버의 묶음이다. 어려운 작업을 끝내면 "이걸 플러그인으로 만들어"라고 한다.
  4. 메모리는 기본으로 꺼져 있다. 도구를 쓴 대화는 메모리에서 제외할 수 있다. 받아쓰기는 가장 덜 쓰이는 좋은 기능이다.
  5. 컴퓨터 조작은 셋이다. 컴퓨터 사용은 API 없는 프로그램, Chrome 확장은 로그인 상태 공유, 앱 안 브라우저는 로컬 웹앱 깊은 테스트.
  6. 프롬프트에서 중요한 것은 마법 문구가 아니라 분명한 지시와 컨텍스트다.
  7. 긴 작업에는 목표 파일, 진행 대시보드, 코드 리뷰와 목표 감사 스레드, Slack 보고를 붙인다. 사이드 스레드는 사라지니 중요한 맥락은 주 스레드로 보낸다.
  8. 목표는 종료 조건을 검증 가능하게 써야 한다. 아니면 원숭이 손이 된다.
  9. 서브에이전트는 모델만 보면 되는 일, 스레드 넘기기는 내가 지켜봐야 하는 일에 쓴다. 훅은 정해진 시점에 반드시 도는 가드레일이다.
  10. 자동화는 한 스레드 안의 하트비트와 새 스레드를 여는 예약 작업으로 나뉜다. 앱 서버로 Codex를 내 제품에 심으면 사용자가 자기 ChatGPT 예산으로 쓴다.

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1앱샷은 스크린샷과 무엇이 다른가?
화면 속 글자가 텍스트로 함께 들어간다. Slack 대화나 문서를 다시 타이핑하지 않고 창을 통째로 Codex에 넘길 수 있다.
Q2플러그인을 이루는 세 가지는?
기술(모범 사례와 절차를 적은 프롬프트), 앱(외부 서비스 연결 설정), MCP 서버(도구 제공).
Q3메모리의 기본 상태와, 안전을 위한 옵션은?
기본은 꺼져 있다. 도구를 쓴 대화에서는 메모리를 만들지 않는 옵션이 있다. 도구가 돌려준 결과에 오래 남기고 싶지 않은 정보가 있을 수 있어서다.
Q4컴퓨터 사용, Chrome 확장, 앱 안 브라우저는 각각 언제 쓰나?
컴퓨터 사용은 API가 없는 데스크톱이나 오래된 프로그램. Chrome 확장은 내 로그인 상태와 권한을 빌려줘야 할 때. 앱 안 브라우저는 로컬 웹앱의 렌더링과 상호작용을 깊게 테스트할 때.
Q5발표자가 보는 프롬프트 엔지니어링의 현재 위치는?
지시를 분명히 하는 일은 여전히 중요하다. 하지만 마법 문구를 찾는 시대는 끝났고, 진짜 중요한 것은 컨텍스트다.
Q615시간 넘게 도는 작업의 진행 상황을 어떻게 파악했나?
목표를 goals.md에 여러 개 적게 하고 progress-dashboard.html을 만들게 했다. 마일스톤마다 코드 리뷰와 목표 감사 스레드가 따로 돌았고, Slack 스레드로 끝난 일, 남은 일, 막힌 일을 보고받았다.
Q7사이드 스레드를 쓸 때 주의할 점은?
사이드 스레드는 일시적이라 시간이 지나면 낡는다. 오래 남겨야 할 맥락은 주 스레드에 전달해야 한다.
Q8목표 기능을 쓸 때 가장 중요한 조언과, 안 지키면 생기는 일은?
끝났다고 판단할 기준을 구체적이고 검증 가능하게 쓴다. 안 그러면 시킨 대로 하긴 했는데 기대와 전혀 다른 결과가 나오는 원숭이 손 상황이 된다.
Q9서브에이전트와 스레드 넘기기 중 무엇을 쓸지 어떻게 정하나?
위임한 작업이 모델에게만 보이면 되면 서브에이전트. 내가 계속 지켜보고 끼어들고 싶으면 스레드 넘기기.
Q10훅은 무엇이고 왜 긴 작업에서 중요한가?
config.toml에 적어 정해진 시점에 반드시 도는 코드다. 로그 전송, API 키 유출 검사, 도구 허용 목록 확인, 턴 종료 시 검증에 쓴다. 자율성을 더 줄수록 감독 없이 오래 돌기 때문에 가드레일이 필요하다.
Q11하트비트 자동화와 예약 작업의 차이는?
하트비트는 스레드 하나 안에서 타이머로 반복하며 끝날 때까지 돈다. 예약 작업은 예약 페이지에서 만들고 실행마다 새 스레드를 연다.
Q12앱 서버로 Codex를 내 제품에 심으면 과금은 어떻게 되나?
사용자가 자기 ChatGPT 구독과 토큰 예산으로 쓴다. 압축과 조종 같은 핵심 기능은 그대로 오고, 컴퓨터 사용처럼 사용자 컴퓨터에 있어야 하는 기능은 빠진다.
