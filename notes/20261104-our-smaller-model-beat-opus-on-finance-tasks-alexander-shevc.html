프런티어 모델을 기다리지 않는 이유

새 모델이 나오면 AI 기능은 저절로 싸지고 좋아진다. 그래도 Ramp는 기다리지 않는다. 작은 전문 모델, KV 캐시 압축, 에이전트 떼 같은 응용 연구로 지금 시간과 돈을 줄인다.

원본 영상: Our Smaller Model Beat Opus on Finance Tasks 발표: Alexander Shevchenko (Ramp 응용 AI 팀, 입사 약 3년)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 발표 전체가 Ramp의 자기 연구와 제품 소개다. 자막에서 뭉개진 이름은 확실한 것만 바로잡았고, 확실하지 않은 것은 들린 대로 적고 (추정)을 붙였다. mm:ss는 영상 위치다.

3분 요약
  1. 새 모델이 나올 때마다 Ramp의 기능은 같은 정확도에 더 싸진다. 그래도 기다리지 않고 응용 연구로 한 층 더 파고든다.
  2. 작은 전문 모델: 지휘는 프런티어 모델이 맡고, 금융 질의응답은 사후 학습한 Qwen 3.5 35B가 맡는다. Ramp는 이 모델이 그 과제에서 Opus 4.6을 넘었다고 한다.
  3. 카트리지: 월말 결산처럼 미리 아는 일은 필요한 문맥을 전날 밤 KV 캐시로 압축해 둔다. 최대 20~30배까지 압축된다.
  4. 에이전트 떼: 에이전트 1만 개로 Ramp 전체를 침투 테스트해 고위험 취약점 7개를 찾았다.
  5. 떼로 돌리면 최대 5배 싼 오픈 웨이트 모델로도 탐지율이 크게 떨어지지 않는다.
  6. 세 사례 모두 시간(지연 시간)과 돈(토큰 비용)을 줄이는 일이다.
  7. 랩이 같은 기능을 API로 내놓아도 손해가 아니다. 먼저 써 본 노하우가 남는다.
01

기다려도 좋아지는데 왜 연구하나 00:30

발표자는 Ramp의 응용 AI 팀에서 약 3년 동안 일했다. LLM과 머신러닝으로 제품을 더 낫게 만드는 팀이다.

발표자는 Ramp를 "쓴 교훈이 가득한 회사"라고 부른다. 쓴 교훈(bitter lesson)은 사람이 공들인 요령보다 더 큰 모델과 계산이 결국 이긴다는 생각이다. 여기서는 모델이 좋아지면 Ramp의 기능도 저절로 좋아진다는 뜻으로 썼다.

  • 인기 기능들이 쓰는 토큰은 늘고 있다.
  • 그런데 기능 한 번당 비용(unit economics)은 오히려 줄었다.
  • 새 프런티어 모델이 계속 나오고, 나올 때마다 더 싸고 빠르고 좋아졌기 때문이다.
  • 그래서 같은 정확도를 훨씬 낮은 비용으로 낸다.

그러면 이런 질문이 나온다. 그냥 기다리면 되지 않나? 01:10 모델을 만들지 않고 모델 위에 제품을 만드는 회사(application layer company)에 왜 응용 연구(applied research) 조직이 필요한가?

02

2023년에도 기다리지 않았다 01:30

발표자는 2023년과 비교해 답한다. 그때는 GPT-4로 에이전트를 만들었고, 손이 아주 많이 갔다.

  • 되돌아가지 못했다. 생각 토큰(thinking tokens)이 없었다. 방향을 잘못 잡으면 실수를 모른 채 밀고 나갔다.
  • 가드레일을 아주 엄격하게 쳤다. 모델이 벗어나지 않게 규칙(guardrails)으로 묶었다.
  • 프롬프트에 매달렸다. 동의어 하나만 바꿔도 행동이 달라졌다. 사용자 의도를 넓게 알아듣도록 강화학습(RL)이 충분히 되지 않았기 때문이다.
  • 문맥을 줄여야 했다. 문맥을 많이 주면 에이전트가 헷갈렸다.

그래도 Ramp는 GPT-4.5나 GPT-5를 기다리지 않았다. 고객인 금융 전문가에게 지금 필요했기 때문이다. 쉽지 않았지만 Ramp Tour Guide를 비롯한 에이전트를 여럿 출시했다. 02:20

2023 · GPT-4에이전트를 손으로 붙잡아야 했다엄격한 가드레일, 정성 들인 프롬프트, 최소한의 문맥
→
2026도구와 문맥을 주면 알아서 한다MCP로 도구를 붙이고 문맥을 넉넉히 줘도 할 일을 잘 이해한다

지금은 에이전트 만들기가 훨씬 쉽다. 발표자는 그래도 한 층 더 파고들면 더 좋은 사용자 경험을 만들 수 있다고 본다. 다만 품이 더 든다. 이어서 Ramp Labs가 실제로 해 본 사례 세 가지를 소개한다. 03:00

03

사례 1: 작은 전문 모델 03:10

Ramp Sheets에서 시작했다 03:20

발표자 기준 작년 11월, Ramp는 스프레드시트 에이전트 Ramp Sheets를 냈다. 두 프런티어 랩이 비슷한 제품을 내기 전이었다. 여러 회사 사용자가 가입해 쓰기 시작했다.

Ramp 직원도, 고객인 회계·재무 전문가도 하루 대부분을 스프레드시트에서 보낸다. 그래서 Ramp Sheets의 하네스(harness)와 두뇌를 Ramp의 다른 화면에도 넣었다.

Opus 4.6이 막힌 곳 04:10

먼저 모델이 어디서 부족한지 찾았다. 당시 최고 모델은 Opus 4.6이었다.

  • 시트를 여러 장 넣고 DCF나 재무 시나리오를 만들어 달라고 하면, 모델은 먼저 계획을 세운다.
  • 그다음 시트를 하나하나 조사해 전체 그림을 파악한다. 여기에 시간이 많이 들었다.
  • Opus 4.6은 좋은 모델이지만 꽤 느렸다. 생각 토큰도 비쌌다.

지휘는 큰 모델, 질의응답은 작은 모델 04:50

Ramp는 금융 질의응답 모델을 따로 학습시켰다. 시트에서 필요한 정보를 찾아 답하는 검색 모델(retrieval model)이다. 프런티어 모델을 버리지 않고 역할을 나눴다.

역할맡은 모델하는 일
오케스트레이터프런티어 모델 (당시 Opus 4.6)계획을 세우고 작업을 지휘한다
금융 질의응답사후 학습한 Qwen 3.5 35B계획 에이전트가 넘긴 금융 질문에 빨리 답한다

Prime Intellect와 함께 Qwen 3.5 계열의 35B(파라미터 350억 개) 모델을 사후 학습(post-training)했다. 05:10

  • 그 과제의 정확도(exact task accuracy)에서 당시 최고였던 Opus 4.6을 넘었다.
  • 지연 시간은 자막상 "high cool" 수준이다. Haiku 수준이라는 말로 보인다(추정).
  • 훨씬 빠르면서 이 일에는 똑같이 똑똑한 모델을 프런티어 오케스트레이터와 함께 쓴다.
  • 실험으로 끝나지 않고 프로덕션에 배포했다.

작은 모델이 Opus 4.6을 넘었다는 건 Ramp가 자기 과제로 잰 결과다. 발표에서 점수, 평가 데이터, 비교 조건은 보여 주지 않았다. 자사 성과 소개라는 점을 감안해 읽자.

04

사례 2: 카트리지로 문맥 미리 준비하기 05:50

두 번째는 지금도 연구 중인 KV 캐시(KV cache) 기법이다. KV 캐시는 모델이 이미 읽은 내용을 다시 계산하지 않도록 저장해 둔 중간 결과다.

발표자가 특히 주목하는 기법은 카트리지(Cartridges)다. 문맥을 최대 20~30배 더 많이 KV 캐시에 압축해 넣는다. 압축은 미리(offline) 해 두고, 에이전트가 일할 때 붙여 쓴다.

예: 월말 결산 06:30

한 달이 끝나면 다음 달 1일에 재무 담당자가 장부를 맞추고 마감한다. 이 일을 월말 결산(month-end close)이라고 한다. 언제 할지, 어떤 자료가 필요한지 미리 안다. 원장(ledger), 채권 연령표(aging report), 관련 문서다.

문맥으로 넣기만 하면1일 아침에 에이전트가 자료를 찾아 읽는다자료를 미리 넣어 줘도, 에이전트는 스스로 찾아보고 전체 그림을 다시 만들어야 한다
→
카트리지전날 밤에 미리 만들어 둔다그 작업을 압축해 카트리지 하나로 만든다. 담당자가 에이전트를 열면 할 일을 이미 알고 있다

장점과 단서 07:10

  • 장점: 사후 학습보다 품이 훨씬 덜 든다. 발표자는 카트리지를 만드는 자기 학습 방식(self-play)이 더 범용적이라서라고 설명한다.
  • 단서: 사후 학습과 달리, 이런 기능은 랩들이 언젠가 API로 내놓을 수 있다. 랩들이 지속 학습(continuous learning)으로 나아가는 흐름의 일부다.
랩이 내놓을 기능을 왜 미리 연구하나 발표자는 랩이 API로 내놓아도 반갑다고 한다. 그동안 이 기법을 어떻게 써야 하는지 사내 노하우(tribal knowledge)가 쌓인다. 그래서 API가 나온 첫날부터 바로 쓸 수 있다.
05

사례 3: 에이전트 1만 개로 침투 테스트 07:50

세 번째는 에이전트 맵리듀스(agentic map reduce)와 에이전트 떼(agentic swarm)다. 큰 일을 여러 에이전트에게 나눠 맡기고(맵), 결과를 모아 정리한다(리듀스).

Ramp Labs 블로그에 사례를 공개했다. 에이전트 1만 개를 동시에 돌려 Ramp 전체를 침투 테스트(pen test)했다. 침투 테스트는 공격자처럼 시스템을 공격해 보안 구멍을 찾는 일이다. 08:00

이 규모를 돌릴 인프라와 연결 작업은 Ramp의 클라우드 에이전트 Ramp Inspect가 맡았다.

  1. 맵: 에이전트 1만 개가 일을 나눠 맡아 취약점을 찾고 티켓을 만든다.
  2. 리듀스 1, 중복 제거: LLM이 겹치는 티켓을 합친다.
  3. 리듀스 2, 재현: LLM이 일부러 공격하는 입장에서 취약점을 재현한다. 진짜이고 중요한지 확인하는 단계다.
결과 08:40 고위험 취약점 7개를 찾아 모두 패치했다.

그중 하나는 이메일로 보낼 수 있는 Lua 스크립트 주입(Lua script injection)이었다. 스택의 어느 부품도 그 자체로는 위험하지 않았다. 여러 부품이 어떻게 이어지는지 끝까지 이해해야 찾을 수 있었다. 에이전트 떼가 그 연결을 맞춰 냈다.

이 과정은 모두 자동으로 돈다. 사람 시간이 들지 않는다. 시작만 하면 되고, 실패해서 걸러진 시도의 비용은 토큰 값뿐이다. 09:10

떼에는 싼 모델도 통한다 09:30

Ramp Labs는 인프라만 만들지 않는다. 떼 안에서 모델을 어떻게 써야 가장 좋은지도 연구한다. 같은 글에 나온 발견이 있다.

오픈 웨이트 모델(open-weight model)은 프런티어 추론 모델보다 최대 5배 싸다. 그런데 떼로 돌리면 탐지율은 5배 떨어지지 않는다. 같은 돈으로 싼 토큰을 더 많이 쓰면 탐지율을 거의 비슷하게 낼 수 있다.

06

공통점: 시간과 돈 10:00

세 사례는 모두 시간과 돈을 아끼려는 시도다. 시간은 지연 시간(latency)이고, 돈은 토큰 비용이다. 발표자는 이게 Ramp의 슬로건 "고객의 시간과 돈을 아낀다"와 같다고 말한다.

사례시간 (지연 시간)돈 (토큰 비용)
작은 전문 모델느린 조사 단계를 빠른 모델에 넘긴다비싼 생각 토큰을 덜 쓴다
카트리지1일 아침의 자료 파악을 전날 밤에 끝낸다발표에서 따로 말하지 않았다
에이전트 떼사람 시간이 들지 않는다실패 비용은 토큰뿐이고, 오픈 웨이트 모델로 최대 5배 줄인다

연구가 들어간 Ramp 제품 10:20

발표자는 Ramp Labs 연구가 반영된 제품 두 가지를 소개한다.

토큰 지출 관리 10:30

회사의 여러 API 키를 연결해, 사내에서 LLM을 어떻게 쓰는지 보여 준다.

  • API 키별, 사용자별 토큰 지출
  • 회계 분류(accounting categories)
  • 지출을 분석해 받을 수 있는 세액 공제
  • LLM 사용을 맥락과 의미로 나눈 분류 체계(taxonomy). 어느 팀이 썼는지를 넘어 어떤 일에 썼는지 보여 준다
Ramp Router 11:10

에이전트의 지연 시간을 줄이는 라우터다. Ramp Labs와 함께 만든 라우팅 전략을 쓴다.

  • 예: Nvidia Switchyard (들린 대로, 추정)
  • 예: 작업 일부를 유연하게 다른 곳으로 넘기는 방식 (smart flex offloading, 들린 대로). 지연 시간과 토큰당 비용을 함께 줄인다
  • 전략은 더 나올 예정이다

이 대목은 Ramp 자사 제품 소개다. 발표 중 QR 코드로 제품 페이지를 안내했다. 제품 효과를 보여 주는 수치는 없었다.

08

Ramp Labs 블로그의 다른 연구 12:00

발표에서 다루지 못한 글들을 짧게 소개했다.

글내용
Portal (들린 대로) 12:10한 모델에 한 사후 학습을 다른 모델로 옮긴다. 예를 들어 Qwen 3.5에 LoRA로 학습한 결과를 새 버전 Qwen이나 다른 계열 모델로 옮긴다. 학습 결과를 잠재 표현(latent)으로 만들어 다른 모델에 투영하는 방식이다. 사후 학습에 든 비용을 여러 모델에 나눠 낼 수 있다.
LLM 사용 분류 12:40에이전트 맵리듀스로 LLM 사용을 분석하고 분류 체계를 만든다. 토큰 지출 관리 제품에 들어갔다.

09

핵심 정리

  1. 새 프런티어 모델이 나올 때마다 Ramp의 기능은 같은 정확도에 더 싸진다. LLM 사용 사례는 1년에 123% 늘었다.
  2. 그래도 기다리지 않는다. 2023년 GPT-4 시절에도 어려움을 무릅쓰고 에이전트를 출시했다.
  3. 지금은 에이전트 만들기가 쉬워졌다. 더 나은 경험을 내려면 한 층 더 파야 한다.
  4. 사례 1: 프런티어 모델은 지휘만 맡고, 느리고 비싼 금융 질의응답은 사후 학습한 작은 모델에 넘겼다.
  5. Ramp는 Qwen 3.5 35B가 그 과제에서 Opus 4.6보다 정확하고 훨씬 빠르다고 한다. 점수는 공개하지 않았다.
  6. 사례 2: 카트리지는 문맥을 최대 20~30배 압축한 KV 캐시를 미리 만든다. 월말 결산처럼 예정된 일에 맞다.
  7. 랩이 같은 기능을 API로 내놓아도 손해가 아니다. 쌓인 사내 노하우로 첫날부터 쓴다.
  8. 사례 3: 에이전트 1만 개로 침투 테스트를 하고 LLM으로 중복 제거와 재현을 해서 고위험 취약점 7개를 찾았다.
  9. 떼로 돌리면 최대 5배 싼 오픈 웨이트 모델로도 탐지율이 크게 떨어지지 않는다.
  10. 세 사례의 공통점은 시간(지연 시간)과 돈(토큰 비용)을 줄이는 것이다.
10

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1발표자가 Ramp를 "쓴 교훈이 가득한 회사"라고 부른 이유는?
새 모델이 나올 때마다 더 싸고 빠르고 좋아져서, Ramp의 기능도 저절로 좋아지기 때문이다. LLM 사용 사례는 1년에 123% 늘었고, 기능 한 번당 비용은 줄었다.
Q22023년 GPT-4로 에이전트를 만들 때 어려웠던 점은?
생각 토큰이 없어 실수해도 되돌아가지 못했다. 동의어 하나에도 행동이 바뀌어 프롬프트에 매달렸다. 문맥을 많이 주면 헷갈려서 문맥을 최소로 줄여야 했다.
Q3그런데도 2023년에 기다리지 않고 출시한 이유는?
고객인 금융 전문가에게 지금 필요했기 때문이다. GPT-4.5나 GPT-5를 기다리지 않고 Ramp Tour Guide 같은 에이전트를 냈다.
Q4Ramp Sheets에서 Opus 4.6이 막힌 지점은?
시트를 여러 장 넣고 DCF 같은 재무 모델을 요청하면, 계획을 세우고 시트를 하나하나 조사하는 데 시간이 많이 들었다. 모델이 느렸고 생각 토큰도 비쌌다.
Q5사후 학습한 Qwen 3.5 35B는 Opus를 대체했나?
아니다. 프런티어 모델은 오케스트레이터로 그대로 두고, 계획 에이전트가 금융 질의응답만 빠른 전문 모델에 넘긴다. 둘을 함께 쓴다.
Q6카트리지가 월말 결산에 잘 맞는 이유는?
언제 어떤 자료(원장, 채권 연령표, 문서)가 필요한지 미리 알기 때문이다. 전날 밤에 압축해 두면 담당자가 에이전트를 여는 순간 할 일을 이미 안다.
Q7랩이 카트리지 같은 기능을 API로 내놓을 수 있는데도 연구하는 이유는?
기법을 어떻게 써야 하는지 사내 노하우가 쌓인다. API가 나온 첫날부터 바로 쓸 수 있다.
Q8침투 테스트 떼에서 리듀스 단계가 한 두 가지 일은?
LLM으로 겹치는 티켓을 합쳤다. 그리고 LLM이 공격하는 입장에서 취약점을 재현해 진짜이고 중요한지 확인했다.
Q9Lua 스크립트 주입 사례가 보여 주는 것은?
부품 하나하나는 안전해도, 여러 부품이 이어지면 취약점이 생길 수 있다. 에이전트 떼는 여러 부품을 끝까지 이어서 이해해 그 연결을 찾아냈다.
Q10떼에 오픈 웨이트 모델을 써도 되는 근거는?
최대 5배 싸지만 떼로 돌리면 탐지율은 5배 떨어지지 않는다. 싼 토큰을 더 많이 써서 거의 비슷한 탐지율을 낸다.
Q11세 사례의 공통점은?
시간(지연 시간)과 돈(토큰 비용)을 줄이는 것이다. Ramp의 슬로건 "고객의 시간과 돈을 아낀다"와 같다.
Q12Portal 연구가 겨냥하는 비용은?
사후 학습 비용이다. 한 모델에 한 학습을 새 버전이나 다른 계열 모델로 옮기면, 그 비용을 여러 모델에 나눠 낼 수 있다.

용어뜻
쓴 교훈Bitter lesson. 사람이 짜 넣은 요령보다 더 큰 모델과 계산이 결국 이긴다는 생각. 발표자는 "모델이 좋아지면 기능도 저절로 좋아진다"는 뜻으로 썼다
프런티어 모델Frontier model. 그 시점에 가장 성능이 좋은 최신 모델
애플리케이션 계층 회사Application layer company. 모델을 직접 만들지 않고, 남이 만든 모델 위에 제품을 만드는 회사
응용 연구Applied research. 새 이론보다 지금 제품에 바로 쓸 방법을 찾는 연구
단위 경제성Unit economics. 기능 한 번, 고객 한 명처럼 작은 단위로 따진 비용과 수익
생각 토큰Thinking tokens. 모델이 답하기 전에 속으로 따져 보는 데 쓰는 토큰
가드레일Guardrails. 모델이 정해진 범위를 벗어나지 않게 막는 규칙
MCPModel Context Protocol. 모델이 외부 도구와 데이터에 연결되는 표준 방식
하네스Harness. 모델을 감싸 도구, 순서, 규칙을 정해 주는 실행 틀
오케스트레이터Orchestrator. 계획을 세우고 다른 모델이나 도구에 일을 나눠 주는 지휘 역할의 모델
사후 학습Post-training. 이미 학습된 모델을 특정 일에 맞게 더 학습시키는 것
LoRALow-Rank Adaptation. 모델 전체 대신 작은 추가 가중치만 학습하는 가벼운 사후 학습 방법
DCFDiscounted cash flow. 앞으로 들어올 현금을 지금 가치로 바꿔 기업 가치를 계산하는 재무 모델
지연 시간Latency. 요청을 보내고 답을 받기까지 걸리는 시간
KV 캐시KV cache. 모델이 이미 읽은 내용을 다시 계산하지 않도록 저장해 둔 중간 계산 결과
카트리지Cartridges. 자료 묶음을 미리 압축한 KV 캐시로 만들어 두고 에이전트에 붙여 쓰는 기법. 발표자는 문맥을 최대 20~30배 더 담는다고 했다
지속 학습Continuous learning. 모델이 배포된 뒤에도 새 정보를 계속 배우는 것
사내 노하우Tribal knowledge. 문서보다 팀의 경험에 쌓인 실무 지식
월말 결산Month-end close. 한 달이 끝난 뒤 장부를 맞추고 마감하는 회계 업무
채권 연령표Aging report. 받을 돈이나 줄 돈을 기한이 지난 기간별로 나눠 보여 주는 보고서
침투 테스트Penetration test. 공격자처럼 시스템을 공격해 보안 구멍을 찾는 시험
맵리듀스Map reduce. 큰 일을 잘게 나눠 동시에 처리하고(맵), 결과를 모아 정리하는(리듀스) 방식
에이전트 떼Agentic swarm. 많은 에이전트를 동시에 돌려 한 문제를 함께 푸는 방식
오픈 웨이트 모델Open-weight model. 학습된 가중치를 공개해 누구나 내려받아 돌릴 수 있는 모델
Lua 스크립트 주입Lua script injection. 공격자가 넣은 Lua 코드가 시스템 안에서 실행되게 만드는 공격
라우터Router. 요청마다 어느 모델이나 경로로 보낼지 정하는 장치
분류 체계Taxonomy. 대상을 기준에 따라 나눈 틀
