코딩 에이전트는 6개월 늦다

모델은 학습 데이터를 모은 뒤 반년쯤 지나서 나온다. 그 사이 바뀐 라이브러리를 모델은 모른다. 검색 도구를 붙이고, 언제 검색할지 규칙을 주고, 질문에 필요한 몇 줄만 넘기면 이 틈을 메울 수 있다.

원본 영상: Your Coding Agent Is 6 Months Out of Date 발표: Jakub Hojsan (Exa 포워드 디플로이드 엔지니어)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 뭉개진 이름은 확실한 것만 알려진 이름으로 바로잡았다. 확실하지 않은 것은 들린 대로 적고 (추정)을 붙였다. 발표자는 Exa 직원이라 제품 관련 주장은 그 점을 감안해 읽자. mm:ss는 영상 위치다.

3분 요약
  1. 발표자가 보여 준 그래프에서 모델은 지식 마감일 뒤 보통 6개월 지나 출시된다. 그 사이 바뀐 저장소는 모델의 사각지대다.
  2. 사각지대에서는 리뷰가 틀린다. 의존성 업데이트 때문에 지운 파라미터를 검색 없는 모델은 "정리 작업"으로 착각한다.
  3. 검색 결과는 페이지 통째로 넘기지 않는다. 질문에 필요한 부분만 넘긴다. 발표자 수치로 10만 자 대신 500자다.
  4. 검색 도구를 붙이는 것만으로는 부족하다. 언제 검색할지 규칙을 줘야 모델이 실제로 검색한다.
  5. Exa가 내세우는 장점은 투명성, 토큰 효율, 비용, 모델 업체 독립이다. 모두 자사 주장이다.
  6. 하이라이트는 LLM 없이 계산으로 뽑아 지연이 없다고 한다. 같은 페이지도 질문이 바뀌면 다른 부분이 나온다.
  7. 오늘 할 일: 리뷰 에이전트에 "의존성이나 버전이 바뀌면 원본 저장소를 확인하고, 찾은 내용에 근거해 리뷰하라"는 규칙을 넣는다.
01

모델이 모르는 6개월 00:20

Exa는 검색 엔진을 만드는 회사다. 발표자는 코딩 에이전트와 리뷰 에이전트에 들어가는 검색을 어떻게 만들었는지 설명한다.

사람이 구글에서 보는 "파란 링크 10개"는 에이전트에게 필요 없다. Exa는 뜻으로 찾는 시맨틱 검색 semantic search 엔진이다. 질문을 받으면 링크 목록 대신 LLM에 바로 넣을 수 있는 짧은 발췌를 돌려준다. Exa는 이 발췌를 하이라이트 highlights라고 부른다.

지식 마감일과 출시일 사이 00:40

모든 LLM에는 지식 마감일 knowledge cutoff이 있다. 학습 데이터를 모은 마지막 날이다.

발표자가 보여 준 그래프에서는 지식 마감일부터 실제 출시일까지 보통 6개월쯤 걸렸다. 그 6개월 동안에도 실제 저장소는 계속 바뀐다. 중요한 변경 기록이 나오고, 리뷰해야 할 PR이 올라온다. 모델은 그 내용을 모른다.

이 틈에서 생기는 문제는 두 가지다.

  • 새로 나온 버전의 라이브러리로는 코드를 쓰지 못한다.
  • 그 버전에서 바뀐 코드는 아예 제대로 리뷰하지 못한다.
02

사각지대에서 틀리는 리뷰 01:10

발표자가 든 예시는 몇 달 전 올라온 cooter 벡터 스토어(추정) 저장소의 PR이다. GPT-5.5의 지식 마감일 이후에 나온 변경이라 모델의 사각지대 blind spot 안에 있다. 이 PR은 inertia check(추정)라는 파라미터를 지운다.

이 diff를 누가 어떻게 리뷰하는지 비교하면 이렇다.

리뷰하는 쪽하는 일결론
사람 01:50Stack Overflow에서 "이 변수가 왜 없어졌나", "왜 컴파일이 안 되나"를 찾는다. 에러 메시지를 그대로 붙여 넣는다원하는 답을 찾고, 고치는 PR을 낸다

03

필요한 500자만 넘기기 02:50

Exa는 GitHub 저장소 페이지를 통째로 돌려주지 않는다. 그 변경을 설명하는 짧은 부분만 돌려준다.

발표자는 이 과정을 해석 단계 interpretation step라고 불렀다. 질문이 정해지면 페이지 전체에서 LLM이 그 질문에 답하는 데 필요한 부분만 골라낸다.

04

검색 도구만으로는 부족하다 03:20

발표자는 에이전트에 검색 도구를 붙이는 것만으로는 안 된다고 강조한다.

흔한 장면: Claude Code와 새 모델 이름 03:30 Claude Code에 "이제 Sonnet 4.6이나 4.7을 쓰고 싶다"고 하면, 모델이 그런 모델은 없다고 답할 때가 있다. Claude Code에는 웹 검색 도구가 기본으로 들어 있는데도 그렇다. 모델은 사용자가 말한 버전이 실제로 있을 수 있다는 걸 모른다. 그래서 검색할 생각을 하지 않는다.

그래서 검색은 두 단계 일이다. 먼저 언제 검색할지 에이전트에게 알려 준다. 검색 도구는 대개 스스로 알아서 쓰이지 않는다. 그다음에 실제로 검색을 실행한다.

도구만 붙인 에이전트검색 도구가 있지만 안 쓴다모르는 버전을 보면 "없다"고 답하거나 그럴듯하게 추측한다
→
도구 + 검색 규칙정해진 상황에서 검색하고, 그 결과에 근거해 답한다규칙이 "언제", 도구가 "어떻게"를 맡는다
발표자가 든 리뷰 에이전트 규칙 03:50 diff가 의존성이나 버전을 올리면, 원본 저장소 upstream를 찾아가 그 변경이 사실인지 확인한다. 그리고 찾은 내용에 근거해 리뷰를 쓴다.

발표자가 함께 일하는 코딩·리뷰 에이전트 고객사에서도 같은 일이 자주 생긴다고 한다. 도구를 하네스 harness에 추가해 놓고 끝내는 것이다.

도구를 하네스에 추가하는 것만으로는 충분하지 않다.발표자의 말을 옮김 · 04:10
05

Exa가 내세우는 네 가지 04:30

발표자는 외부 검색 도구인 Exa를 쓰면 얻는 것을 네 가지로 정리했다. 비교 대상은 OpenAI나 Anthropic이 모델 API에 넣어 둔 내장 웹 검색이다.

1 · 투명성 04:40

내장 웹 검색은 블랙박스다. 검색 API를 부르고, 찾은 내용을 합쳐 요약한다. 최대 10초쯤 걸린다. 돌려받는 건 출처 일부뿐이고 본문은 없다.

Exa: 어떤 쿼리로 찾았는지, 어느 출처의 어떤 발췌를 모델에 넘겼는지 전체 기록 trace을 준다. 이걸 텔레메트리 telemetry에 넣어 두면 문제가 생겼을 때 추적할 수 있다.

2 · 토큰 효율 05:10

페이지 전체를 모델에 필요한 부분으로 줄인 하이라이트를 준다.

예: 3절의 10만 자 대신 500자.

3 · 비용 05:20

모델 비용이 워낙 커서 웹 검색 비용은 눈에 잘 띄지 않는다.

발표자의 주장: 작업량이 충분히 크면 Exa가 내장 검색보다 싸고, 대부분 품질도 낫다. 구체적인 숫자는 말하지 않았다.

4 · 모델 업체 독립 05:30

외부 검색 도구를 쓰면 검색 방식이 하나로 통일된다. GLM, 새 Anthropic 모델, 새 OpenAI 모델이 나와도 똑같이 부른다.

효과: 모델을 바꿔도 API 하나와 파라미터 한 벌을 그대로 쓴다.

발표자는 Exa 직원이고, 이 네 가지는 모두 자사 제품에 대한 주장이다. 비교 수치나 근거는 발표에 나오지 않았다. 그 점을 감안해 읽자.

06

질문마다 다른 하이라이트 06:00

발표자가 보여 준 화면에 따르면, Exa는 하이라이트를 뽑을 때 LLM을 쓰지 않는다. 검색하는 순간 페이지에서 특정 줄을 계산으로 골라낸다. 그래서 페이지 내용을 함께 받아도 검색이 느려지지 않는다고 했다.

같은 사이트, 다른 질문 06:40

발표자는 자기 개인 웹사이트로 시연했다.

질문돌아온 하이라이트
약력사진을 좋아하고, 쉬는 날에는 오토바이를 탄다는 부분
전화번호같은 사이트의 전혀 다른 부분

같은 페이지라도 질문이 바뀌면 다른 부분이 나온다. 코딩에서는 이게 중요하다. GitHub 저장소에는 코드가 엄청나게 많다. 그걸 다 모델에 넣고 싶지도 않고, 다른 모델에게 요약시키고 싶지도 않다.

조건이 붙은 질문에도 쓸 수 있다. 발표자가 든 예는 "Nvidia 최신 뉴스 중 젠슨 황을 언급한 것"이다.

내장 검색과의 차이 5절의 내장 웹 검색은 모델이 검색 결과를 합쳐 다시 쓴다. 발표자 설명으로는 Exa 하이라이트는 원문에서 줄을 그대로 뽑아 온다.
07

코딩 다음: Exa Agent 07:40

발표자가 Exa에 들어온 이유도 코딩이었다. 코딩 문서를 찾으려고 Exa 검색 API를 쓰려는 사람이 많았다고 한다. 발표자는 지금 Cursor, Cognition, Warp, CodeRabbit이 Exa로 웹 검색을 한다고 소개했다.

새 제품 Exa Agent는 검색 과정을 직접 짜고 싶지 않지만 좋은 검색 결과는 필요한 경우를 위한 것이다. 웹뿐 아니라 제휴한 데이터 업체의 정보에서도 하이라이트를 뽑는다.

사람 찾기 시연 08:40

발표자는 AI Engineer 행사 참석자를 찾는 쿼리를 보여 줬다. 이 행사와 장소를 언급한 적 있는 사람이 모두 나왔고, 연사 대부분이 들어 있었다. 같은 방식으로 Exa 직원 전체와 그 이메일, LinkedIn을 찾아 영업 연락에 쓸 수도 있다고 했다.

정리자 메모: 개인 연락처를 모아 영업에 쓰려면 해당 지역의 개인정보 규정부터 확인해야 한다.

쓰는 방법 09:20

Exa는 MCP 서버로 붙일 수 있다. 발표자는 MCP를 지원하는 거의 모든 곳에서 쓸 수 있다고 했다.

08

질의응답 10:20

수십억 개 문서의 순위는 어떻게 매기나 10:20

여러 단계를 거친다고 답했다.

  1. 질문을 임베딩 embedding으로 바꾼다.
  2. 키워드 필터링과 시맨틱 검색을 함께 쓴다.
  3. 리랭커 reranker로 순위를 다시 매긴다.
  4. 관련 없는 결과는 버린다.

인덱스는 엄격하게 골라 낸 문서로 만든다. 문서 수는 구글보다 적지만 품질은 높다고 했다. 규모는 수백억 건이라고 한다.

원하는 형식으로 결과 받기 11:20

질문은 자막에 잡히지 않았다. 답을 보면 결과를 정해진 형식으로 받는 기능에 대한 질문으로 보인다.

  • 원하는 항목을 자연어로 적으면 스키마 schema를 만들어 준다. 확인을 누르면 결과가 그 스키마를 따른다.
  • 항목 수 한도는 Deep(추정) 모드가 10개, Agent가 100개라고 했다. 100개는 발표자도 확실하지 않다고 덧붙였다.
  • 추가 속성 additional properties을 켜면 스키마에 없는 항목도 받을 수 있다.
09

핵심 정리

  1. 모델은 지식 마감일 뒤 보통 6개월쯤 지나 출시된다(발표자 그래프). 그동안 바뀐 저장소는 모델의 사각지대다.
  2. 사각지대에서는 새 버전으로 코드를 쓰지 못하고, 바뀐 코드를 리뷰하지도 못한다.
  3. 검색이 없으면 리뷰 에이전트는 diff만 보고 그럴듯한 설명을 붙인다. 의존성 업데이트 때문에 지운 파라미터를 "정리 작업"으로 본다.
  4. 검색이 있으면 원본 저장소와 변경 기록을 확인해 진짜 이유와 옮겨 가는 방법까지 설명한다.
  5. 검색 결과는 페이지 통째로가 아니라 질문에 필요한 부분만 넘긴다. 10만 자 대신 500자.
  6. 검색 도구를 붙이는 것만으로는 부족하다. 언제 검색할지 규칙을 줘야 한다.
  7. 리뷰 에이전트 규칙의 예: 의존성이나 버전이 바뀌면 원본을 확인하고, 찾은 내용에 근거해 리뷰한다.
  8. Exa가 내세우는 장점은 투명성, 토큰 효율, 비용, 모델 업체 독립이다. 자사 주장이다.
  9. 하이라이트는 LLM 없이 질문 기준으로 원문 줄을 뽑는다고 한다. 같은 페이지도 질문마다 다른 부분이 나온다.
  10. Exa 검색은 임베딩, 키워드 필터, 시맨틱 검색, 리랭커를 거친다. 인덱스는 수백억 건 규모로 골라서 관리한다.
10

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1발표자가 말한 "6개월"은 무엇과 무엇 사이의 간격인가?
모델의 지식 마감일과 실제 출시일 사이. 발표자가 보여 준 그래프에서 보통 6개월쯤이었다.
Q2지식 마감일 뒤에 바뀐 저장소에 대해 모델이 못 하는 두 가지는?
새 버전의 라이브러리로 코드를 쓰는 것, 그리고 그 버전에서 바뀐 코드를 리뷰하는 것.
Q3검색 없는 LLM은 파라미터를 지운 PR을 어떻게 판단했나? 실제 이유는?
diff가 일관돼 보여서 "정리 작업"이라고 판단했다. 실제로는 의존성 버전이 올라가면서 필요해진 리팩터링이었다.
Q4검색이 있을 때 리뷰 에이전트는 무엇을 찾아보나?
저장소 자체와 그 변경 기록에 적힌 호환성 깨지는 변경. 그걸 근거로 변경 이유와 옮겨 가는 방법을 설명한다.
Q5Exa는 페이지 통째로 대신 무엇을 넘기나? 발표자가 든 글자 수는?
질문에 답하는 데 필요한 부분만 뽑은 하이라이트. 10만 자 대신 500자로, 200분의 1이다.
Q6Claude Code에 웹 검색 도구가 있는데도 Sonnet 4.6이 없다고 답하는 이유는?
모델이 그 버전이 실제로 있을 수 있다는 걸 모르고, 언제 검색해야 하는지도 모른다. 도구는 있어도 쓸 계기가 없다.
Q7검색을 제대로 쓰게 하는 두 단계는?
먼저 언제 검색할지 규칙으로 알려 주고, 그다음 실제로 검색을 실행한다.
Q8발표자가 말한 내장 웹 검색의 "블랙박스" 문제는?
검색하고 요약하는 과정이 보이지 않는다. 최대 10초쯤 걸리고, 출처 일부만 오고 본문은 오지 않는다.
Q9Exa가 내세우는 네 가지 장점은? 읽을 때 주의할 점은?
투명성, 토큰 효율, 비용, 모델 업체 독립. 발표자가 Exa 직원이라 자사 주장이고, 비교 수치는 발표에 없었다.
Q10같은 웹사이트에 "약력"과 "전화번호"를 물으면 결과가 어떻게 다른가? 무엇을 보여 주나?
약력은 취미 이야기, 전화번호는 전혀 다른 부분이 나온다. 하이라이트가 질문을 기준으로 검색하는 순간 뽑힌다는 뜻이다.
Q11질의응답에서 설명한 Exa 검색의 단계는?
질문을 임베딩으로 바꾸고, 키워드 필터링과 시맨틱 검색을 함께 쓰고, 리랭커로 다시 순위를 매기고, 관련 없는 결과를 버린다.

용어 정리

용어뜻
지식 마감일Knowledge cutoff. 모델의 학습 데이터를 모은 마지막 날. 그 뒤의 일은 모델이 모른다
사각지대Blind spot. 지식 마감일 뒤에 생긴, 모델이 모르는 변화
시맨틱 검색Semantic search. 글자가 똑같은지가 아니라 뜻이 가까운지로 찾는 검색
하이라이트Highlights. 페이지에서 질문에 필요한 부분만 뽑은 짧은 발췌
diff바뀐 코드 부분만 모은 것
의존성 업데이트Dependency bump. 프로젝트가 쓰는 외부 라이브러리의 버전을 올리는 것
변경 기록Changelog. 버전마다 무엇이 바뀌었는지 적은 문서
호환성 깨지는 변경Breaking change. 기존 코드가 그대로는 동작하지 않게 만드는 변경
마이그레이션바뀐 버전에 맞춰 기존 코드를 옮겨 고치는 일
원본 저장소Upstream. 내가 가져다 쓰는 라이브러리의 원래 저장소
하네스Harness. 모델을 감싸 도구, 순서, 규칙을 정해 주는 실행 틀
토큰모델이 글을 읽고 쓰는 단위. 모델 비용과 속도가 토큰 수에 달려 있다
트레이스Trace. 한 번의 작업이 어떤 단계를 거쳤는지 남긴 기록
텔레메트리Telemetry. 시스템 동작 기록을 자동으로 모은 데이터
임베딩Embedding. 글의 뜻을 숫자 목록으로 바꾼 것. 뜻이 비슷하면 숫자도 가깝다
리랭커Reranker. 1차로 찾은 결과의 순위를 더 정밀하게 다시 매기는 모델
스키마Schema. 결과에 들어갈 항목과 형식을 정한 틀
MCPModel Context Protocol. AI 앱에 외부 도구와 데이터를 같은 방식으로 붙이는 규약
포워드 디플로이드 엔지니어Forward Deployed Engineer. 고객 곁에서 제품 도입을 직접 돕는 엔지니어
