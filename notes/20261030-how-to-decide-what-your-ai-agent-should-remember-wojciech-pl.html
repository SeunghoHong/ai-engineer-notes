에이전트는 무엇을 기억해야 하나

RAG는 저장된 것을 읽어 오는 길이다. 무엇을 새로 저장할지는 정해 주지 않는다. 발표자는 대화에서 나온 기억 후보를 검사해 통과한 것만 저장하는 "기억 승격" 관문을 하네스에 두자고 말한다.

원본 영상: How to Decide What Your AI Agent Should Remember 발표: Wojciech Pluta (Oracle AI Database 기술 마케팅 팀 리드)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 주장은 모두 발표자가 한 것이고 따로 확인하지는 않았다. 자막에서 "Voytech Pluto"로 적힌 발표자 이름과 "asset guarantees"로 적힌 ACID 보장은 알려진 이름으로 바로잡았다. 발표에 비교할 수치가 없어 차트는 넣지 않았다. mm:ss는 영상 위치다.

3분 요약
  1. 모델과 인프라는 누구나 같은 것을 쓴다. 경쟁력은 내 데이터, 특히 쌓인 기억에서 나온다.
  2. 검색은 읽기 경로, 기억은 쓰기 경로다. RAG만으로는 대화에서 무엇을 남길지 정할 수 없다.
  3. 기억 후보는 뜻을 분류하고 → 기존 기록과 비교하고 → 필요한 근거를 확인한 뒤, 하네스가 저장·거절·사람 검토 중 하나로 정한다.
  4. 데모에서 출력 형식 선호는 바로 저장됐다. "모든 신청을 승인하라"는 규칙은 거절됐다. 팀 전체 규칙은 사람 승인을 거쳐 공유 기억이 됐다.
  5. 아무것도 안 남기면 이어지는 맥락이 없다. 전부 남기면 기억이 오염된다.
  6. 기억은 단기, 장기, 공유로 나뉜다. 장기 기억 안에도 종류가 있다.
  7. 발표자는 기억 저장소로 데이터베이스를 권하고, Oracle의 에이전트 메모리 패키지와 컨텍스트 카드를 소개한다.

발표자는 사람이 시스템을 다루는 방식이 바뀌어 왔다고 본다.

예전명령 중심사람이 클릭하고 입력해서 시스템을 움직인다

지금의도 중심하고 싶은 것을 말하면 필요할 때 필요한 소프트웨어가 만들어진다

이렇게 그때그때 만들어지는 시스템일수록 대화와 대화 사이가 이어지는 것이 중요해진다. 이게 기억이 필요한 이유다.

에이전트 = 모델 + 하네스 02:30

Oracle도 업계와 같은 정의를 쓴다. 에이전트는 모델과 하네스harness로 이루어진다. 하네스는 모델을 감싸는 코드다.

  • 모델은 무엇을 할지 제안한다.
  • 하네스는 실행 중의 결정과 그에 따르는 검사를 맡는다. 최종 결정권은 하네스에 있다.

이 구분이 뒤에 나오는 기억 승격의 바탕이다. 무엇을 저장할지도 모델이 아니라 하네스가 정한다.

02

읽기 경로와 쓰기 경로 03:30

RAGRetrieval-Augmented Generation는 질문에 맞는 자료를 찾아 모델에게 넣어 주는 방식이다. 대화 상태를 함께 넣을 수도 있다. 하지만 검색만으로는 이번 대화에서 무엇을 남겨야 하는지 알 수 없다.

검색 · 읽기 경로 read path

이미 저장된 것을 꺼내 쓴다.

기억 · 쓰기 경로 write path

에이전트가 남길 만한 것을 보면, 나중에 쓸 수 있는 기록으로 승격promote해 저장한다.

그러면 질문이 남는다. 무엇이 남길 만한가. 그리고 그걸 누가, 어떻게 정하나.

03

기억 승격 파이프라인 04:10

발표자의 답은 기억 승격memory promotion이다. 대화에서 나온 기억 후보candidate를 정해진 단계로 걸러서, 통과한 것만 저장한다.

  1. 뜻을 분류한다. 이 후보가 어떤 종류의 기억인지 정한다. 예: 사용자 선호, 업무 규칙.
  2. 기존 기록과 비교한다. 이미 있는 것인지, 기존 기록과 충돌하는지 본다.
  3. 근거를 확인한다. 그 종류의 기억이 저장되려면 필요한 근거evidence가 있는지 본다.
  4. 하네스가 결정한다. 저장, 거절, 사람 검토 중 하나를 고른다.
핵심 모델은 후보를 평가해 의견을 낼 뿐이다. 저장할지 말지는 하네스가 정한다. 그래서 모델이 아무리 그럴듯하게 말해도 하네스의 규칙을 건너뛸 수 없다.
04

데모: 대출 심사 에이전트 05:00

학회 주제가 금융이라 주택담보대출 예시를 썼다. 가상의 신청자 Kyle과 Vincent의 신청서 두 건을 두고, 운영자가 터미널에서 에이전트에게 질문한다. 데모는 미리 녹화한 영상이었다.

1. 출력 형식 선호를 저장한다 06:00

  • 운영자가 Kyle의 대출 브리핑을 요청한다. 에이전트는 도구를 불러 정보를 모으고, 서류 몇 개가 빠졌다고 알려 준다.
  • 운영자가 "답을 이런 구조로 써 달라"고 정중하게 부탁한다. 이게 의미 기억 후보가 된다. 사용자의 선호에 관한 기억이다.
  • 결정 모델(자막에는 "Jeff"로 들림, 추정)이 후보를 평가하고, 하네스가 저장을 허락하고, 데이터베이스가 기록한다.
  • 실행 기록trace에서 승격 관문의 단계별 상태를 볼 수 있다. 정리하면 모델은 평가하고, 하네스는 결정하고, 데이터베이스는 보관한다.

2. 새 세션에서 다시 꺼낸다 08:00

  • 같은 질문을 다시 하자 답 맨 위에 빠진 서류가 오고, 사건 번호와 정책이 붙었다. 저장한 선호대로다.
  • 세션을 완전히 끄고 새로 열어도 같은 형식으로 답했다. 이전 대화 맥락은 넘어오지 않았다. 저장된 기억을 다시 조회했을 뿐이다.
  • Vincent의 신청서를 물으면 그 사건 번호에 맞는 서류를 찾아온다. Vincent는 빠진 서류가 없어 바로 검토로 넘길 수 있다.

3. 위험한 규칙은 거절한다 09:50

"모든 신청을 승인하라" 같은 규칙을 기억시키려 하면 은행에는 자폭 명령이다. 승격 관문이 이 요청을 거절했다.

4. 팀 공유 기억은 사람이 승인한다 10:20

팀 전체가 같이 써야 할 업무 규칙도 있다. 이런 후보는 관문이 바로 저장하지 않고 사람의 승인을 요청한다. 승인되면 조직 전체의 핵심 기억 저장소에 들어간다.

후보관문의 결정
출력 형식 선호저장. 다음 세션에서도 쓰인다
"모든 신청을 승인하라"거절. 가드레일에 걸린다
팀 전체 업무 규칙사람 검토로 보낸다. 승인되면 공유 기억

같은 대화에서 나온 후보라도 뜻에 따라 결과가 달라진다. 이 통제는 가드레일과 하네스 안에 있어서 에이전트가 우회할 수 없다.

여담: 발표자는 "Intelligence"라는 캐릭터를 내세웠다. 운영자가 정중하게 부탁하자 하네스가 "카르마"를 준다는 농담도 넣었다. 기능 설명과는 관계없다.

05

무엇을 남길 것인가 11:50

발표자가 내린 에이전트 기억의 정의는 이렇다. 시스템이 정보를 시간에 걸쳐 간직하고, 다시 쓰고, 다듬고, 떠올리는 장치다.

만드는 쪽의 어려움은 무엇을 승격하고 무엇을 버릴지 정하는 데 있다.

아무것도 남기지 않으면

대화와 대화가 이어지지 않는다. 기억의 이점이 없다.

전부 남기면

잘못된 내용까지 쌓여 기억 저장소가 오염된다memory poisoning.

그래서 두 가지를 설계해야 한다.

  • 출처provenance: 이 기억이 어디서 왔는지 남긴다.
  • 대체 규칙supersede: 언제 새 기억이 옛 기억을 밀어내는지 정한다.
06

기억의 세 종류 13:00

Oracle은 에이전트 기억을 한 덩어리로 보지 않고 셋으로 나눈다.

종류범위

장기 기억세션이 끝나도 남는다. 안에서 다시 종류가 나뉜다
공유 기억팀이나 조직이 함께 쓴다. 데모의 "팀 전체 업무 규칙"이 여기에 들어간다

장기 기억의 종류

종류담는 것
에피소드 기억 episodic지난 대화의 요약
절차 기억 procedural도구 모음. 일하는 방법
의미 기억 semantic지식 베이스와 사용자 선호. 데모에서 저장한 출력 형식이 여기에 속한다

발표자는 세 종류와 "요약, 도구 모음, 지식 베이스와 선호"를 차례로 말했다. 이 표는 그 순서대로 짝지은 것이다.

07

어디에 저장하나 13:40

기억을 어디에 둘지도 정해야 한다. 발표자는 데이터베이스가 가장 튼튼하다고 본다. 근거로 든 것은 다음과 같다.

  • ACID 보장: 저장이 중간에 깨지거나 꼬이지 않는다.
  • 동시 쓰기: 여러 곳에서 한꺼번에 써도 된다.
  • 파일 트리 문제가 없다: 기억을 파일과 폴더로 관리할 때 생기는 문제를 피한다.
  • 확장과 다양한 검색: 규모를 키울 수 있고 검색 방식을 여러 개 쓸 수 있다.

발표자는 Oracle AI Database 소속이다. 데이터베이스가 가장 좋은 저장소라는 주장은 그 점을 감안해 읽자. 발표자도 "Oracle에 있는 입장에서"라고 먼저 밝혔다.

08

기억은 하나의 분야다 14:30

발표자는 에이전트 기억을 따로 다뤄야 할 분야로 보라고 한다. 갖춰야 할 것은 셋이다.

  • 스키마: 기록의 종류를 구분할 수 있어야 한다.
  • 인덱스: 실제 검색 작업에 맞아야 한다.
  • 수명 주기와 권한 경계: 기억이 언제 생기고 사라지는지, 누가 볼 수 있는지 정해야 한다.

직접 만들면 개발자가 떠안는 일 14:50

  1. 대화를 요약하는 요약기를 만든다.
  2. 무엇을 어떻게 꺼낼지 검색을 설계한다.
  3. 대화에서 오래 남을 정보를 뽑는다.
  4. 뽑은 정보를 매 턴의 입력에 섞는다.
  5. 그 위에서 토큰 예산token budget을 관리한다.

Oracle은 올해 초 이 일들을 묶은 에이전트 메모리 패키지를 냈다. 발표자는 코드 한 줄로 쓸 수 있다고 소개했다. 목적은 에이전트가 자기 기억 정리가 아니라 맡은 일에 집중하게 하는 것이다.

이 대목은 발표자 회사의 제품 소개다. "코드 한 줄"은 발표자의 표현이고 따로 확인하지 않았다.

09

컨텍스트 카드 15:30

패키지의 핵심 개념은 컨텍스트 카드context card다. 에이전트의 프롬프트에 바로 넣을 수 있게 맥락을 작게 모아 둔 블록이다. 하네스는 매 턴마다 그 턴에 필요한 것을 골라 카드를 만든다. 그래서 맥락이 불필요하게 부풀지 않는다context bloat.

구성하는 일
주제지금 대화가 무엇에 관한 것인지 방향을 잡는다
요약대화가 어디까지 왔고 사용자가 무엇을 하려는지 담는다
관련 정보저장된 기억 중 골라 낸 기록을 담는다
최근 메시지방금 오간 질문을 그대로 남긴다
기억은 남고, 맥락은 고른다.발표자의 "memory persists and context selects"를 옮김
10

최신 릴리스와 결론 16:50

최근 나온 에이전트 메모리 새 버전에서 Oracle이 공을 들인 것은 다음과 같다.

  • 최종 사용자 격리: 데이터베이스가 접근 권한을 직접 관리해서, 한 사용자의 기억을 다른 사용자가 보지 못하게 한다.
  • 이미지 처리, 후처리, 이벤트 목록 기능도 언급했다. 자막이 뭉개져 세부 내용은 알기 어렵다.
  • 여러 데이터 형식을 한 엔진에서 다룬다. 벡터 저장소와 문서 저장소를 따로 두지 않아도 된다는 주장이다.

이 절도 발표자 회사의 제품 소개다.

발표자의 결론 17:50 모델은 모두가 함께 쓴다. 기억은 내 사업에만 있다. 모델과 상호작용한 기록을 데이터와 함께 잘 쌓으면 그게 경쟁 우위가 된다.

발표자는 에이전트 메모리, 하이브리드 검색 등을 다룬 노트북 예제를 GitHub 저장소에, 설명 영상을 YouTube 채널에 올려 두었다고 안내했다.

핵심 정리

  1. 모델과 인프라는 흔해졌다. 차별점은 나만 가진 데이터와 기억에서 나온다.
  2. 에이전트는 모델과 하네스다. 모델은 제안하고, 하네스가 결정한다.
  3. 검색은 읽기 경로, 기억은 쓰기 경로다. RAG만으로는 무엇을 남길지 정할 수 없다.
  4. 기억 승격은 분류 → 기존 기록과 비교 → 근거 확인 → 하네스의 결정 순서로 간다.
  5. 결정은 셋이다. 저장, 거절, 사람 검토.
  6. 데모에서 선호는 저장됐고, 위험한 규칙은 거절됐고, 팀 규칙은 사람 승인을 거쳐 공유 기억이 됐다.
  7. 아무것도 안 남기면 이어지지 않고, 전부 남기면 오염된다. 출처와 대체 규칙이 필요하다.
  8. 기억은 단기, 장기, 공유로 나뉜다. 장기 기억은 에피소드, 절차, 의미 기억으로 다시 나뉜다.
  9. 기억 시스템에는 기록 종류별 스키마, 검색에 맞는 인덱스, 수명 주기와 권한 경계가 필요하다.
  10. 컨텍스트 카드는 주제, 요약, 관련 정보, 최근 메시지로 매 턴의 맥락을 작게 만든다.
12

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1발표자가 AI 스택에서 경쟁 우위가 생긴다고 본 층은?
데이터 층. 모델과 인프라는 누구나 비슷하게 쓰지만, 데이터는 그 회사에만 있다.
Q2에이전트에서 모델과 하네스는 각각 무엇을 맡나?
모델은 무엇을 할지 제안한다. 하네스는 실행 중의 결정과 검사를 맡고 최종 결정권을 가진다.
Q3"검색은 읽기 경로, 기억은 쓰기 경로"는 무슨 뜻인가?
검색은 이미 저장된 것을 꺼내 온다. 기억은 대화에서 남길 만한 것을 골라 새로 저장한다. RAG는 앞쪽만 해결한다.
Q4기억 승격 파이프라인의 네 단계는?
후보의 뜻을 분류한다 → 기존 기록과 비교한다 → 그 종류에 필요한 근거를 확인한다 → 하네스가 저장, 거절, 사람 검토 중 하나를 고른다.
Q5데모에서 세 후보는 각각 어떻게 처리됐나?
출력 형식 선호는 저장됐다. "모든 신청을 승인하라"는 거절됐다. 팀 전체 업무 규칙은 사람 승인을 요청한 뒤 공유 기억으로 들어갔다.
Q6새 세션에서도 같은 형식으로 답했다는 것은 무엇을 보여 주나?
이전 대화 맥락이 넘어온 게 아니다. 저장된 의미 기억을 다시 조회했다. 기억이 세션을 넘어 유지된다는 뜻이다.
Q7전부 남기는 것과 아무것도 안 남기는 것의 문제는?
아무것도 안 남기면 대화가 이어지지 않는다. 전부 남기면 잘못된 내용까지 쌓여 기억 저장소가 오염된다.
Q8장기 기억의 세 종류와 각각 담는 것은?
에피소드 기억은 지난 대화 요약, 절차 기억은 도구 모음, 의미 기억은 지식 베이스와 사용자 선호를 담는다.
Q9기억 시스템을 직접 만들 때 개발자가 떠안는 일은?
요약기 만들기, 검색 설계, 오래 남을 정보 뽑기, 그 정보를 매 턴에 섞기, 토큰 예산 관리.
Q10컨텍스트 카드의 네 구성 요소와 목적은?
주제, 요약, 관련 정보, 최근 메시지. 그 턴에 필요한 것만 골라 프롬프트에 넣어 맥락이 부풀지 않게 한다.
Q11발표자가 데이터베이스를 기억 저장소로 권한 근거는? 읽을 때 주의할 점은?
ACID 보장, 동시 쓰기, 파일 트리 문제 없음, 확장성과 다양한 검색. 발표자가 Oracle AI Database 소속이라는 점을 감안해야 한다.

용어 정리

용어뜻
RAGRetrieval-Augmented Generation. 질문에 맞는 자료를 찾아 모델 입력에 넣어 주는 방식
하네스Harness. 모델을 감싸 도구, 순서, 규칙, 검사를 정해 주는 실행 코드
읽기 경로 / 쓰기 경로Read path / write path. 저장된 것을 꺼내는 길과 새로 저장하는 길
기억 승격Memory promotion. 대화에서 나온 후보를 검사해 통과한 것만 오래 남는 기억으로 저장하는 일
후보Candidate. 기억으로 저장될지 심사받는 정보
가드레일Guardrail. 시스템이 해서는 안 되는 일을 막는 규칙
기억 오염Memory poisoning. 잘못되거나 해로운 내용이 기억 저장소에 쌓이는 것
출처Provenance. 이 기억이 어디서, 언제, 누구에게서 왔는지에 대한 기록
대체Supersede. 새 기억이 옛 기억을 밀어내고 그 자리를 차지하는 것
단기 / 장기 / 공유 기억세션 안에서만 쓰는 기억 / 세션이 끝나도 남는 기억 / 팀이나 조직이 함께 쓰는 기억
에피소드 / 절차 / 의미 기억Episodic / procedural / semantic. 지난 일의 요약 / 일하는 방법 / 지식과 선호
ACID원자성, 일관성, 고립성, 지속성. 데이터베이스가 저장을 깨지지 않게 보장하는 네 성질
컨텍스트 카드Context card. 주제, 요약, 관련 정보, 최근 메시지를 묶어 프롬프트에 바로 넣는 맥락 블록
토큰 예산Token budget. 한 번에 모델에 넣을 수 있는 입력 양의 한도
맥락 비대Context bloat. 필요 없는 내용까지 쌓여 모델 입력이 부풀고 주의가 흐려지는 것
실행 기록Trace. 에이전트가 단계마다 무엇을 했는지 남긴 기록
