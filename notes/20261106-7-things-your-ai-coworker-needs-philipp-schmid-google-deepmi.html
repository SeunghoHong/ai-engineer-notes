AI 동료에게 필요한 일곱 가지

AI 에이전트를 새로 들어온 동료처럼 맞이하려면 두뇌, 컴퓨터, 업무 지침, 도구, 로그인, 사내 규칙, 근무 일정이 필요하다. 발표자는 Gemini API의 managed agents로 이 일곱 가지를 하나씩 채워 금융 업무 동료를 만든다.

원본 영상: 7 Things Your AI Coworker Needs 발표: Philipp Schmid (Google DeepMind)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 뭉개진 이름은 확실한 것만 알려진 이름으로 고쳤고, 나머지는 들린 대로 쓰고 "(추정)"을 붙였다. mm:ss는 영상 위치다.

발표자는 Google DeepMind 소속이고, 이 발표는 자사 제품인 Gemini와 managed agents를 소개한다. 제품의 장점을 말하는 대목은 그 점을 감안해 읽자.

3분 요약
  1. AI는 챗봇 → 도구를 쓰는 어시스턴트 → 자기 컴퓨터를 가진 자율 동료로 옮겨 가고 있다. 일을 맡기고 몇 시간 뒤 결과를 받는다.
  2. 사람 신입처럼 AI 동료에게도 두뇌, 컴퓨터, 업무 지침, 도구, 로그인, 사내 규칙, 근무 일정이 필요하다.
  3. managed agents는 모델에게 원격 샌드박스를 준다. 도구 호출을 내 쪽에서 돌리지 않아도 되고, API 한 번이면 된다.
  4. 지식은 세 층으로 나눈다. 늘 붙는 시스템 지시문은 짧게, 스킬은 필요할 때만 읽게, 긴 내용은 참고 문서와 스크립트로 쪼갠다. 모두 파일이다.
  5. 로그인: 진짜 키는 샌드박스 밖에 쓰기 전용으로 둔다. 에이전트는 가짜 값만 갖고, 네트워크 프록시가 허용한 도메인에서만 진짜 키로 바꿔 끼운다.
  6. 훅은 정규식으로 도구 호출을 걸러 사람 승인을 받게 한다. cron 트리거는 정해진 시각에 에이전트를 깨운다.
  7. 시연: 아침마다 포트폴리오를 점검해 시트를 고치고, Slack 질문에는 추천만 하고 직접 거래하지는 않는 금융 동료.
01

챗봇에서 동료로 00:20

발표의 목표는 금융 업무를 혼자 해내는 AI 동료를 직접 만들어 보는 것이다. 발표자는 먼저 지난 2년 동안 AI가 어떻게 바뀌었는지 짚는다.

시기형태하는 일
2년 전챗봇"프랑스의 수도는?" 같은 간단한 질문에 답한다
그다음어시스턴트내 컴퓨터의 도구를 쓴다. 첫 코딩 에이전트가 코드를 대신 써 준다
지금자율 동료자기 컴퓨터를 받는다. 일을 맡기면 몇 시간 뒤 결과를 가져온다

마지막 단계를 발표자는 디지털 직원 digital employee을 만드는 일이라고 부른다.

02

동료에게 필요한 일곱 가지 00:50

사람이든 AI든 새로 온 동료가 일하려면 갖춰 줘야 할 것이 있다. 발표자는 이를 일곱 가지로 나누고, 각각을 Gemini 쪽 기능에 하나씩 대응시킨다.

필요한 것사람 동료라면발표에서 채운 방법
1. 두뇌일을 해낼 머리Gemini 모델
2. 컴퓨터작업물을 저장하고 고쳐 나갈 자리managed agents의 샌드박스
3. 업무 지침신입은 회사 환경과 업무 영역을 모른다. 팀마다 정해진 작업 방식도 있다시스템 지시문, 스킬 파일
4. 도구업무용 소프트웨어Google 검색, 코드 실행, MCP 서버, 직접 만든 함수
5. 로그인계정과 인증 정보네트워크 프록시로 지키는 인증 정보
6. 사내 규칙해도 되는 일, 하면 안 되는 일, 승인받아야 하는 일훅
7. 근무 일정언제 출근하고 언제 일하는가cron 트리거

"업무 지침"은 발표의 playbook을 옮긴 말이다. 신입 직원에게 건네는 업무 매뉴얼에 가깝다.

03

두뇌: 새 Gemini 모델 01:50

발표 전날 Google은 새 Gemini 모델을 공개했다. 자막에는 모델 이름이 "Gemini 4 Argon"으로 들린다(추정). 발표자가 꼽은 특징은 다음과 같다.

  • 컨텍스트 창 context window이 100만 토큰이다. 입력과 출력이 한 창을 함께 쓴다. 발표자는 출력도 최대 100만 토큰까지 낼 수 있다고 했다.
  • 수학과 추론이 크게 좋아졌다. 증명 같은 문제를 풀 때 생각에 쓸 수 있는 토큰이 64K(약 6만 4천) 이상이다.
  • "벤치마크 점수만 좋은 것 아니냐"는 의심은 늘 있다. 발표자는 Google 안에서 많이 써 봤다며 직접 써 보라고 권했다.

시작하는 법과 가격 02:40

  • Interactions API로 부른다. 발표자 말로는 코드 네 줄이면 된다.
  • API 키는 AI Studio에서 받는다.
  • 가격은 입력 2달러, 출력 10달러다. 발표자는 프런티어 모델치고 싼 편이라고 했다.
  • 지금 돌리고 있는 에이전트에게 링크를 주고 "Gemini 4를 설정해서 써 봐"라고 시켜도 된다고 했다.

Google 안에서 쓴 사례 03:10

공개 전 몇 주 동안 사내에서 먼저 썼다고 한다. 발표자가 든 예는 이렇다.

  • Chrome 팀: Chromium 브라우저의 코드를 떼어 내는 작업을 앞당겼다.
  • Gemma: Google의 공개 모델 Gemma를 더 쉽고 효율적으로 돌릴 수 있게 했다.
  • Google Cloud의 ADK 팀: 에이전트 개발 프레임워크를 개선했다.
  • 사내 코드베이스: 내부 코드 작업에서도 큰 개선을 봤다.
동료의 데모: Python 3D 레이 트레이서 03:50 발표자의 동료가 Gemini에게 Python으로 3D 레이 트레이서를 만들게 했다. 외부 도구 없이 Python만으로 Gemini가 전부 만들었다. 작동 원리를 설명하는 음성은 Gemini TTS 모델과 Lyria로 붙였다. 발표자는 "아주 야심차게 시도하라"고 권했다.

자막의 "Luria"는 Google의 생성 모델 Lyria로 보고 고쳤다. 이 절은 발표자 회사의 새 모델을 소개하는 부분이다.

04

컴퓨터: managed agents 04:20

managed agents는 Gemini API의 제품이다. 원격 에이전트 remote agent를 쉽게 만들게 해 준다. 핵심은 Gemini에게 도구를 돌릴 샌드박스 sandbox를 주는 것이다. 샌드박스는 바깥과 격리된 실행 공간이다.

보통의 에이전트내가 실행한다모델이 JSON 형식의 함수 호출을 만든다. 내가 받아 내 기계에서 실행하고, 결과를 다시 모델에게 보낸다. 이 루프를 내가 돌린다.
→
managed agents모델이 자기 컴퓨터에서 실행한다Gemini가 샌드박스에서 코드를 돌리고 파일을 쓴다. 나는 API를 한 번 부른다.

부르는 법 05:10

  1. 모델 ID 자리에 에이전트 ID를 넣는다. 발표에서 쓴 ID는 자막에 "anti-gravity preview 09"로 들린다(추정).
  2. 프롬프트를 준다.
  3. 실행 환경을 원격으로 정한다. 그러면 Google이 관리하는 샌드박스에서 돈다.

오늘의 동료 만들기 05:30

발표자는 오늘 만들 동료를 "Bug"라고 부른다(들린 대로, 추정). 두뇌는 Gemini, 컴퓨터는 managed agents다. 에이전트를 정의할 때는 네 가지를 적는다.

항목뜻발표에서 쓴 값
ID나중에 에이전트를 부를 이름bug
기본 에이전트밑에서 도는 에이전트 하네스. 모델을 감싸 도구와 실행 순서를 정해 주는 틀이다Antigravity와 같은 하네스
모델쓸 모델새 Gemini 모델
시스템 지시문에이전트의 역할을 정하는 글"You are bug"

부를 때는 Interactions API의 create를 쓴다. 모델 ID나 기본 에이전트 대신, 직접 만든 에이전트 bug를 넣는다.

Antigravity를 쓰고 있다면 발표자에 따르면 원격 에이전트는 Google의 코딩 에이전트 Antigravity와 같은 하네스를 쓴다. 로컬에서 Antigravity를 쓰던 사람은 같은 하네스를 원격에서 쓰는 셈이다.
05

모든 것은 파일 06:30

에이전트의 컴퓨터도 일을 시작하려면 파일과 기본 뼈대가 필요하다. managed agents는 세 가지 방법으로 작업 환경을 미리 채운다.

방법내용
파일 직접 넣기스킬이나 AGENTS.md 내용을 요청에 바로 넣는다
GitHub 저장소스킬이 든 저장소를 연결한다. 공개 저장소와 비공개 저장소 모두 된다
GCS 버킷Google Cloud Storage 버킷을 연결한다

managed agents에서는 모든 것이 파일이다. 스킬도, 훅도, 시스템 지시문도 파일로 들어 있다. 에이전트의 컴퓨터는 결국 하나의 파일 시스템이다. 그래서 에이전트는 이런 일도 할 수 있다.

  • 스스로 나아지려고 새 스킬을 만든다.
  • 이전 세션에서 기억하거나 배운 것을 저장한다.
06

업무 지침: 지식 세 층 07:10

새 직원에게 업무 지침서를 주듯 에이전트에게도 지식을 준다. 발표자는 이 지식을 세 층으로 나눈다.

층담는 곳언제 읽나원칙
1. 늘 붙는 지식시스템 지시문모든 요청아주 짧게 쓴다
2. 골라 쓰는 지식스킬. 짧은 설명과 본문으로 나뉜다설명을 보고 에이전트가 필요하다고 판단할 때 본문을 읽는다본문도 길고 빽빽하게 쓰지 않는다
3. 깊이 들어가는 지식스킬에 딸린 참고 문서와 스크립트특정 작업에 더 많은 맥락이 필요할 때잘게 쪼개 따로 둔다
왜 나누나: 컨텍스트는 귀하다 시스템 지시문은 모든 요청에 실린다. 길면 모든 요청이 비싸진다. 스킬 본문도 읽을 때마다 비용이 든다. 그래서 늘 필요한 것만 위층에 두고, 나머지는 필요할 때 꺼내 읽게 한다.

예시 스킬: 포트폴리오 감사 08:20

발표에서 보여 준 스킬은 포트폴리오를 점검하는 스킬이다. 자막으로 보면 다음 내용을 담고 있다.

portfolio audit 스킬
  • 언제 이 스킬을 써야 하는가
  • 어떻게 실행하는가에 대한 지시
  • 에이전트가 돌릴 Python 스크립트
  • 결과로 무엇을 해야 하는가
  • 결과를 어디에 저장하는가

설명은 짧게, 실제 계산은 스크립트에 맡긴다. 세 층 구조를 그대로 따른 모양이다.

07

도구: 내장, MCP, 직접 만든 함수 08:40

사람은 업무용 소프트웨어를 쓴다. 에이전트가 쓰는 도구는 세 종류다. managed agents에서는 에이전트를 만들 때 도구 목록도 함께 정한다.

종류예특징
내장 도구Google 검색, 코드 실행Gemini API에 들어 있다. 따로 할 일이 없다
MCP 서버Google Workspace의 Gmail·스프레드시트 MCP 서버, 내가 만든 MCP 서버외부 서비스를 붙인다. MCP Model Context Protocol는 AI가 외부 도구를 쓰는 표준 연결 방식이다
직접 만든 함수내 코드 안의 함수에이전트가 함수 호출을 만들면 내가 실행하고 결과를 돌려준다

직접 만든 함수는 평소 모델에 함수를 붙이던 방식과 같다. 차이는 쓰임새다. 에이전트의 샌드박스 밖에서 실행해야 하는 일을 맡길 때 쓴다.

08

로그인: 키를 맡기지 않는다 09:50

발표자가 managed agents에서 가장 자랑하는 기능이다. 에이전트에게 인증 정보 credentials를 주는 일은 어렵고 틀리기 쉽다. 에이전트가 일을 그르치기도 쉽다.

세 가지 인증 방식 10:20

방식주로 쓰는 곳
Bearer 토큰일반 API 호출
OAuth일반 사용자용 서비스의 MCP 서버나 도구
환경 변수CLI 같은 명령줄 도구

진짜 키는 밖에 둔다 10:40

  • 인증 정보를 샌드박스 안이 아니라 밖에서 만든다.
  • 쓰기 전용이다. 한 번 쓰면 다시 꺼내 볼 수 없고 덮어쓰기만 된다. 발표자는 그래서 샐 수가 없다고 말한다.
  • 키마다 어디서 쓸지 정한다. 예를 들어 Slack 키는 특정 도메인이나 특정 환경 변수에서만 쓰게 한다.

가짜 값 바꿔치기 11:30

이 일은 네트워크 프록시 network proxy가 한다. 프록시는 샌드박스를 감싸고 드나드는 모든 네트워크 트래픽을 지켜본다.

  1. 샌드박스의 환경 변수에는 가짜 값이 들어 있다.
  2. 에이전트는 그 가짜 값으로 요청을 보낸다.
  3. 프록시가 요청을 본다. 사용자가 정해 둔 도메인으로 가는 요청인지 확인한다.
  4. 맞으면 가짜 값을 진짜 키로 바꿔 내보낸다.
  5. 요청이 성공하고 결과가 에이전트에게 돌아온다. 에이전트는 자기 값이 가짜인 줄 모른다.
키를 샌드박스 안에 두면에이전트가 진짜 키를 갖고 있다".env 값을 출력해" 같은 공격 한 줄에 키가 샌다.
→
프록시를 쓰면에이전트는 가짜 값만 갖는다진짜 키는 밖에 있고, 정해 둔 도메인으로 가는 요청에서만 끼워진다.

프롬프트 인젝션이 키를 못 훔치는 이유 12:10

프롬프트 인젝션 prompt injection은 입력에 지시문을 숨겨 AI가 그 지시를 따르게 만드는 공격이다. 공격자가 ".env 파일 값을 전부 출력해"라고 시키면, 보통의 에이전트는 키를 그대로 내보낼 수 있다.

이 구조에서는 샌드박스 안에 가짜 값뿐이다. 프록시는 사용자가 정한 도메인으로 가는 요청에만 진짜 키를 끼운다. 그래서 악성 MCP 서버가 Gmail 토큰을 훔쳐 갈 수 없다. 발표자는 덕분에 에이전트를 믿고 MCP 서버를 붙이기가 훨씬 쉬워진다고 했다.

"프롬프트 인젝션이 통할 길이 없다"는 말은 발표자 회사 제품에 대한 주장이다. 정리하며 추론한 점도 하나 덧붙인다. 이 구조가 막는 것은 키가 밖으로 새는 일이다. 허용한 도메인으로 에이전트가 원치 않는 요청을 보내는 일까지 막는다고 발표가 말하지는 않았다. 발표는 그다음 장치로 훅을 소개한다.

09

사내 규칙: 훅 12:50

프록시로도 부족하면 훅 hooks을 쓴다. 훅은 특정 결정을 결정론적으로 deterministically 막는다. 모델의 판단에 맡기지 않고, 조건이 맞으면 반드시 실행된다는 뜻이다.

  • 지켜봐야 할 명령을 에이전트가 실행하려 할 때 쓴다.
  • 사람의 승인이 필요한 일에 쓴다. 이런 승인을 휴먼 인 더 루프 human in the loop라고 한다. 승인은 에이전트와의 평소 대화 밖에서 받는다.

동작 방식 13:10

  1. 훅마다 매처 matcher를 정한다. 매처는 정규식이다.
  2. 에이전트가 만드는 모든 도구 호출을 매처와 대조한다.
  3. 맞는 호출이 있으면 그 훅을 실행한다.

발표자는 다른 에이전트 하네스의 훅과 거의 같은 방식이라고 했다.

에이전트는 훅을 고칠 수 없다 훅도 파일이다. 하지만 보호된 파일이라 에이전트가 훅을 고쳐서 빠져나갈 수 없다.

예시(발표에 없음): 메일 발송이나 주문 실행 같은 도구 호출에 매처를 걸면, 사람이 승인하기 전에는 그 호출이 실행되지 않게 할 수 있다.

10

근무 일정: 트리거 13:30

일곱째는 에이전트가 누가 시키기 전에 먼저 움직이게 하는 것이다. 발표자는 이를 에이전트를 더 능동적으로 proactive 만드는 일이라고 한다.

지금 지원 · cron 트리거

정해진 일정에 에이전트를 실행한다. 예를 들어 아침 8시마다 정해진 입력으로 같은 환경에서 돌린다.

쓰임: 실사 due diligence나 감사처럼 주기적으로 반복하는 점검

준비 중 · 웹훅 14:00

외부 서비스가 이벤트를 보내면 에이전트가 바로 깨어난다. 1차 점검을 하고 Slack이나 Microsoft Teams로 바로 알린다.

장점: 이 연결을 위해 따로 인프라를 관리하지 않아도 된다

11

시연: 포트폴리오 감사 동료 14:30

발표자는 Gemini의 도움으로 브라우저 안에 Google Sheets처럼 생긴 화면을 만들었다. 화면의 버튼을 누르면 cron 트리거가 울린 것처럼 흉내 낸다. 실제로 managed agents API를 부른다.

  1. 에이전트가 먼저 포트폴리오 감사 스킬을 읽는다.
  2. 스킬을 보고 무엇을 해야 하는지 파악한다.
  3. 금융 서비스를 호출해 시장이나 주가가 바뀌었는지 확인한다.
  4. 결과를 바탕으로 시트를 자동으로 고친다.

실제 운영에서는 이 트리거가 매일 오전 8시 30분에 사람 손 없이 돈다. 에이전트가 Slack에 접근할 수 있으면, 트레이딩 채널에 무엇이 바뀌었는지 올릴 수도 있다.

Slack에서 추천 묻기 15:50

발표자가 Slack에서 에이전트에게 "추천할 거 있어?"라고 묻는다. 에이전트는 포지션 세 개를 들어 답한다. 이전 대화를 모두 알고 있어서, 무엇이 바뀌었는지 맥락까지 설명한다.

추천은 하되 행동하지 않는다 에이전트는 추천만 하고 직접 거래하지는 않았다. 시스템 지시문에 그렇게 정해 두었기 때문이다. 사람 동료에게 "제안은 하되 결정은 승인받고 하라"고 정해 주는 것과 같다.

발표자는 이 에이전트를 돌리는 데 필요한 인프라가 모두 managed agents 안에 있다고 강조했다. 이미 쓰는 도구에 붙이기 쉽다는 뜻이다.

12

한 서비스에 모은 일곱 가지 16:40

발표자는 일곱 가지를 한 서비스 안에서 다 채울 수 있다고 정리한다.

  • 두뇌는 Gemini, 컴퓨터는 managed agents다.
  • 스킬은 로컬 컴퓨터에서 다른 에이전트에 쓰던 것을 그대로 줄 수 있다.
  • 도구로 MCP 서버를 붙여 외부 서비스와 데이터 제공 업체를 연결한다.
  • 인증 정보를 안전하게 넣고 교체할 수 있다.
  • 훅은 반드시 지켜야 할 규칙을 결정론적으로 지킨다.
  • 트리거는 에이전트가 먼저 움직이게 한다.
Go hire your first AI co-worker. (첫 AI 동료를 채용하라.)발표자의 마지막 말
13

핵심 정리

  1. AI는 챗봇에서 도구를 쓰는 어시스턴트를 거쳐, 자기 컴퓨터를 가진 자율 동료로 옮겨 가는 중이다.
  2. AI 동료에게도 신입처럼 두뇌, 컴퓨터, 업무 지침, 도구, 로그인, 사내 규칙, 근무 일정이 필요하다.
  3. managed agents는 모델에게 원격 샌드박스를 준다. 도구 호출 루프를 내가 돌리지 않는다.
  4. 에이전트 정의는 ID, 기본 하네스, 모델, 시스템 지시문이면 된다. 부를 때는 모델 ID 대신 에이전트 ID를 쓴다.
  5. 스킬, 훅, 시스템 지시문, 기억까지 모두 파일이다. 파일 직접 넣기, GitHub, GCS로 환경을 미리 채운다.
  6. 지식은 세 층이다. 늘 붙는 시스템 지시문은 짧게, 스킬은 필요할 때, 긴 내용은 참고 문서와 스크립트로.
  7. 도구는 내장 도구, MCP 서버, 직접 만든 함수다. 샌드박스 밖에서 돌아야 할 일은 직접 만든 함수로 둔다.
  8. 진짜 키는 밖에 쓰기 전용으로 둔다. 프록시가 허용한 도메인에서만 가짜 값을 진짜 키로 바꿔 끼운다.
  9. 훅은 정규식 매처로 도구 호출을 걸러 사람 승인을 받게 한다. 에이전트는 훅을 고칠 수 없다.
  10. cron 트리거로 정해진 시각에 일하게 한다. 웹훅은 준비 중이다.
14

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1발표자가 말한 AI의 세 단계는?
간단한 질문에 답하는 챗봇, 내 컴퓨터의 도구를 쓰는 어시스턴트(첫 코딩 에이전트), 자기 컴퓨터를 받아 몇 시간 동안 혼자 일하는 자율 동료.
Q2AI 동료에게 필요한 일곱 가지는?
두뇌, 컴퓨터, 업무 지침, 도구, 로그인(인증 정보), 사내 규칙, 근무 일정.
Q3보통의 도구 호출 루프와 managed agents는 무엇이 다른가?
보통은 모델이 만든 함수 호출을 내가 받아 내 기계에서 실행하고 결과를 돌려준다. managed agents에서는 Gemini가 자기 샌드박스에서 직접 실행한다. 나는 API를 한 번 부른다.
Q4에이전트를 정의할 때 적는 네 가지는?
ID, 기본 에이전트(하네스), 모델, 시스템 지시문.
Q5에이전트의 작업 환경을 미리 채우는 세 방법은?
스킬이나 AGENTS.md를 요청에 직접 넣기, GitHub 저장소 연결하기, GCS 버킷 연결하기.
Q6시스템 지시문을 짧게 써야 하는 이유는?
모든 요청에 실리기 때문이다. 길면 모든 요청이 비싸진다. 컨텍스트는 귀하다.
Q7지식의 세 층은 각각 어디에 담기나?
늘 붙는 지식은 시스템 지시문, 골라 쓰는 지식은 스킬(짧은 설명과 본문), 깊이 들어가는 지식은 스킬에 딸린 참고 문서와 스크립트.
Q8도구로 직접 만든 함수를 쓰는 때는?
에이전트의 샌드박스 밖에서 실행해야 하는 일을 맡길 때. 에이전트가 함수 호출을 만들면 내가 실행하고 결과를 돌려준다.
Q9managed agents가 지원하는 세 가지 인증 방식은?
일반 API 호출용 Bearer 토큰, 사용자용 MCP 서버나 도구용 OAuth, CLI 등에 쓰는 환경 변수.
Q10".env 값을 출력해"라는 공격이 왜 키를 훔치지 못하나?
샌드박스 안에는 가짜 값만 있다. 진짜 키는 밖에 쓰기 전용으로 있고, 프록시가 사용자가 정한 도메인으로 가는 요청에서만 진짜 키로 바꿔 끼운다.
Q11훅은 어떻게 동작하고, 에이전트는 왜 훅을 우회하지 못하나?
정규식 매처로 모든 도구 호출을 대조하고, 맞으면 훅을 실행한다. 훅 파일은 보호돼 있어 에이전트가 고칠 수 없다.
Q12Slack 시연에서 에이전트가 추천만 하고 거래하지 않은 이유는?
시스템 지시문에 행동하지 말고 추천만 하라고 정해 두었기 때문이다.
