YOLO 모드를 안전하게 쓰는 법

코딩 에이전트에게 "나쁜 짓은 하지 마"라고 부탁해서는 내 컴퓨터를 지킬 수 없다. 발표자는 프롬프트 다섯 번으로 자기 은행 정보를 털어 보인 뒤, 에이전트를 microVM 안에 가두는 Docker의 sbx를 대안으로 보여 준다.

원본 영상: YOLO Mode, Safely: MicroVM Sandboxes for Any Agent 발표: Rowan Christmas (Docker 프로덕트 매니저, 샌드박스 제품 담당)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치와 주장은 모두 발표자가 말한 것이고 따로 확인하지 않았다. 발표자는 이 제품을 맡은 Docker 직원이니, 제품의 장점에 관한 말은 그 점을 감안해 읽자. 자막에서 뭉개진 이름(Zelle, CrowdStrike, Datadog, Codex)은 알려진 이름으로 바로잡았다. mm:ss는 영상 위치다.

3분 요약
  1. 발표자는 Mac의 Claude Code에게 프롬프트 다섯 번으로 자기 브라우저 기록과 은행 정보를 찾게 했다.
  2. 대놓고 시키면 경고가 나왔다. "보안 연구 중"이라고 하자 그냥 도왔다. 에이전트 도구의 거절은 믿을 만한 방어선이 아니다.
  3. 대안은 에이전트를 microVM에 가두는 것이다. 자기 커널을 돌리고, 파일 시스템을 나누고, 진짜 비밀값은 안에 들이지 않고, 모든 행동을 기록한다.
  4. claude 대신 sbx run claude로 실행하면 된다. 같은 공격을 해도 샌드박스 안의 에이전트는 브라우저가 있는지도 모른다. 네트워크는 기본 차단이다.
  5. 그래서 권한 확인을 끈 채(YOLO 모드) 에이전트를 돌려도 피해가 샌드박스 안에서 끝난다.
  6. 다음 단계는 거버넌스다. 어떤 사람이 어떤 에이전트에게 맡겼는지 추적하고, 정책으로 권한을 줄이고, 저장소 단위로 권한을 나눈다.
01

내 컴퓨터를 털어 본 실험 01:10

우리는 에이전트를 감싼 코딩 도구, 곧 하네스harness가 우리를 지켜 준다고 믿는다. 위험한 일을 시키면 가끔 멈춰 주기 때문이다. "AI가 운영 DB를 날렸다"는 뉴스를 보면 나는 그런 실수를 안 한다고 생각한다.

발표자는 그 믿음을 시험했다. 안전하다고 들어 온 도구로 자기 자신을 해킹하면 어디까지 갈 수 있을까. Mac에서 Claude Code 데스크톱 앱을 열고, 먼저 브라우저 기록을 찾아 달라고 했다. 바로 찾았다.

에이전트가 찾아낸 것 01:40
  • 브라우저 기록
  • 쓰고 있는 은행 계좌들
  • 최근 수표를 주문한 기록
  • 송금 서비스 Zelle을 쓴 기록
  • 송금에 쓴 계좌의 끝 네 자리

슬라이드의 은행 이름은 발표자가 바꿔 넣은 가짜다. 발표자 말로는 에이전트가 찾은 데이터 자체는 진짜였다.

먼저 알아챈 건 보안팀 02:30

다음 날 회사 보안팀에서 연락이 왔다. 발표자의 컴퓨터가 해킹당한 것 같다는 경고였다. 발표자는 발표 준비 중이었다고 해명해야 했다.

보안팀이 보내 준 CrowdStrike 보고서는 이 행동을 컴퓨터에서 자격 증명credentials을 빼내는 알려진 수법으로 분류했다. 발표자는 "10점 만점에 9점을 받았다"고 농담했다. 위험도를 매긴 점수로 보인다.

이번엔 본인이 시킨 일이었다 03:10 다행히 발표자 본인이 직접 한 실험이었다. 하지만 같은 지시는 외부 스크립트나 MCP 서버를 통해 몰래 들어올 수도 있다. 이런 공격을 프롬프트 인젝션prompt injection이라고 한다. 발표자는 이게 쉽게 일어날 수 있는 일이라고 본다.

03

부탁 대신 경계 03:50

발표자는 지금의 보안 수준을 이렇게 꼬집는다. 에이전트의 시스템 프롬프트를 열어 보면 "나쁜 짓은 하지 말아 주세요" 같은 문장이 들어 있다. 부탁하는 수준이라는 뜻이다.

대안은 마이크로 가상 머신microVM 샌드박스다. 발표자에 따르면 Docker를 비롯한 여러 곳이 최근에 내놓았다. 개발자에게 익숙한 Docker 컨테이너와 비교하면 다음 장치가 더해진다.

장치하는 일
자기 커널VM마다 자기 운영체제 커널을 돌린다
파일 시스템 격리에이전트는 허락받은 폴더만 본다
비밀값 바꿔 끼우기샌드박스 안에는 진짜 비밀값 대신 가짜 값placeholder만 들어간다. 네트워크 요청을 보낼 때 이 가짜 값을 진짜 값으로 바꿔 넣는다
감사 기록에이전트가 한 일을 빠짐없이 남긴다audit trail

발표에 없는 배경 설명: 일반 컨테이너는 호스트와 커널을 함께 쓴다. microVM이 자기 커널을 돌린다는 건 호스트와 한 겹 더 떨어져 있다는 뜻이다.

샌드박스 안가짜 값만 있다에이전트가 아무리 뒤져도 진짜 비밀값을 볼 수 없다

please라고 말하고 무슨 일이 생기나 지켜보지 말고, 설계부터 안전하게.발표자의 말을 옮김 04:30
유용함과 안전 사이의 균형 04:40 에이전트가 아무것도 못 하게 막으면 쓸모가 없다. 샌드박스의 목적은 에이전트가 할 일은 다 하게 두면서, 그 결과가 밖으로 새지 않게 하는 것이다.
04

명령어 한 줄 차이 05:10

발표자는 두 터미널을 나란히 보여 줬다. 왼쪽은 그냥 claude, 오른쪽은 sbx run claude다. "차이가 많죠"라고 농담했지만 두 화면은 거의 같다. 오른쪽에 권한 확인 건너뛰기bypass permissions가 켜져 있다는 점만 다르다.

claude
  • 내 컴퓨터에서 바로 실행된다
  • 브라우저 기록을 찾으라고 하자 바로 찾았다
sbx run claude
  • 지금 폴더를 대상으로 새 VM을 띄우고, 그 안에서 에이전트를 실행한다
  • 그 밖의 것은 아무것도 보지 못한다
  • 같은 요청에 브라우저가 설치돼 있다고 생각하지도 않았다

추가로 친 것: 앞에 붙인 sbx run뿐이다. 발표자는 "일곱 번 더 쳤다"고 했다.

sbx run 뒤에 띄어쓰기까지 세면 일곱 번이 아니라 여덟 번이다. 어느 쪽이든 아주 적다.

네트워크도 기본 차단 06:10

밖으로 나가는 요청egress과 들어오는 요청ingress도 같은 방식으로 막는다.

  • The Pirate Bay: 막힐 줄 알고 일부러 접속을 시켜 봤다. 기본 설정에서 차단됐다.
  • 텔레메트리: 화면에는 Claude가 Datadog 쪽으로 보내는 사용 기록 요청이 많이 보였다. 발표자는 Claude를 쓰면 Anthropic에 데이터를 많이 보내는 셈이라고 했다. 샌드박스에서는 이것도 막혔다.

텔레메트리에 어떤 내용이 담겼는지는 발표에서 다루지 않았다. 발표자의 관찰로만 읽자.

발표자 말로는 Docker의 모든 개발자가 이제 샌드박스 안에서 코드를 쓴다. 안 쓰면 혼난다고 한다. 기본값이 이렇게 잡혀 있을 뿐이고, 설정은 모두 바꿀 수 있다.

05

왜 microVM 경계인가 07:10

발표자의 결론은 간단하다. 하네스 수준에서 막는 방식은 잘 통하지 않는다.

하네스 수준프롬프트와 거절로 막는다에이전트는 돌아갈 길을 찾는다. 호스트 컴퓨터까지 닿으면 이미 늦다
→
microVM 경계에이전트를 VM 안에 가둔다에이전트가 무엇을 하든 VM 밖으로 나오지 못한다

발표자는 이 문제를 매일 겪는 사람으로 컨설팅을 하는 사람, 보안 책임자CSO가 있는 회사, 고객 일을 맡는 사람을 꼽는다.

06

누가 시켰는지 남기기 07:40

안전하게 막는 것만으로는 부족하다. 에이전트가 여러 일을 하게 하려면, 일이 생긴 뒤 원인을 거슬러 올라갈 수 있어야 한다. Docker가 다음으로 준비하는 것은 에이전트 단위의 신원 추적과 위임 체인delegation chain이다.

  1. 어떤 일이 일어났다.
  2. 기록을 보면 어떤 에이전트가 그 일을 했는지 나온다.
  3. 그 에이전트에게 일을 맡긴 사람이 누구인지도 나온다.
  4. 이 기록을 바탕으로 정책을 쓴다. 새로운 일이 생기면 에이전트가 할 수 있는 범위를 줄인다.

정책은 Cedar라는 정책 언어로 쓴다. "왜 이런 일이 생겼는지 모르겠다"는 상황을 없애는 것이 목표다.

이 기능은 발표에서 앞으로 나올 것으로 소개됐다.

08

어떤 에이전트든 같은 방식 09:40

sbx는 Mac, Windows, Linux에서 각자 쓰는 패키지 매니저로 설치한다. 실행은 sbx run 하나로 시작한다.

제목의 "어떤 에이전트든"은 말 그대로다. 샌드박스는 온전한 VM이라서 Claude만 돌리는 게 아니다.

  • 셸
  • Codex 같은 다른 코딩 에이전트
  • Python 작업
  • 웹 서버

기본 흐름은 Claude Code나 Codex를 바로 띄우는 것이다. 평소 쓰던 것과 똑같이 느껴지지만 보호 장치가 다 켜져 있다.

관련 저장소는 읽기 전용으로 10:20

다른 파일 시스템도 샌드박스에 연결mount할 수 있다. 발표자는 작업하는 코드와 관련된 저장소를 읽기 전용으로 연결한다.

  • 에이전트는 다른 코드베이스를 읽고 참고할 수 있다.
  • 내 작업을 끝내려고 다른 저장소에 멋대로 커밋할 수는 없다.

발표자가 원하는 건 보장이다. 에이전트가 정해 준 API로, 말한 그대로 일하고 있다는 보장이다.

09

핵심 정리

  1. 하네스의 거절은 방어선이 아니다. "보안 연구 중"이라는 말 한마디에 넘어갔다.
  2. 발표자는 프롬프트 다섯 번으로 자기 브라우저 기록, 은행 계좌, 계좌 끝 네 자리를 찾게 했다.
  3. 같은 일은 스크립트나 MCP 서버를 통한 프롬프트 인젝션으로도 일어날 수 있다.
  4. 프롬프트에 "나쁜 짓 하지 마"라고 쓰는 건 부탁이다. 안전은 설계로 만든다.
  5. microVM은 자기 커널을 돌리고 파일 시스템을 나눈다.
  6. 진짜 비밀값은 샌드박스에 들어가지 않는다. 요청이 나갈 때 가짜 값이 진짜 값으로 바뀐다. 모든 행동은 기록된다.
  7. sbx run claude 한 줄이면 시작된다. 샌드박스 안의 에이전트는 브라우저가 있는지도 몰랐다.
  8. 네트워크는 기본 차단이다. 모르는 사이트도, 텔레메트리도 막혔다.
  9. 방어선은 하네스가 아니라 microVM 경계에 둔다. 호스트에 닿으면 이미 늦다.
  10. 다음은 거버넌스다. 누가 맡겼는지 추적하고, Cedar 정책으로 권한을 줄이고, 저장소 단위로 권한을 나눈다.

다섯 번. 대놓고 시키면 경고가 나왔지만 "보안을 연구하는 중"이라고 하자 그냥 도왔다.
Q3이 실험이 실제 공격과 달랐던 점과, 그래도 걱정해야 하는 이유는?
발표자 본인이 직접 시킨 실험이었다. 하지만 같은 지시가 외부 스크립트나 MCP 서버를 통한 프롬프트 인젝션으로 들어올 수 있다.
Q4발표자가 꼽은 microVM 샌드박스의 네 가지 장치는?
자기 커널 실행, 파일 시스템 격리, 비밀값 바꿔 끼우기, 감사 기록.
Q5샌드박스 안의 에이전트가 진짜 비밀값을 볼 수 없는 이유는?
안에는 가짜 값만 들어간다. 네트워크 요청이 나갈 때 그 가짜 값이 진짜 값으로 바뀐다.
Q6같은 브라우저 기록 요청을 sbx run claude에서 하면 어떻게 됐나?
에이전트는 컴퓨터에 브라우저가 설치돼 있다고 생각하지도 않았다. 지정한 폴더 밖은 보이지 않기 때문이다.
Q7네트워크 기본 차단의 예로 나온 두 가지는?
The Pirate Bay 접속 차단과, Claude가 Datadog 쪽으로 보내는 텔레메트리 차단.
Q8하네스 수준의 방어가 부족한 이유는?
에이전트는 돌아갈 길을 찾는다. 그러다 호스트 컴퓨터까지 닿으면 이미 늦다. 그래서 방어선을 microVM 경계에 둔다.
Q9위임 체인이 답하려는 질문은?
"이 일이 왜 일어났나." 어떤 에이전트가 했고, 그 에이전트에게 누가 맡겼는지 추적한다. 그 기록으로 Cedar 정책을 써서 권한을 줄인다.
Q10지금 되는 거버넌스 통제와, 요청이 많아 준비 중인 통제는?
지금: 네트워크 허용·차단, 파일 시스템 연결 지점, MCP 서버 목록. 준비 중: L7 네트워크 제어, GitHub 저장소별 파일 권한, 에이전트 신원 추적.
Q11발표자가 관련 저장소를 읽기 전용으로 연결하는 이유는?
에이전트가 다른 코드베이스를 참고는 하되, 내 작업을 끝내려고 다른 저장소에 멋대로 커밋하지 못하게 하려고.
Q12제목의 "YOLO 모드를 안전하게"는 무슨 뜻인가?
권한 확인을 건너뛰고 에이전트가 알아서 일하게 두되, microVM 안에 가둬서 피해가 그 안에서 끝나게 한다는 뜻이다.

용어 정리

용어뜻
YOLO 모드에이전트가 행동마다 사람의 허락을 받지 않고 알아서 실행하게 두는 방식. Claude Code에서는 권한 확인 건너뛰기(bypass permissions)로 켠다
하네스Harness. 모델을 감싸 도구, 순서, 규칙을 정해 주는 실행 틀. Claude Code, Codex 같은 코딩 도구가 여기에 해당한다
샌드박스Sandbox. 프로그램을 바깥과 분리된 공간에서 실행해, 그 안에서 벌어진 일이 밖으로 번지지 않게 하는 장치
microVM빨리 뜨고 가볍게 돌도록 만든 작은 가상 머신. 자기 커널을 따로 돌린다
커널Kernel. 운영체제의 핵심. 하드웨어와 파일, 프로세스를 관리한다
컨테이너Container. 앱과 실행 환경을 묶어 분리해 돌리는 방식. 호스트와 커널을 함께 쓴다
호스트Host. 샌드박스나 VM을 돌리고 있는 실제 컴퓨터
PIIPersonally Identifiable Information. 이름, 계좌번호처럼 특정 개인을 알아볼 수 있는 정보
자격 증명Credentials. 비밀번호, 토큰, API 키처럼 내가 누구인지 증명하는 정보
CrowdStrike회사 컴퓨터에 설치해 수상한 행동을 잡아내는 보안 제품
프롬프트 인젝션Prompt injection. 입력 안에 지시문을 숨겨 AI가 원래 지시 대신 그걸 따르게 만드는 공격
MCP 서버Model Context Protocol 서버. 에이전트가 외부 도구와 데이터에 접근하게 해 주는 연결 지점
가짜 값Placeholder. 진짜 비밀값 자리에 대신 넣어 두는 값
감사 기록Audit trail. 누가 언제 무엇을 했는지 나중에 확인할 수 있게 남긴 기록
egress / ingress밖으로 나가는 네트워크 트래픽 / 안으로 들어오는 네트워크 트래픽
텔레메트리Telemetry. 프로그램이 사용 기록을 자동으로 모아 보내는 데이터
위임 체인Delegation chain. 사람이 에이전트에게, 에이전트가 다른 에이전트에게 일을 맡긴 연결 고리를 기록한 것
Cedar누가 무엇을 할 수 있는지를 규칙으로 적는 정책 언어
L7 네트워크 제어네트워크의 7번째 계층, 곧 애플리케이션 계층에서 하는 통제. 주소뿐 아니라 요청 내용을 보고 허용 여부를 정한다
마운트Mount. 다른 디스크나 폴더를 지정한 위치에 연결해 쓸 수 있게 하는 것. 읽기 전용으로 연결하면 읽기만 된다
