Docker 없이 GPU에 AI 앱 올리기

AI 앱을 서버리스 GPU에 올리려면 코드를 고칠 때마다 Docker 이미지를 다시 만들고 올려야 한다. Runpod Flash는 그 과정을 빼고, 파이썬 코드를 로컬처럼 실행해 클라우드 GPU에서 돌린 뒤 명령 하나로 배포하게 한다.

원본 영상: AI Apps in a Flash: Ship to GPUs Without Docker 발표: Dean Quiñanola (Runpod 스태프 엔지니어)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치와 동작 설명은 모두 발표자가 말한 것이고 따로 확인하지는 않았다. 자막에서 이름이 뭉개진 곳은 확실할 때만 알려진 이름으로 바로잡았다. mm:ss는 영상 위치다.

발표자는 Runpod 소속이고, 발표 전체가 Runpod의 제품 Flash를 소개하는 내용이다. 장점 설명은 그 점을 감안해 읽자.

3분 요약
  1. 지금 서버리스 AI 앱 배포는 코드 수정 → Docker 빌드 → 레지스트리 푸시 → 실행을 반복한다. 발표자 경험으로 한 바퀴에 약 15분이다.
  2. Flash의 목표는 이 루프를 코드 쓰기 → 실행 → 결과 보기로 줄이는 것이다. Docker가 없고, 그냥 파이썬 코드다.
  3. 개발 중에는 로컬 FastAPI 서버가 뜨고, 함수를 호출하면 그 순간 서버리스 GPU 엔드포인트가 만들어져 실행된다.
  4. 코드를 고치면 바로 반영된다. 새로 적은 파이썬 의존성도 실행 중에 설치된다.
  5. 개발 서버를 끄면 엔드포인트도 함께 사라진다. 놀고 있는 GPU가 남지 않는다.
  6. flash deploy 한 번으로 묶고, 올리고, 서비스한다. 고객이 쓰는 백엔드가 된다.
  7. 엔드포인트끼리는 함수 호출처럼 통신하고, 네트워크 볼륨으로 캐시를 공유한다. 서버리스 외의 Pod 지원은 준비 중이다.
01

한 바퀴에 15분, Docker 루프 00:10

서버리스 AI 앱을 지금 배포하는 방식은 이렇다.

  1. 코드를 쓴다.
  2. Dockerfile을 만들고 docker build 같은 명령을 여러 개 돌린다.
  3. 이미지를 Docker Hub 같은 레지스트리에 올린다.
  4. 실행해 본다. 원하는 결과가 아니면 코드를 고치고 1번으로 돌아간다.

발표자의 경험으로는 바꾸는 내용에 따라 이 한 바퀴가 15분쯤 걸린다. 결과를 보고 싶은 사람에게는 긴 시간이다.

누가 이 문제를 겪나 소프트웨어 엔지니어와 ML 엔지니어다. 아이디어나 실험 결과를 빨리 보고 싶을 뿐, DevOps 작업을 하고 싶은 게 아니다.
02

Flash가 바꾸려는 것 01:10

발표자는 개발 반복 루프 자체를 뜯어고쳐야 한다고 말한다. 목표는 네 가지다.

  • Docker가 필요 없다.
  • GPU가 내 컴퓨터에 달린 것처럼 코드를 실행한다.
  • 변경을 즉시 테스트한다.
  • 필요하면 빠르게 디버그한다.
지금코드 → Docker 빌드 → 푸시 → 실행한 바퀴 약 15분 (발표자 경험)
→
Flash코드 → 실행 → 결과로컬에서 도는 것처럼 느껴지게

발표자가 꼽는 특징은 세 가지다. 더 빨리 만들고 배포한다. 내부에서 여러 기법으로 자원 사용을 최적화한다. 그리고 그냥 파이썬 코드라 직관적이다. 로컬에서 GPU로 돌릴 수 있는 것이면 클라우드에서도 그대로 돌린다는 생각이다.

03

지금 할 수 있는 일 02:20

기능설명
서버리스 엔드포인트현재는 서버리스에 묶여 있다. 큐 방식 엔드포인트와 로드 밸런스 엔드포인트를 쓸 수 있다. Pod 지원은 작업 중이다.
엔드포인트 간 통신서버가 여러 개여도 서로 주소를 알 필요가 없다. 코드에서 함수를 부르면 로컬 호출처럼 보이지만, 배포 후에는 각 엔드포인트끼리 알아서 통신한다.
네트워크 볼륨 연결볼륨에 웜 캐시를 둔다. 서버리스가 확장될 때 캐시가 볼륨을 통해 새 워커로 이어진다.
라이브 서버리스발표자가 가장 중요하다고 꼽은 기능. 로컬에서 하듯 코딩하고 테스트한다.
프로덕션 배포장난감 프로젝트로 끝나지 않도록 CLI로 추론 서비스를 배포한다.

엔드포인트 간 통신은 발표자가 직접 만들어 넣은 기능이라고 소개했다.

04

데모 1: 첫 실행과 콜드 스타트 03:40

데모는 함수 하나를 빠르게 키워 가는 과정이다. 첫 함수는 PyTorch에 어떤 GPU가 있는지 묻는 것뿐이다.

  1. flash dev를 실행하면 로컬에 FastAPI 서버가 뜬다. 여기서 함수를 눌러 볼 수 있다.
  2. 함수를 실행하면 그때 서버리스 엔드포인트가 만들어진다. Runpod 콘솔을 새로 고치면 엔드포인트가 보인다.
  3. 워커가 준비되는 동안 컨테이너 로그를 볼 수 있다.
  4. 결과: NVIDIA GeForce RTX 4090에서 돌았고, RAM과 GPU 개수가 함께 나왔다.
콜드 스타트 05:00 첫 실행은 워커가 뜰 때까지 기다려야 했다. 발표자는 모든 서버리스 플랫폼에 공통인 현상이라고 설명했다. 이 노트에서는 콜드 스타트를 "쉬고 있던 서버가 첫 요청을 받고 깨어나는 데 걸리는 시간"으로 쓴다.
05

데모 2: 코드를 바꾸고 바로 다시 05:30

핵심 질문은 "함수를 고치고 바로 테스트하고 싶으면?"이다. 발표자는 텍스트 생성 코드를 덧붙이고 파이썬 의존성을 추가했다.

  • 코드를 저장하자 로컬 서버가 새로 고쳐졌다.
  • "string cheese는 진짜인가"를 물었다. 로그는 전보다 단순하게 나온다. 사용자가 로그에 파묻히지 않게 한 것이다.
  • 실행 중에 새 의존성을 그 자리에서 설치했다. Hugging Face 토큰 없이 서버와 통신한다는 경고도 띄웠다.
  • 첫 답은 "답할 수 없다"는 거절이었다. 토큰을 켜는 것은 코드만 바꾸는 일이라 바로 다시 띄웠다.
  • "배트맨은 누구인가"를 물었더니 가상의 인물이라는 답이 나왔다.

이 구간에서 보여 주려는 것은 결과의 품질이 아니다. 코드를 고친 뒤 Docker를 거치지 않고 몇 초 안에 다시 실행했다는 점이다.

06

데모 3: 이미지 생성과 롤아웃 07:50

텍스트보다 무거운 작업으로 이미지 생성 함수를 추가했다. 프롬프트는 "string cheese 배트맨"이었다.

  • 로컬 서버를 새로 고치자 이미지 생성 함수가 나타났다.
  • 로그에 "롤아웃 진행 중"이 떴다. 이전 버전 워커가 아직 돌고 있어서, 발표자는 기다리지 않고 그 워커를 종료한 뒤 새 버전으로 실행했다.
  • 응답은 base64 문자열로 왔다. 브라우저에서 그대로 이미지로 렌더링했다.
  • 결과 이미지는 string cheese와는 거리가 있었지만, 파이프라인이 끝까지 돈 것은 확인됐다.

롤아웃은 새 코드 버전을 워커에 순서대로 적용하는 과정이다. 발표 중에는 이전 버전이 남아 있었고, 발표자가 수동으로 끊었다. 이 동작이 설계된 것인지 데모 환경의 문제인지는 발표에서 설명하지 않았다.

07

프로덕션 배포 09:50

개발 서버를 취소하자 엔드포인트도 함께 해제됐다. 쓰지 않는 GPU 엔드포인트가 남지 않는다.

그다음 flash deploy를 실행했다. 발표자가 설명한 흐름은 이렇다.

  1. 애플리케이션 전체를 아카이브로 묶는다.
  2. Runpod 서버로 올린다. Docker는 쓰지 않는다.
  3. 배포가 끝나면 엔드포인트 ID가 나온다.
  4. 그 ID로 요청을 보낸다. 데모 프롬프트는 "나비넥타이를 한 아기 해달"이었다.

발표자는 이 시점부터 백엔드가 더 이상 로컬에 있지 않다고 강조했다. 고객이 쓰는 애플리케이션의 백엔드로 바로 쓸 수 있다. 워커 로그가 끝나자 해달 이미지가 나왔다. 나비넥타이는 없었다.

배포 단계에서 바뀐 것 개발 중에 쓰던 로컬 FastAPI 서버는 없어지고, 같은 코드가 Runpod에 올라가 ID로 호출된다. 코드를 다시 쓰거나 이미지를 만드는 단계가 없다.
08

해커톤 사례 12:10

발표 전날 해커톤에서 Funka(추정)라는 참가자가 Flash 위에 래퍼를 만들었다.

  • 실험 목록과 모델 사양을 적은 시트를 올린다.
  • 시트의 항목마다 엔드포인트를 펼쳐 만들고, 학습을 돌리고, 결과를 모아 보고한다.
  • Flash를 처음 써 보는 상태에서 3~4시간 만에 만들었다. 가능한지조차 발표자에게 물어봐야 했다.

이 프로젝트는 해커톤에서 우승했다. 발표자는 Flash가 "함수 하나를 GPU에서 돌리는 것"에서 "여러 실험을 한꺼번에 펼치는 것"까지 짧은 시간에 닿을 수 있다는 예로 들었다.

09

시작하는 법 13:10

순서할 일
1Runpod 계정을 만든다. 발표 당시 QR 코드로 10달러 크레딧을 줬다.
2Flash를 설치하고 코드를 쓴다.
3로그인해서 API 키를 넣는다.
4초기화하면 뼈대 애플리케이션을 만들어 준다.
5flash dev로 로컬 개발, flash deploy로 프로덕션 배포.

발표자가 가장 권한 것은 GitHub의 Runpod Flash 예제 저장소다. 여러 사례가 모여 있다. AI 코딩 도구를 쓴다면 그 저장소에서 Claude Code를 실행해 구조를 익히게 할 수 있고, 스킬도 제공한다고 했다.

예제 저장소의 정확한 URL은 발표 슬라이드에만 있어 자막으로는 알 수 없다. 정확한 명령 문법도 flash dev와 flash deploy 외에는 발표에서 말로만 설명했다.

10

핵심 정리

  1. 서버리스 AI 앱의 병목은 코드 → Docker 빌드 → 푸시 → 실행 루프다. 발표자 경험으로 한 바퀴 약 15분.
  2. Flash는 루프를 코드 → 실행 → 결과로 줄인다. Docker가 없고 그냥 파이썬이다.
  3. flash dev는 로컬 FastAPI 서버를 띄운다. 함수를 부르면 그때 서버리스 GPU 엔드포인트가 만들어진다.
  4. 첫 실행에는 콜드 스타트가 있다. 서버리스 공통 현상이다.
  5. 코드를 고치면 바로 반영되고, 새 파이썬 의존성은 실행 중에 설치된다.
  6. 새 버전 롤아웃 중에는 이전 워커가 남을 수 있다. 데모에서는 수동으로 끊었다.
  7. 개발 서버를 끄면 엔드포인트도 해제된다. 놀고 있는 GPU를 남기지 않는다.
  8. flash deploy는 앱을 묶어 올리고 엔드포인트 ID를 준다. 그 ID가 고객용 백엔드가 된다.
  9. 엔드포인트끼리는 함수 호출처럼 통신한다. 네트워크 볼륨의 웜 캐시가 확장 시 새 워커로 이어진다.
  10. 지금은 서버리스(큐·로드 밸런스)만 지원한다. Pod 지원은 준비 중이다.

점검 퀴즈

코드 작성, Docker 빌드, 레지스트리 푸시, 실행. 결과가 틀리면 처음으로 돌아간다. 한 바퀴 약 15분.

FastAPI 서버. 여기서 함수를 눌러 보면 그때 서버리스 GPU 엔드포인트가 만들어진다.

이전 버전 워커가 아직 돌고 있어서 기다리지 않고 종료한 뒤 새 버전으로 실행했다.

앱을 아카이브로 묶고, Runpod 서버로 올리고, 서비스한다. 끝나면 엔드포인트 ID가 나온다.
Q10엔드포인트 간 통신 기능이 해결하는 불편은?
서버가 여럿일 때 각 서버의 주소를 알아야 하는 것. 코드에서 함수를 부르듯 쓰면 배포 후에는 엔드포인트끼리 알아서 통신한다.
Q11해커톤 참가자가 3~4시간 만에 만든 것은?
실험 시트를 올리면 항목마다 엔드포인트를 펼쳐 학습을 돌리고 결과를 모아 보고하는 Flash 래퍼.
Q12현재 지원 범위와 준비 중인 것은?
서버리스(큐 엔드포인트, 로드 밸런스 엔드포인트)만 지원한다. Pod 지원은 작업 중이다.

발표 내용을 실행 항목으로 바꾼 것이다. 체크 표시는 이 브라우저에만 저장된다.

용어 정리

용어뜻
서버리스 serverless서버를 직접 관리하지 않고, 요청이 올 때만 실행 환경이 떠서 일하고 사라지는 방식
엔드포인트 endpoint요청을 받아 처리하는 주소. 여기서는 GPU 위에서 함수를 실행하는 단위
워커 worker엔드포인트의 요청을 실제로 처리하는 실행 인스턴스
콜드 스타트 cold start쉬고 있던 워커가 첫 요청을 받고 깨어나는 데 걸리는 시간
롤아웃 rollout새 코드 버전을 워커에 순서대로 적용하는 과정
큐 엔드포인트 queue endpoint요청을 줄에 세웠다가 워커가 차례로 처리하는 엔드포인트
로드 밸런스 엔드포인트 load balanced endpoint요청을 여러 워커에 나눠 보내는 엔드포인트
PodRunpod에서 서버리스가 아니라 계속 켜 두는 GPU 머신 단위. Flash 지원은 준비 중
네트워크 볼륨 network volume여러 워커가 함께 붙여 쓰는 저장 공간. 캐시를 여기에 두면 새 워커도 바로 쓴다
웜 캐시 warm cache미리 받아 둔 모델 파일 등. 다시 내려받지 않아도 되게 한다
FastAPI파이썬 웹 API 프레임워크. 데모에서 로컬 테스트 서버로 쓰였다
Hugging Face 토큰Hugging Face 서버에서 모델을 받을 때 쓰는 인증 키
base64이미지 같은 이진 데이터를 글자로 바꿔 보내는 방식. 브라우저가 다시 이미지로 그릴 수 있다
래퍼 wrapper기존 도구를 감싸 다른 방식으로 쓰게 해 주는 코드
