KV 캐시로 에이전트 공격을 찾는다

에이전트를 지키는 가드레일은 보통 들어가고 나오는 글자를 검사한다. 발표자는 모델이 이미 계산해 둔 KV 캐시를 읽으면, 글자 검사를 빠져나간 공격도 계산의 이상으로 드러난다고 주장한다.

원본 영상: Your KV Cache Can Spot Attacks on Your AI Agents 발표: Ari Azarafrooz (Intrinsec AI 창업자)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 뭉개진 이름은 확실한 것만 고쳤고, 나머지는 "(추정)"을 붙였다. mm:ss는 영상 위치다.

3분 요약
  1. KV 캐시는 보통 속도를 위한 저장소로 쓰인다. 발표자는 이것을 보안 신호로도 쓰자고 제안한다.
  2. 지금의 가드레일은 입력과 출력의 글자를 검사한다. 그 검사를 빠져나간 공격도 모델 안에서는 결국 계산이 된다.
  3. 장점은 세 가지다. 데이터가 이미 있고, 가드레일의 사각지대를 덮고, 데이터가 서버 안에 머문다.
  4. 방법은 세 단계다. 정상 트래픽의 기준선을 배우고, 기준선에 비해 드문 KV 페이지를 찾고, 그것을 분류하고 설명한다.
  5. 붙일 곳은 두 곳이다. 추론 엔진 안(실시간)과 KV 캐시 저장소(사후 탐색).
  6. 발표자 회사의 실험에서 음성 에이전트의 숨은 지시를 찾고 위치까지 짚었다. 텍스트 에이전트에서는 상위 경보 10개 중 7~8개가 의미 있었다.
  7. 남은 숙제는 둘이다. 모델마다 KV의 좌표가 다르고, KV 데이터가 너무 크다(256토큰에 약 40MB).
01

KV 캐시는 원래 속도용 00:10

이 발표는 에이전트를 만들고, 추론 스택 inference stack을 직접 운영하거나 운영할 계획인 사람을 위한 것이다. 추론 스택은 학습된 모델을 서버에서 돌려 답을 만드는 소프트웨어 묶음이다.

언어 모델은 글을 토큰 하나씩 만든다. 새 토큰을 만들 때마다 앞의 토큰들을 다시 참고한다. 앞 토큰마다 계산한 키와 값 keys and values을 저장해 두면 같은 계산을 반복하지 않아도 된다. 이 저장소가 KV 캐시 KV cache다.

그래서 KV 캐시는 보통 처리량 throughput을 올리는 장치로 여겨진다. 발표자는 이것을 보안의 눈으로 다시 보자고 한다.

02

지금의 방어: 가장자리 지키기 00:20

AI 에이전트 앱이 잘못되는 길은 많고, 계속 늘어난다. 발표자가 든 예는 이렇다.

  • 프롬프트 인젝션 prompt injection
  • 탈옥 jailbreak
  • 잘못된 도구 호출 broken tool call, 민감한 도구 호출 sensitive tool call
  • 민감 데이터 노출 sensitive data exposure
  • 숨은 백도어 hidden backdoor
  • 드리프트 drift

지금은 주로 가장자리 edge를 지킨다. 모델에 들어가는 입력과 나오는 출력을 검사한다는 뜻이다. 방법은 두 가지가 흔하다.

  • 판정 모델 judge model을 두고, 프롬프트와 응답을 정책과 대조하게 한다.
  • 실패 유형마다 분류기 classifier를 따로 만든다.
03

모든 입력은 계산이 된다 01:00

모델은 행동하기 전에 모든 입력을 계산으로 바꾼다. 응답을 만들기 전에 계산이 먼저 일어난다. 그 응답이 다음 도구 호출이 되기 전에도 마찬가지다.

KV 캐시는 엔진이 남긴 그 계산의 기록이다. 요즘 추론 엔진은 이 기록을 이미 공짜로 쓰고 읽는다.

04

KV 우선 신호의 세 가지 이유 01:30

발표자는 이 접근을 KV 우선 보안 신호 KV-first security signals라고 부른다. 이유는 세 가지다.

1 · 데이터가 이미 있다

추론 스택이 어차피 만들고 버리던 데이터다. 새로 모을 필요가 없다. 그 더미에서 쓸 만한 것만 고르면 된다.

2 · 사각지대를 덮는다

가드레일을 빠져나간 입력도 모델 안에서는 결국 계산이 된다. 글자 검사가 놓친 것도 계산에는 흔적을 남긴다.

3 · 데이터가 제자리에 있다

KV 캐시는 추론 서버 안에 머문다. 입력과 출력을 읽을 수 없는 환경에서도 쓸 수 있다. 그래서 개인정보 보호가 중요한 곳에 맞다.

05

방법은 세 단계 02:00

  1. 기준선을 배운다. 우리 서비스의 평소 추론 트래픽에서 KV 페이지가 보통 어떻게 생겼는지 익힌다. 기준선 baseline은 정상 상태를 보여 주는 기준 데이터다.
  2. 드문 페이지를 찾는다. 기준선에 비해 드문 KV 페이지가 이상 anomaly 후보다.
  3. 분류하고 설명한다. 찾은 이상이 어떤 종류인지 꼬리표를 붙이고, 무엇이 이상한지 설명한다.

KV 페이지 KV page는 KV 캐시를 토큰 몇 개 단위로 잘라 둔 조각이다. 뒤에 나오는 음성 실험은 16토큰짜리 페이지를 썼다.

06

스택의 어디에 붙이나 02:20

발표자는 KV 캐시 덕분에 추론이 상태를 갖게 됐다고 본다 stateful. 계산 결과가 요청이 끝난 뒤에도 남아 다음 요청에 다시 쓰인다는 뜻이다. 발표자가 든 예는 둘이다.

  • LMCache 같은 KV 캐시 관리 계층은 KV 캐시를 GPU에서 원격 저장소까지 내려 보관한다.
  • llm-d와 NVIDIA Dynamo는 새 요청을, 필요한 KV 페이지를 이미 가진 작업 서버로 보낸다.

즉 KV 페이지는 이미 인프라 안을 돌아다닌다. 이상 탐지나 분류기를 붙일 자리는 두 곳이다.

두 연결 지점 02:50

추론 엔진 안 · 실시간

vLLM 같은 추론 엔진 안에 직접 넣는다. 장점은 실시간이라는 점이다. 경보가 다음 도구 호출이나 정책 판단에 함께 실려 간다.

쓰임: 계산에서 본 이상으로 기존 정책과 가드레일을 더 단단하게 만든다.

KV 캐시 저장소 · 위협 탐색

LMCache에 붙여 저장된 KV 페이지를 읽는다. 나머지와 어울리지 않는 페이지를 찾는다.

쓰임: 실시간 차단보다, 쌓인 기록에서 숨은 위협을 찾아내는 위협 탐색 threat discovery에 맞다.

추론 엔진 이름은 자막에서 뭉개졌다("via LMs, you name so forth"). vLLM으로 읽었다(추정).

사례 2: 텍스트 에이전트 05:00

자막에는 "client 314 billion", "bill 110 cash"로 나온다. 9장의 40MB 계산이 Qwen3-14B의 구성과 맞아서 그렇게 읽었다.

발표 화면에는 결과가 두 개 있었다.

  • 왼쪽: 공격 트래픽과 정상 트래픽이 어떻게 갈라지는지 보여 주는 그림.
  • 오른쪽(발표자가 더 의미 있다고 본 것): Hugging Face에 있는 ATBench(추정)를 썼다. 정상 에이전트 실행 기록을 기준선으로 삼았다. 시험한 에이전트 실패는 8종이고, 도구 설명에 심은 공격부터 잘못된 정보까지 들어 있다. 05:20

상위 경보 10개 중 7~8개가 실제로 의미 있고 쓸모 있는 이상 활동이었다. 05:40 경보 대부분이 헛경보가 아니었다는 뜻이다.

발표자 팀은 다른 이상보다 유독 두드러지는 이상 유형이 있는지도 살폈다고 했다. 그 결과는 자막에 나오지 않는다.

09

운영에서 어려운 두 가지 06:00

1. 모델이 바뀐다

모델은 계속 바뀐다. 파인튜닝한 모델과 새 버전이 나온다. 에이전트마다 다른 모델을 쓰기도 한다. 라우터 router가 요청마다 전문 모델을 고르기도 한다.

그런데 모델마다 KV 페이지를 자기만의 좌표 coordinates로 쓴다. 같은 문장이라도 모델이 다르면 KV 값이 다르다는 뜻이다. 그래서 선택지는 둘이다.

선택지문제
모델마다 따로 학습모델마다 기준선, 분류기, 설명 모델을 다 만들어야 한다. 계산 비용이 감당이 안 된다
공통 공간으로 옮기기모든 모델의 KV를 하나의 공통 표현 공간 shared representation space으로 옮기는 방법을 찾아야 한다

2. 실시간이면 큰 데이터를 옮겨야 한다 06:30

발표자가 든 예는 Qwen3-14B(추정)의 256토큰 묶음이다. 이 묶음 하나의 KV가 약 40MB다.

CacheGen 같은 압축·스트리밍 기법이 도움은 된다. 그래도 보안 분석을 위해 데이터를 옮기고 실시간으로 대응하기에는 아직 느리다.

검산 (예시: 발표에 없는 계산) 토큰 하나의 KV 크기는 2(키와 값) × 층 수 × KV 헤드 수 × 헤드 차원 × 숫자 하나의 바이트 수다. Qwen3-14B의 공개 구성(40층, KV 헤드 8개, 헤드 차원 128)과 16비트 숫자(2바이트)를 가정하면 2 × 40 × 8 × 128 × 2 = 163,840바이트, 토큰당 160KiB다. 256토큰이면 40MiB(약 42MB)다. 발표자가 말한 "약 40MB"와 맞는다.
10

회사 소개와 마무리 06:50

발표자는 이 두 문제를 Intrinsec AI가 푼다고 말한다. 자체 추론 스택을 만들면서 보안을 처음부터 설계에 넣으려는 팀을 찾고 있다고 했다.

Ari Azarafrooz는 이 방식을 파는 회사의 창업자다. 장점 위주의 설명과 자체 실험 결과는 그 점을 감안해 읽자. 두 문제를 풀었다는 말에는 발표 안에서 근거가 나오지 않는다.

이 발표에서 가져갈 것 KV 캐시는 속도용 저장소이면서, 모델이 무엇을 계산했는지 보여 주는 기록이다. 글자를 검사하는 가드레일 옆에 계산을 검사하는 신호를 하나 더 둘 수 있다. 다만 모델마다 기준선을 다시 만들어야 하고, 데이터가 커서 실시간 적용은 아직 어렵다.
11

핵심 정리

  1. KV 캐시는 토큰마다 계산한 키와 값을 모아 둔 것이다. 보통은 속도를 위해 쓴다.
  2. 에이전트는 프롬프트 인젝션, 탈옥, 잘못된 도구 호출, 민감 데이터 노출, 백도어, 드리프트로 잘못될 수 있다.
  3. 지금의 방어는 가장자리를 지킨다. 판정 모델이나 분류기가 입력과 출력의 글자를 검사한다.
  4. 모델은 행동 전에 모든 입력을 계산으로 바꾼다. KV 캐시는 그 계산의 기록이다.
  5. 가드레일을 빠져나간 공격도 계산은 된다. 그래서 KV 신호는 사각지대를 덮는 보완책이다.
  6. KV 데이터는 이미 엔진에 있고 서버 밖으로 나가지 않는다. 입력과 출력을 읽을 수 없는 환경에 맞다.
  7. 방법은 기준선 → 드문 페이지 찾기 → 분류와 설명이다.
  8. 붙일 곳은 추론 엔진 안(실시간)과 KV 캐시 저장소(위협 탐색)다.
  9. 발표자 회사 실험: 음성의 숨은 지시를 찾고 위치를 짚었다. 텍스트에서는 상위 경보 10개 중 7~8개가 의미 있었다.
  10. 숙제는 모델마다 다른 좌표와 큰 데이터(256토큰에 약 40MB)다.
12

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1KV 캐시는 원래 무엇을 위해 있나?
토큰마다 계산한 키와 값을 저장해, 다음 토큰을 만들 때 같은 계산을 반복하지 않게 한다. 처리량을 올리는 장치다.
Q2지금 에이전트를 지키는 흔한 방법 두 가지는?
판정 모델로 프롬프트와 응답을 정책과 대조한다. 또는 실패 유형마다 분류기를 따로 만든다. 둘 다 입력과 출력을 검사하는 가장자리 방어다.
Q3KV 캐시를 보안 신호로 쓸 수 있다고 보는 근거는?
모델은 행동하기 전에 모든 입력을 계산으로 바꾸고, KV 캐시는 그 계산의 기록이다. 가드레일을 빠져나간 입력도 계산에는 흔적을 남긴다.
Q4KV 우선 보안 신호의 세 가지 장점은?
데이터가 이미 있다. 가드레일의 사각지대를 덮는다. 데이터가 서버 안에 머물러 개인정보 보호가 중요한 곳에 맞다.
Q5발표자가 제시한 세 단계 방법은?
정상 트래픽에서 KV 페이지의 기준선을 배운다. 기준선에 비해 드문 페이지를 찾는다. 찾은 이상을 분류하고 설명한다.
Q6추론 엔진 안에 붙일 때와 KV 캐시 저장소에 붙일 때의 차이는?
엔진 안은 실시간이라 경보가 다음 도구 호출이나 정책 판단에 함께 실린다. 저장소 쪽은 쌓인 KV 페이지를 훑어 어울리지 않는 것을 찾는 위협 탐색에 맞다.
Q7첫 사례로 음성 에이전트를 고른 이유는?
걸러낼 글자가 아예 없어서, 글자를 검사하는 가드레일을 바로 쓸 수 없는 경우이기 때문이다.
Q8음성 실험에서 이상 탐지가 알려 준 두 가지는?
숨은 지시가 든 음성이 이상하다는 것, 그리고 요청의 어느 페이지가 이상한지다.
Q9설명 모델이 음성 요청에 붙인 꼬리표의 예는? 무엇이 놀라운가?
개인 정보, 집 주소, 위치 데이터, 여행 정보, 목적지. 이 모델은 오디오로 학습하지 않았는데도 맞는 꼬리표를 냈다고 한다.
Q10텍스트 에이전트 실험에서 상위 경보 10개의 결과는?
7~8개가 실제로 의미 있고 쓸모 있는 이상 활동이었다. 발표자 회사의 자체 실험이다.
Q11모델이 바뀌면 왜 문제가 되고, 선택지는 무엇인가?
모델마다 KV 페이지를 자기만의 좌표로 쓴다. 모델마다 기준선과 분류기를 따로 학습하면 비용이 너무 크다. 그래서 모든 모델의 KV를 공통 표현 공간으로 옮기는 방법이 필요하다.
Q12실시간 분석이 어려운 이유는?
KV 데이터가 크다. 256토큰 묶음 하나가 약 40MB다. CacheGen 같은 압축·스트리밍을 써도 보안 분석용으로 옮겨 실시간 대응하기에는 아직 느리다.

용어 정리

용어뜻
KV 캐시KV cache. 모델이 토큰마다 계산한 키와 값을 저장해 둔 것. 같은 계산을 반복하지 않게 한다
키와 값Key / Value. 어텐션 계산에서 토큰마다 만드는 두 벡터. 키는 다른 토큰이 찾아볼 때 쓰는 표지이고, 값은 실제로 가져가는 내용이다
KV 페이지KV page. KV 캐시를 토큰 몇 개 단위로 잘라 둔 조각
처리량Throughput. 정해진 시간에 처리하는 요청이나 토큰의 양
추론 엔진 / 추론 스택Inference engine / stack. 학습된 모델을 돌려 답을 만드는 소프트웨어와 그 주변 묶음
가드레일Guardrail. 에이전트가 정책을 어기지 않도록 입력과 출력을 검사하는 장치
판정 모델Judge model. 다른 모델의 입력이나 출력을 보고 정책 위반인지 판단하는 모델
분류기Classifier. 입력을 정해진 종류 중 하나로 나누는 모델
프롬프트 인젝션Prompt injection. 입력 안에 지시문을 숨겨 AI가 원래 지시 대신 그걸 따르게 만드는 공격
탈옥Jailbreak. 모델이 지켜야 할 안전 규칙을 우회하게 만드는 공격
백도어Backdoor. 특정 신호가 들어오면 숨은 동작을 하도록 모델에 몰래 심은 것
드리프트Drift. 시간이 지나며 동작이 처음 기대에서 조금씩 벗어나는 것
기준선Baseline. 평소 정상 상태가 어떤지 보여 주는 기준 데이터
이상 탐지Anomaly detection. 기준선에서 벗어난 드문 것을 찾는 방법
상태를 갖는 추론Stateful inference. 요청이 끝나도 계산 결과가 남아 다음 요청에 다시 쓰이는 방식
LMCacheKV 캐시를 GPU 밖 저장소까지 내려 보관하고 다시 쓰게 하는 관리 계층
llm-d, NVIDIA Dynamo여러 서버에 걸쳐 추론을 돌리는 프레임워크. 필요한 KV 캐시를 가진 서버로 요청을 보낸다
위협 탐색Threat discovery. 쌓인 기록을 훑어 숨은 공격을 찾아내는 일
특징Feature. 모델이 판단에 쓰는 입력 값
파인튜닝Fine-tuning. 이미 학습된 모델을 특정 데이터로 더 학습시키는 것
라우터Router. 요청마다 어느 모델로 보낼지 고르는 장치
공통 표현 공간Shared representation space. 서로 다른 모델의 내부 값을 같은 기준으로 비교하도록 옮겨 놓는 공간
CacheGenKV 캐시를 압축하고 스트리밍해 빨리 옮기는 기법
