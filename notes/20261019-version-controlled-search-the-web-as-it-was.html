그날의 웹으로 백테스트하기

지금 웹을 검색하면 이미 일어난 일까지 결과에 섞여 나온다. Exa는 웹 페이지를 날짜별로 저장해 "그날 검색했다면 무엇이 나왔을까"를 재현하게 했고, 이것으로 금융 예측 모델과 에이전트를 공정하게 백테스트하자고 제안한다.

원본 영상: Version-Controlled Search: The Web as It Was 발표: Ryan Ahern (Exa 포워드 디플로이드 엔지니어)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 발표자는 Exa 소속이고, 발표 대부분이 자사 제품 소개다. 자막에서 뭉개진 제품 이름(예: "adverse search"는 Exa search)은 문맥상 확실한 것만 바로잡았다. mm:ss는 영상 위치다.

3분 요약
  1. 사람들은 이제 검색을 에이전트에게 맡긴다. 에이전트는 자세한 질의로 여러 번 검색해서 과제당 검색 횟수가 훨씬 많다.
  2. Exa는 에이전트가 부르는 웹 검색 엔진이다. 품질, 비용, 지연 시간 세 가지를 내세운다.
  3. 비용은 검색 한 번의 단가가 아니라 작업 전체 비용으로 봐야 한다. 필요한 문장만 골라 보내면 전체 페이지보다 토큰이 95% 줄어든다고 한다.
  4. Exa Snapshot은 웹 스냅샷 4,000억 개 이상을 날짜로 검색하게 한다. URL 하나를 그날 모습으로 가져오거나, 검색 자체를 과거 시점에서 실행할 수 있다.
  5. 라이브 검색에는 정답이 이미 섞여 있다. 인수 예측 모델을 라이브 검색으로 시험하면 모델이 예측하지 않고 정답을 읽는다.
  6. 과거 시점 검색으로 백테스트하는 방식은 세 가지다. 기존 모델에 웹 데이터를 보태기, 에이전트가 만든 특징을 더하기, 에이전트에게 예측 전체를 맡기기.
  7. "회사 이름이 Dominion인가" 같은 과적합 특징을 과거 데이터로 걸러 내면, 몇 달을 기다리지 않고 일반화를 확인할 수 있다.
01

검색은 이제 에이전트가 한다 01:00

발표자는 청중에게 손을 들게 했다. 예전에는 Google에 직접 검색했지만, 이제는 ChatGPT나 Claude 같은 AI에게 검색을 맡긴다는 사람이 대부분이었다.

발표자는 이것이 시장 전체의 흐름이라고 본다. 사람은 이제 검색을 에이전트에게 맡기고, 에이전트가 검색을 대신 처리한다.

사람의 검색키워드 몇 개를 넣는다상위 결과 몇 개만 본다. 안 나오면 질의를 한두 번 바꾸고 포기한다.
→
에이전트의 검색 01:20원하는 것을 길고 자세히 적는다지치지 않고 여러 번 검색한다. 답하기 전에 주변 영역까지 훑는다.

그래서 에이전트는 과제 하나당 검색 횟수가 사람보다 훨씬 많다. 이 차이가 검색 도구에 요구되는 조건을 바꾼다.

02

Exa가 쓰이는 곳 02:10

Exa는 에이전트가 부르는 웹 검색 엔진이다. 발표자 설명으로는 웹 크롤링 인프라, 데이터베이스, 임베딩 모델, 검색 구조를 모두 직접 만들었다.

  • Cursor: 코딩 에이전트가 작업 중에 최신 문서를 찾을 때 쓴다.
  • Gamma: 슬라이드를 만들다 "2018년 Apple의 SEC 자료"가 필요할 때 쓴다.

금융권 고객 03:00

발표자는 헤지펀드, 자산운용사, 국부펀드, VC와 많이 일한다. 이들도 최신 정보가 필요하다.

고객 유형웹에서 찾는 것
헤지펀드거래에 쓸 정보. 시장 평균을 넘는 수익 기회, 즉 알파 alpha를 찾는다
보험사거래 상대와 보험 대상에 대한 정보. 위험 모델을 정확하게 유지하려는 목적이다
VC곧 뜰 스타트업. 정형 데이터셋에 아직 없는 회사를 웹 어디서든 찾아야 한다
03

품질, 비용, 지연 시간 04:00

발표자는 Exa를 검색 "연구소"라고 소개했다. 에이전트가 검색하는 방식이라는 한 가지 문제에만 집중한다는 뜻이다. 내세우는 원칙은 세 가지다.

이 절은 Exa 직원이 자사 제품의 장점을 설명하는 대목이다. 수치와 "최고 수준" 같은 주장은 그 점을 감안해 읽자.

품질 04:20

검색 한 번에 필요한 것을 가져오면 에이전트의 도구 호출 tool call이 줄어든다. 호출이 줄면 추론 비용이 내려간다. 엉뚱한 결과에 끌려가는 일도 줄어서 작업 성공률이 오른다.

Exa는 최근 새 벤치마크를 냈다. 어떤 모델이 검색을 부르는지와 어떤 검색을 붙였는지가 섞이면 검색 자체의 성능을 따로 보기 어렵다. 이 벤치마크는 둘을 떼어 검색 도구만 평가하려는 것이다.

비용 05:00

중요한 건 검색 한 번의 단가가 아니다. 에이전트가 작업 하나를 끝내는 데 든 전체 비용이다. 에이전트는 검색을 여러 번 하기 때문이다.

그래서 만든 기능이 동적 하이라이트 dynamic highlights다. 예전에는 페이지 하나 안에서 필요한 부분을 골랐다. 지금은 검색 결과 전체를 놓고 꼭 필요한 문장 조각만 골라 컨텍스트 창에 넣는다.

발표자는 이렇게 하면 토큰을 95% 적게 쓰면서 결과 품질은 더 높다고 말한다. 입력 토큰이 줄면 에이전트의 추론 비용도 함께 준다.

지연 시간 06:00

인프라를 직접 가진 덕분에 아주 짧은 지연으로 검색할 수 있다고 한다.

반대쪽 끝에는 오래 걸리는 딥 리서치 deep research가 있다. 몇 주 전에 낸 ExaAgent Ultra(추정)는 장시간 검색 벤치마크 여럿에서 최고 수준이라고 발표자는 말한다. 검색 하네스를 직접 갖고 있어서 에이전트와 검색이 맞물리는 방식까지 설계할 수 있다는 설명이다.

04

Exa Snapshot: 웹의 버전 기록 06:50

이 발표의 주제다. 최근 출시한 Exa Snapshot은 웹 스냅샷 4,000억 개 이상을 날짜로 검색하게 해 준다. 발표자는 금융 업계에서 특히 쓸모가 크다고 본다.

버전 기록이 생기는 원리 07:10

  1. 검색 회사는 최신 정보를 넣으려고 웹을 계속 다시 긁는다.
  2. 긁을 때마다 페이지가 바뀌었는지, 즉 신선도 freshness를 확인한다.
  3. 확인한 그 시점의 페이지를 저장해 두면 URL마다 버전 기록이 쌓인다.

새 기능을 위해 따로 모은 데이터가 아니다. 신선도를 확인하던 과정에서 함께 남은 기록이다.

두 가지 접근 방법 07:30

URL + 날짜

원하는 URL과 날짜를 주면, 그 날짜나 그 이전에 저장된 모습을 돌려준다. 그때 요청했다면 받았을 페이지다.

어떤 페이지를 볼지 이미 알 때 쓴다.

버전 검색 · version search 07:50

검색 자체를 과거 시점에서 실행한다. 결과는 그 시점이나 그 이전에 나왔을 것만 나온다.

발표자가 "더 흥미롭다"고 한 쪽이다. 무엇을 찾을지 모를 때 쓴다.

이 절의 기능 설명과 규모(4,000억 개)는 Exa 소속 발표자가 자사 제품을 소개한 내용이다.

05

예: OpenAI 매출 숫자가 바뀐 과정 08:10

발표자는 같은 질문을 두 시점에서 검색한 화면을 나란히 보여 줬다. 왼쪽은 10월 1일 기준 스냅샷 검색이다. 오른쪽은 슬라이드를 만들기 며칠 전의 라이브 검색이다.

10월 초에는 OpenAI의 연환산 매출 annualized run rate이 700억 달러 안팎이라는 이야기가 돌았다. 발표자는 이 보도가 Axios에서 처음 나왔다고 말했다. 시장은 이 숫자로 회사 가치를 가늠했다.

이후 다른 보도들은 500억 달러에 가깝다고 했다. 발표자 설명은 이렇다. 매출 일부는 클라우드 업체를 거쳐 들어왔다. 처음 숫자는 이를 총매출 gross로 잡았다. 중간 업체로 넘어가는 몫 pass-through을 빼고 순매출 net로 보면 숫자가 줄어든다.

수치와 보도 경위는 발표자가 인용한 것이고, 원 보도를 따로 확인하지 않았다. 두 숫자의 차이는 200억 달러로, 처음 숫자의 약 29%다.

06

시장보다 먼저 찾을 수 있었나 09:20

발표자가 말하려는 건 OpenAI 매출 자체가 아니다. 이런 불일치를 찾아내는 에이전트나 제품을 만든다면, 이제 과거로 돌아가 물어볼 수 있다는 점이다.

과거 시점 검색으로 던질 수 있는 질문
  • 시장이 알아차리기 전, 분석가의 비판 글이 나오기 전에 인터넷에는 어떤 정보가 있었나?
  • SEC 공시의 회계 각주에 이미 단서가 있었나?
  • 덜 알려진 매체가 먼저 찾아냈다면, 그 출처를 다르게 평가해야 하나?

백테스트로 이어진다 10:10

더 중요한 건 이걸 백테스트 backtest할 수 있다는 점이다. 백테스트는 과거 데이터로 "그때 이 방법을 썼다면 맞혔을까"를 확인하는 일이다.

  1. 비슷한 사례로 표본 약 50개를 만든다.
  2. 모델이나 에이전트를 그 표본에 돌려 불일치를 찾는지 본다.
  3. 학습에 쓰지 않은 홀드아웃 holdout 표본으로 다시 확인한다.
  4. 홀드아웃에서도 잘 되면, 이런 신호를 찾는 능력이 일반화됐다고 판단한다.

발표자는 웹 검색에서 백테스트가 가능해진 것이 새로운 일이라고 강조한다.

07

라이브 검색은 답을 흘린다 10:50

지금의 검색 제품은 모두 라이브다. 검색하는 순간까지의 모든 정보가 결과에 들어 있다.

발표자의 예는 "이 회사가 인수될까"를 맞히는 모델이다. 라이브 검색을 쓰면 인수 발표 기사가 바로 나온다. 이미 일어난 일이라 어디에나 퍼져 있기 때문이다. 이렇게 시험하면 모델은 예측하지 않고 정답을 읽는다.

라이브 검색인수 발표 기사가 이미 결과에 있다정답이 새어 들어와 모델의 실력을 알 수 없다.
→
스냅샷 검색기준일 이전 결과만 보인다발표 전에 있던 정보만으로 맞혀야 한다.

그래서 기준 시점을 여러 개 잡는다. 11:10 인수 발표 1일 전, 7일 전, 한 달 전으로 검색해 각각 맞힐 수 있었는지 본다. 이런 회사를 여러 개 모아 표본을 만들고 모델을 학습시키고 평가한다.

08

백테스트의 세 가지 유형 11:40

발표자는 지금 Snapshot으로 백테스트하는 시스템을 세 가지로 나눴다. 뒤로 갈수록 에이전트가 맡는 몫이 커진다.

유형 1 · 기존 모델에 웹 데이터 보태기 11:50

머신러닝이나 결정 트리 같은 전통적인 모델을 그대로 쓴다. 과거 웹의 비정형 데이터를 정형 데이터로 바꿔 입력으로 넣는다.

  • 소프트웨어 가격
  • 감성 분석 sentiment
  • 특정 사이트의 이용 약관

가격 페이지처럼 과거 버전이 따로 남지 않는 정보가 많다. 감성 신호는 언제 나왔는지가 중요하다. 발표자는 이 유형을 "현 상태에 하나를 더한" 수준이라고 했다.

유형 2 · 에이전트가 만든 특징 더하기 13:00

잘 돌아가는 기존 모델에 에이전트가 만든 특징 한두 개를 더한다.

  • 부정적 언론 스캔 adverse media scan: 여러 번 검색하고 여러 경로를 따라간 뒤 결과를 구조화한다
  • 주식 리서치: 기업 전체를 훑어 추정 매출이나 직원 수 같은 특징을 모은다

실전에서는 Exa 검색으로 특징을 만들고, Snapshot으로 그 특징을 백테스트한다. 14:10 예를 들어 넉 달 전 포트폴리오에 넣은 기업을 그때 스캔했다면 뭐라고 했을지 보고 지금과 비교한다. 금융 고객은 "검색이 더 낫다"는 말을 믿을 필요 없이 기존 절차와 비교해 확인할 수 있다.

유형 3 · 에이전트가 예측 전체를 맡기 14:40

예측이나 시뮬레이션 전체를 에이전트가 진행한다. 내부 지식 검색, 데이터 피드, 웹 검색을 오가며 일한다. 일부 스타트업이 이 방향으로 일한다고 한다.

웹 전체를 흉내 내는 내부 자료를 따로 만들 필요가 없다. 대신 웹 검색 도구의 시점을 고정해 미래 정보가 새지 않게 한다. 그렇지 않으면 검색 한 번으로 "인수됐다"는 기사를 찾아 100% 정확도로 맞혀 버린다. 발표자는 이 유형을 "아마 미래"라고 했다.

09

워크숍 사례와 과적합 16:00

발표 전날 Exa는 Snapshot 워크숍을 열었다. 약 100명이 앞의 인수 예측 예제를 직접 풀었다. 발표자는 점수가 높았던 참가자의 특징 목록 하나를 보여 줬다.

특징내용비고
1지난 1년 안에 투자자나 대주주가 회사 전체 매각을 공개적으로 요구했나공개적인 매각 압박이 있었는지 본다
2주가가 지난 5년 최고가보다 60% 이상 낮은가발표자가 "흥미로운 것"으로 꼽았다. 주가가 크게 떨어진 회사인지 본다
3회사 이름이 Dominion인가과적합 overfitting. 학습 데이터에만 맞고 다른 회사에는 통하지 않는다

에이전트도 라이브 데이터로 학습하면 이렇게 학습 데이터에 과적합할 수 있다. 17:00

Snapshot이 있으면 과거로 돌아가 이런 특징을 시험할 수 있다. 평가 eval와 에이전트 하네스를 과적합을 잡도록 짤 수 있다. 다른 사례에도 통하는지, 즉 일반화되는지도 확인할 수 있다.

라이브 환경에서만 시험하면 17:20 특징 설명을 바꾼 뒤 실제 시간이 흐르기를 기다려야 한다. 에이전트가 정말 예측하는지, 과적합인지 알려면 몇 달이 걸릴 수 있다.

원하는 만큼 복잡한 특징 17:40

시맨틱 검색 semantic search은 키워드가 아니라 뜻으로 찾는 검색이다. 이걸 쓰면 키워드 검색으로는 만들기 어려운 복잡한 특징도 문장으로 적을 수 있다.

발표자가 든 예는 일부러 과장한 것이다. "AI Engineer 팟캐스트에 출연한 VC 임원에 관한 부정적 보도가 있었나" 같은 식이다. 이렇게 특징을 원하는 만큼 구체적으로 만든 뒤, 백테스트로 실제 예측력이 있는지 확인하면 된다.

발표 정리 18:20

  1. Exa를 품질 좋고 비용 효율적인 에이전트용 검색으로 써 보고, 내 모델에 실제로 도움이 되는지부터 확인한다.
  2. Exa Snapshot으로 웹 검색 특징을 넣은 금융, 위험, 예측 모델을 백테스트해 정말 가치를 더하는지 본다.

발표 전체가 Exa 제품 소개다. 백테스트와 미래 정보 누출 문제는 일반적인 이야기지만, 해법으로 제시한 도구는 발표자 회사의 제품이라는 점을 감안해 읽자.

11

핵심 정리

  1. 사람은 이제 검색을 에이전트에게 맡긴다. 에이전트는 자세한 질의로 여러 번 검색해 과제당 검색 횟수가 훨씬 많다.
  2. Exa는 크롤러, 데이터베이스, 임베딩 모델, 검색 구조를 직접 갖춘 에이전트용 검색 엔진이다.
  3. 검색 품질이 좋으면 도구 호출이 줄어 비용이 내려가고 성공률이 오른다.
  4. 비용은 호출 단가가 아니라 작업 전체 비용으로 본다. 동적 하이라이트는 토큰을 95% 줄인다고 한다.
  5. Exa Snapshot은 신선도를 확인하며 쌓은 웹 스냅샷 4,000억 개 이상을 날짜로 검색하게 한다.
  6. 접근은 두 가지다. URL을 특정 날짜 모습으로 가져오기, 검색 자체를 과거 시점에서 실행하기(버전 검색).
  7. OpenAI 연환산 매출 예(700억 → 500억 달러)처럼, 시장이 알기 전에 어떤 단서가 있었는지 과거 시점으로 찾아볼 수 있다.
  8. 라이브 검색에는 정답이 섞여 있다. 예측 모델은 기준일 이전 결과만 써서 평가해야 한다.
  9. 백테스트 유형은 세 가지다. 웹 데이터 보태기, 에이전트가 만든 특징 더하기, 에이전트에게 예측 전체 맡기기.
  10. "회사 이름이 Dominion인가" 같은 과적합 특징을 과거 데이터와 홀드아웃으로 걸러 내면 몇 달을 기다리지 않고 일반화를 확인할 수 있다.
12

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1사람과 에이전트의 검색 방식은 어떻게 다른가?
사람은 키워드 몇 개를 넣고 상위 결과만 본 뒤 금방 포기한다. 에이전트는 원하는 것을 자세히 적고 지치지 않고 여러 번 검색한다. 그래서 과제당 검색 횟수가 훨씬 많다.
Q2검색 품질은 왜 비용과 이어지나?
한 번에 필요한 것을 가져오면 도구 호출이 줄어 추론 비용이 내려간다. 엉뚱한 결과에 끌려가는 일도 줄어 성공률이 오른다.
Q3에이전트의 검색 비용은 무엇을 기준으로 봐야 하나?
검색 한 번의 단가가 아니라, 에이전트가 작업 하나를 끝내는 데 든 전체 비용이다.
Q4동적 하이라이트는 무엇을 하고, 발표자가 말한 효과는?
검색 결과 전체를 놓고 꼭 필요한 문장 조각만 골라 보낸다. 전체 페이지 텍스트보다 토큰을 95% 적게 쓰면서 품질은 더 높다고 한다.
Q5Exa는 어떻게 웹 페이지의 버전 기록을 갖게 됐나?
최신 정보를 위해 웹을 계속 다시 긁으며 페이지가 바뀌었는지 확인한다. 그때마다 확인 시점의 모습을 저장해 URL별 버전 기록이 쌓였다.
Q6Snapshot의 두 가지 접근 방법은?
URL과 날짜를 주고 그 날짜나 이전 모습을 받는 방법. 검색 자체를 과거 시점에서 실행해 그때 나왔을 결과만 받는 버전 검색.
Q7OpenAI 연환산 매출이 700억에서 500억 달러로 바뀐 이유는? (발표자 설명 기준)
클라우드 업체를 거쳐 들어온 매출을 총액으로 잡았다. 중간 업체로 넘어가는 몫을 빼고 순매출로 보면 숫자가 작아진다.
Q8라이브 검색으로 인수 예측 모델을 시험하면 무엇이 문제인가?
인수 발표 기사가 이미 결과에 있어서 모델이 예측하지 않고 정답을 읽는다. 발표 1일 전, 7일 전, 한 달 전 같은 기준일 이전 결과만 써야 실력을 잴 수 있다.
Q9Snapshot으로 백테스트하는 세 가지 유형은?
기존 모델에 과거 웹 데이터를 정형화해 보태기. 기존 모델에 부정적 언론 스캔 같은 에이전트형 특징 더하기. 에이전트에게 예측 전체를 맡기되 웹 검색 시점을 고정하기.
Q10"회사 이름이 Dominion인가"라는 특징은 무엇을 보여 주나?
과적합이다. 학습 데이터에만 맞는 특징이라 다른 회사에는 통하지 않는다. 홀드아웃과 과거 시점 검색으로 일반화되는지 확인해야 한다.
Q11라이브 환경에서만 시험하면 어떤 한계가 있나?
특징을 바꾼 뒤 실제 시간이 흐르기를 기다려야 한다. 예측인지 과적합인지 아는 데 몇 달이 걸릴 수 있다.
