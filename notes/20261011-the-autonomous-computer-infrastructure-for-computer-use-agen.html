자율 컴퓨터: 신경망과 코드를 한 루프로

컴퓨터 사용 에이전트에게 일을 믿고 맡기려면, 화면을 보고 적응하는 신경망 에이전트와 매번 똑같이 도는 코드가 함께 있어야 한다. Simular의 Ang Li는 둘을 한 루프로 묶고, 에이전트가 쓸 컴퓨터를 클라우드로 옮기는 길을 보여 준다.

원본 영상: The Autonomous Computer: Infrastructure for Computer Use Agents 발표: Ang Li (Simular 공동 창업자·CEO, 전 DeepMind 연구자)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치와 성과는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 뭉개진 이름은 확실한 것만 바로잡았고, 확실하지 않은 이름에는 (추정)을 붙였다. 질의응답의 질문은 자막에 거의 잡히지 않아 답을 보고 짐작했다. mm:ss는 영상 위치다.

3분 요약
  1. 컴퓨터 사용 에이전트는 API를 부르지 않고 화면을 보며 마우스와 키보드로 일한다. API가 없는 오래된 업무 프로그램도 맡길 수 있다.
  2. 발표자의 원칙은 신경-기호다. 화면을 이해하는 신경망 에이전트(VLM 에이전트)와, 정해진 대로 도는 코드를 쓰는 코딩 에이전트를 함께 쓴다.
  3. 신경망 쪽은 Agent S로 세 세대를 거쳤다. 2024년 말 OSWorld 20%에서 시작했고, 발표자에 따르면 2025년 12월 사람의 성적을 넘었다.
  4. 하지만 실제 고객이 원하는 건 한 번 성공이 아니라 k번 돌려 k번 모두 성공(pass^k)이다. 이 기준에서는 최고 에이전트도 성능이 떨어진다.
  5. 코드는 매번 같지만 환경이 바뀌면 깨진다. 신경망은 적응하지만 매번 결과가 다르다. 이것이 안정성-가소성 딜레마다.
  6. 해법은 에이전트가 일하면서 코드를 쓰게 하는 것이다. 성공하면 스킬로 저장해 다음엔 코드부터 돌리고, 깨지면 신경망으로 넘어가 고친다. 반복할수록 토큰 비용이 준다.
  7. 에이전트가 쓸 컴퓨터는 내 컴퓨터 한 대에서 클라우드의 여러 대로 옮겨 간다. Windows와 macOS에 이어 Linux와 Android도 준비 중이다.
01

코드 10년, 신경망 10년, AGI 10년 00:10

Ang Li는 Simular의 공동 창업자이자 CEO다. 컴퓨터를 다룬 지 올해로 30년째이고, 그 시간을 10년씩 셋으로 나눈다.

시기한 일
첫 10년매일 코드를 썼다
다음 10년박사 과정과 DeepMind에서 신경망을 학습시키며 AI 논문을 냈다
최근 10년2017년 DeepMind에 들어가 AGI(범용 인공지능, artificial general intelligence)를 연구했다

이 경력이 회사의 원칙이 됐다. 범용 AI 시스템은 신경-기호여야 한다. 신경-기호(neurosymbolic)는 신경망과 코드를 함께 쓴다는 뜻이다. 01:50

발표자는 이 워크숍에서 세 가지를 주겠다고 했다. 02:10

  • 컴퓨터 사용 에이전트의 기초 지식. 청중의 절반은 이 분야가 처음이라고 봤다.
  • 회사가 인프라로 만든 도구 네 가지와, 다른 개발자들이 만든 응용 사례
  • 아직 클로즈드 베타인 제품의 초대 코드
02

컴퓨터 사용 에이전트란 03:00

발표자는 CEO라서 하루 종일 컴퓨터 앞에 있지 않는다. 대신 휴대폰으로 에이전트에게 문자를 보낸다.

데모에서는 청중과 찍은 셀카를 보내며 "LinkedIn에 올려 줘"라고 했다. 에이전트는 바로 올리지 않고 먼저 몇 가지를 되물었다.

이 에이전트에게는 Windows 데스크톱 한 대가 통째로 있다. 에이전트는 그 안에서 마우스와 키보드를 움직여 LinkedIn을 연다. 이것이 컴퓨터 사용 에이전트(computer use agent)다. 컴퓨터를 가진 에이전트라는 뜻이다.

에이전트 여러 대 05:00

에이전트를 여러 개 둘 수도 있다. 발표자가 보여 준 녹화에서는 이름이 다른 에이전트 넷이 각자 일했다. 발표자가 짚은 일은 이렇다.

  • QA: 제품을 테스트한다. 발표자는 테스트를 큰 쓰임새로 꼽았다.
  • 리서치: 자료를 조사한다.
  • 고객 지원: Discord 채널에 들어가 올라온 내용을 살핀다.

실제 에이전트는 느리다. 몇 시간 분량의 녹화를 30초로 줄여 보여 줬다.

API 에이전트와 무엇이 다른가 05:40 지금 흔히 말하는 에이전트는 대부분 API를 부른다. 무엇을 하는지 눈으로 볼 수 없다. 컴퓨터 사용 에이전트는 화면을 직접 다루고, 하는 일이 눈에 보인다. API가 없는 프로그램도 맡길 수 있어서, 발표자는 이쪽이 더 큰 범주라고 본다.
03

2년 전에는 아이콘 하나도 어려웠다 06:00

Simular는 2023년에 시작했다. GPT-3.5와 GPT-4V가 나온 직후다.

그 무렵 발표자는 GPT-4V에게 화면을 보여 주고 iMessage 아이콘을 누르게 했다. 한 번에 되지 않아서, 결과를 보고 위치를 고쳐 가는 반복 보정을 붙였다.

  1. 첫 시도: 틀린 곳을 눌렀다.
  2. 두 번째: 메일 아이콘으로 갔다.
  3. 세 번째: iMessage를 눌렀다.

성공한 데모는 이것 하나뿐이었다. Zoom 아이콘을 누르라고 하자 전혀 되지 않았다.

그래도 기반 모델(foundation model)은 계속 좋아질 거라고 봤다. 다만 당장 풀 수 있는 문제는 아니었다. 그래서 이 문제를 풀 전체 전략부터 세웠다.

04

자율 컴퓨터 = 자율성 + 컴퓨터 07:30

회사는 목표를 자율 컴퓨터(autonomous computer)라고 부른다. 컴퓨터가 온갖 일을 스스로 하면 자율적이라는 뜻이다. 이름이 두 단어이듯 문제도 두 방향으로 나뉜다.

자율성 · autonomy

컴퓨터의 상황을 이해하고, 추론하고, 계획하고, 실수에서 스스로 회복한다. 사람이 옆에서 지켜보지 않아도 돼야 한다.

  • 신경: VLM 에이전트
  • 기호: 코딩 에이전트
컴퓨터 · computer

에이전트가 어떤 컴퓨터를 쓰는가. 2년 전에는 쉬운 문제로 봤다. 누구에게나 컴퓨터가 있으니까.

  • 로컬 컴퓨터
  • 클라우드 컴퓨터

그래서 처음에는 자율성에 집중했다. 컴퓨터 쪽은 12장에서 다룬다.

발표자는 신경-기호가 자율주행차를 포함한 모든 자율 시스템의 공통 구조라고 말한다. 08:30

  • 신경: VLM 에이전트. VLM(vision language model)은 이미지와 글을 함께 이해하는 모델이다.
  • 기호: 코딩 에이전트. 컴퓨터를 코드로 조작한다.

2년 전에는 VLM이 거의 쓸모가 없었다. 그래서 먼저 코드 층을 만들어 컴퓨터를 믿을 만하게 제어했다. 동시에 연구팀을 따로 꾸려 VLM 에이전트를 키웠다.

컴퓨터가 주는 세 가지 신호 09:20

자율주행차는 라이다, 레이더, 카메라로 길을 본다. 발표자는 자기 일을 "디지털 세계의 자율주행차"라고 부른다. 핸들 대신 마우스와 키보드를 잡는다. 컴퓨터에도 신호가 세 가지 있다.

신호무엇인가
스크린샷화면을 찍은 이미지
접근성 트리Accessibility tree. 운영체제가 창, 버튼, 아이콘을 나무 구조로 표현한 것. macOS와 Windows가 서로 다른 형식을 쓴다
DOM 트리웹 페이지의 구조. 브라우저를 많이 쓰니 가장 익숙하다

발표자는 접근성 트리를 "운영체제가 화면을 그릴 때 쓰는 기본 층"이라고 설명했다. 정확히는 앱이 화면 낭독기 같은 보조 기술에 내보내는 화면 구조다. 그래서 질의응답에서 발표자도 말했듯, 앱 개발자가 일부를 일부러 빼고 내보낼 수 있다.

05

VLM 에이전트 세 세대: Agent S 10:30

신경 쪽의 결과물은 Agent S다. 여러 기반 모델 위에 얹는 하네스(harness)다. 하네스는 모델을 감싸 도구, 순서, 규칙을 정해 주는 실행 틀이다. 2년 전에는 이런 이름이 없었는데, 지금은 다들 하네스라고 부른다고 발표자는 말한다.

Agent S는 모델 비종속(model-agnostic)이다. 기반 모델을 쉽게 바꿔 끼울 수 있다. 성적은 OSWorld로 쟀다. OSWorld는 실제 운영체제 위에서 컴퓨터 사용 에이전트를 채점하는 벤치마크다.

세대방식결과 (발표자 인용)
Agent S
2024년 말		VLM이 너무 약해서 접근성 트리만 썼다. 화면의 버튼마다 ID를 붙여 한 줄로 늘어놓고, 언어 모델에게 "지금 누를 버튼의 ID"를 고르게 했다. 이를 ID 기반 그라운딩이라 한다OSWorld 20%로 당시 최고. ICLR 2025 에이전트 AI 워크숍 최우수 논문상
Agent S2
2025년 초		접근성 트리를 버리고 화면만 본다. 관리자와 작업자로 층을 나눈, 사람 조직 같은 구조다. 큰 기반 모델 옆에 70억 매개변수(7B) 오픈소스 모델을 붙였다한 하네스 안에서 모델 둘이 모델 하나보다 낫다는 걸 보였다
Agent S3
2025년 말		테스트 시점 확장. 에이전트 여러 개가 같은 과제를 풀게 한다2025년 12월 OSWorld에서 사람의 성적을 넘었다

그라운딩(grounding)은 "이걸 눌러"라는 지시를 화면의 정확한 요소나 위치에 연결하는 일이다. 2024년 초 OSWorld의 성공률은 5% 정도였다. 그래서 20%도 당시엔 아주 반가운 숫자였다.

Agent S2에는 스타트업 쪽 반응이 컸다고 한다. 작은 모델을 직접 학습시켜 붙이면 큰 연구소를 넘을 수 있다는 뜻이어서다. 발표자 말로는 Claude나 OpenAI의 컴퓨터 사용 에이전트보다 20% 나았다. 무엇을 기준으로 한 20%인지는 말하지 않았다. 13:10

Agent S3 실험에서는 공정하게 비교하려고 "작업자 수 × 단계 수"를 전체 자원 예산으로 잡았다. 같은 예산에서 에이전트를 10개 쓰면 성공률이 더 잘 올랐다. 13:50

발표자에 따르면 Anthropic과 OpenAI도 올해(2026년) 3월에 같은 사람 수준에 닿았다.

벤치마크는 연구용 시험이다 14:40 OSWorld에서 사람을 넘었다고 실제 업무에서 완벽하다는 뜻은 아니다. 발표 며칠 전 나온 OSWorld 2에서는 최고 모델이 20% 정도다. 발표자는 지금을 컴퓨터 사용 에이전트의 "두 번째 단계"라고 부른다.

Agent S는 발표자 회사의 오픈소스 프로젝트다. 벤치마크 성과와 "큰 연구소보다 낫다"는 말은 이 점을 감안해 읽자.

해커톤 우승작: FaceTime으로 Mac 고치기 15:10

작년 10월 Cal Hacks 우승작은 오픈소스 Agent S로 만들었다. Cal Hacks는 버클리에서 열리는 큰 해커톤이다.

밖에 나와 있다가, 집에서 돌리던 모델 학습이 CUDA 메모리 부족 오류로 멈춘 걸 알았다고 하자. 집에 가는 대신 Mac에 FaceTime을 건다. "VS Code에서 이 오류 고쳐 줘"라고 말하면, 에이전트가 VS Code를 열고 오류가 난 파일을 찾아 텐서 크기를 줄인다.

발표자는 이것이 OpenClaw 프로젝트가 시작되기도 전의 일이라고 짚었다.

06

한 번 성공이 아니라 매번 성공 17:20

벤치마크에서 사람을 넘었다면 다음은 무엇일까. 발표자는 pass^k라는 기준에서 답을 찾았다.

바이브 코딩의 기준pass@kk번 시도해서 한 번만 성공하면 된다. 코드가 안 돌면 프롬프트를 고쳐 다시 만들면 그만이다. 지난 실패는 상관없다.
→
컴퓨터 사용의 기준pass^kk번 돌려 k번 모두 성공해야 한다. 서버에 올려 매일 돌려도 사람이 들여다볼 필요가 없어야 한다.

2년 전 첫 고객들부터 다들 같은 걸 물었다. "에이전트를 서버에 올려서 이 업무를 매일 돌릴 수 있나요? 매번 확인하고 고치지 않아도 되나요?" 그런데 이 기준을 재는 벤치마크는 없었다.

예시: 매번 성공은 왜 어려운가 발표에 없는 계산이다. 한 번 성공률이 80%이고 실행마다 결과가 서로 독립이라고 하자. 세 번 모두 성공할 확률은 0.8 × 0.8 × 0.8, 약 51%다. 한 번 성적이 좋아도 매번 성공할 확률은 훨씬 낮을 수 있다.

같은 에이전트를 세 번 돌려 보니 18:40

핵심 정리

  1. 컴퓨터 사용 에이전트는 화면을 보고 마우스와 키보드로 일한다. API가 없는 소프트웨어도 맡길 수 있다.
  2. 자율 컴퓨터는 자율성과 컴퓨터로 나뉜다. 자율성은 신경(VLM 에이전트)과 기호(코딩 에이전트)로 나뉜다.
  3. 컴퓨터의 신호는 스크린샷, 접근성 트리, DOM 세 가지다. 만능 신호는 없어서 여럿을 함께 쓴다.
  4. Agent S는 접근성 트리(20%) → 화면만 보는 관리자·작업자 구조 → 여러 에이전트 동시 시도로 발전했다. 발표자에 따르면 OSWorld에서 사람을 넘었다.
  5. 실제 업무의 기준은 pass^k, 곧 매번 성공이다. 이 기준에서는 최고 에이전트도 성능이 떨어진다.
  6. 에이전트가 모호한 부분을 먼저 질문하게 하면 신뢰성이 오른다.
  7. 코드는 안정적이지만 고집이 세고, VLM은 적응하지만 불안정하다. 이것이 안정성-가소성 딜레마다.
  8. 신경-기호 루프: 에이전트가 일하며 코드를 쓰고, 성공하면 스킬로 저장해 다음엔 코드부터 돈다. 깨지면 VLM으로 넘어가 고친다.
  9. 그래서 반복할수록 LLM 호출과 비용이 줄고, 목표는 토큰 0이다.
  10. 에이전트가 쓸 컴퓨터는 클라우드 여러 대로 간다. 정확성과 안전은 검증 루프와 코드 → 에이전트 → 사람 순서의 가드레일로 지킨다.

Q4Agent S2와 S3는 각각 무엇을 보여 줬나?

Q5pass@k와 pass^k의 차이는? 고객은 왜 pass^k를 원하나?
pass@k는 k번 중 한 번만 성공하면 되고, pass^k는 k번 모두 성공해야 한다. 고객은 서버에서 매일 돌려도 사람이 들여다볼 필요가 없기를 원한다.
Q6OSWorld 상위 에이전트를 세 번씩 돌리면 어떻게 됐나? 섭동 환경에서는?
모든 에이전트의 성능이 떨어졌고, 가장 좋은 에이전트도 10% 가까이 떨어졌다. 지시나 환경을 조금 바꾸면 더 나빠졌다.
Q7신뢰성을 높이는 간단한 프롬프트 요령은?

Q8코딩 에이전트와 VLM 에이전트는 안정성-가소성 딜레마에서 각각 어디에 있나?
코딩 에이전트는 안정성 쪽 끝이다. 매번 같지만 환경이 바뀌면 깨진다. VLM 에이전트는 가소성 쪽 끝이다. 적응하지만 결과가 매번 다르다.
Q9제품 데모에서 "수요일 첫 발표자" 질문은 어떻게 처리됐나?
저장된 스킬의 코드를 리플레이하면서 매개변수를 화요일에서 수요일로 바꿨다. 필터 단계에서 걸리자 신경 모드(VLM 에이전트)로 넘어가 처리했다.
Q10신경-기호 방식에서 반복할수록 비용이 줄어드는 이유는?
두 번째 실행부터는 일의 상당 부분을 LLM 호출 없이 코드가 처리한다. 발표자 어림으로 50% 정도다. 최종 목표는 토큰 소비 0이다.
Q11100% 정확해야 하는 일에 발표자가 제시한 방법 두 가지는?
하나는 채운 양식을 모델에게 다시 보여 검증하고, 틀리면 다시 시키는 루프다. 다른 하나는 글로 된 접근성 트리로 100% 일치를 확인하며 코드를 결정적으로 다시 돌리는 것이다.
Q12발표자가 말한 가드레일의 순서는?
규칙(코드)이 먼저 걸러 낸다. 규칙이 못 잡으면 에이전트가 보고, 그다음 사람이 확인한다. 되돌릴 수 없는 행동은 멈추고 승인을 구한다.

신경-기호Neurosymbolic. 유연하게 판단하는 신경망과, 정해진 대로 도는 코드·규칙을 함께 쓰는 방식
VLMVision language model. 이미지와 글을 함께 이해하는 모델
기반 모델Foundation model. 여러 일에 두루 쓰도록 크게 학습한 모델
접근성 트리Accessibility tree. 앱이 창, 버튼, 글자를 나무 구조로 운영체제에 내보낸 것. 원래 화면 낭독기 같은 보조 기술용이다
DOM 트리웹 페이지의 요소를 나무 구조로 나타낸 것
그라운딩Grounding. "이걸 눌러"라는 지시를 화면의 정확한 요소나 위치에 연결하는 일
하네스Harness. 모델을 감싸 도구, 순서, 규칙을 정해 주는 실행 틀
모델 비종속Model-agnostic. 특정 모델에 묶이지 않고 바꿔 끼울 수 있는
OSWorld실제 운영체제 위에서 컴퓨터 사용 에이전트의 과제 성공률을 재는 벤치마크
테스트 시점 확장Test-time scaling. 학습을 더 하는 대신, 실행할 때 계산을 더 써서 성능을 올리는 방법
pass@kk번 시도해 한 번이라도 성공하면 성공으로 치는 기준
pass^kk번 돌려 모두 성공해야 성공으로 치는 기준
섭동 환경Perturbed environment. 지시문이나 환경을 조금씩 바꾼 시험 조건
RPARobotic process automation. 사람이 하던 반복 화면 작업을 스크립트로 자동화하는 방식
Playwright브라우저 자동화의 사실상 표준 도구
결정적Deterministic. 같은 입력이면 매번 같은 결과가 나오는 성질
연속 학습Continual learning. 배운 것을 잊지 않으면서 새것을 계속 배우게 하는 연구 분야
안정성-가소성 딜레마Stability-plasticity dilemma. 배운 것을 지키는 힘과 새것에 적응하는 힘이 서로 부딪히는 문제
파레토 프런티어Pareto frontier. 한쪽을 더 좋게 하려면 다른 쪽을 내줘야 하는, 최선의 조합들이 이루는 경계
스킬성공한 작업의 코드를 저장해 다음에 다시 쓰는 단위
리플레이Replay. 저장한 코드를 다시 돌리는 것
치유 루프Healing loop. 코드가 깨지면 에이전트가 원인을 보고 고쳐 다시 저장하는 과정
가드레일Guardrail. 에이전트의 위험한 행동을 막는 별도 감시 장치
ERPEnterprise resource planning. 회계, 재고, 인사 같은 기업 업무를 묶어 관리하는 소프트웨어
레거시 시스템Legacy system. 오래됐지만 여전히 업무에 쓰는 소프트웨어
MFAMulti-factor authentication. 비밀번호 말고도 인증 앱 코드 같은 두 번째 증거를 요구하는 로그인 방식
SOPStandard operating procedure. 회사가 정해 둔 표준 업무 절차서
월드 모델World model. 환경이 행동에 어떻게 반응할지 흉내 내는 모델
