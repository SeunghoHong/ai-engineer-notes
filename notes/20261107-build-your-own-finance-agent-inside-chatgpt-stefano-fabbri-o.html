ChatGPT 안에 금융 에이전트 만들기

OpenAI에서 금융 고객을 맡는 엔지니어들이 ChatGPT Work의 금융 서비스 기능과 Codex 플러그인을 보여 준다. 핵심 메시지는 하나다. 새 앱을 따로 만들기보다, 회사가 이미 쓰는 ChatGPT Work와 Codex 안에 스킬과 플러그인으로 업무를 얹으라는 것이다.

원본 영상: Build Your Own Finance Agent Inside ChatGPT 발표: Stefano Fabbri, Oliver Steffmann (OpenAI 응용 AI 엔지니어링 팀, 뉴욕 금융 기관 담당). 같은 팀의 Dom이 중간에 두 번 답했다.

영어 워크숍의 자동 자막을 바탕으로 한글로 정리했다. 실습 화면은 자막에 남지 않아서 말로 설명한 부분만 담았다. 수치와 주장은 모두 발표자가 말한 것이고, 원 출처를 따로 확인하지 않았다. 모델 이름(6.1 Soul, Astra, Terra, Luna)과 일부 고유명사는 들린 대로 적고 "(추정)"을 붙였다. mm:ss는 영상 위치이고, 한 시간이 넘으면 h:mm:ss로 적었다.

발표자 세 명 모두 OpenAI 직원이고, 이 워크숍은 OpenAI 제품 소개를 겸한다. 제품의 장점에 관한 말은 그 점을 감안해 읽자.

3분 요약
  1. OpenAI의 화면은 셋이다. ChatGPT, 지식 노동자용 ChatGPT Work, 엔지니어용 Codex. 금융 서비스 기능은 지금 ChatGPT Work 웹에만 있다.
  2. ChatGPT for Financial Services는 데이터, 금융 업무에 맞춘 모델, 엑셀·PPT 산출물을 묶은 기업용 제품이다.
  3. 발표자가 꼽는 차별점은 데이터다. 원본을 그냥 붙이지 않고 데이터셋마다 모델이 쓰기 좋게 가공하고 설명을 붙였다.
  4. 플러그인은 스킬 + MCP 서버 + 도구 설정 + UI다. 업계 전문가와 만든 기본 플러그인이 80%를 주고, 회사가 20%를 채운다.
  5. 사내 개발자는 별도 앱 대신 플러그인을 만들어 이미 승인된 화면에 배포한다. 로그인, 권한, 보안 정책을 다시 만들 필요가 없다.
  6. 비용은 오케스트레이터만 가장 강한 모델로 두고, 하위 에이전트는 싼 모델과 잘 쓴 스킬로 줄인다. 발표자는 결과의 약 95%가 나온다고 했다.
  7. 평가(eval)가 가장 막히는 곳이다. 단순하게 시작하고, LLM 채점은 1~5점 대신 예/아니오로 묻는다. 규제 업무에는 결정마다 근거 로그를 남긴다.

03

데이터를 모델이 읽기 좋게 08:40

발표자가 꼽는 가장 큰 차별점은 데이터를 넣는 방식이다.

흔한 방식원본 데이터를 API로 넘긴다모델이 파일을 받아 알아서 해석한다
→
이 제품데이터셋마다 맞춤 도구와 설명을 붙인다무엇이 어디 있고 무엇이 중요한지까지 함께 준다
  • 10-K, 10-Q 같은 공시는 파일만 주지 않는다. 파일 안 어디에 무엇이 있는지 설명을 같이 준다.
  • 데이터셋마다 무엇이 중요하고 무엇이 아닌지 맥락을 붙였다.
  • 예를 들어 시세와 수익률을 다룰 때 흔히 하는 착각을 피하는 법까지 적었다.
  • 데이터셋 하나하나를 공급 업체와 함께 넣었다. "어떻게 줘야 모델이 가장 잘 쓰나"를 맞추기 위해서다.

발표자는 이 작업을 데이터 온톨로지data ontology라고 부른다. 데이터의 구조와 의미를 정리해 둔 틀이라는 뜻이다.

맞춤 임베딩을 썼나? 35:00 아니라고 답했다. 데이터를 미리 가공하고, 그 데이터셋 전용으로 다듬은 도구 호출을 만든 것이다. 내부 구조(온톨로지, 그래프)는 사용자에게 열려 있지 않다. 엔지니어보다 지식 노동자를 위한 제품이기 때문이라고 했다.

Oliver는 자산운용사에서 비슷한 일을 직접 해 봤다. SEC 파일을 대량으로 받고, 새 정보를 계속 챙기고, 그걸 빠르게 내줄 맥락 계층context layer을 만드는 일은 기술적으로 어렵다고 했다.

04

플러그인: 80%는 받고 20%는 채운다 10:10

OpenAI 제품팀은 금융 업무용 플러그인을 만들었다. 투자은행용과 주식 리서치용이 대표적이다.

OpenAI가 말하는 플러그인은 스킬 묶음과 MCP 서버를 합친 것이다. MCPModel Context Protocol는 모델이 외부 도구와 데이터에 접속하는 표준 방식이다.

상위 투자은행, 자산운용사, 리서치 회사와 함께 만들었다. 스킬 자체는 마크다운 파일과 템플릿이다. 다만 그 안에 업계 전문 지식이 담겼다는 것이 발표자의 설명이다.

  1. 기본 스킬을 그대로 가져온다.
  2. 그 스킬로 예약 작업이나 파이프라인을 만들어, 하려는 일을 재현해 본다.
  3. 빠진 부분과 자기 회사의 관점을 더한다.

기본 제공 사례 12:00

피치북pitch book 준비, 실적 분석, 가치 평가, LBO 모델링이 처음부터 들어 있다. 투자은행 쪽에 치우쳐 있고, 오늘 실습은 자산관리 쪽이다.

Stefano는 자본시장 출신이다. 투자은행 사람들과 가치 평가를 이야기해야 했을 때, 이 플러그인 예제를 몇 개 돌려 보고 빠르게 따라잡았다고 했다.

답을 보여 주는 방식까지 37:40

플러그인은 데이터를 어떻게 보여 줄지도 안다. 매출을 물으면 표와 차트로 답한다. 같은 Astra(추정) 모델을 플러그인 없이 쓰면 꼭 그렇게 하지는 않는다. 모델을 바꾼 게 아니라 보여 주는 법에 대한 맥락을 준 것이다.

05

실습 1: 자산관리 어드바이저 14:20

목표는 어드바이저가 고객과 이야기하는 시간을 늘리는 것이다. 그러려면 뒤에서 하는 준비 작업을 줄여야 한다.

  1. 고객 포트폴리오에 변화가 생긴다.
  2. 무슨 일이 있었는지 분석한다. 손익과 성과 요인 분석performance attribution을 만든다.
  3. 왜 바뀌었는지 설명을 정리한다.
  4. 고객 미팅을 준비하고, 고객에게 보여 줄 자료를 만든다.
  5. 포트폴리오의 균형을 되돌릴 방법rebalancing을 제안한다.

실습 사이트에는 고객 예시 데이터(zip 파일)와 프롬프트가 있다. 포트폴리오 질문, 리서치, 차트 그리기 같은 하위 실습을 골라 할 수 있다.

사이트의 프롬프트를 복사해 넣으면 화면에 플러그인과 내부 도구 호출이 보인다. 프롬프트 안에 "ChatGPT for Financial Services를 써라"는 힌트를 넣어 플러그인을 부르는 방식이다.

프롬프트 하나에 몇 분이 걸린다. 빨리 하려면 6.1 Soul(추정) 모델에서 Ultra Fast를 켠다. 발표자는 Ultra Fast가 평균 초당 약 300토큰을 낸다고 했다03:10.

실습 사이트는 웹사이트를 띄워 주는 Sites 기능(추정)으로 만들었다. 참가자는 가상 투자금 10만을 받고, 단계를 마칠 때마다 돈이 늘었다. 상위 세 명이 OpenAI 물병을 받았다.

Oliver가 아쉬워한 것 39:10 과거 시세를 API로 바로 받을 수 있으면 좋겠지만, 데이터 업체 라이선스 때문에 쉽지 않다. 그래서 사내에 이미 시세·포트폴리오 시스템이 있다면 직접 플러그인을 만들 기회라고 했다. 같은 시각화를 쓰면서 ChatGPT Work와 데스크톱 양쪽에 둘 수 있다.
06

스킬, 플러그인, 플러그인 확장 18:50

서버가 꼭 있어야 하나? 53:40

플러그인에 따라 다르다. 스킬만 묶은 플러그인도 있다. 사내 데이터에 붙으려면 MCP 서버와 인증이 필요하다.

  • 시스템 간 인증: 플러그인이 회사 시스템에 자기 자격으로 접속한다.
  • 사용자 대신 인증: Codex에 로그인한 사람의 권한으로 접속한다.

플러그인 확장이 바꾸는 것 56:40

화면 왼쪽 아래에 자기 아이콘을 넣을 수 있다. 설정과 내비게이션도 바꿀 수 있다. 그리고 대화 맥락을 읽고 필요한 순간에 맞춤 UI를 띄운다.

발표자가 든 장면 어드바이저가 대화 중에 고객 미팅을 준비한다고 말한다. 그러면 사내 시스템에서 그 고객의 지표를 보여 주는 화면이 뜬다. 다섯 군데 사이트를 돌아다니지 않고, 늘 쓰는 AI 도구 안에서 일을 끝낸다.

Figma와 Adobe 같은 파트너가 만든 더 복잡한 앱 예시도 OpenAI 웹사이트에 있다고 했다1:21:10.

07

비용: 오케스트레이터만 비싸게 42:10

Stefano에 따르면 최근 3개월 고객사의 가장 큰 관심사는 토큰 효율과 비용이었다.

상황권하는 구성 (발표자 설명)
완전히 새 코드베이스, 새 연구가장 강한 모델(Astra)을 쓴다. 성능 여유가 필요하다
반복되는 업무기대하는 바를 자세히 적은 스킬을 만들고, 싼 모델(Luna(추정), 6.1 Soul)을 쓴다

Stefano는 감사가 필요한 업무에 표준화된 확장 로그를 붙인다고 했다. 최종 분석만 남기지 않는다. 각 결정이 어떤 데이터와 어떤 논리에서 나왔는지 거슬러 올라갈 수 있게 한다.

금융처럼 규제가 많은 산업에서는 이 추적이 결정적이다. 그래서 산출물을 만들 때 감사 가능한 로그를 함께 저장한다.

16

핵심 정리

  1. OpenAI의 화면은 ChatGPT, ChatGPT Work, Codex다. 금융 서비스 기능은 ChatGPT Work 웹에 있다.
  2. 금융 서비스 판의 세 축은 데이터, 금융 업무에 맞춘 모델, 산출물이다.
  3. 발표자가 말하는 차별점은 데이터를 모델이 읽기 좋게 가공하고 설명을 붙인 것이다. 맞춤 임베딩은 아니다.
  4. 플러그인은 스킬 + MCP 서버 + 도구 설정 + UI다. 기본 플러그인이 80%, 회사가 20%를 채운다.
  5. 플러그인 확장은 화면 자체를 맞춤으로 바꾼다. 발표 당시에는 데스크톱에서만 됐다.
  6. 사내 개발자는 별도 앱 대신 이미 승인된 화면에 플러그인을 배포한다. 로그인, 권한, 승인을 다시 만들지 않는다.
  7. 비용은 오케스트레이터만 비싼 모델, 하위 에이전트는 싼 모델과 좋은 스킬로 줄인다. 효과는 평가로 직접 잰다.
  8. 스킬은 핵심 역량만 남기고 함께 쓴다. 새 모델이 나오면 다시 테스트한다.
  9. Codex 하네스는 오픈소스고, 압축 모드가 몇 시간짜리 작업을 가능하게 한다. 보안은 관리형 정책 파일로 통제한다.
  10. 평가는 단순하게 시작하고 예/아니오로 묻는다. 규제 업무에는 결정마다 근거 로그를 남긴다.

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1OpenAI가 나눈 세 화면과 각각의 주 사용자는?
ChatGPT(누구나), ChatGPT Work(지식 노동자, 에이전트와 플러그인), Codex(엔지니어링 일). 금융 서비스 기능은 ChatGPT Work 웹에만 있다.
Q2ChatGPT for Financial Services의 세 축은?
내장·외부 데이터, 금융 업무에 맞춘 모델, 발표 자료와 스프레드시트 같은 산출물 생성.
Q3발표자가 꼽은 데이터의 차별점은? 맞춤 임베딩인가?
원본을 그대로 넘기지 않고, 데이터셋마다 전처리와 설명, 전용 도구 호출을 붙였다. 맞춤 임베딩은 아니라고 답했다.
Q4플러그인은 무엇으로 이루어지고, 스킬과 무엇이 다른가?
스킬 + MCP 서버 + 도구 설정 + UI 컴포넌트를 묶은 패키지다. 스킬은 재사용하는 지시와 지식이라 사내 시스템 연결과 인증은 못 한다.
Q5플러그인 확장은 무엇을 바꾸고, 발표 당시 어디서 쓸 수 있었나?
아이콘, 설정, 내비게이션 같은 화면 일부를 바꾸고, 대화 맥락에 맞춰 맞춤 UI를 띄운다. 데스크톱 앱에서만 됐다.
Q6별도 앱 대신 플러그인을 권하는 이유는?
로그인, 접근 권한, 보안 승인을 새로 만들지 않고 이미 승인된 화면에 끼운다. 배포가 빨라지고, 사용자는 일하던 곳을 떠나지 않는다.
Q7다중 에이전트 비용을 줄이는 구성은?
오케스트레이터만 가장 강한 모델로 두고, 하위 에이전트는 싼 모델과 잘 쓴 스킬로 돌린다. 발표자는 결과의 약 95%가 나온다고 했고, 평가로 직접 확인하라고 했다.
Q8팀에 스킬이 너무 많으면 생기는 문제와 권고는?
관리가 어렵고 처리도 느려진다. 핵심 역량만 스킬로 남기고, 새 모델이 나오면 다시 테스트한다.
Q9딥리서치 에이전트에서 비평 에이전트가 하는 일은?
하위 에이전트들의 결과를 모아 서로 충돌하는지 찾는다. 충돌하면 새 하위 에이전트를 띄워 조사시키고, 보고서가 품질 기준을 넘을 때까지 반복한다.
Q10압축 모드는 무엇이고 왜 중요한가?
보조 모델이 대화 맥락에서 중복을 빼 크기를 한도 안에 유지한다. 2시간짜리 논문 재현 같은 긴 작업이 가능해진다.
Q11평가가 막히는 이유와 두 가지 요령은?
주제 전문가의 업무 지식과 엔지니어의 데이터셋 작업이 만나야 해서 어렵다. 요령은 단순하게 시작하기(LLM 채점부터 하지 않기), 1~5점 대신 예/아니오로 묻기.
Q12goal 모드에 주는 목표는 어떤 형태가 좋은가?
숫자 점수. 예를 들어 평가 데이터셋 점수를 최대로 올리도록 프롬프트를 조정하라고 시킨다.
Q13규제 업무에서 산출물과 함께 남기는 것은?
각 결정이 어떤 데이터와 어떤 논리에서 나왔는지 거슬러 올라갈 수 있는 감사 로그.
