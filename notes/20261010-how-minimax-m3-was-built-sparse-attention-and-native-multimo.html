MiniMax M3를 만든 두 가지 선택

MiniMax는 100만 토큰 문맥을 감당하려고 흔히 쓰는 GQA 구조에 맞춘 희소 어텐션을 새로 설계했다. 그리고 텍스트 성능을 지키려고 이미지 학습을 첫 단계부터 섞었다. 두 결정 모두 알고리즘만이 아니라 GPU와 학습 과정의 제약에서 출발했다.

원본 영상: How MiniMax M3 Was Built: Sparse Attention and Native Multimodality 발표: Olive Song (MiniMax 강화학습 연구원)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 뭉개진 용어는 확실한 것만 바로잡았다. soda는 SOTA로, large head beam은 large head dimension으로, top key는 top-k로 고쳤다. 발표 화면의 그림은 자막에 없어서 발표자의 설명만 옮겼다. mm:ss는 영상 위치다.

3분 요약
  1. M3는 가중치를 공개한 모델이다. 발표자는 최상위 코딩·에이전트 능력, 100만 토큰 문맥, 처음부터 멀티모달을 함께 갖춘 첫 오픈 웨이트 모델이라고 소개한다.
  2. 긴 문맥은 MSA(MiniMax Sparse Attention)로 감당한다. 가벼운 인덱스 브랜치가 중요한 블록을 고르고, 메인 브랜치는 그 블록만 본다. full attention보다 prefill 9배, decode 15배 빠르다고 한다.
  3. DeepSeek의 DSA는 MQA 구조에 맞춘 설계다. 흔히 쓰는 GQA에 그대로 얹으면 헤드 다양성이 사라지고, GPU 메모리 읽기가 쪼개지고, top-k 계산이 무겁다.
  4. MSA의 해법은 세 가지다. KV 헤드마다 따로 고르기, 토큰 대신 블록으로 고르기, 전용 커널. 알고리즘과 인프라를 함께 설계한 결과다.
  5. 멀티모달을 사전학습 뒤에 넣으면 텍스트 능력이 떨어졌다. 중간에 넣으면 설정에 따라 결과가 흔들렸다. 첫 단계부터 넣으니 텍스트 성능이 거의 떨어지지 않았다.
  6. 처음부터 학습한 모델은 어텐션 맵에서 텍스트와 이미지가 고르게 섞여 있다. 나중에 넣은 모델은 텍스트가 이미지를 거의 보지 않는다.
  7. 비전 쪽에서는 ViT 안에 여러 프레임을 함께 보는 3D 어텐션이 효과가 컸다. 4프레임이 성능과 효율의 균형점이었다.
01

M3의 세 기둥 01:00

MiniMax는 언어 모델 말고도 음성 모델, 영상 생성 모델, 코딩 에이전트 모델을 내 왔다. 발표자는 여러 모달리티modality를 함께 다루는 몇 안 되는 연구소라고 소개한다. 모달리티는 텍스트, 이미지, 음성처럼 정보의 종류를 말한다.

M3는 가중치를 공개한 오픈 웨이트open weight 모델이다. 발표자는 아래 세 가지를 한 모델에 담은 첫 오픈 웨이트 모델이라고 말한다.

기둥내용발표자가 든 근거
코딩·에이전트작업을 스스로 쪼개고, 코딩 에이전트 안에서 일한다지금 하는 코딩 일의 90%를 대신할 수 있다
100만 토큰 문맥코드베이스 전체를 한 번에 넣을 수 있다MSA 덕분에 full attention보다 prefill 9배, decode 15배 빠르다
처음부터 멀티모달학습 첫 단계부터 시각 이해와 언어 생성을 함께 배웠다화면을 보고 컴퓨터를 조작하는 에이전트computer use 같은 응용으로 이어진다

prefill은 입력 전체를 처음 한 번에 읽어 들이는 단계다. decode는 답을 한 토큰씩 만들어 내는 단계다. 긴 문서를 넣는 일은 prefill이, 긴 답을 쓰는 일은 decode가 시간을 좌우한다.

발표자는 MiniMax 소속이다. M3의 성능, 속도, "코딩 일의 90%" 같은 말은 자사 모델에 대한 주장이니 그 점을 감안해 읽자. 이 발표에는 다른 모델과 비교한 벤치마크 수치가 나오지 않는다.

02

희소 어텐션의 기본 구조 02:30

어텐션attention은 토큰 하나가 다른 토큰들 가운데 어디를 얼마나 참고할지 정하는 계산이다. full attention은 모든 토큰을 빠짐없이 본다. 문맥이 100만 토큰이면 참고할 상대도 100만 개다. 계산과 메모리 읽기가 그만큼 늘어난다.

희소 어텐션sparse attention은 중요한 일부만 골라서 본다. 두꺼운 책에서 답을 찾을 때 목차로 관련 장을 먼저 고르고 그 장만 정독하는 것과 비슷하다.

설계 원칙 02:40 구조가 단순할수록 규모를 키울 때 더 잘 된다. 발표자는 설계 전체에서 이 원칙을 따랐다고 말한다. 목표는 늘 더 깔끔하고 단순한 구조였다.

두 갈래로 나뉜다 02:50

인덱스 브랜치 · index branch
  • 가벼운 full attention을 돌린다
  • query 헤드 4개와 key 헤드 1개만 쓴다
  • 메인 브랜치의 어텐션 점수와 비슷해지도록 KL loss로 학습한다

역할: 메인 브랜치가 어디를 중요하게 볼지 미리 흉내 내서, 점수가 높을 곳을 찾는다.

메인 브랜치 · sparse branch
  • 모든 토큰을 보지 않는다
  • 인덱스 브랜치가 고른 블록의 key와 value만 가져온다
  • 그 일부로만 어텐션을 계산한다

역할: 실제 어텐션 계산. 볼 범위가 줄어든 만큼 빨라진다.

  1. 인덱스 브랜치가 모든 토큰에 싸게 점수를 매긴다.
  2. 점수가 높은 블록을 고른다.
  3. 메인 브랜치가 그 블록의 key와 value로만 어텐션을 계산한다.

발표자는 "메인 브랜치"와 "희소 브랜치"를 같은 뜻으로 섞어 썼다.

03

DSA를 그대로 쓰지 않은 이유 04:00

발표자가 가장 강조한 점은 이 설계가 알고리즘만 보고 나온 게 아니라는 것이다. 알고리즘과 인프라를 함께 설계했다co-design.

출발점은 DeepSeek의 희소 어텐션인 DSADeepSeek Sparse Attention다. 발표자는 DSA를 강한 설계로 평가한다. 다만 DeepSeek 자체 구조에 맞춰 최적화돼 있다고 본다. 특히 MQA와 큰 head 차원의 조합에 맞춰져 있다.

MQAGQA
원어Multi-Query AttentionGrouped-Query Attention
KV 헤드1개를 모든 query 헤드가 함께 쓴다여러 개. query 헤드를 몇 묶음으로 나눠 묶음마다 하나씩 쓴다
발표의 예1 × 5124 × 128
발표에서의 위치DSA가 맞춰진 DeepSeek 구조발표자가 "더 흔히 쓰는" 구조로 꼽은 것. M3가 택한 쪽

GQA에 DSA를 그대로 얹으면 구현과 인프라 쪽에서 문제가 여럿 생긴다. 그래서 MiniMax는 기존 설계를 빌려 오는 대신, GQA와 실제 시스템 효율이라는 제약 안에서 구조를 다시 생각했다.

04

GQA에서 생기는 세 문제 05:00

① 알고리즘 · 헤드 다양성이 사라진다 05:10

GQA는 KV 헤드가 여러 개라서, 묶음마다 서로 다른 곳을 볼 여지가 있다. 그런데 DSA처럼 인덱스 결과를 하나로 합쳐 모든 헤드에 똑같이 쓰면, 모든 KV 헤드가 같은 토큰만 본다.

결과: GQA를 쓰는 이유인 다양성이 상쇄된다.

② 인프라 · 메모리 읽기가 쪼개진다 05:40

GPU는 이어진 데이터를 한 번에 읽을 때 빠르다. MQA는 KV를 큰 덩어리 하나로 볼 수 있다. GQA는 같은 총 차원을 여러 헤드로 나눠 담아서 헤드마다 따로 읽어야 한다.

결과: 메모리 접근 부담이 늘고, 연산 대비 메모리 접근 비율이 떨어진다.

③ 계산 · top-k가 무겁다 06:30

중요한 토큰을 고르려면 인덱스가 아주 많은 토큰 후보 중에서 점수 상위 k개를 뽑아야 한다. top-k는 데이터끼리 의존 관계가 있어서 GPU에서 완전히 병렬로 돌리기 어렵다.

결과: 토큰 단위로 고르면 계산과 결과 합치기 비용이 무시할 수 없을 만큼 커진다.

05

MSA의 해법 06:50

KV 헤드마다 따로 고른다 07:00

DSA를 그대로 쓰면인덱스 결과를 하나로 합친다모든 KV 헤드가 같은 토큰을 본다
→
MSA합치지 않고 헤드마다 따로 고른다헤드마다 다른 토큰 묶음을 봐서 GQA의 다양성이 남는다

토큰 대신 블록으로 고른다 07:40

이전토큰 단위 선택후보가 토큰 수만큼 많다. top-k와 결과 합치기가 무겁다
→
MSA블록 단위 검색여러 토큰을 묶은 블록이 후보라서 후보 수가 크게 준다. 이어진 덩어리를 읽으니 GPU 메모리 접근도 효율적이다

블록 단위 검색block-level retrieval은 문제 ②와 ③을 함께 줄인다. 후보가 줄어 top-k와 합치기 비용이 내려간다. 메모리 접근 효율과 연산 대비 메모리 접근 비율은 올라간다.

발표자는 이렇게 바꿔도 성능이 크게 떨어지지 않는다는 것을 확인했다고 말한다.

성능이 유지된다는 근거 수치는 자막에 나오지 않는다. 화면에 있었을 수도 있지만 이 노트에서는 확인하지 못했다.

학습과 추론용 전용 커널 08:20

커널kernel은 GPU에서 실제로 도는 저수준 계산 코드다. MiniMax는 학습용과 추론용 커널을 따로 설계했다. 발표에서 세부는 다루지 않았다. 발표자는 이 부분이 희소 어텐션을 실제로 빠르게 만드는 시스템 부품이라고 설명한다.

이 설계 덕분에 M3의 학습을 100만 토큰 문맥까지 효율적으로 늘릴 수 있었다.

세 해법은 어디서 나왔나 헤드별 선택은 알고리즘 문제를 고친다. 블록 단위 검색과 전용 커널은 GPU 사정에서 나왔다. 좋은 알고리즘도 하드웨어가 읽기 좋은 모양이 아니면 실제로는 빠르지 않다. 발표자가 말하는 "알고리즘과 인프라를 함께 설계한다"는 이 뜻이다.
06

처음부터 멀티모달 08:50

M3는 학습 첫 스텝부터 텍스트와 시각 데이터를 함께 배웠다. 이를 네이티브 멀티모달native multimodal이라 부른다. 발표자는 지금의 오픈 웨이트 모델들과 매우 다른 방식이라고 말한다.

출발점은 분명했다. 시각-언어 모델VL model만 따로 두면 쓸 곳이 제한적이다. 텍스트 능력과 합쳐야 쓸모가 커지는데, 학습 중에 둘을 합치기가 어렵다.

핵심 질문 09:30 텍스트 핵심 성능을 해치지 않고 멀티모달 능력을 넣을 수 있는가. MiniMax는 이 질문에 답하려고 여러 학습 전략을 큰 규모에서 직접 시험했다.
07

멀티모달을 넣는 세 시점 09:50

사전학습 끝에는 decay 단계가 있다. 학습률을 점점 낮춰 모델을 안정적으로 수렴시키는 구간이다. 세 전략은 멀티모달 데이터를 이 단계 기준으로 언제 넣느냐가 다르다.

전략넣는 시점결과
① CPT 방식 09:50사전학습 decay 단계가 끝난 뒤. 가장 흔한 방법모델이 이미 대부분 수렴한 상태다. 멀티모달 데이터가 배운 텍스트 능력을 방해해 성능이 떨어진다
② 중간 투입 10:10decay 단계 전. 텍스트 토큰을 어느 정도 본 뒤결과가 데이터 혼합 비율과 학습률 같은 설정에 크게 흔들린다. 한 실험에서는 학습률을 낮추면 성능 하락이 줄었지만, 다른 실험에서는 그 결론이 맞지 않았다
③ 처음부터 11:00학습 첫 스텝같은 텍스트 토큰 예산에서 텍스트 성능이 거의 떨어지지 않았다. 최종 채택

②가 탈락한 이유가 하나 더 있다. 대규모 사전학습 도중에는 멀티모달 하나 때문에 학습률 같은 설정을 마음대로 바꿀 수 없다. 설정에 민감한 방법은 큰 규모에서 쓰기 어렵다.

"같은 텍스트 토큰 예산"은 텍스트 데이터 양을 똑같이 맞춘 조건이라는 뜻이다. 텍스트 성능을 비교한 구체적인 수치는 자막에 나오지 않는다.

08

어텐션 맵으로 본 차이 11:30

어텐션 맵attention map은 각 토큰이 다른 토큰을 얼마나 참고하는지 색으로 그린 그림이다. 밝을수록 많이 참고한다. 발표자는 두 방식으로 학습한 모델의 어텐션 맵을 비교했다.

CPT 방식 · 나중에 넣음

텍스트 토큰이 이미지 토큰을 거의 보지 않는다. 그림에서 이미지 토큰 구역이 대부분 어둡다.

해석: 두 모달리티가 제대로 합쳐지지 않았다.

네이티브 · 처음부터

텍스트 토큰과 이미지 토큰 사이에 뚜렷한 경계가 보이지 않는다. 어텐션이 고르게 섞여 있다.

해석: 모델이 처음부터 시각 정보와 텍스트 정보를 자연스럽게 섞는 법을 배웠다.

발표자의 정리는 이렇다. 이 학습 전략은 시각 능력을 덧붙이는 일이 아니다. 가장 강한 텍스트 능력을 지키면서 멀티모달을 모델 안에 녹이는 일이다.

어텐션 맵 그림은 영상 화면에만 있다. 여기서는 발표자의 설명만 옮겼다.

09

비전 구조와 3D 어텐션 12:30

발표자는 전체 구조가 "비교적 표준적"이라고 말한다. 흐름은 세 단계다.

  1. 이미지나 영상을 ViTVision Transformer가 처리해 비주얼 토큰을 만든다.
  2. 텍스트 시퀀스 안에 있던 이미지 자리표시자placeholder를 비주얼 토큰으로 바꿔 끼운다.
  3. 비주얼 임베딩과 텍스트 임베딩을 함께 언어 모델에 넣는다.

ViT 안의 3D 어텐션 13:00

중요한 발견은 ViT 안에 3D 어텐션을 넣으면 시각 이해가 크게 좋아진다는 것이다.

일반 ViT프레임 하나 안에서만 어텐션영상이면 다른 프레임의 패치끼리 ViT 단계에서 직접 만나지 않는다
→
3D 어텐션여러 프레임의 패치가 서로 본다시간 흐름과 프레임 사이 관계를 더 잘 잡는다

효과는 영상에만 그치지 않았다. 일부 이미지 벤치마크에도 이득이 옮겨 갔다. 발표자는 이를 영상 전용 개선이 아니라 시각 표현 전체가 강해진 신호로 본다.

프레임 수는 4개 14:00 3D 어텐션을 프레임 수 제한 없이 늘릴 수는 없다. 시스템 부담과 부하 분산 문제가 생긴다. MiniMax의 실험에서는 4프레임이 성능과 효율의 균형이 가장 좋았다.
10

핵심 정리

  1. M3는 최상위 코딩·에이전트 능력, 100만 토큰 문맥, 처음부터 멀티모달을 함께 갖춘 오픈 웨이트 모델로 소개됐다.
  2. 설계 원칙은 "구조가 단순할수록 더 잘 확장된다"이다.
  3. MSA에서는 가벼운 인덱스 브랜치가 블록을 고르고, 메인 브랜치는 그 블록만 본다. 발표자 수치로 prefill 9배, decode 15배 빠르다.
  4. DSA는 MQA에 맞춘 설계라서 GQA에 그대로 쓰면 맞지 않는다.
  5. 세 문제는 헤드 다양성 상실, 쪼개진 메모리 읽기, 무거운 top-k다.
  6. 세 해법은 헤드별 선택, 블록 단위 검색, 전용 커널이다. 알고리즘과 인프라를 함께 설계했다.
  7. 멀티모달을 사전학습 뒤에 넣으면 텍스트가 떨어졌고, 중간에 넣으면 설정에 따라 결과가 흔들렸다.
  8. 첫 스텝부터 넣으면 같은 텍스트 토큰 예산에서 텍스트 성능이 거의 떨어지지 않았다.
  9. 처음부터 학습한 모델은 어텐션 맵에서 텍스트와 이미지가 섞여 있다. 나중에 넣은 모델은 따로 논다.
  10. ViT 안 3D 어텐션이 시각 이해를 끌어올렸고, 4프레임이 균형점이었다.
11

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1M3의 세 기둥은?
최상위 코딩·에이전트 능력, 100만 토큰 문맥 창, 학습 첫 단계부터의 멀티모달.
Q2인덱스 브랜치는 무엇을 하고, 어떻게 학습하나?
query 헤드 4개, key 헤드 1개로 가벼운 full attention을 돌려 점수가 높을 곳을 찾는다. 메인 브랜치의 어텐션 점수와 비슷해지도록 KL loss로 학습한다.
Q3DSA를 GQA에 그대로 쓰면 알고리즘 쪽에서 무엇을 잃나?
헤드 다양성. 인덱스 결과를 하나로 합쳐 쓰면 모든 KV 헤드가 같은 토큰만 보게 되어 GQA의 다양성이 상쇄된다.
Q41 × 512와 4 × 128은 총 차원이 같은데 왜 GPU에서 차이가 나나?
1 × 512는 한 덩어리로 이어서 읽는다. 4 × 128은 헤드마다 네 번 따로 읽어야 한다. 메모리 접근 부담이 늘고 연산 대비 메모리 접근 비율이 떨어진다.
Q5토큰 단위 top-k가 무거운 이유는?
후보가 토큰 수만큼 많고, top-k는 데이터 의존성이 있어 GPU에서 완전히 병렬화하기 어렵다. 결과를 합치는 비용도 든다.
Q6MSA의 세 해법은?
KV 헤드마다 따로 고르기, 토큰 대신 블록 단위로 검색하기, 학습과 추론용 전용 커널.
Q7블록 단위 검색이 좋아지게 하는 두 가지는?
후보 수가 줄어 top-k와 결과 합치기 비용이 내려간다. 이어진 덩어리를 읽어 메모리 접근 효율과 연산 대비 메모리 접근 비율이 올라간다.
Q8사전학습 decay 뒤에 멀티모달을 넣는 CPT 방식이 실패한 이유는?
모델이 이미 대부분 수렴한 뒤라 멀티모달 데이터가 배운 텍스트 능력을 방해해 성능이 떨어졌다.
Q9decay 전 중간 투입이 채택되지 않은 이유는?
결과가 데이터 혼합과 학습률에 크게 흔들렸고, 한 실험의 결론이 다른 실험에서 맞지 않았다. 대규모 사전학습 중에는 멀티모달 때문에 설정을 마음대로 바꿀 수도 없다.
Q10어텐션 맵에서 CPT 방식과 네이티브 방식은 어떻게 달랐나?
CPT 방식은 텍스트 토큰이 이미지 토큰을 거의 보지 않아 이미지 구역이 어둡다. 네이티브 방식은 두 토큰 사이에 뚜렷한 경계 없이 섞여 있다.
Q11ViT 안 3D 어텐션의 효과와, 프레임 수를 4개로 정한 이유는?
프레임 사이 패치가 서로 직접 보게 되어 시간 흐름과 프레임 간 관계를 더 잘 잡는다. 일부 이미지 벤치마크도 좋아졌다. 프레임을 무한정 늘리면 시스템과 부하 분산 문제가 생겨, 실험상 균형이 가장 좋은 4프레임을 골랐다.
Q12"prefill 9배, decode 15배"를 읽을 때 주의할 점은?
비교 대상은 full attention이다. 어떤 문맥 길이와 하드웨어에서 잰 값인지 발표에 나오지 않았다. 자사 모델에 대한 발표자의 주장이다.

용어 정리

용어뜻
오픈 웨이트Open weight. 학습된 가중치를 공개해 누구나 받아서 돌릴 수 있는 모델
SOTAState of the art. 현재 최고 수준
모달리티Modality. 텍스트, 이미지, 음성처럼 정보의 종류
문맥 창Context window. 모델이 한 번에 받아들일 수 있는 토큰의 양
prefill / decodeprefill은 입력 전체를 처음 한 번에 읽는 단계. decode는 답을 한 토큰씩 만드는 단계
full attention모든 토큰이 다른 모든 토큰을 참고하는 기본 어텐션
희소 어텐션Sparse attention. 중요한 일부 토큰만 골라 참고하는 어텐션
MSA / DSAMiniMax Sparse Attention / DeepSeek Sparse Attention. 각 회사의 희소 어텐션 설계
인덱스 브랜치Index branch. 어디를 볼지 싸게 미리 골라 주는 가벼운 어텐션 갈래
KL loss두 확률 분포가 얼마나 다른지 재는 값을 줄이도록 하는 학습 목표
KV 헤드어텐션에서 key와 value를 만드는 단위. 여러 query 헤드가 나눠 쓸 수 있다
MQA / GQAMQA는 KV 헤드 하나를 모든 query 헤드가 같이 쓴다. GQA는 query 헤드를 묶음으로 나눠 묶음마다 KV 헤드를 하나씩 쓴다
top-k점수가 가장 높은 k개를 뽑는 계산
연산 대비 메모리 접근 비율Compute-to-memory access ratio. 메모리에서 한 번 읽어 온 데이터로 얼마나 많은 계산을 하는지. 높을수록 GPU를 잘 쓴다
커널Kernel. GPU에서 실제로 도는 저수준 계산 코드
decay 단계사전학습 끝에 학습률을 점점 낮춰 모델을 수렴시키는 구간
CPTContinued pre-training. 사전학습을 마친 모델에 새 데이터를 더해 이어서 학습하는 방식
네이티브 멀티모달Native multimodal. 학습 첫 단계부터 여러 모달리티 데이터를 함께 넣어 학습하는 것
어텐션 맵Attention map. 각 토큰이 다른 토큰을 얼마나 참고하는지 색으로 그린 그림
ViTVision Transformer. 이미지를 작은 조각(패치)으로 나눠 트랜스포머로 처리하는 모델
3D 어텐션여러 프레임의 패치가 서로를 참고하게 하는 어텐션. 가로, 세로에 시간 축이 더해진다
부하 분산Load balancing. 계산을 여러 GPU에 고르게 나누는 일
