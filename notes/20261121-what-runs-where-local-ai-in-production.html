무엇을 어디서 돌릴까: 로컬 AI 실전

오픈 모델은 빠르게 따라붙었고, 이제 결과를 가르는 것은 하드웨어와 소프트웨어 최적화다. 발표자는 워크플로에 맞춘 하드웨어, 칩·모델별 추론 엔진, 작은 특화 모델, 로컬에서만 가능한 지속 학습을 다음 흐름으로 본다.

원본 영상: What Runs Where? Local AI in Production 발표: Ahmad Osman (Osmantic 창업자·CEO)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 뭉개진 이름은 확실한 것만 바로잡았고, 나머지는 들린 대로 쓰고 (추정)을 붙였다. 발표자는 슬라이드 170장을 준비했지만 일부만 다뤘다. mm:ss는 영상 위치다.

3분 요약
  1. 오픈소스 AI는 최적화 문제, 로컬 AI는 사용자 경험 문제다. 두 문제를 함께 풀어야 한다.
  2. 오픈 모델과 닫힌 모델의 격차는 어떤 벤치마크를 믿느냐에 따라 "50% 넘게 뒤처짐"부터 "2점 앞섬"까지 갈린다.
  3. 2026년 2월부터 토큰은 사람보다 에이전트가 더 많이 쓴다. 에이전트는 대부분 도구 실행을 기다린다.
  4. 하드웨어는 워크플로로 고른다. 프리필은 연산이, 디코드는 메모리 대역폭이 병목이다. 대역폭이 높아도 소프트웨어가 받쳐 주지 않으면 진다.
  5. 추론 엔진은 모델별·칩별로 최적화해야 한다. 양자화도 층마다 다르게 한다. 파이프라인 전체를 재고 고친다.
  6. 좋은 데이터와 실행 기록이 있으면 작은 특화 모델이 1% 비용으로 프런티어급 품질을 낼 수 있다(발표자가 인용한 Airbnb 사례).
  7. 다음 흐름은 지속 학습이다. 한 사람에게 맞춘 학습은 로컬에서만 가능하다고 발표자는 본다.
01

최적화 문제와 사용자 경험 문제 00:50

발표자는 6월 AI Engineer World's Fair에서 NVIDIA와 함께 로컬 AI 서밋을 열었다. 그때 지금의 로컬 AI가 "1990년대의 리눅스" 같다고 말했다. 쓸 수는 있지만 생태계와 인프라가 아직 자리 잡지 않은 단계라는 뜻이다.

그 뒤로 변화가 보이기 시작했다. 여러 GPU 연산을 하나로 합친 메가 커널 mega kernel이 나왔다. 모델을 실제로 돌려 답을 만드는 소프트웨어인 추론 엔진 inference engine도 새로 나왔다. 모델별, 칩별, 워크플로별로 최적화하려는 사람이 늘었다. 발표자는 이것이 맞는 방향이라고 본다.

여기서 오픈소스 AI는 가중치를 공개해 누구나 내려받아 돌릴 수 있는 모델 open-weight model과 그 생태계를 말한다.

발표 전체를 꿰는 한 줄 01:30 오픈소스 AI는 최적화 문제다. 로컬 AI는 사용자 경험 문제다. 두 문제는 동시에 풀어야 한다.

클라우드 없이 만든 게임 01:40

발표자 회사는 NVIDIA와 함께 RTX Spark용 최적화 추론 엔진을 내놓았다. 시연용 게임은 Windows의 RTX Spark에서 만들었다. 클라우드는 쓰지 않았다. 모델에 도구와 작업 순서를 붙여 주는 실행 틀인 하네스 harness도 회사가 만든 Portal을 썼다.

Best Buy 출시 행사에서는 이 게임을 해 보려는 사람이 몰렸다. 발표자는 이제 일반인도 로컬 AI에 관심을 보인다고 말한다.

발표자 회사는 NVIDIA와 이 제품을 함께 출시했다. 뒤에 나오는 하드웨어 추천은 이 관계를 감안해 읽자.

로컬 모델이 클라우드보다 빨랐다 02:40

발표자는 두 답변을 보여 주고 어느 쪽이 로컬 모델인지 물었다. 하나는 로컬에서 돌린 Qwen 3.6 27B, 다른 하나는 OpenAI 클라우드의 GPT 5.5였다. 답의 내용은 비슷했다. 속도는 로컬이 빨랐다.

04

토큰은 이제 에이전트가 쓴다 04:00

발표자가 보여 준 그래프에 따르면, AI가 해낼 수 있는 긴 작업의 길이가 2023년 3월 이후 4개월마다 두 배가 되고 있다. 작업 길이는 사람이 하면 걸리는 시간으로 잰다. 속도가 줄어드는 기미는 없다.

OpenRouter의 2026년 10월 데이터도 인용했다. OpenRouter는 여러 회사의 모델 API를 한곳에서 파는 중개 서비스다. 이곳에서 처리되는 토큰은 조 단위다. 2026년 2월 이후로는 사람보다 에이전트가 만드는 토큰이 더 많다. 발표자는 사람이 다시 앞서는 일은 없을 것이라고 본다. 04:40

토큰과 돈은 다른 곳으로 간다 06:20

토큰 기준

OpenRouter에서 가장 많은 토큰을 쓴 쪽은 DeepSeek V4.1 Flash 같은 오픈 모델이다. 대부분의 작업이 여기로 간다.

돈 기준

가장 많은 돈이 쓰인 모델은 Opus 5.5다. 돈은 주로 닫힌 모델로 간다.

많이 쓰이는 모델과 많이 버는 모델이 다르다. 양으로는 오픈 모델이 이미 주류다.

에이전트는 대부분 기다린다 07:10

에이전트가 일하는 시간의 대부분은 토큰을 만드는 시간이 아니다. 셸 명령을 실행하고 결과가 돌아오기를 기다리는 시간이다. 초당 토큰 수보다 이 처리 시간이 더 큰 병목이다.

그래서 발표자는 RTX 3090 한 장만 있어도 쓸모가 크다고 말한다. 새 칩과 더 비동기적인 소프트웨어가 필요하다고 보는 이유도 여기에 있다.

05

작고 특화된 모델에 건다 05:50

발표자는 2025년 3월부터 "미래는 작고 특화된 모델"이라고 말해 왔다. 3년 안에 10억(1B) 파라미터 모델이 Opus 5.5를 이길 것이라고 예측한다.

Opus 5.5도 특화 모델이다 09:00

발표자는 Opus 5.5가 Fable 5.2보다 싸면서도 대부분의 사람이 신경 쓰는 일에서는 더 낫다고 본다. 코딩에 맞춰 강화학습 reinforcement learning, RL을 극단적으로 많이 했기 때문이라는 해석이다.

그래서 발표자는 Opus 5.5를 코드 작성과 실행에는 믿는다. 문제 해결에는 믿지 않는다. Fable이나 Astra(추정)에 비하면 Opus 5.5도 "작고 특화된 모델"이라고 부른다.

발표자와 Osmantic 09:50

발표자 Ahmad Osman은 이집트 카이로 출신이고 Osmantic의 창업자이자 CEO다. 누군가 "Osman이 Open Source Man의 줄임말이냐"고 물어 왔고, 발표자는 그 뜻을 받아들이기로 했다는 농담을 했다.

회사의 전제는 이렇다. 모든 단계에 프런티어급 지능이 필요하지는 않다. 많은 일은 작고 특화된 모델로 해낼 수 있다.

  • RTX Pro 6000 두 장: 사진 태깅, 영상과 음성 처리를 맡았다

밤 9시에 시작해 새벽 3시에 끝났다. 전에는 전문가를 고용해야 했던 일이다. 발표자는 3년 안에 작은 특화 모델이 집에서 이 일을 할 것이라고 본다.

Osmantic은 "작고 특화된 모델이면 충분하다"는 전제로 세운 회사다. 이 주장은 회사의 사업 방향과 맞닿아 있으니 감안해 읽자.

06

클라우드는 남의 지하실 12:30

클라우드는 결국 다른 사람의 지하실이다.발표자의 표현을 옮김 (원문: "the cloud is someone else's basement")

Fable 5.2든 Qwen이든, 모든 모델은 어딘가의 기계에서 돈다. 책상 밑 기계든 남의 데이터센터든, 누군가에게는 로컬이다. 발표자는 이 사실을 받아들이자고 말한다.

"프런티어 모델이니 클라우드를 써야 한다"는 말에도 되묻는다. 어떤 벤치마크로 본 프런티어인가. 어떤 작업에서의 프런티어인가. 앞에서 본 것처럼 벤치마크끼리도 크게 엇갈린다.

회사의 하네스 Portal에는 구름 이모지를 붙였다. 이제 집에도 클라우드가 있다는 뜻이다. 코드명은 발표자 고향에서 딴 Cairo다.

아직 못 푼 문제도 있다. 긴 문맥 long context을 제대로 다루는 방법은 아직 없다. 메모리도 여전히 큰 문제다.

지하실의 RTX 3090 14장 14:10

발표자의 지하실에는 RTX 3090 14장이 있다. 이 장비로도 DeepSeek R1(671B)은 겨우 올라갔다. 발표자는 6시간 생방송을 하며 이 모델을 DDR4 메모리에 올려 돌렸다.

  • 속도는 초당 약 8토큰이었다.
  • 문맥이 1만 6천 토큰쯤 되자 매우 느려졌다.
  • 그래도 내 기계에서 모델이 단계별로 따져 보는 추론 reasoning을 처음 봤다.

몇 달 뒤 GPT-OSS 120B가 나왔다. 크기는 훨씬 작은데 할 수 있는 일은 더 많았다. 오픈 모델이 따라붙는 속도가 그만큼 빠르다.

발표자는 2025년 초에 이미 작은 모델로 집에서 스크린샷 정리 도구를 만들었다. 모델은 그때도 충분히 쓸 만했다. 다만 그 위에 시스템 엔지니어링을 얹으려는 사람이 없었다. 15:10

DeepSeek R1은 2025년 1월, GPT-OSS는 2025년 8월에 공개됐다. 발표의 "2025년 2월"과 "4개월 뒤"는 기억에 기댄 말로 보인다.

07

양자화는 층마다 다르게 15:50

양자화 quantization는 모델의 숫자를 더 적은 비트로 저장해 메모리를 줄이는 기술이다. 이 분야가 빠르게 좋아지고 있다.

  • NVIDIA의 4비트 숫자 형식인 NVFP4 관련 작업이 많아졌다.
  • NVIDIA가 RTX Pro 6000 전용 추론 엔진을 새로 냈다.
  • 같은 Blackwell 세대라도 RTX Pro 6000과 데이터센터용 B200·B300은 다른 칩이다. 그래서 집이나 프로슈머 장비용 최적화가 따로 나오고 있다.

양자화 인지 학습 16:30

발표자는 양자화 인지 학습 quantization-aware training, QAT을 이렇게 설명했다. 학습하면서 모델이 스스로를 다시 평가한다. 많이 쓰는 층은 높은 정밀도로 남기고, 덜 쓰는 층을 압축한다.

보통 QAT는 학습 중에 양자화된 상태를 흉내 내, 모델이 낮은 정밀도에 미리 적응하게 하는 방법을 말한다. 층마다 정밀도를 달리 두는 설명은 바로 아래의 동적 양자화에 더 가깝다.

Q1발표자가 오픈소스 AI와 로컬 AI를 각각 무슨 문제라고 했나?
오픈소스 AI는 최적화 문제, 로컬 AI는 사용자 경험 문제다. 두 문제는 동시에 풀어야 한다.
Q2오픈·닫힌 모델의 격차가 벤치마크마다 다르게 보이는 예는?
HLE 계열 지표에서는 닫힌 모델이 50% 넘게 앞선다. Terminal Bench에서는 오픈 모델이 2점 앞선다. 그래서 공개 벤치마크보다 내 작업으로 재야 한다.
Q3에이전트 작업에서 RTX 3090 한 장도 쓸모가 큰 이유는?
에이전트는 대부분 셸 명령과 도구 실행 결과를 기다린다. 초당 토큰 수보다 처리 대기가 더 큰 병목이다.
Q4프리필과 디코드는 각각 무엇이 병목인가?
프리필은 연산, 디코드는 메모리 대역폭이 병목이다. 프롬프트가 길면 첫 토큰이 늦게 나온다.
Q5dense 27B 모델이 DGX Spark에서 느린 이유는?
토큰마다 27B 파라미터를 모두 읽어야 하는데 DGX Spark의 대역폭(273GB/s)이 낮다. 토큰마다 일부만 쓰는 MoE 모델이 유리하다.
Q6대역폭이 4배 넘게 높은 M5가 DGX Spark 두 대에 진 이유를 발표자는 무엇으로 봤나?
소프트웨어다. Mac 쪽은 AI용 소프트웨어 최적화가 부족하고, NVIDIA의 CUDA 생태계가 훨씬 앞서 있다.
Q7요청 50개를 동시에 보낸 실험에서 드러난 것은?
RTX Pro 6000은 합계 초당 약 1,300토큰을 냈고, 다른 기계는 요청을 하나씩 처리했다. 동시 처리를 지원하는 엔진이 없는 소프트웨어 문제다. 에이전트를 병렬로 돌리는 시대에는 이 차이가 크다.
Q8모든 층을 4비트로 양자화하면 어떻게 되나? 대안은?
모델이 망가질 수 있다. 대안은 층별 사용 정도를 측정해 16비트, 8비트, 1비트처럼 다르게 압축하는 동적 양자화다.
Q9토크나이저를 100배 빠르게 했는데 전체는 1.1%만 빨라졌다. 교훈은?
한 단계가 빨라져도 전체는 그 단계의 비중만큼만 빨라진다. LLM 파이프라인은 시스템 엔지니어링이므로 전체를 재고 모든 단계를 최적화해야 한다.
Q10친구의 로컬 모델이 GPU 팬 RGB 색 바꾸기에 실패한 이유는?
검색 도구가 없었다. 모델은 학습 이후에 나온 도구와 하드웨어 정보를 몰랐다. 검색을 붙이자 같은 모델이 성공했다.
Q11발표자가 인용한 Airbnb 사례와, 특화 모델을 만드는 순서는?
2B 모델로 프런티어급 품질을 1% 비용에 냈다. 순서는 프런티어 에이전트의 트레이스 수집 → 평가 파이프라인 → 합성 데이터 파이프라인 → 강화학습이다.
Q12Qwen 3.6 27B가 Qwen 3.5 397B MoE를 이긴 일은 무엇을 보여 주나?
파라미터당 지능 밀도가 빠르게 오른다는 것이다. 약 15분의 1 메모리로 더 큰 모델을 이겼다. 그래서 하드웨어는 내년에 돌릴 모델을 기준으로 계획해야 한다.
Q13지속 학습이 로컬에서 일어나야 한다고 보는 이유와, 발표자가 꼽은 세 재료는?
큰 제공자는 전체 사용자 평균에 맞춰 학습할 뿐, 한 사람용 모델을 학습시키고 호스팅할 수 없다. 재료는 Engram, 결정 모델, 가중치 편집이다.

용어 정리

용어뜻
로컬 AI내 기계나 내가 통제하는 기계에서 모델을 돌리는 것
오픈 모델Open-weight model. 가중치를 공개해 누구나 내려받아 돌릴 수 있는 모델
추론 엔진Inference engine. 모델을 실제로 돌려 토큰을 만드는 소프트웨어. 예: llama.cpp, vLLM
하네스모델에 도구, 작업 순서, 규칙을 붙여 주는 실행 틀
커널 / 메가 커널GPU에서 도는 연산 프로그램 / 여러 연산을 하나로 합쳐 오가는 비용을 줄인 커널
프리필Prefill. 입력 프롬프트 전체를 처리해 KV 캐시를 만드는 단계. 연산이 병목
디코드Decode. 출력 토큰을 하나씩 만드는 단계. 메모리 대역폭이 병목
TTFTTime to first token. 요청 후 첫 토큰이 나오기까지 걸린 시간
KV 캐시이미 처리한 토큰의 중간 계산값(키와 값)을 저장해 두는 메모리
메모리 대역폭1초에 메모리에서 읽을 수 있는 데이터 양. 단위는 GB/s
배칭Batching. 여러 요청을 묶어 한꺼번에 처리하는 것
dense 모델토큰마다 모든 파라미터를 쓰는 모델
MoEMixture of Experts. 여러 전문가 중 일부만 토큰마다 골라 쓰는 모델
활성 파라미터Active parameters. MoE에서 토큰 하나를 만들 때 실제로 쓰는 파라미터 수
양자화Quantization. 모델의 숫자를 적은 비트로 저장해 메모리를 줄이는 것
QATQuantization-aware training. 학습 중에 양자화를 미리 겪게 해 낮은 정밀도에 강하게 만드는 방법
동적 양자화Dynamic quantization. 층마다, 또는 실행 중에 정밀도를 다르게 정하는 양자화
NVFP4NVIDIA의 4비트 부동소수점 숫자 형식
CUDANVIDIA GPU용 프로그래밍 플랫폼
추측 디코딩Speculative decoding. 작은 모델이 토큰을 미리 써 보고 큰 모델이 한 번에 검증해 속도를 높이는 방법
트레이스Trace. 에이전트가 실행되며 한 단계씩 무엇을 했는지 남긴 기록
합성 데이터Synthetic data. 모델을 써서 만들어 낸 학습용 데이터
강화학습Reinforcement learning, RL. 결과에 보상을 주며 모델을 훈련하는 방법
증류Distillation. 큰 선생 모델의 출력으로 작은 학생 모델을 가르치는 것
분포 밖 과제Out-of-distribution. 학습 데이터에서 거의 보지 못한 종류의 과제
지속 학습Continual learning. 모델이 배포된 뒤에도 쓰이면서 계속 배우는 것
EngramDeepSeek이 공개한 조회형 메모리 연구. 모델이 SSD나 RAM의 표에서 정보를 꺼내 쓴다(발표자의 설명)
보상 해킹Reward hacking. 모델이 과제를 제대로 풀지 않고 채점의 빈틈을 노려 점수만 올리는 것
RSIRecursive self-improvement. AI가 AI 연구를 하며 스스로를 계속 개선하는 루프
