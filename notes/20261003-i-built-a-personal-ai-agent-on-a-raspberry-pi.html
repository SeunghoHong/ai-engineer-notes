라즈베리 파이로 만든 개인 에이전트

발표자는 옷장에 있던 Raspberry Pi 4B에 작은 개인 AI 에이전트를 올렸다. 생각은 클라우드의 Claude가 하고, Pi는 메시지와 음성을 받아 기억을 그래프 데이터베이스에 쌓는다.

원본 영상: I Built a Personal AI Agent on a Raspberry Pi 발표: Jeremy Adams (Neo4j)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 발표의 절반은 무대 위 라이브 데모라서, 화면에만 나온 쿼리와 그래프는 발표자가 말로 설명한 만큼만 옮겼다. 자막에서 뭉개진 이름은 확실한 것만 바로잡았고, 확실하지 않은 것에는 "(추정)"을 붙였다. mm:ss는 영상 위치다.

3분 요약
  1. 발표자는 개인 에이전트를 노트북에 두기 싫었다. 싸고, 열려 있고, 고쳐 쓸 수 있고, 속을 이해할 수 있는 것을 원해서 옷장의 Raspberry Pi 4B를 꺼냈다.
  2. OpenClaw 대신 NanoClaw를 골랐다. 소스 파일 15개 정도로 작고, 에이전트를 Docker 컨테이너 안에 가둬 돌린다.
  3. Pi는 추론을 하지 않는다. WhatsApp으로 받은 메시지를 클라우드의 Claude에 넘기고, MCP 서버로 Neo4j 그래프 DB를 조회한다.
  4. 기억은 POLE+O로 저장한다. 사람, 사물, 장소, 사건, 조직을 노드로 두고 관계로 잇는다. 이 기억 스킬도 비행기 안에서 에이전트에게 시켜 만들었다.
  5. USB 마이크와 버튼을 달아 음성을 받아쓰게 했다. 그리고 행사장 부스를 돌며 각 부스의 메시지를 녹음했다.
  6. 행사장 Wi-Fi는 믿지 않았다. 오프라인이면 정규식으로 부스 번호를 뽑아 Pi 안의 Neo4j에 저장한다.
  7. 모은 메모는 나중에 클라우드로 올려 주제 노드로 묶었다. WhatsApp 대화 전체도 기억으로 정리해, 같은 에이전트가 MCP로 다시 꺼내 쓴다.
01

목에 건 Raspberry Pi 02:00

발표는 라이브 데모로 시작한다. 발표자는 목에 건 Raspberry Pi에 무대 위에서 부품을 하나씩 꽂았다.

부품하는 일
Raspberry Pi 4B에이전트가 도는 본체. 최신 모델은 아니지만 쓸 만하다
무선 마이크와 USB 수신기에이전트에게 말을 건다
HDMI 비디오 캡처 장치Pi 화면을 노트북의 QuickTime으로 받아 청중에게 보여 준다
배터리몸에 걸고 다닐 수 있게 전원을 댄다
블루투스 키보드Pi를 직접 조작한다

발표자는 이 보드에서 오랫동안 32비트 운영체제를 썼다. 64비트 ARM을 돌릴 수 있다는 건 나중에야 알았다. 모든 걸 돌릴 수는 없지만, 꽤 많은 걸 돌릴 수 있다.

Pi 안에는 세 가지가 들어 있다. 개인 에이전트 NanoClaw, 컨테이너를 돌리는 Docker, 그리고 Docker로 띄운 Neo4j 데이터베이스다.

03

OpenClaw 대신 NanoClaw 08:00

발표자는 OpenClaw를 쓰지 않았다. 취향에 더 맞는 NanoClaw를 찾았다.

기준NanoClaw
크기소스 파일 15개 정도. 코드 줄 수가 적다
격리에이전트 프로세스를 Docker 컨테이너 안에서 돌린다. 에이전트가 시스템을 함부로 건드리지 못한다
바탕Claude Agent SDK 위에 만들었다
고쳐 쓰기프로젝트가 직접 고쳐 쓰라고 권한다. Claude Code와 스킬로 수정한다
대화 창구Telegram 등도 된다. 발표자는 휴대폰에 이미 있던 WhatsApp을 골랐다

Linux에서 돌고, 이미 익숙한 Docker를 쓴다는 점도 발표자에게는 중요했다.

04

두뇌는 클라우드에 08:50

처음 구조는 단순했다.

  1. iPhone이나 MacBook의 WhatsApp으로 메시지를 보낸다.
  2. 메시지는 WhatsApp 클라우드에 올라간다.
  3. Pi의 NanoClaw가 그 메시지를 끌어온다. 처음 한 번 자격 증명을 받아 등록해 두면 된다.
  4. NanoClaw는 Claude Agent SDK로 클라우드의 Claude에 일을 맡긴다.
  5. 답이 WhatsApp으로 돌아온다.
Pi는 생각하지 않는다 Pi에서는 LLM 추론inference이 전혀 일어나지 않는다. 생각은 모두 클라우드의 Claude가 한다. Pi가 맡는 일은 메시지 받기, 도구 연결, 데이터 저장이다.
큰 두뇌는 있다. 다만 선 너머 클라우드에 있다.발표자의 표현을 옮김
05

그래프 101과 첫 질문 09:30

클라우드에는 Neo4j 데이터베이스도 있다. Neo4j는 데이터를 그래프로 저장하는 그래프 데이터베이스다.

그래프는 두 가지로 이뤄진다. 동그라미로 그리는 노드node, 그리고 노드 사이를 잇는 관계relationship, edge다. 발표자가 든 예는 사람 노드 2개와 영화 노드 1개다.

시작 노드관계끝 노드
Tom Hanks (사람)출연했다Forrest Gump (영화)
Robert Zemeckis (사람)감독했다Forrest Gump (영화)

WhatsApp으로 DB에 묻기 10:00

발표자는 영화 데이터를 DB에 채웠다. 그리고 WhatsApp으로 "Tom Hanks가 출연한 영화를 알려 줘"라고 물었다.

에이전트는 MCP 서버로 Neo4j에 접속했다. MCPModel Context Protocol는 에이전트가 외부 도구와 데이터에 붙는 표준 방식이다.

첫 답은 "설정이 깨져 있다"였다. 발표자가 Pi에서 인증을 고치자 영화 목록이 돌아왔다. 데이터는 DB에서 나와 Claude Agent SDK를 거쳐 답이 되고, WhatsApp으로 돌아왔다.

예시: 이 질문을 Neo4j의 질의 언어 Cypher로 쓰면 MATCH (p:Person {name: 'Tom Hanks'})-[:ACTED_IN]->(m:Movie) RETURN m.title 정도가 된다. 발표 화면에 나온 쿼리는 아니다.

비행기에서도 된다 10:40 발표자가 탄 비행기에서는 Wi-Fi를 결제하지 않아도 메시지 앱이 됐다. 그래서 비행 중에도 WhatsApp으로 에이전트와 대화할 수 있었다. 다음 단계인 기억도 비행기 안에서 만들었다.
06

POLE+O로 만든 기억 11:00

비행기 안에서 다음 질문이 떠올랐다. 에이전트에게 기억memory을 붙일 수 있을까? 원하는 모습이 뚜렷하지는 않았다. 마침 블로그 글에서 POLE+O라는 모델을 읽은 참이었다.

글자원어뜻
PPerson사람
OObject사물
LLocation장소
EEvent사건
+OOrganization조직

발표자는 이 모델이 유럽의 경찰 수사에서 나왔다고 소개했다. 형사 드라마에서 벽에 사진을 붙이고 실로 잇는 장면을 떠올리면 된다. 그것도 그래프다.

발표자는 WhatsApp으로 에이전트에게 POLE+O로 기억 시스템을 만들 수 있냐고 물었다. 에이전트는 그 자리에서 기억 스킬skill을 썼다. 저장 위치는 재부팅해도 지워지지 않는 마운트 지점mount point이라고 했다.

스키마는 단순하다. 기억 노드가 있고, 거기에 관련된 것들이 연결된다. 발표자는 농담으로 "아주 고급 스키마"라고 불렀다. 시기로는 Obsidian보다 뒤, Karpathy의 위키 방식(추정)보다 앞이라고 했다.

데모: 기억 그래프 12:10

발표자는 DevRel 행사를 다니며 에이전트에게 다닌 곳을 기록하게 했다. 무대에서는 Neo4j Aura에 접속해 그 기억들을 연결된 그래프로 띄웠다.

  • Menlo Park의 Snowflake 사무실에 가서 누군가와 이야기한 기억
  • Menlo Park는 따로 장소 노드로 있다
  • 어느 AI 밋업 행사
  • Rebecca, Jeremy 같은 사람 노드

발표자도 이 DB가 잡동사니 창고 같다고 인정했다. 그래도 기억을 저장하는 용도로는 확실히 쓸 수 있었다.

07

마이크와 버튼 달기 13:20

이번에는 Pi 자체에 무엇을 더 올릴 수 있을지 생각했다.

어떤 사람은 창밖에 마이크를 두고 뒷마당 새소리를 녹음했다. 그리고 BirdNET 모델로 어떤 새인지 알아냈다. 발표자는 이걸 보고 음성 받아쓰기voice-to-text를 떠올렸다.

그래서 Pi에 USB 마이크를 달고 받아쓰기를 붙였다. Pi의 핀에 직접 연결한 버튼도 만들었다. 버튼을 누르면 받아쓰기 모델이 돌고, 녹음하는 동안 LED가 켜진다.

무대 데모 14:00 데모 직전에 버튼이 떨어져서 다시 꽂았다. 발표자는 "지금 AI Engineer 무대에서 준비한 발표를 하고 있다"고 녹음했다. LED가 켜졌으니 녹음은 됐다.

녹음이 메시지로 잘 도착했는지는 발표 중에 확인하지 않았다.

08

부스를 돌며 기록하기 14:40

발표자는 이 기기를 AI Engineer 행사에 걸고 다니고 싶었다. 무엇을 녹음할지 고민하다가 답을 정했다. 부스를 하나씩 돌며 각 부스가 내건 메시지를 녹음하는 것이다.

  1. 전시 업체 목록을 넣었다. 부스마다 번호와 이름이 있다. 업체끼리 연결도 없는 아주 단순한 모델이다. 데이터 정리도 좀 해야 했다.
  2. 오프라인 모드를 만들었다. 행사장 Wi-Fi는 보통 형편없기 때문이다.
  3. Pi 안에도 Neo4j를 띄웠다. 연결이 끊겨도 기록을 저장할 곳이 필요했다.
평소클라우드에서 처리한다클라우드의 Claude가 생각하고, 기억은 클라우드 Neo4j에 쌓는다

오프라인일 때Pi 안에서 끝낸다받아쓴 글에서 정규식regex으로 부스 번호를 뽑는다. 그 번호로 쿼리를 만들어 Pi 안의 Neo4j에 넣는다

Pi 안의 데이터 보기 16:00

발표자는 Cypher 셸 브라우저로 목에 건 Pi의 DB를 조회했다. 비싼 GUI 없이 Neo4j에 붙으려고 발표자가 직접 만든 작은 프로그램이다. Cypher는 Neo4j의 질의 언어다.

전시 업체를 모두 찾는 쿼리를 돌리자 Microsoft, MiniMax(추정) 같은 이름이 나왔다. 업체마다 "이 부스에서 이런 이야기를 들었다" 식의 원본 메모가 붙어 있다.

09

클라우드에서 주제 찾기 16:40

원본 메모는 나중에 클라우드의 Neo4j로 올렸다. 클라우드에서는 데이터를 보강enrich했다. 메모를 깨끗이 정리하고, 업체를 다른 노드에 연결했다.

업체에서 출발하는 경로를 찾는 쿼리를 돌리자, 업체들이 주제theme 노드로 묶여 보였다. 예를 들어 "평가와 관측"evaluation and observability 주제에는 Buildkite와 LangChain이 연결됐다.

발표자는 이걸 아마 아무도 갖고 있지 않은 새 지식이라고 불렀다. 행사장을 직접 걸어 다니며 모은 데이터에서 나왔기 때문이다.

주제를 어떻게 뽑았는지는 발표에서 자세히 말하지 않았다.

예시: 경로 질의는 Cypher로 MATCH path = (e:Exhibitor)--(t:Theme) RETURN path처럼 쓸 수 있다. 발표 화면에 나온 쿼리는 아니다.

10

대화 전체를 기억으로 18:20

발표 끝 무렵, 발표자는 그 뒤에 기억 시스템을 키운 이야기를 했다.

그동안 에이전트와 WhatsApp으로 나눈 대화가 꽤 쌓여 있었다. 발표자는 이 대화를 전부 Neo4j의 에이전트 메모리 서비스agent memory service에 넣었다. 서비스는 대화에서 기억을 뽑아 정리했다distill.

이제 사람, 장소, 개념별로 기억을 훑어볼 수 있다. 이 기억은 MCP 서버로 열려 있다. 그래서 목에 건 그 Pi의 에이전트가 기억을 다시 꺼내 쓴다.

처음에이전트가 쓴 스킬이 기록한다POLE+O 스킬이 그때그때 기억을 저장한다
→
지금대화 전체에서 기억을 뽑는다메모리 서비스가 기억을 정리하고, MCP로 에이전트에게 돌려준다

발표자는 Neo4j 소속이다. 이 발표에 나온 그래프 DB, Aura, 에이전트 메모리 서비스, GraphAcademy는 모두 Neo4j 제품이다. 기억을 그래프로 저장하자는 방향도 그 점을 감안해 읽자.

발표는 Neo4j 부스 P3 안내와 무료 실습 강의 GraphAcademy 소개로 끝났다.

설계 선택 한눈에 보기

발표에 흩어져 있는 선택과 이유를 한 표로 모았다.

선택발표자가 든 이유
노트북 대신 Pi 4B에이전트가 아직 충분히 단단하지 않다고 봐서 개인 노트북과 떼어 놓았다. 옷장에 있던 기기라 돈도 안 든다
OpenClaw 대신 NanoClaw작아서 속을 이해할 수 있다. 직접 고쳐 쓰라고 권한다
Docker 컨테이너에이전트가 시스템을 함부로 건드리지 못하게 한다
추론은 클라우드 Claude작은 기기로도 큰 두뇌를 쓴다
WhatsApp휴대폰에 이미 있었다. 기내에서도 메시지가 오갔다
POLE+O 그래프사람, 사물, 장소, 사건, 조직과 그 관계로 기억을 남긴다
Pi 안의 Neo4j행사장 Wi-Fi가 끊겨도 기록을 잃지 않는다
정규식오프라인에서도 받아쓴 글에서 부스 번호를 뽑는다
12

핵심 정리

  1. 발표자는 개인 에이전트를 노트북에서 떼어 옷장의 Raspberry Pi 4B에 올렸다.
  2. 기준은 싸고, 열려 있고, 고칠 수 있고, 이해할 수 있는가였다.
  3. OpenClaw 대신 NanoClaw를 골랐다. 소스 파일 15개 정도로 작고, 에이전트를 Docker 컨테이너에 가둔다.
  4. Pi는 추론을 하지 않는다. 큰 두뇌는 클라우드의 Claude이고, Pi는 메시지와 도구와 데이터를 맡는다.
  5. 대화 창구는 WhatsApp이다. 기내 Wi-Fi를 사지 않아도 메시지가 오갔다.
  6. 에이전트는 MCP 서버로 Neo4j 그래프 DB에 묻고 답한다.
  7. 기억은 POLE+O로 저장한다. 이 기억 스킬도 에이전트가 직접 썼다.
  8. USB 마이크, 버튼, LED를 달아 음성을 받아쓰게 했다.
  9. 행사장 Wi-Fi를 믿지 않고 오프라인 모드를 만들었다. 정규식으로 부스 번호를 뽑아 Pi 안의 Neo4j에 넣는다.
  10. 모은 메모는 클라우드에서 주제 노드로 묶었고, 대화 전체는 메모리 서비스로 정리해 MCP로 에이전트에게 돌려줬다.

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1발표자가 개인 에이전트를 노트북에 올리지 않은 이유는?
시스템 관리자와 DevOps 출신이라, 이런 도구가 충분히 단단해지기 전에는 노트북에 올리고 싶지 않았다. 대신 싸고, 열려 있고, 고칠 수 있고, 이해할 수 있는 걸 원했다.
Q2Craigslist의 Mac Mini를 사지 않은 이유 두 가지는?
OpenClaw가 미리 깔려 있다는 점이 위험 신호였다. 그리고 가격이 올라 더는 600달러짜리 "작은 클로"가 아니었다.
Q3NanoClaw를 고른 이유는?
소스 파일 15개 정도로 작아 속을 이해하기 쉽다. 에이전트를 Docker 컨테이너에서 돌려 시스템을 함부로 못 건드리게 한다. Claude Agent SDK 위에 만들었고, 직접 고쳐 쓰라고 권한다.
Q4이 에이전트의 LLM 추론은 어디서 일어나나?
Pi에서는 전혀 일어나지 않는다. 클라우드의 Claude가 한다. Pi는 메시지를 받고 도구와 DB를 잇는다.
Q5"Tom Hanks가 출연한 영화" 질문은 어떤 길을 거쳐 답이 됐나?
WhatsApp 메시지가 Pi의 NanoClaw로 온다. 에이전트가 MCP 서버로 Neo4j 영화 DB를 조회한다. Claude Agent SDK로 답을 만들어 WhatsApp으로 돌려준다. 처음에는 인증 설정이 깨져 있어 고쳐야 했다.
Q6POLE+O의 다섯 글자는 각각 무엇인가?
Person 사람, Object 사물, Location 장소, Event 사건, 그리고 더한 O는 Organization 조직이다.
Q7발표자는 기억 스킬을 어떻게 만들었나?
비행기 안에서 WhatsApp으로 에이전트에게 POLE+O 기억 시스템을 만들 수 있냐고 물었다. 에이전트가 직접 스킬을 썼고, 재부팅해도 남는 마운트 지점에 저장한다고 했다.
Q8Pi에 단 버튼과 LED는 각각 무슨 일을 하나?
버튼은 받아쓰기 모델을 켠다. LED는 녹음 중임을 보여 준다.
Q9오프라인 모드는 어떻게 동작하나?
Pi 안에 Neo4j를 띄워 둔다. 받아쓴 글에서 정규식으로 부스 번호를 뽑고, 그걸로 쿼리를 만들어 로컬 DB에 넣는다.
Q10클라우드로 올린 부스 데이터에서 무엇을 찾았나?
업체들이 주제 노드로 묶였다. 예를 들어 "평가와 관측" 주제에 Buildkite와 LangChain이 연결됐다. 발표자는 이걸 직접 걸어 다니며 만든 새 지식이라고 했다.
Q11기억 시스템을 키운 뒤, 에이전트는 기억을 어떻게 다시 쓰나?
WhatsApp 대화 전체를 Neo4j 에이전트 메모리 서비스에 넣어 기억으로 정리했다. 그 기억이 MCP 서버로 열려 있어서 같은 Pi의 에이전트가 불러 쓴다.
