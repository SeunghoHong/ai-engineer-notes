지능을 빌리지 말고 키워라

폐쇄형 모델 비용이 빠르게 오르면서 오픈 모델로 옮기는 팀이 늘고 있다. 발표자는 오픈 모델을 내 일에 맞게 학습하고, 바로 배포하고, 다시 학습하는 루프로 품질 격차를 메울 수 있다고 말한다.

원본 영상: Stop Renting Intelligence: The Train-to-Deploy Loop for Specialized AI 발표: Jatashri(추정) · Fireworks AI 응용 머신러닝 팀 일부를 이끈다. "Jet"으로 불러 달라고 했다

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 뭉개진 이름은 확실한 것만 알려진 이름으로 바로잡았다(예: Versell → Vercel, RFD → RFT, humix → numerics). mm:ss는 영상 위치다.

발표자는 Fireworks AI 소속이고, 발표 대부분이 자사 플랫폼 소개다. 고객 사례 수치와 "학습과 서빙을 한 플랫폼에서 해야 한다"는 주장은 그 점을 감안해 읽자.

3분 요약
  1. 폐쇄형 모델이 비싸지면서 오픈 모델로 옮기는 팀이 늘고 있다. 발표자는 오픈 모델이 대부분 실서비스에 쓸 만하다고 본다.
  2. 오픈 모델이 품질에서 밀린다면, 차이를 메우는 건 내 일에 맞춘 추가 학습이다.
  3. AI 스택은 "한 번 배포하고 끝"에서 학습과 배포를 계속 반복하는 루프로 바뀌고 있다.
  4. 추론 쪽에서 Fireworks는 자체 엔진 FireAttention과 CUDA 커널까지 고객 워크로드에 맞춰 조정한다. 발표자는 Cursor 13배, Vercel 40배 개선을 사례로 들었다.
  5. 학습 쪽 상품은 세 가지다. 학습 에이전트(맡기기), 관리형 학습(설정하고 누르기), 학습 API(직접 짜기).
  6. 요즘 인기인 RFT는 좋은 평가 함수가 관건이다. Genspark는 RFT로 품질을 12% 올렸다고 한다.
  7. 루프를 받치는 장치는 원클릭 배포, 모니터링, 체크포인트 재학습, 핫로딩, 학습과 서빙의 수치 일치다.
01

왜 오픈 모델로 옮기나 00:00

발표자는 청중에게 두 가지를 물었다. ChatGPT나 Anthropic 같은 폐쇄형 모델 closed-source model을 쓰는 사람이 얼마나 되는지. 그리고 그 비용이 너무 빨리 오른다고 느끼는 사람이 얼마나 되는지.

꽤 많은 사람이 손을 들었다. 발표자에 따르면 Fireworks 고객들도 같은 길을 걷고 있다. 비용과 성능 때문에 오픈 모델 open-source model로 옮기는 중이다.

발표의 질문은 두 가지다. 오픈 모델은 어디서 강한가. 그리고 오픈 모델의 품질을 폐쇄형 모델 수준으로 어떻게 끌어올리나.

제목의 "지능을 빌리지 말라 Stop Renting Intelligence"는 남의 모델을 API로 빌려 쓰는 대신, 내 일에 맞게 학습한 모델을 직접 갖자는 뜻으로 읽힌다. 발표 본문에서 이 표현을 직접 쓰지는 않았다.

02

지금 AI 업계의 세 가지 사실 01:20

발표자가 "지금 AI 생태계에서 참인 것"으로 꼽은 세 가지다.

  1. 오픈 모델은 대부분 실서비스에 쓸 수 있다. 발표자는 GLM 5.2를 예로 들며, 특히 코딩 용도에서 그렇다고 했다.
  2. 품질 격차는 맞춤 학습으로 메운다. 오픈 모델이 폐쇄형 모델을 넘거나 따라잡지 못한다면, 차이를 만드는 건 모델을 얼마나 잘 맞춤 학습하고 개선하느냐다.
  3. AI 스택이 루프로 바뀐다. 모델을 한 번 서빙하고 끝내지 않는다. 같은 오픈 모델을 학습하고, 추론에 쓰고, 다시 학습한다.
지금까지한 번 서빙하고 끝정해진 모델을 가져다 배포한다

앞으로학습과 추론을 계속 도는 루프새 데이터와 피드백으로 같은 모델을 계속 개선한다

Fireworks는 이 루프를 쉽고 싸게 만드는 회사라고 자신을 소개했다 02:20. 오픈 모델을 학습하는 일과 대규모로 서빙하는 일을 한곳에서 한다.

06

SFT, RFT, DPO와 평가 함수 10:00

세 상품에서 지도 파인튜닝(SFT), 강화 파인튜닝(RFT), DPO를 쓸 수 있다고 했다. 다만 학습 에이전트는 RFT를 지원하지 않는다고 바로 덧붙였다.

방식무엇을 주고 학습하나 (일반적인 뜻, 발표 밖 보충)
SFTsupervised fine-tuning 입력과 모범 답의 쌍을 보여 주고 그대로 따라 하게 한다
RFTreinforcement fine-tuning 모델이 낸 답을 평가 함수로 채점하고, 점수가 높아지는 쪽으로 학습한다
DPOdirect preference optimization 같은 질문에 대한 더 좋은 답과 덜 좋은 답의 쌍으로, 좋은 쪽을 고르게 학습한다

발표자에 따르면 요즘은 RFT가 아주 인기다. RFT의 관건은 좋은 평가 함수 evaluator function다. 평가 함수는 모델의 답에 점수를 매기는 규칙이다.

예시: 코드를 만드는 모델이라면 "생성한 코드가 테스트를 통과하면 1점, 아니면 0점"처럼 정할 수 있다. 발표에 나온 예는 아니다.

평가 함수 정의를 도와준다 Genspark 사례처럼 Fireworks가 평가 함수 정의, 데이터셋 정리, 하이퍼파라미터 선택을 함께 해 준다. 하이퍼파라미터 선택은 특히 RFT에서 중요하다고 했다. 학습 에이전트가 RFT를 지원하지 않으니, 큰 사용 사례라면 직접 도와주겠다고 했다.
07

데이터 플라이휠 11:00

발표 첫머리의 세 번째 사실로 돌아간다. 많은 팀이 학습하고, 서빙하고, 다시 학습하고, 다시 서빙하는 루프를 원한다. 사용자에게서 새 데이터와 피드백이 계속 들어오기 때문이다. 이 루프를 데이터 플라이휠 data flywheel이라고 부른다.

  1. 학습한다.
  2. 배포한다. 학습이 끝나면 클릭 한 번으로 실서비스에 올린다.
  3. 지켜본다. 토큰 수, 캐시 적중률, 추측 디코딩용 모델 speculator을 학습했다면 그 성능을 본다.
  4. 피드백을 모은다. 수집한 지표에서 개선할 거리를 찾는다.
  5. 다시 학습한다. 쓰던 체크포인트에서 이어 새 체크포인트를 만든다. 그리고 2번으로 돌아간다.

학습 상품을 여러 개 두고, 서빙을 싸고 빠르게 만드는 것도 모두 이 루프를 매끄럽게 하려는 것이라고 했다 11:20.

08

루프를 받치는 기능 12:20

기능하는 일발표자가 덧붙인 말
GPU 확보여러 클라우드, 네오클라우드와 제휴해 연산 자원을 마련한다그래서 대규모 서빙이 가능하다
핫로딩 12:40새 체크포인트를 다운타임 없이 실서비스에 반영한다. 버튼 하나로 모델 가중치를 바꿔 끼운다Cursor 모델을 학습할 때 Cursor를 위해 만든 기능이다. 다른 사람에게도 쓸모 있겠다 싶어 공개했다
수치 일치 13:20학습과 추론을 같은 플랫폼에서 해, 학습 뒤 서빙할 때 수치 차이가 생기지 않게 한다아래 설명 참고
원클릭 배포학습과 추론이 한곳에 있어 학습한 모델을 바로 실서비스 규모로 배포한다루프가 끊기지 않는 이유
수치 일치 numerical fidelity란 많은 고객이 A 플랫폼에서 학습하고 B 플랫폼에서 서빙한다. 발표자에 따르면 이렇게 하면 모델 품질에 문제가 생긴다. 두 플랫폼의 수치 계산 방식 numerics이 항상 맞지는 않기 때문이다. 그래서 Fireworks는 학습과 추론을 한 플랫폼에서 하고, 그 사이에 수치 차이가 없도록 보장한다고 했다.

이 주장은 학습과 서빙을 한곳에서 파는 회사의 주장이다. 학습과 서빙을 다른 곳에서 할 계획이라면, 학습 때 평가 점수와 서빙 후 결과를 직접 비교해 확인하자.

09

데모: 학습 에이전트 14:10

  1. 학습 데이터셋이 Fireworks 안 어디에 있는지 알려 준다.
  2. 평가용 데이터셋도 함께 준다. 학습용과 평가용을 따로 두는 경우가 많기 때문이다.
  3. 파인튜닝을 요청하고, 모델과 하이퍼파라미터 선택도 맡긴다.
  4. 에이전트가 계획을 내놓는다 15:00. SFT 계획, 기본 모델을 고른 이유, 하이퍼파라미터, 전체 학습 과정을 설명한다. 데모에서는 Qwen3-8B(추정, 자막은 "quen 38B")를 골랐다.
  5. 계획이 괜찮으면 승인한다.
  6. 에이전트가 단계를 하나씩 진행하며 결과를 알려 준다.
  7. 끝나면 설정, 기본 모델, 하이퍼파라미터와 그 영향을 요약한다 16:00. 정확도와 F1 점수 같은 지표도 보여 준다.
  8. 마지막으로 다음에 할 일을 추천한다.

사람이 하는 일은 데이터 위치를 알려 주고, 원하는 것을 설명하고, 계획을 승인하는 것뿐이다.

10

데모: 관리형 학습에서 배포까지 16:10

  1. 데이터셋을 올리고 모델을 고른다.
  2. 평가 설정에서 평가용 데이터셋을 고른다.
  3. 필요하면 선택 설정에서 하이퍼파라미터를 세밀하게 정한다.
  4. Create 버튼을 누르면 학습 작업이 시작된다 17:00.
  5. 끝난 작업을 누르면 쓴 데이터셋, 하이퍼파라미터, 학습 중 손실 곡선을 볼 수 있다.
  6. 작업을 복제해 설정만 바꿔 다시 돌릴 수 있다.
  7. 배포 화면에서 방금 학습한 모델을 고르고 Deploy를 누른다 17:40.

배포 설정은 직접 정해도 되고, 미리 만든 템플릿 18:00 중에서 골라도 된다. 템플릿은 throughput, fast, minimal 같은 것이다. 처리량, 지연 시간, 첫 토큰까지 걸리는 시간 같은 지표를 기준으로 일반적인 워크로드에 맞춰 둔 설정이다.

학습 API는 데모가 없다 18:20

학습 API는 고객마다 설정이 달라서 데모를 준비하지 않았다고 했다. 학습 루프와 손실 함수를 직접 짜고 싶다면 Fireworks 웹사이트의 쿡북을 따라 해 보라고 권했다.

11

정리와 읽을 때 주의할 점 18:40

발표자는 학습에서 추론까지 이어지는 루프의 전체 모습을 보여 주는 것으로 발표를 마쳤다. 메시지는 하나다. 오픈 모델을 내 일에 맞게 학습하고, 바로 배포하고, 다시 학습하는 루프를 돌려라.

발표에서 빠진 것
  • 발표는 비용 문제로 시작했지만, 폐쇄형 모델과 비교해 비용이 얼마나 줄었는지는 숫자로 나오지 않았다.
  • 오픈 모델이 폐쇄형 모델 품질을 따라잡았다는 직접 비교도 없다. Genspark의 12%는 학습 전후 비교다.
  • 13배, 40배는 무엇과 비교한 값인지 밝히지 않았다.
  • 학습과 서빙을 한 플랫폼에서 해야 한다는 주장은 그 플랫폼을 파는 회사의 주장이다.

그래도 남는 생각은 쓸 만하다. 모델을 한 번 고르고 끝내지 말고, 평가 기준을 세우고, 서비스에서 모은 데이터로 계속 개선하는 구조를 갖추라는 것이다. 이 구조는 어느 플랫폼을 쓰든 적용할 수 있다.

12

핵심 정리

  1. 폐쇄형 모델 비용이 빠르게 오르면서 오픈 모델로 옮기는 팀이 늘고 있다.
  2. 발표자는 오픈 모델이 대부분 실서비스에 쓸 만하다고 본다. 특히 코딩에서 그렇다고 했다.
  3. 품질 격차는 내 일에 맞춘 학습으로 메운다.
  4. AI 스택은 한 번 서빙하고 끝이 아니라 학습과 배포를 반복하는 루프가 된다.
  5. 추론 속도는 엔진과 CUDA 커널을 워크로드에 맞춰 조정해 올린다. 추측 디코딩, 분리 서빙, 양자화도 쓴다.
  6. 학습 상품은 세 가지다. 에이전트(맡기기), 관리형(설정하고 누르기), API(직접 짜기).
  7. SFT, RFT, DPO를 지원하고 요즘은 RFT가 인기다. RFT의 관건은 좋은 평가 함수다.
  8. 루프는 학습, 원클릭 배포, 모니터링, 피드백 수집, 체크포인트에서 재학습 순서로 돈다.
  9. 루프를 받치는 기능은 GPU 확보, 핫로딩, 학습과 서빙의 수치 일치다.
  10. 고객 수치(13배, 40배, 12%)는 비교 기준이 공개되지 않은 자사 발표 수치로 읽는다.
13

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1발표자가 꼽은 지금 AI 업계의 세 가지 사실은?
오픈 모델은 대부분 실서비스에 쓸 수 있다. 품질 격차는 맞춤 학습으로 메운다. AI 스택은 한 번 서빙하고 끝내는 방식에서 학습과 추론을 반복하는 루프로 바뀐다.
Q2FireAttention이 고객 워크로드에 맞춰 조정한다는 층은 어디까지인가?
추론 엔진 전체와 CUDA 커널까지다. CUDA 커널은 모델의 계산을 GPU 명령으로 바꾸는 번역층이고, Fireworks는 이 커널을 직접 만든다.
Q3최적화를 요청할 때 고객이 가져오는 네 가지 정보는?
요청당 입력 토큰 수, 출력 토큰 수, 프롬프트 캐시 적중률, 맞춰야 할 지연 시간 목표.
Q4추측 디코딩에서 고객이 직접 학습할 수 있는 것은? 잘 학습하면 무엇이 좋아지나?
초안 모델(draft model). 데이터셋을 올려 파인튜닝처럼 학습한다. 잘 학습하면 본 모델이 빨라지고, 지연 목표를 맞추기 쉬워지고, 처리량이 늘어난다.
Q5세 학습 상품과 각각의 주 사용자는?
학습 에이전트는 이 분야에 새로 들어온 PM과 빌더. 관리형 학습은 대부분의 고객. 학습 API는 학습 루프와 손실 함수를 직접 짜려는 ML 엔지니어.
Q6관리형 학습에서 학습 중 상태를 보는 두 가지 방법은?
Fireworks 대시보드에서 에폭별 학습 정도와 손실 곡선을 본다. 또는 Weights & Biases API 키를 넣어 지표를 그쪽으로 내보낸다.
Q7학습 에이전트가 지원하지 않는 학습 방식과 그 대안은?
RFT를 지원하지 않는다. 큰 사용 사례라면 Fireworks가 평가 함수 정의, 데이터셋 정리, 하이퍼파라미터 선택을 직접 도와준다.
Q8Genspark 사례에서 Fireworks가 한 일과 결과는?
데이터셋을 정리하고, 평가 함수를 정의하고, RFT로 학습했다. 발표자에 따르면 품질이 12% 올랐다.
Q9데이터 플라이휠은 어떤 순서로 도나?
학습, 원클릭 배포, 모니터링(토큰 수, 캐시 적중률, speculator 성능), 피드백 수집, 쓰던 체크포인트에서 이어 재학습. 그리고 다시 배포로 돌아간다.
Q10핫로딩은 무엇이고, 처음에 누구를 위해 만들었나?
새 체크포인트를 다운타임 없이 실서비스에 반영하는 기능이다. 버튼 하나로 가중치를 바꿔 끼운다. Cursor 모델을 학습할 때 Cursor를 위해 만들었다가 일반에 공개했다.
Q11학습과 서빙을 다른 플랫폼에서 하면 생긴다고 한 문제는? 이 주장을 어떻게 읽어야 하나?
두 플랫폼의 수치 계산 방식이 맞지 않아 모델 품질에 문제가 생긴다고 했다. 학습과 서빙을 한곳에서 파는 회사의 주장이니, 직접 비교해 확인하는 것이 좋다.
Q12학습 에이전트 데모에서 학습이 끝난 뒤 보여 준 것은?
설정, 기본 모델, 하이퍼파라미터와 그 영향의 요약. 정확도와 F1 점수 같은 지표. 그리고 다음에 할 일 추천.
