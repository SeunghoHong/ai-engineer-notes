모델은 모두 같다, 차이는 인텔리전스 플레인에서 난다

누구나 같은 AI 모델을 쓴다. 에이전트의 차이는 그 에이전트가 무엇을 알고, 무엇을 기억하고, 무엇을 볼 수 있고, 어떻게 나아지는지에서 생긴다. 발표자는 이 네 가지를 묶어 "인텔리전스 플레인"이라고 부른다.

원본 영상: Everyone Has the Same AI Models. Here's What Sets Agents Apart 발표: Richmond Alake (Oracle)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 뭉개진 이름은 확실한 것만 바로잡고, 나머지는 "(추정)"을 붙였다. mm:ss는 영상 위치다.

발표자는 Oracle 소속이다. 후반부는 Oracle 제품 소개이고, 데모도 발표자가 직접 만든 것이다. 그 점을 감안해 읽자.

3분 요약
  1. 모두가 같은 모델과 같은 정보를 쓴다. 발표 전체를 꿰는 주장은 하나다. 정보는 지능이 아니다.
  2. 컨트롤 플레인은 에이전트가 무엇을 해도 되는지 관리한다. 인텔리전스 플레인은 에이전트가 어떻게 점점 나아지는지를 다룬다.
  3. 인텔리전스 플레인은 네 가지다. 지식, 메모리, 데이터 접근 거버넌스, 지속 학습.
  4. 2차대전 미드웨이 사례: 같은 정보를 가진 두 팀 중, 몇 달 치 기록을 쌓아 둔 팀이 맞는 답을 냈다.
  5. 발표자의 데모에서 인텔리전스 플레인을 갖춘 에이전트는 토큰 3만 2천 개를, 단순한 에이전트는 20만 개를 썼다.
  6. 온톨로지와 시맨틱 레이어는 용어의 뜻을 정확히 잡아 준다. 정확도 차이는 작아도 금융 같은 분야에서는 크다.
  7. 오늘 할 일: 메모리를 데이터로 다루고, 메모리 기록을 모으고, 그 기록으로 작은 모델을 다시 학습시킨다. 메모리를 직접 소유하라.
01

에이전트 메모리 복습 00:10

발표자는 청중에게 키워드를 하나씩 던지고, 들어 본 사람은 손을 들게 한다. 키워드가 바뀔수록 손이 줄어들 거라는 게 발표자의 예상이다.

첫 키워드는 에이전트 메모리 agent memory다. 거의 모두가 손을 들었다. 발표자는 1년 전 같은 행사에서 이 주제로 발표했을 때는 아무도 몰랐다고 말한다.

에이전트 메모리는 에이전트가 정보를 다루는 방식이다. 발표자는 이를 "4R"로 정리한다 01:00.

4R뜻
보존 retain정보를 남겨 둔다
재사용 reuse남긴 정보를 다시 쓴다
회상 recall필요할 때 꺼내 온다
정제 refine쓰면서 다듬는다

메모리를 나누는 기준도 있다.

  • 기간: 단기 메모리와 장기 메모리
  • 인지 기능: 의미 기억 semantic, 일화 기억 episodic, 절차 기억 procedural, 작업 기억 working memory

이 발표는 메모리에서 한 걸음 더 나아간다.

02

컨트롤 플레인 01:40

두 번째 키워드는 컨트롤 플레인 control plane이다. 손이 조금 줄었다.

컨트롤 플레인은 에이전트를 한곳에서 관리하는 시스템이다. 에이전트가 어떤 도구를 쓸 수 있는지, 무엇을 해도 되고 무엇을 하면 안 되는지 정한다. 여러 소프트웨어 회사가 자기 제품을 컨트롤 플레인이라고 내세운다. 발표자도 이런 시스템이 필요하다고 본다.

구성 요소하는 일
신원 identity에이전트가 누구인지 정한다
정책과 가드레일지켜야 할 규칙과 넘으면 안 되는 선
오케스트레이션과 권한에이전트를 실행하고 권한을 준다
감사 auditing무엇을 했는지 기록하고 확인한다
03

소프트웨어 팩토리 02:40

세 번째 키워드는 소프트웨어 팩토리 software factory다. 손이 더 줄었다.

발표자에 따르면 이 말은 새것이 아니다. 1968년 General Electric의 Bob Bemer가 논문에서 처음 썼다. 프로그램을 측정 가능하고 반복 가능한 방식으로 만들자는 뜻이었다.

지금의 소프트웨어 팩토리는 소프트웨어를 안정적으로 찍어 내는 시스템이다. 정해진 절차와 작업 흐름을 주고, 보통 여러 에이전트가 동시에 그 흐름을 실행한다.

발표자는 GE에서 인턴을 했다고 밝히며 이 이야기를 꺼냈다. 1968년이라는 연도와 논문은 발표자가 인용한 것이다.

04

AF는 미드웨이다 04:30

네 번째 키워드 인텔리전스 플레인 intelligence plane에는 세 명만 손을 들었다 03:50. 발표자는 작년 메모리 발표 때처럼 약속한다. 오늘 이야기가 청중을 다른 사람보다 6개월 앞서게 해 줄 거라고.

이어서 2차대전 이야기를 꺼낸다.

  1. 미국에는 일본 해군의 통신을 가로채 해독하는 팀이 여럿 있었다. 그중 둘이 중요하다. 워싱턴 팀과 진주만 팀이다.
  2. 일본군 통신에 "AF"라는 암호가 자주 나왔다. 무엇을 가리키는지가 태평양 전쟁의 흐름을 좌우했다.
  3. 진주만 팀(Station HYPO)은 지하실에서 가로챈 메시지를 몇 달 동안 종이에 기록해 쌓았다.
  4. 이 팀은 AF가 아시아와 북미 사이의 작은 섬 미드웨이라고 결론 내렸다.
  5. 워싱턴 팀은 같은 정보를 가졌고, 아마 자원도 더 많았고, 조직과 통제력도 있었다. 그런데 전혀 다른 해석을 내놓았다.
  6. 채택된 것은 진주만 팀의 해석이었다.
발표자가 말하려는 것 진주만 팀이 몇 달 동안 쌓은 기록은 곧 메모리다. 워싱턴 팀이 가진 것은 통제였다. 정보는 같았지만 결과는 달랐다. 이 방에 있는 사람들도 같은 모델과 같은 정보를 쓴다. 그것만으로는 지능도, 남과 다른 강점도 생기지 않는다.
05

인텔리전스 플레인이란 07:30

에이전트를 이루는 층을 쌓아 올린 것을 에이전트 스택 agent stack이라고 한다. 컨트롤 플레인은 이 스택의 일부 층만 가로지른다. 인텔리전스 플레인은 스택 전체를 가로지른다. 그래서 에이전트를 실행하고 관리하는 데서 그치지 않고, 데이터와 메모리로 배우게 만든다.

정의하면 이렇다 08:10. 인텔리전스 플레인은 에이전트가 시간이 갈수록 나아지게 하는 시스템의 한 부분이다. 네 가지를 담는다.

알아야 할 것지식knowledge
기억해야 할 것메모리memory
볼 수 있는 것거버넌스와 데이터 접근governance, data access
나아지는 방법지속 학습continual learning

발표자는 이 중 어느 것도 새롭지 않다고 말한다. 이미 일부를 하고 있는 팀도 많다. 새로운 것은 이것들을 하나의 층으로 묶어 생각하는 방식이다.

08

참조 아키텍처 12:00

발표자는 인텔리전스 플레인을 시스템 구성 요소로 나눠 그렸다. 지금은 구성 요소마다 공급 업체가 다를 수 있다.

  1. 에이전트 런타임: 에이전트가 실행되는 곳
  2. 메모리와 지식: 런타임이 가져다 쓴다
  3. 메모리 매니저: 메모리와 지식을 관리한다. 데이터 플랫폼 위에 놓인다
  4. 메모리 기록 쌓기: 런타임이 실행 중 남긴 메모리 기록 memory traces을 메모리 매니저에 넣는다
  5. 지속 학습 루프: 쌓인 기록으로 모델을 고친다
  6. 다시 런타임으로: 고친 모델을 런타임에 돌려준다. 1번으로 돌아간다

이 구성 요소들은 세 개의 플레인 위에 놓인다. 데이터 플레인, 컨트롤 플레인, 인텔리전스 플레인이다. 발표자는 이 중 빠져 있는 것이 인텔리전스 플레인이라고 본다.

09

왜 지금인가 13:10

  • 프런티어 모델: 스케일링 법칙 덕분에 모델이 얼마나 좋아질지 미리 예측할 수 있었다.
  • 오픈 웨이트 모델 open weights: 프런티어 모델보다 3~6개월 정도 뒤처진 수준이다.
  • 결정 모델 decision models: 최근에 생긴 변화다. 시스템 안의 판단 하나를 맡는 작은 모델이다.

발표자는 결정 모델 때문에 시스템을 보는 눈이 바뀌었다고 말한다. 시스템을 구조 수준에서 보며 "여기서 무엇을 결정 모델로 바꿀 수 있을까"를 묻게 됐다. 몇 년 전에는 검색 파이프라인에 모델이 한두 군데만 있었다. 지금은 파이프라인 곳곳에 모델을 둘 수 있다.

데모: 두 분석가 에이전트 14:00

인터넷 사정 때문에 라이브로 돌리지 않고 결과 화면을 보여 줬다. 코드는 QR 코드로 공개했다.

naive analyst 단순한 분석가

토크노믹스 14:30

발표자는 비용, 정확도, 지연 시간을 묶어 토크노믹스 tokenomics라고 부른다. 거버넌스를 갖춘 분석가는 99% 맞혔고, 토큰도 훨씬 적게 썼다.

거버넌스를 갖춘 쪽에는 가드레일, 캐시, 프롬프트 캐싱도 들어 있다. 발표자는 이런 요소를 갖추면 두 가지를 얻는다고 말한다. 하나, 프로덕션에 맞게 최적화된다. 둘, 쌓이는 데이터로 배우고 자란다.

비교 대상인 단순한 분석가를 어떻게 구성했는지는 발표에 나오지 않는다. Oracle 소속 발표자가 Oracle 기반으로 만든 데모라는 점도 함께 감안하자.

온톨로지: "거래 상대방이 뭐지?" 15:30

두 에이전트에게 카운터파티 counterparty, 곧 거래 상대방이 무엇인지 물었다.

  • 단순한 쪽은 키워드 검색으로 관련 항목을 찾아 답했다.
  • 온톨로지 ontology가 있는 쪽은 개념 사이의 관계를 알고 있어서 더 정확한 답을 냈다.

시맨틱 레이어: "집중도가 무슨 뜻이지?" 16:00

"집중도" concentration가 무슨 뜻인지 물었다. 시맨틱 레이어 semantic layer가 없는 단순한 쪽은 틀렸다. 시맨틱 레이어가 있는 쪽은 맞혔다.

핵심 정리

  1. 모두가 같은 모델을 쓴다. 정보는 지능이 아니다.
  2. 에이전트 메모리는 정보를 보존·재사용·회상·정제하는 방식이다(4R).
  3. 컨트롤 플레인은 신원, 정책, 오케스트레이션, 감사로 에이전트가 무엇을 해도 되는지 관리한다.
  4. 인텔리전스 플레인은 지식, 메모리, 데이터 접근 거버넌스, 지속 학습으로 에이전트가 어떻게 나아지는지를 다룬다.
  5. 미드웨이 사례: 같은 정보를 가진 두 팀 중 몇 달 치 기록(메모리)을 쌓은 팀이 맞혔다.
  6. 업계는 프롬프트 층 → 컨텍스트 층 → 컨트롤 플레인을 지나 인텔리전스 플레인으로 간다.
  7. 참조 아키텍처의 핵심은 루프다. 런타임 → 메모리 기록 → 지속 학습 → 고친 모델 → 런타임.
  8. 데모에서 인텔리전스 플레인을 갖춘 에이전트는 토큰을 3만 2천 개, 단순한 에이전트는 20만 개 썼다.
  9. 온톨로지와 시맨틱 레이어는 도메인 용어의 뜻을 바로잡는다. 금융처럼 중요한 일에서는 작은 차이도 크다.
  10. 메모리 라우팅, 임베딩, 리랭킹을 내 메모리 기록으로 다시 학습시키는 것이 가장 쉬운 시작점이다.

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1에이전트 메모리의 "4R"은 무엇인가?
보존(retain), 재사용(reuse), 회상(recall), 정제(refine).
Q2컨트롤 플레인의 네 구성 요소는?
신원, 정책과 가드레일, 오케스트레이션과 권한, 감사.
Q3컨트롤 플레인과 인텔리전스 플레인은 무엇이 다른가?
컨트롤 플레인은 에이전트가 무엇을 해도 되는지 관리하고 스택의 일부 층만 가로지른다. 인텔리전스 플레인은 에이전트가 어떻게 나아지는지를 다루고 스택 전체를 가로지른다.
Q4인텔리전스 플레인이 담는 네 가지는?
지식(알아야 할 것), 메모리(기억해야 할 것), 거버넌스와 데이터 접근(볼 수 있는 것), 지속 학습(나아지는 방법).
Q5미드웨이 이야기에서 진주만 팀과 워싱턴 팀을 가른 것은?
정보는 같았다. 진주만 팀은 몇 달 동안 가로챈 메시지를 기록해 쌓았다(메모리). 워싱턴 팀은 자원과 통제력이 있었지만 다른 해석을 냈다.
Q6발표자가 제시한 세 개의 공식은?
에이전트 = 모델 + 하네스. 통제 = 거버넌스 + 보안. 지능 = 지식 + 메모리 + 학습.
Q7참조 아키텍처에서 모델이 나아지는 루프를 순서대로 말하면?
에이전트 런타임이 메모리 기록을 메모리 매니저에 남긴다. 그 기록이 지속 학습 루프로 들어간다. 고친 모델이 다시 런타임으로 돌아간다.
Q8데모에서 두 분석가가 쓴 토큰 수와 그 비율은?
거버넌스를 갖춘 분석가 3만 2천 개, 단순한 분석가 20만 개. 약 6.25배 차이다.
Q9온톨로지와 시맨틱 레이어 데모에서 각각 던진 질문은?
온톨로지는 "카운터파티(거래 상대방)가 무엇인가", 시맨틱 레이어는 "집중도가 무슨 뜻인가". 두 경우 모두 해당 층이 있는 에이전트가 더 정확했다.
Q10메모리 라우팅이란 무엇이고, 결정 모델을 쓰면 무엇이 좋은가?
LLM이나 컨텍스트 층의 결과를 대화 메모리, 작업 흐름 메모리 같은 알맞은 저장소로 보내는 일이다. 코드로 규칙을 짜는 대신 결정 모델을 쓰면 쉽고 싸다.
Q11발표자가 꼽은 "가장 쉽게 시작할 곳" 세 가지는?
메모리 라우팅, 임베딩, 리랭킹. 메모리 기록을 모으고, 정리하고, 모델을 다시 학습시킨다.
Q12지속 학습이 일어나는 세 공간은?
토큰 공간, 가중치 공간, 잠재 공간(프롬프트 캐싱 쪽).
