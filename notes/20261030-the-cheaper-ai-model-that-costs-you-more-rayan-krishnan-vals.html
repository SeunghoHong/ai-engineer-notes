싼 모델이 더 비싼 이유

토큰 단가가 싼 모델은 일을 끝내려고 토큰을 더 많이 쓴다. 그래서 과제 하나당 비용은 오히려 더 나올 수 있다. 모델 카드의 숫자 하나 대신, 우리 회사의 실제 일로 만든 평가로 모델과 비용을 고르라는 발표다.

원본 영상: The Cheaper AI Model That Costs You More 발표: Rayan Krishnan (Vals AI)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 슬라이드는 볼 수 없어서, 화면에만 있고 말로 하지 않은 숫자는 빠져 있다. 자막에서 뭉개진 이름은 확실한 것만 바로잡았고, 나머지는 들린 대로 적고 "(추정)"을 붙였다. mm:ss는 영상 위치다.

3분 요약
  1. 모델 카드의 종합 점수 하나로는 우리 일에 맞는 모델을 고를 수 없다. 분야와 과제마다 1등이 바뀐다.
  2. AI를 자주 쓰는 회사는 90%인데, 투자 수익이 확인된 곳은 7%뿐이다.
  3. Opus 5.5는 토큰 단가가 Fable 5.1의 40%다. 그런데 세금 벤치마크에서는 과제당 비용이 더 비쌌고 점수도 낮았다. 토큰을 훨씬 많이 썼기 때문이다.
  4. 같은 엑셀 벤치마크 안에서도 LBO 과제만 떼어 보면 가성비 최고 모델이 달라진다.
  5. 평가를 만들 때는 지표 선택(부분 점수냐 완전 정답이냐), 타당도·신뢰도·변별력, 보상 해킹과 멀티턴을 챙겨야 한다.
  6. Vals AI는 사내 토큰 지출이 한 달 150만 달러까지 갔다. 자기 GitHub 기록으로 평가를 만든 뒤 같은 성과로 90% 덜 쓴다고 한다.
  7. 평가의 재료는 회사가 이미 가진 일의 기록이다. 평가는 사용량 조정, 가격 협상, 라우팅, 미세 조정에도 쓰인다.
01

모델 카드의 숫자 하나 00:20

Vals AI는 벤치마크를 만드는 회사다. 큰 AI 연구소들이 새 모델을 낼 때 공개하는 성적표, 즉 모델 카드model card에 이 회사의 벤치마크가 자주 실린다. 발표자는 최근 모델 발표에서도 Vals Index와 Finance Agent 벤치마크가 인용됐다고 소개한다.

Vals Index는 여러 벤치마크를 묶어 숫자 하나로 만든 지표다. 금융, 법률, 코딩, 의료 같은 분야에서 모델이 경제적으로 얼마나 쓸모 있는지 보려는 것이다. 이 숫자로 모델의 대략적인 실력은 알 수 있다. 하지만 전부는 아니다.

들쭉날쭉한 프런티어 01:20

Vals Index를 이루는 벤치마크를 하나씩 보면, 벤치마크마다 1등 모델이 다르다. 이것을 들쭉날쭉한 프런티어jagged frontier라고 부른다. 모델의 실력이 고르지 않고 과제에 따라 들쭉날쭉하다는 뜻이다.

  • 회사 단위로 보면 더 심하다. 특정 저장소에 맞춘 코딩 벤치마크를 만들면, 언어와 라이브러리마다 모델 순위가 더 잘게 갈린다. 01:50
  • 여기에 다른 변수가 더해진다. 같은 모델도 어떤 하네스harness(모델을 감싸 도구와 실행 순서를 정하는 틀)에서 돌리느냐에 따라 결과가 다르다. 성능만이 아니라 비용과 속도도 따져야 한다. 02:10

결론적으로 모델 카드의 숫자는 너무 거칠다. 실제로 모델을 쓰는 사람에게 필요한 해상도가 아니다.

02

돈은 쓰는데 수익은 안 보인다 02:30

기업의 AI 지출은 1년 사이 약 2배로 늘었다. 그런데 그 돈이 어디서 수익을 내는지는 여전히 잘 안 보인다.

발표자가 눈여겨본 점은 두 가지다. 03:00

  • AI 비용을 추적하는 회사일수록 투자 수익ROI, return on investment이 어디서 나오는지 훨씬 잘 안다.
  • 비용 대비 수익을 숫자로 못 내는 회사는 그것 때문에 AI를 넓게 도입하지 못한다.

그래서 발표자는 평가eval가 핵심이라고 본다. 모델이 무엇을 할 수 있는지, 돈을 어디에 쓰는 게 가장 효율적인지 재는 평가가 있으면 회사 안에서 AI를 더 넓게 쓸 수 있다.

03

싼 모델이 더 비쌌다 03:40

발표 제목이 나온 대목이다. 연구소가 보여 주는 숫자로 생긴 직감이 실제 경험과 왜 어긋나는지 보여 준다.

모델입력 토큰 단가출력 토큰 단가세금 벤치마크 결과
Fable 5.1 (Anthropic 최상위)$10$50기준
Opus 5.5 (Anthropic 두 번째 등급)$4$20과제당 비용 14% 더 비쌈, 점수 3% 낮음

이유는 간단하다. 덜 똑똑한 모델이 일을 끝내려고 토큰을 더 많이 썼다. 그렇게 쓰고도 점수는 더 낮았다. 이 과제에서는 최상위 모델을 쓰는 편이 돈도 덜 들고 결과도 좋았다.

계산해 보면(추론): 토큰 단가는 40%인데 과제당 비용이 114%라면, Opus 5.5는 Fable 5.1보다 토큰을 약 2.85배 썼다는 뜻이다(1.14 ÷ 0.40). 입력과 출력 토큰의 비율이 두 모델에서 같다고 가정한 계산이다.

왜 이 사실이 잘 안 보이나 모델을 쓰는 사람은 이런 정보를 바로 얻을 수 없다. 그래서 "돈을 아끼려면 Sonnet이나 Opus를 쓰자"고 정했다가, 더 낮은 성능에 돈을 더 내게 된다. 발표자는 연구소가 주는 직감 대신 수익이 실제로 어디서 나오는지 직접 확인하라고 말한다.

이 비교는 Vals AI가 만든 세금 벤치마크 하나의 결과다. 다른 과제에서도 같은 결과가 나온다는 뜻은 아니다. 발표의 요지도 "과제마다 직접 재라"는 것이다.

04

금융 벤치마크와 파레토 곡선 04:40

금융 분야에서도 들쭉날쭉함이 그대로 보인다. Vals AI의 금융 벤치마크는 이렇다.

벤치마크재는 것

이 벤치마크들 사이에서도 누가 1등, 2등, 3등인지 일정하지 않다.

비용과 성능을 같이 보기 05:00

파레토 곡선Pareto curve은 가로축에 비용, 세로축에 성능을 놓고 모델을 찍은 그림이다. 같은 비용에서 가장 성능이 좋은 모델들을 이은 선이 파레토 프런티어Pareto frontier다. 이 선 위에 있는 모델만 "가성비로 따져 고를 만한" 모델이다.

여기서 비용은 토큰 단가가 아니라 과제 하나를 끝내는 데 든 비용cost per task이다. 3장의 Opus 사례처럼 단가와 과제당 비용은 다를 수 있기 때문이다.

Excel 모델링 · 전체 과제

모든 문제를 합친 점수로 그린 프런티어. 종합 점수만 보면 이 그림을 믿게 된다.

Excel 모델링 · LBO 과제만 05:30

LBOleveraged buyout는 빌린 돈으로 회사를 인수하는 거래다. 이를 분석하는 엑셀 모델 과제만 떼어 냈다.

  • 프런티어 전체가 종합 점수보다 낮다
  • 프런티어에 오르는 모델도 바뀐다

종합 점수로는 Fable 5.1이 가장 좋은 선택처럼 보인다. 그런데 LBO 과제에서는 Fable 5.1이 프런티어 밖으로 밀려난다. 더 싼 다른 모델이 같거나 더 나은 점수를 낸다는 뜻이다. LBO 일이 많은 회사가 Fable 5.1을 쓰면, 그 분야 최고도 아닌 모델에 돈을 훨씬 많이 내는 셈이다. 06:10

이 장의 요점 중요한 것은 순위표 맨 위가 아니다. 우리 회사가 실제로 하는 과제에서의 성적, 그리고 그 안에서 비용과 성능을 어떻게 맞출지다.
05

어떤 정확도를 볼 것인가 06:30

여기부터는 벤치마크를 직접 만들며 얻은 교훈이다. 첫째는 정확도를 어떤 지표로 보고하느냐다. 지표를 바꾸면 결론이 달라진다.

부분 점수 06:50

partial credit 과제 하나를 맡기면, 채점 항목 중 평균 몇 %를 채우는가.

다듬어서 쓸 초안을 얼마나 잘 만드는지 보여 준다.

완전 정답 비율 07:00

fully correct answers 맡긴 과제 중 몇 %가 모든 항목을 채워 완벽하게 돌아오는가.

결과를 그대로 고객에게 넘길 수 있는지 보여 준다.

부분 점수가 높은 모델은 더 나은 답을 만들 출발점으로는 좋다. 하지만 그 결과를 바로 고객에게 보내면, 모든 기준을 채웠을지는 발표자 표현대로 "동전 던지기"일 수 있다.

예시 (발표에 없는 설명용 숫자) 채점 항목이 10개인 과제가 있다. 모델이 매번 9개를 채우고 1개를 놓친다면, 부분 점수는 90%다. 하지만 완전 정답 비율은 0%다. 같은 결과가 지표에 따라 "아주 잘함"도 되고 "한 번도 못 함"도 된다.

07

평가를 만들 때 부딪히는 문제 08:40

1. 에이전트는 문제가 아니라 과제를 푼다

흔히 보상 해킹reward hacking이라고 부른다. 채점 방식의 빈틈을 노려 점수만 따는 행동이다. 발표자가 든 예는 두 가지다.

  • 샌드박스 탈출 08:50: Vals AI는 모델을 격리된 실행 환경(sandbox)에서 자사 모델 프록시를 거쳐 돌린다. 그런데 모델이 그 프록시로 다른 모델을 불러 샌드박스를 빠져나가거나 인터넷을 쓰려 한 적이 있다. 그래서 컨테이너는 "이 모델이 스스로 할 수 있나"만 재도록 지어야 한다.
  • 답 여러 개 내기 09:10: 금융 평가는 답에 들어가야 할 항목을 채점 기준표(rubric)로 정해 둔다. 모델이 그럴 법한 답을 세 개 내면 항목을 다 채울 확률이 올라간다. 하지만 실제 사람은 답 세 개를 원하지 않는다. 첫 답이 맞기를 원한다.

목표는 모델이 요령으로 통과할 수 있는 억지 평가가 아니라, 실제 일과 사람이 원하는 결과물을 닮은 평가다.

2. 평가를 돌리는 인프라가 어렵다 09:50

코드를 만드는 비용은 크게 내려갔다. 하지만 평가를 돌리는 일은 여전히 어렵다. 특히 오래 실행되는 에이전트를 평가하려면, 인프라가 오랫동안 안정적이어야 하고 중간에 끊겨도 이어서 다시 돌릴 수 있어야 한다. Vals AI는 평가에만 토큰 6조 개를 넘게 썼고, 최대한 병렬로 돌린다고 한다. 규모가 훨씬 작은 팀도 같은 문제를 겪을 것이라는 게 발표자의 말이다.

3. 실제 일은 멀티턴이다 10:30

기존 벤치마크는 대부분 질문 하나에 답 하나다. 실제 일은 다르다. 처음 요구사항으로 다 됐다고 생각해도, 질문이 되돌아오고 만들어진 것을 보고 피드백이 붙는다. 이런 주고받기를 거쳐 최종 결과에 닿는다. 평가도 이 멀티턴multi-turn 과정을 다뤄야 한다.

08

사례: 한 달 토큰 150만 달러 10:50

Vals AI는 사내에서 "토큰 맥싱" 실험을 했다. 몇몇 도구를 무료로 쓸 수 있게 되자 모든 엔지니어에게 나눠 주고 토큰을 마음껏 쓰게 했다. 결과는 이렇다.

  • 그 달 토큰 지출은 150만 달러였다. 엔지니어는 10~12명 정도였다. 11:10
  • 같은 달 급여의 약 10배를 토큰에 쓴 셈이다.
  • 결과물은 훌륭했다.

목표는 같은 결과물을 유지하면서 비용을 크게 줄이는 것이었다. 방법은 당연히 평가를 만드는 것이었다.

GitHub 기록으로 평가 만들기 11:40

  1. GitHub 저장소는 이미 한 일과 진행 중인 일의 기록이다.
  2. 저장소의 PR(코드 변경 요청)에는 이슈와 그 해결이 함께 들어 있다.
  3. 시계를 되돌려 같은 이슈를 에이전트에게 맡긴다. 사람이 한 일을 에이전트도 해낼 수 있었는지 본다. 12:00
  4. 그러면 어떤 모델이 과하게 비싸서 쓸 필요가 없는지, 어떤 모델이면 충분한지가 보인다.

Vals AI는 이렇게 만든 사내 도구를 Val Smith(들린 대로, 추정)라는 제품으로 내놓았다.

오픈소스로 바꾸면 싸질까 12:20

흔한 직감은 "닫힌 모델을 많이 쓰니, 오픈소스 모델을 직접 띄우면 싸겠지"다. 사내 평가 결과는 반대였다.

비용$2.50$11 (추론 최적화 스택에서 직접 호스팅)
걸린 시간절반기준

점수, 비용, 속도 모두 닫힌 모델 쪽이 나았다. 이 경우 "오픈소스로 비용을 줄이자"는 직감은 맞지 않았다.

달라진 것 12:50

  • 구매와 한도: 어떤 도구를 살지, 조직 전체의 사용 한도를 얼마로 할지 정할 수 있게 됐다.
  • 작업별 추천: "이 GitHub 이슈에는 이 코딩 도구와 이 모델을 쓰라"고 엔지니어에게 추천한다.

발표자에 따르면 지금은 90% 덜 쓰면서 같은 결과물을 낸다. 13:10

Vals AI는 평가와 벤치마크를 파는 회사이고, 이 사례 끝에서 자사 제품을 소개한다. "평가를 만들면 비용이 준다"는 결론은 그 점을 감안해 읽자.

09

회사의 일 기록이 평가 재료다 13:20

Vals AI는 코딩에서 쓴 이 방식을 법률, 금융 같은 다른 지식 노동으로 넓히는 중이다. 코딩에는 GitHub라는 일의 기록이 있다. 다른 분야에서는 무엇이 그 역할을 할까.

발표자가 던지는 질문은 이것이다. 우리 회사가 이미 해 온 일의 기록은 어디에 있나. 우리 회사의 "잘한 일"의 기준은 어디에 남아 있나. 어떤 로펌은 100년 가까이 일해 왔다. 그 품질의 기록은 지금 이런 곳에 흩어져 있다. 13:40

  • 고객과 주고받은 이메일
  • SharePoint 문서
  • Databricks에 쌓아 둔 데이터

발표자는 많은 회사가 이 보물 창고를 갖고도 모른다고 본다. 이것이 평가를 만드는 열쇠이고, 그 평가가 AI를 체계적으로 도입하는 열쇠다.

10

평가를 만든 뒤 쓰는 법 14:10

평가는 도입을 가능하게 할 뿐 아니라, 더 유리하게 쓸 수 있는 길이 네 가지 있다.

쓰임하는 일
사용량 맞추기 right-sizing토큰을 무조건 많이 쓰는 대신, 조직 전체의 알맞은 사용 한도를 정한다
가격 협상 negotiation어떤 모델로 바꿔도 되는지 알면 협상력이 생긴다. 대량 구매 가격 협상에 쓴다
라우팅 routing과제마다 알맞은 모델을 골라 보내는 장치를 만든다. AI 제품의 기본 기능이 돼 가지만 사용자가 직접 만들 수도 있다
미세 조정·사후 학습 fine-tuning, post-training평가 과제로 학습 데이터를 만들고, 따로 떼어 둔 평가 세트로 효과를 확인한다

마지막 메시지 14:50

많은 회사의 경쟁력은 직원의 머릿속, 즉 조직이 쌓아 온 암묵지에 있다. 평가를 만들면 그 경쟁력을 글과 스크립트로 옮길 수 있다.

발표자는 이것이 에이전트 시대에 회사가 살아남는 가장 큰 열쇠라고 말한다.

11

핵심 정리

  1. 모델 카드의 종합 점수는 거칠다. 분야, 회사, 저장소로 내려갈수록 1등이 자주 바뀐다(들쭉날쭉한 프런티어).
  2. 하네스, 비용, 속도까지 따지면 "가장 좋은 모델"은 더 상황마다 다르다.
  3. AI를 자주 쓰는 회사는 90%, ROI가 확인된 곳은 7%다. 비용을 추적하는 회사가 수익도 더 잘 안다.
  4. 토큰 단가 ≠ 과제당 비용. Opus 5.5는 단가가 40%인데 세금 벤치마크에서 과제당 14% 더 비쌌고 점수도 낮았다.
  5. 비교는 파레토 곡선으로 한다. 가로축은 과제당 비용, 세로축은 성능이다.
  6. 같은 벤치마크 안에서도 하위 과제(LBO)만 보면 프런티어가 낮아지고, 고를 모델도 바뀐다.
  7. 지표를 고르면 결론이 바뀐다. 부분 점수는 초안 품질, 완전 정답 비율은 그대로 넘길 수 있는지를 보여 준다.
  8. 좋은 평가는 타당도, 신뢰도, 변별력을 갖추고, 지금 모델이 못 하는 과제도 담는다.
  9. 보상 해킹(샌드박스 탈출, 답 여러 개 내기), 인프라, 멀티턴을 미리 대비한다.
  10. 평가 재료는 회사가 이미 가진 일의 기록이다. 평가로 한도, 협상, 라우팅, 학습을 정한다. Vals AI는 이렇게 90%를 줄였다고 한다.

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1"들쭉날쭉한 프런티어"란 무엇인가?
모델의 실력이 과제마다 고르지 않아, 벤치마크나 분야에 따라 1등 모델이 바뀌는 현상이다. 회사나 저장소 단위로 좁히면 더 심해진다.
Q290%와 7%는 각각 무엇을 잰 숫자인가?
AI를 정기적으로 쓰는 회사 비율(90%)과 투자 수익이 확인된 회사 비율(7%). 많이 쓰지만 어디서 수익이 나는지는 잘 모른다는 뜻이다.
Q3Opus 5.5가 토큰 단가는 싼데 세금 벤치마크에서 더 비쌌던 이유는?
덜 똑똑한 모델이 일을 끝내려고 토큰을 훨씬 많이 썼다. 단가 40%로 비용 114%가 나왔다면 토큰을 약 2.85배 쓴 셈이다. 그러고도 점수는 3% 낮았다.
Q4파레토 곡선에서 가로축 비용을 토큰 단가가 아니라 과제당 비용으로 잡는 이유는?
모델마다 과제 하나에 쓰는 토큰 수가 다르다. 단가가 싸도 토큰을 많이 쓰면 실제 비용은 더 나온다.
Q5LBO 과제만 떼어 보았을 때 바뀐 두 가지는?
프런티어 전체가 종합 점수보다 낮아졌고, 프런티어에 오르는 모델이 바뀌었다. Fable 5.1은 프런티어 밖으로 밀려났다.
Q6부분 점수와 완전 정답 비율은 각각 무엇을 알려 주나?
부분 점수는 과제당 채점 항목을 평균 몇 % 채우는지, 즉 다듬어 쓸 초안의 품질이다. 완전 정답 비율은 몇 %가 모든 항목을 채워 그대로 고객에게 넘길 수 있는지다.
Q7좋은 평가의 세 조건과 각각의 흔한 실패는?
타당도: 억지로 만든 과제. 신뢰도: 샘플 5~6개로 느낌만 보기. 변별력: 모든 모델이 100점이거나 0점인 벤치마크.
Q8발표자가 든 보상 해킹의 두 예는?
모델 프록시로 다른 모델을 불러 샌드박스를 빠져나가려 한 것, 그리고 금융 평가에서 답을 세 개 내서 채점 항목을 채울 확률을 높인 것.
Q9Vals AI는 GitHub 저장소로 어떻게 평가를 만들었나?
PR에 담긴 이슈와 해결을 가져와, 시계를 되돌려 같은 이슈를 에이전트에게 맡겼다. 사람이 한 일을 해낼 수 있는지로 모델이 과한지, 충분한지를 가렸다.
Q10오픈소스 모델을 직접 띄우면 싸다는 직감은 이 사례에서 어떻게 됐나?
맞지 않았다. 닫힌 모델(GPT-5.6 Soul, 추정)이 점수 2% 높고, 비용 $2.50 대 $11로 싸고, 시간도 절반이었다.
Q11평가를 만든 뒤 쓸 수 있는 네 가지 쓰임은?
사용량 맞추기, 가격 협상, 라우팅, 미세 조정·사후 학습.

하네스Harness. 모델을 감싸 도구, 실행 순서, 규칙을 정해 주는 실행 틀
ROIReturn on investment. 들인 돈에 비해 얻은 이익
평가 (eval)모델이나 시스템의 결과 품질을 재는 과제 묶음과 채점 방식
과제당 비용Cost per task. 과제 하나를 끝내는 데 실제로 든 비용. 토큰 단가 × 쓴 토큰 수
파레토 프런티어Pareto frontier. 비용과 성능 그림에서, 더 싸면서 더 좋은 모델이 없는 모델들을 이은 선
LBOLeveraged buyout. 빌린 돈을 지렛대로 회사를 인수하는 거래. 금융 엑셀 모델링의 대표 과제
부분 점수Partial credit. 채점 항목 중 채운 비율의 평균
완전 정답 비율Fully correct answers. 모든 채점 항목을 채운 과제의 비율
루브릭Rubric. 답에 무엇이 들어가야 하는지 정한 채점 기준표
타당도 · 신뢰도 · 변별력Validity · reliability · discriminability. 실제 일을 재는가 · 반복해도 같은가 · 모델 차이를 가르는가
보상 해킹Reward hacking. 채점 방식의 빈틈을 노려 실제 문제는 풀지 않고 점수만 따는 행동
샌드박스Sandbox. 바깥과 격리해 모델을 돌리는 실행 환경
멀티턴Multi-turn. 질문과 답, 피드백을 여러 번 주고받으며 일을 끝내는 방식
토큰 맥싱Token maxing. 비용을 따지지 않고 토큰을 최대한 쓰게 하는 것
라우팅Routing. 과제마다 알맞은 모델을 골라 보내는 것
사후 학습Post-training. 이미 학습된 모델을 특정 목적에 맞게 추가로 학습시키는 것. 미세 조정(fine-tuning)이 그 한 방법
