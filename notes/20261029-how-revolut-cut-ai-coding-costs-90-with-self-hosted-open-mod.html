레볼루트는 왜 코딩 모델을 직접 띄웠나

레볼루트는 엔지니어 2,000명이 쓰는 코딩 모델을 오픈 모델 GLM으로 바꾸고 자체 GPU에 올렸다. 비용은 10분의 1로 줄었다. 토큰 걱정이 사라지자 기능 하나를 끝내는 시간이 크게 줄었다.

원본 영상: How Revolut Cut AI Coding Costs 90% With Self-Hosted Open Models 발표: David Abitbol (Revolut AI 운영 책임자)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 이름이 뭉개진 곳은 확실한 경우만 바로잡았고, 나머지는 "(추정)"을 붙였다. mm:ss는 영상 위치다.

3분 요약
  1. 상용 코딩 에이전트는 한 사람이 한 달에 수천~수만 달러를 썼다. 그래서 엄격한 예산 제한을 걸었고, 효과는 작았다.
  2. 오픈 모델 GLM을 자체 GPU에 올려 토큰을 무제한으로 풀자 코딩 시간은 60%, 리드 타임은 70% 줄었다.
  3. 리드 타임이 더 많이 줄었다. 엔지니어링의 병목은 코딩만이 아니라 메일, Jira, Confluence 같은 주변 일이었다.
  4. 엔지니어 2,000명에 B200 GPU 56장이 든다. 토큰 100만 개당 30센트이고, 청구액은 상용 API의 10분의 1이다.
  5. 체감 품질은 첫 토큰까지 걸리는 시간이 정한다. 3초 아래가 목표이고 5초를 넘으면 불만이 쏟아진다.
  6. GPU를 늘리지 않고 설정 튜닝만으로 그 시간을 10초 넘게에서 1.6초로 줄였다.
  7. 은행 규제는 가중치만 받아 자기 인프라에 올리기, 샌드박스로 사람 승인을 보장하기, 로그를 깊게 남기기로 통과했다.
01

레볼루트와 발표 배경 00:00

레볼루트는 유럽의 디지털 은행이다. 발표자가 소개한 규모는 이렇다.

  • 고객 8천만 명, 45개 시장에서 영업
  • 지난 1년간 유럽에서 가장 많이 내려받은 금융 앱
  • 올해 7월 기준 유럽 최대 비상장 기업

회사는 제품을 많이, 빨리 내놓는 걸 중시한다. 그래서 엔지니어링 문화와 생산성에 관심이 크다. 발표는 오픈 모델을 전용 GPU에 직접 올려 쓰는 자체 호스팅self-hosting의 기술적 세부를 다룬다.

발표자는 엔지니어 2,000명의 지난 1년 성과를 두 지표로 보여 줬다.

도입 순서 02:10

  1. 2025년 1월: 사내에 처음 AI를 들였다. Gemini였다. 회사 내부 데이터를 AI에 넣을 수 있게 된 첫 시점이다.
  2. 2025년 2월 무렵: Claude Code를 시험하기 시작했다. 발표자는 당시 Claude Code가 지금처럼 안전하지 않았다고 농담처럼 덧붙였다.
  3. 2026년 1월: Claude Code를 회사 전체로 넓혔다.
  4. 2026년 4월: 오픈 모델을 자체 호스팅하기 시작했다. 코딩에는 GLM을 쓴다.

자막에는 "January 25th", "April 26th"로 나온다. 앞뒤 맥락상 날짜가 아니라 2025년 1월, 2026년 4월을 말한 것으로 읽었다(추정). Claude Code 전사 도입도 자막에는 "January"로만 나와 2026년 1월로 읽었다(추정).

Gemini 단계의 효과는 단순했다. 엔지니어가 Stack Overflow를 뒤지거나 문서를 읽을 일이 줄었다.

모든 수치는 레볼루트 내부 측정이다. 같은 기간 모델 자체도 빠르게 좋아졌으므로, 개선 폭 전부를 자체 호스팅 하나의 효과로 보기는 어렵다(추론).

03

비싼 토큰에 예산을 걸었다 02:40

Claude Code를 처음 넓힐 때 회사는 비용을 크게 의심했다. 엔지니어 한 명이 한 달에 1천 달러, 많게는 1만 달러를 썼다. 그만큼 성과가 나는지는 분명하지 않았다.

그래서 엄격한 예산 한도를 걸고 배포했다. 결과는 기대에 못 미쳤다.

다음 목표 엔지니어에게 토큰을 무제한으로 주자. 비용 걱정 없이 쓰게 하되, 전체 비용은 지금의 일부로 줄이자. 그 답으로 오픈 모델을 살펴봤다.
04

무제한 토큰이 바꾼 것 03:10

2026년 4월부터 오픈 모델 GLM-5.1(추정)을 자체 호스팅했다. 효과는 극적이었다. 코딩 시간은 60%, 리드 타임은 70% 줄었다.

병목은 코딩이 아니었다 03:30

눈여겨볼 점은 리드 타임이 코딩 시간보다 더 많이 줄었다는 것이다. 기능 하나를 끝내는 데 코드를 쓰는 시간만 드는 건 아니다.

  • 받은 메일함 뒤지기
  • Jira 티켓 정리
  • Confluence 문서 찾기

토큰이 무제한이면 이런 주변 일에도 AI를 마음껏 쓴다. 분기 말을 위해 토큰을 아끼거나, 가장 어려운 일에만 쓰려고 참을 필요가 없다.

05

오픈 모델이 기본, 프런티어는 예외 04:00

지금 레볼루트에서는 오픈 모델이 우선이다. 비용 구조가 유리하다. 비용이 GPU 임대료로 고정되어 있어서, 월말에 청구서를 보고 놀랄 일이 없다.

가장 성능이 좋은 프런티어 모델frontier model은 예외로만 쓴다. Codex, Claude Code, Gemini도 계속 쓴다. 발표자도 최신 모델들이 훌륭하다고 인정했다. 다만 기본값은 아니다.

06

자체 호스팅에서 볼 숫자 04:20

항목값설명
GPUB200 56장엔지니어 2,000명에게 GLM-5.3(추정)을 서비스하는 데 필요한 대략적인 양. GPU 한 장당 엔지니어 약 36명이다(계산)
모델 크기약 8천억 개 파라미터발표자는 GLM을 "큰 모델"이라고 했다
첫 토큰 시간3초 이하 목표5초를 넘으면 발표자의 Slack이 불만으로 터진다. 경험으로 찾은 한계다

비용100만 토큰당 30센트여러 사용 유형을 섞은 평균 단가

빠르게 받는 것보다 빨리 시작하는 게 중요하다 04:40

첫 토큰 시간TTFT, time to first token은 요청을 보내고 첫 글자가 돌아오기까지 걸리는 시간이다. 사람이 체감하는 기준은 이것이다.

반면 처리 속도throughput는 생각만큼 중요하지 않다. 일하는 방식이 바뀌었기 때문이다. 이제 사람들은 모델이 생각하는 과정을 지켜보지 않는다. 여러 작업을 동시에 돌려 놓고 끝나면 확인한다.

07

같은 GPU로 성능 끌어올리기 05:40

GPU를 빌려 모델 가중치를 올리고 바로 추론을 돌리면 성능이 형편없다. 성능은 작업 특성에 맞춘 설정값에 크게 좌우된다.

발표자는 4월부터 8월까지의 변화를 보여 줬다. 두 선을 비교한다.

  • 수요: 초당 요청 수RPS, requests per second. 지연을 만드는 원인이다.
  • 첫 토큰 시간: 최적화 목표다.

이 기간 내내 GPU 수는 56장 그대로였다.

발표자는 이를 수요가 76% 늘어나는 동안 성능이 88% 좋아졌다고 요약했다.

발표자가 말한 대략값으로 계산하면 숫자가 맞지 않는다. 초당 요청이 약 3에서 7 이상이 됐다면 증가율은 76%가 아니라 130% 이상이다. 첫 토큰 시간이 10초에서 1.6초가 됐다면 84% 단축이다. 88%가 되려면 시작값이 약 13초여야 하는데, "10초 초과"와 모순되지는 않는다. 차트의 정확한 값은 자막만으로 알 수 없어 어느 쪽이 맞는지 확인하지 못했다.

교훈 손볼 수 있는 설정이 많다. 오픈 모델을 대규모로 서비스하려면 하드웨어를 늘리기 전에 설정부터 튜닝해야 한다.
08

손봐야 할 설정 07:00

발표자는 "비법은 없다"고 했다. 대신 살펴볼 항목을 꼽았다.

설정발표자 권고이유
컨텍스트 길이25만 6천 토큰이면 충분100만 토큰도 서비스할 수 있지만 실제로 필요하지 않다. 발표자는 "긴 컨텍스트는 사기"라고까지 말했다
양자화Blackwell 세대 GPU라면 FP4보다 높이지 말 것. NVFP4가 가장 좋다FP8 대신 FP4를 쓰면 GPU 사용량이 약 40% 줄고, 정확도 손실은 없다고 했다
텐서 병렬화TP4에 들어가도 TP8을 검토GLM은 GPU 4장에 들어가지만 KV 캐시 자리가 모자란다. 작업량이 크면 8장으로 나누는 편이 낫다
캐시 적중률코딩 작업은 90% 이상코딩 에이전트는 같은 앞부분을 반복해서 보내므로, 이미 계산한 결과를 다시 써야 한다
그 밖의 기법투기적 디코딩, 프리필 방식, PD 분리(추정)발표자가 "더 난해한 것들"로 이름만 꼽았다

발표에서는 "FP4에서 FP8로 가면 40% 절약"이라고 말했지만, 절약은 FP8에서 FP4로 내릴 때 생긴다. 표에는 방향을 바로잡아 적었다. "정확도 손실 없음"은 발표자의 주장이다. NVFP4는 자막의 "VFP4"를 NVIDIA의 FP4 형식으로 고친 것이다.

"그 밖의 기법"은 자막이 뭉개졌다. "sequential pre-fill"은 들린 대로 옮겼고 chunked prefill일 수 있다(추정). "PGD zag"는 프리필과 디코드를 다른 GPU로 나누는 PD disaggregation으로 추정했다.

09

운영 구성: 이미지와 하네스 08:10

텍스트 전용 모델의 빈자리

GLM은 텍스트만 다루는 모델이다. 이미지를 못 읽는 게 불편한 사람도 있다. 발표자는 매번 같은 선택을 하겠다고 했다. 더 똑똑한 모델을 고르고, 이미지 인식은 다른 방법으로 해결한다.

  • 로컬 라우터: 이미지 인식 요청만 Gemini 같은 다른 모델로 보내고, 본 작업은 GLM이 한다. 발표자가 예로 든 도구 이름은 "Open Codex"로 들렸다(추정).
  • 비전 모델: 꼭 필요하면 GLM-5V Flash(추정)가 잘 맞는다. 사내 UI 디자이너가 잘 쓰고 있고, UI 작업의 처리 시간이 크게 줄었다.

하네스는 그대로 09:00

자체 호스팅한 모든 엔드포인트는 OpenAI 호환 API로 열려 있다. Responses API도 지원한다. 그래서 OpenCode, Codex CLI, Codex 앱 같은 기존 하네스harness에 그대로 붙여 쓸 수 있다. 발표자가 권하는 구성이다.

10

규제와 보안 09:20

중국 오픈 모델에 대한 우려

발표자는 이 부분을 CIO에게 하는 말이라고 했다. 중국에서 만든 오픈 모델을 쓰는 데 대한 거부감이 크다. 하지만 중국으로 가는 추론 엔드포인트를 쓰는 게 아니다. 가중치만 받아서 미국에 있는 서버에 올린다. 그러니 데이터 공유 측면에서는 문제가 없다는 것이 발표자의 판단이다.

사람 승인을 보장하는 샌드박스 09:50

레볼루트는 EU 규제를 받는 은행이라 가장 엄격한 컴플라이언스 기준을 적용받는다. 통한 논리는 이렇다.

  1. 코딩 작업은 자율 에이전트autonomous agent가 아니다. 항상 사람이 중간에서 승인한다human in the loop.
  2. 이걸 증명하려고 샌드박스를 만든다. Claude Code나 Codex 같은 도구의 "승인 요청" 기능을 쓰고, 허용하지 않을 작업의 규칙을 정한다. 예를 들어 grep은 허용하고 Gradle은 막는다.
  3. 그러면 규제 당국은 이것이 별도 감독이 필요한 자율 에이전트가 아니라고 확신할 수 있다.

샌드박스는 다른 위험도 막는다.

  • 내부 악용: 큰 회사에는 나쁜 의도를 가진 사람이 있을 수 있다. 발표자는 "큰 회사에서 뭘 발견하게 될지 알면 놀랄 것"이라고 했다.
  • 프롬프트 인젝션: 요즘 모델이 똑똑해져서 예전만큼 큰 문제는 아니지만, 늘 대비해야 한다.

데이터 보호와 로그 10:50

  • 데이터 위치: 데이터가 미국, EU, 영국, 이스라엘처럼 EU와 동등한 보호 수준을 인정받은 나라에 있으면 괜찮다. 발표자는 이를 "data equivalency framework"라고 불렀고, EU의 적정성 결정을 가리키는 것으로 보인다(추정).
  • 데이터 보관: 추론 서비스나 GPU 임대 업체는 기본적으로 데이터를 보관하지 않는다zero data retention고 했다.
  • 관측: OpenTelemetry로 로그를 탄탄하게 남긴다. 사고가 나면 깊이 파고들 수 있어야 한다. 사용 분석에도 쓴다.

규제 통과 논리와 데이터 공유 판단은 레볼루트의 사례이자 발표자의 판단이다. 법률 검토 결과로 그대로 가져다 쓰면 안 된다.

11

핵심 정리

  1. 예산 한도를 건 상용 코딩 에이전트는 비용에 비해 효과가 작았다.
  2. GLM을 자체 호스팅해 토큰을 무제한으로 풀자 코딩 시간 60%, 리드 타임 70%가 줄었다.
  3. 리드 타임이 더 많이 줄었다. 병목은 코딩 바깥의 주변 일에도 있었다.
  4. 오픈 모델이 기본이고, 프런티어 모델은 예외로만 쓴다.
  5. 엔지니어 2,000명에 B200 56장, 100만 토큰당 30센트, 청구액은 10분의 1이다.
  6. 체감 기준은 첫 토큰 시간이다. 3초 이하가 목표, 5초가 한계다. 처리 속도는 초당 200토큰이면 충분하다.
  7. GPU를 늘리지 않고 튜닝만으로 첫 토큰 시간을 10초 넘게에서 1.6초로 줄였다.
  8. 설정 요점: 컨텍스트 256K, FP4(NVFP4), 필요하면 TP8, 캐시 적중률 90% 이상.
  9. 이미지는 다른 모델로 라우팅하고, OpenAI 호환 API로 기존 하네스에 붙인다.
  10. 규제는 가중치만 자기 인프라에, 샌드박스로 사람 승인 보장, 데이터 미보관, OpenTelemetry로 통과한다.
12

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1리드 타임과 코딩 시간은 각각 무엇을 재나?
리드 타임은 기능을 맡은 순간부터 머지되어 배포 준비가 끝날 때까지다. 코딩 시간은 실제로 코드를 쓰는 데 든 시간이다.
Q2Claude Code를 처음 넓혔을 때 효과가 작았던 이유는?
엔지니어가 한 달에 1천~1만 달러를 써서 비용이 의심스러웠다. 그래서 엄격한 예산 한도를 걸었고, 엔지니어가 토큰을 아껴 쓰게 됐다.
Q3GLM 자체 호스팅 뒤 리드 타임이 코딩 시간보다 더 줄었다. 무엇을 뜻하나?
엔지니어링의 병목이 코딩만이 아니라는 뜻이다. 메일, Jira, Confluence 같은 주변 일에도 시간이 많이 들었고, 무제한 토큰으로 그 일까지 AI에 맡겼다.
Q4엔지니어 2,000명에 필요한 GPU와 토큰 단가는?
B200 56장, 100만 토큰당 30센트(혼합 평균). 청구액은 상용 API의 10분의 1이다.
Q5발표자가 처리 속도보다 첫 토큰 시간을 더 중요하게 본 이유는?
사람들이 이제 모델의 생각 과정을 지켜보지 않는다. 여러 작업을 동시에 돌리고 끝나면 확인한다. 그래서 초당 200토큰이면 충분하고, 체감은 첫 응답이 얼마나 빨리 오느냐가 정한다.
Q6첫 토큰 시간의 목표와 한계는?
3초 이하가 목표다. 5초를 넘으면 사용자 불만이 쏟아진다.
Q74월에서 8월 사이 첫 토큰 시간을 줄인 방법은? GPU는 몇 장 늘렸나?
서빙 설정을 튜닝했다. GPU는 56장 그대로였다. 수요가 늘었는데도 10초 넘게에서 1.6초로 줄었다.
Q8발표자가 "긴 컨텍스트는 사기"라고 한 뜻은?
100만 토큰을 서비스할 수 있어도 실제로는 25만 6천 토큰이면 충분하다. 필요 없는 길이에 자원을 쓰지 말라는 뜻이다.
Q9GLM이 TP4에 들어가는데도 TP8을 검토하라는 이유는?
4장에 나누면 KV 캐시 자리가 모자란다. 작업량이 크면 8장으로 나눠 캐시 공간을 확보하는 편이 낫다.
Q10텍스트 전용 모델로 이미지 요청을 처리하는 방법은?
로컬 라우터로 이미지 인식 요청만 Gemini 같은 다른 모델로 보낸다. 꼭 필요하면 GLM 계열 비전 모델을 따로 쓴다.
Q11EU 은행 규제를 통과한 핵심 논리는?
코딩 작업은 항상 사람이 승인하므로 자율 에이전트가 아니다. 샌드박스로 허용 작업 규칙을 정해 이를 보장한다.
Q12중국에서 만든 모델을 써도 데이터 공유 측면에서 괜찮다고 본 이유는?
중국의 추론 엔드포인트를 쓰지 않는다. 가중치만 받아 미국에 있는 서버에 올리므로 데이터가 밖으로 나가지 않는다.

용어 정리

용어뜻
자체 호스팅Self-hosting. 모델을 외부 API로 부르지 않고 직접 확보한 GPU에 올려 운영하는 것
오픈 모델가중치를 공개해 누구나 받아서 돌릴 수 있는 모델. 발표에서는 "오픈소스 모델"이라고 불렀다
가중치Weights. 학습으로 얻은 모델의 숫자 값 묶음. 이것만 있으면 모델을 직접 돌릴 수 있다
프런티어 모델Frontier model. 각 회사의 가장 성능이 좋은 최신 상용 모델
리드 타임Lead time. 일을 맡은 순간부터 배포 준비가 끝날 때까지 걸린 시간
B200 · BlackwellNVIDIA의 데이터센터 GPU와 그 세대 이름
첫 토큰 시간TTFT, time to first token. 요청을 보내고 첫 응답 조각이 올 때까지 걸리는 시간
처리 속도Throughput. 초당 만들어 내는 토큰 수(TPS)
초당 요청 수RPS, requests per second. 서버에 들어오는 수요의 크기
혼합 단가Blended cost. 입력, 출력, 캐시 등 여러 토큰 유형을 섞어 낸 평균 가격
양자화Quantization. 모델 숫자를 더 적은 비트로 표현해 메모리와 계산을 줄이는 것. FP8, FP4는 각각 8비트, 4비트 부동소수점이다
NVFP4NVIDIA가 Blackwell용으로 만든 4비트 부동소수점 형식
텐서 병렬화Tensor parallelism. 모델 하나를 여러 GPU에 쪼개 올리는 방법. TP4는 4장, TP8은 8장에 나눈다
KV 캐시모델이 앞 문맥을 다시 계산하지 않도록 중간 결과를 GPU 메모리에 저장해 둔 것
캐시 적중률Cache hit rate. 요청의 앞부분을 이미 계산해 둔 결과로 처리한 비율
투기적 디코딩Speculative decoding. 작은 모델이 먼저 토큰을 추측하고 큰 모델이 한꺼번에 검증해 속도를 높이는 기법
프리필Prefill. 입력 문맥 전체를 처음 한 번 읽어 KV 캐시를 채우는 단계. 이후 토큰을 하나씩 만드는 단계는 디코드라고 한다
하네스모델을 감싸 도구, 순서, 규칙을 정해 주는 실행 틀. 예: OpenCode, Codex
OpenAI 호환 APIOpenAI API와 같은 형식으로 요청을 받는 엔드포인트. 기존 도구를 주소만 바꿔 붙일 수 있다
휴먼 인 더 루프Human in the loop. 에이전트의 작업 중간에 사람이 승인하는 구조
샌드박스에이전트가 할 수 있는 작업을 규칙으로 제한한 격리 환경
프롬프트 인젝션입력 안에 지시문을 숨겨 AI가 원래 지시 대신 그걸 따르게 만드는 공격
데이터 미보관Zero data retention. 업체가 요청과 응답을 저장하지 않는 정책
OpenTelemetry로그, 지표, 추적 데이터를 모으는 표준 도구 모음
