AI 에이전트는 어떻게 결제하나

사용자가 ChatGPT나 Google AI 모드 안에서 물건을 고르면, 결제는 누가 어떻게 처리할까. PayPal의 Sam Parsons가 판매자 입장에서 쓸 수 있는 세 가지 길을 보여 준다. 공통점은 하나다. 판매자는 어느 길로 오든 결국 평소 쓰던 결제 토큰 하나를 받는다.

원본 영상: How AI Agents Pay: Checkout in ChatGPT and Google AI Mode 발표: Sam Parsons (PayPal 시니어 스태프 엔지니어, 에이전트 커머스 담당)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 발표 내용은 모두 발표자의 설명이고 원 문서를 따로 확인하지는 않았다. 자막에서 이름이 뭉개진 곳은 확실한 것만 알려진 이름으로 바로잡았다. mm:ss는 영상 위치다.

발표자는 PayPal 소속이고, 발표 내용은 PayPal 엔터프라이즈 결제 제품을 전제로 한다. 제품 소개의 성격이 강하니 그 점을 감안해 읽자.

3분 요약
  1. PayPal 엔터프라이즈 결제는 Braintree의 새 이름이다. 큰 기업의 결제를 대신 처리하는 사업이다.
  2. 에이전트에서 결제를 받는 길은 세 가지다. ChatGPT 인스턴트 체크아웃, Google AI 모드, 그리고 MCP 앱에서 외부 결제 페이지로 넘기기.
  3. ChatGPT는 OpenAI의 에이전트 커머스 프로토콜, Google은 유니버설 커머스 프로토콜을 쓴다. 발표자에 따르면 두 규격은 거의 같다.
  4. 어느 길이든 사용자의 카드 번호는 토큰으로 바뀐 뒤 판매자에게 간다. 판매자는 카드 번호를 만지지 않는다.
  5. 토큰은 특정 판매자, 최대 금액, 통화, 만료 시간으로 제한된다. 거래에는 어느 에이전트에서 왔는지 출처가 붙는다.
  6. ChatGPT 길은 판매자가 MCP 앱으로 UI를 직접 만든다. Google 길은 UI 없이 상품 목록과 결제 엔드포인트만 세운다.
  7. 세 번째 길은 어느 에이전트에서나 쓸 수 있고 판매자가 모든 것을 통제하지만, 채팅 밖으로 나갔다 와야 해서 마찰이 조금 더 크다.
01

누가, 무엇을 말하나 00:10

발표자 Sam Parsons는 PayPal에서 에이전트 커머스 agentic commerce 영역을 맡고 있다. 에이전트 커머스란 사람 대신, 또는 사람과 함께 AI 에이전트가 물건을 고르고 사는 것을 말한다.

발표의 주제는 "에이전트가 산 물건의 돈을 판매자가 어떻게 받느냐"다. 사람이 중간에 확인하는 경우도 있고 아닌 경우도 있다.

Braintree가 곧 PayPal 엔터프라이즈 결제 Braintree는 PayPal이 운영하던 대기업용 결제 처리 사업이다. 지금은 PayPal 엔터프라이즈 결제 PayPal Enterprise Payments로 이름이 바뀌었다. 발표자는 "아주 큰 회사들의 엄청난 거래량을 처리한다"고 설명한다. 이 노트에서는 줄여서 "PayPal 결제"라고 쓴다.
02

세 가지 길 01:00

발표자가 가장 전하고 싶은 메시지는 이것이다. PayPal 결제는 판매자가 여러 곳에서 오는 결제를 받을 수 있게 다리를 놓고 있다. 이 영역은 빠르게 바뀌고 있어서 앞으로 몇 달, 1년 사이에 훨씬 많은 길이 생길 것이라고 한다.

발표자는 두 프로토콜의 규격 문서를 보면 거의 똑같다고 말한다. 아직 초기 단계라 앞으로 어떻게 될지는 두고 봐야 한다는 단서도 붙인다.

03

MCP 앱이란 02:10

MCP는 AI 에이전트가 외부 도구를 부르는 표준 규약이다 Model Context Protocol. MCP 서버는 그 규약으로 도구를 내놓는 프로그램이다.

MCP 앱 MCP app은 MCP 서버에 화면을 함께 담은 것이다. HTML과 JavaScript로 만든 UI가 서버 안에 들어 있고, 에이전트가 그 UI를 채팅창 안에 그대로 띄운다.

  • ChatGPT에서는 "앱"으로 추가해 띄운다.
  • Claude에서는 같은 것을 "커넥터" connector라고 부른다.
  • Goose 등 다른 에이전트들도 지원한다. 발표자는 이를 범용 표준이라고 본다.
왜 중요한가 채팅창은 ChatGPT의 것이지만, 그 안에 뜨는 상품 화면은 판매자가 설계한다. 어떤 상품을 어떻게 보여 줄지, 모양과 느낌을 판매자가 정한다. 뒤에 나오는 세 길 가운데 두 길이 이 MCP 앱 위에서 돌아간다.
04

ChatGPT 인스턴트 체크아웃 03:00

인스턴트 체크아웃 Instant Checkout은 ChatGPT 대화 중에 바로 구매까지 끝내는 기능이다. 발표에서 설명한 흐름은 다섯 단계다.

단계누가무엇을
1. 의도사용자ChatGPT에서 사고 싶은 것을 찾는다
2. 탐색판매자의 MCP 앱살 만한 상품을 판매자가 설계한 화면으로 보여 준다
3. 결제 시작MCP 앱 → ChatGPT"이 상품을 사겠다"고 호스트에 알린다. 여기서 에이전트 커머스 프로토콜이 쓰인다
4. 토큰화ChatGPT → PayPal 결제사용자가 카드 번호를 넣거나 저장된 카드를 고르면, 그 정보가 토큰으로 바뀐다
5. 완료와 청구ChatGPT → 판매자토큰이 판매자에게 전달되고, 판매자가 그 토큰으로 돈을 청구한다

데모에서 본 것 04:50

데모는 여행 앱이었다. 사용자가 ChatGPT에서 호텔을 찾자, 판매자가 만든 호텔 목록 화면이 채팅 안에 떴다. 발표자는 "이 화면은 ChatGPT UI가 아니라 판매자가 통제하는 UI"라고 강조한다.

"결제로 진행"을 누르자 이번에는 ChatGPT가 제공하는 인스턴트 체크아웃 화면이 열렸다. 이 화면은 판매자가 만든 것이 아니다. 사용자는 여기서 테스트 카드 번호를 넣었다. 결제가 끝나자 다시 판매자의 MCP 앱으로 돌아왔고, 예약 확정 상태로 화면이 바뀌어 있었다.

판매자 입장에서 달라지는 것 04:10

판매자가 할 일은 두 가지다. MCP 앱으로 사용자 경험을 제공하는 것, 그리고 PayPal 결제에서 오는 토큰을 받는 것이다. 이 토큰은 판매자가 평소 처리하던 토큰과 똑같이 생겼다. 정산, 환불, 지불 거절 chargeback, 규정 준수는 모두 기존과 같은 방식으로 PayPal 결제가 지원한다.

05

토큰화와 통합 지점 06:00

토큰화 tokenization는 실제로 결제할 수 있는 카드 번호를, 대신 돌려 써도 안전한 토큰으로 바꾸는 것이다. 토큰은 여기저기 전달해도 카드 정보 보안 규정인 PCI 범위를 넓히지 않는다.

인스턴트 체크아웃에서는 호스트인 ChatGPT가 토큰화를 맡는다. ChatGPT가 카드 정보를 PayPal 결제에 보내고, PayPal 결제가 토큰을 돌려준다. 판매자는 이 과정에 손대지 않는다. 판매자는 토큰만 받아 안전하게 결제한다.

판매자가 코드를 붙이는 두 곳 07:00

  1. MCP 앱 위젯 안의 JavaScript. 결제 화면을 띄우라고 ChatGPT에 요청하는 코드다. OpenAI가 정한 방식대로 쓴다.
  2. MCP 서버의 결제 완료 도구. 발표에서는 "complete checkout" 도구라고 불렀다. ChatGPT가 이 도구를 호출하면서 토큰을 넘겨준다. 판매자는 그 토큰으로 평소처럼 결제를 처리한다.

발표자는 이 두 곳만 붙이면 된다며 "꽤 단순하다"고 말한다. 다만 MCP 앱 자체를 만드는 일은 따로 남는다.

06

Google AI 모드 08:30

Google AI 모드에서는 흐름이 조금 다르다. 사용자가 AI 모드에서 운동화를 산다고 하자.

단계누가무엇을
1. 쇼핑사용자AI 모드에서 상품을 찾는다
2. 세션 생성Google 에이전트 → 판매자유니버설 커머스 프로토콜로 그 판매자에 사용자 몫의 세션을 만든다. 세션은 판매자에 속한 개체다
3. 토큰화Google Pay → PayPal 결제사용자가 결제하겠다고 하면 Google Pay가 PayPal 결제와 토큰화를 진행한다
4. 완료Google → 판매자토큰을 판매자에게 전달한다
5. 청구판매자 → PayPal 결제"이 토큰으로 이 거래를 처리해 달라"고 요청한다

발표자는 "사실 ChatGPT와 아주 비슷한 모델"이라고 말한다. 정산, 환불, 지불 거절, 위험 관리, 규정 준수는 판매자 입장에서 평소와 같다. 다만 토큰이 다른 길로 들어왔을 뿐이다.

UI를 만들지 않는다 09:50

Google 길의 가장 큰 차이는 판매자가 MCP 앱을 만들지 않는다는 점이다. 화면을 설계할 일이 없다. 대신 "내 상품은 이것들이고, 결제는 이 주소로 보내라"는 정보만 제공한다. 즉 엔드포인트를 세우는 일이 통합의 전부다.

  1. well-known JSON 파일. 유니버설 커머스 프로토콜용 공개 설정 파일이다. "이 가게의 결제는 Braintree, 곧 PayPal 결제로 처리한다"는 표시와 판매자 ID, 클라이언트 키를 적는다. 발표자에 따르면 이 값들은 공개돼도 안전하다.
  2. 결제 완료 엔드포인트. Google이 체크아웃 세션 ID와 함께 "완료" 호출을 보낸다. 그 안에 Google Pay 결제 뒤의 카드를 나타내는 토큰이 들어 있다. 판매자는 그걸로 결제를 처리한다.

자막에는 "brainree or PayPal and price payments"로 들린다. 문맥상 "Braintree, 곧 PayPal 엔터프라이즈 결제"를 뜻하는 것으로 정리했다.

07

MCP 앱 + 외부 결제 페이지 11:10

세 번째 길은 ChatGPT나 Google에 묶이지 않는다. MCP 앱을 지원하는 어느 에이전트에서나 쓸 수 있다. 판매자가 전체 경험을 완전히 통제하는 방식이다.

  1. MCP 앱 위젯이 채팅 안에 상품 카드와 결제 버튼을 보여 준다.
  2. 결제 버튼을 누르면 외부 결제 페이지가 새로 열린다. 판매자는 세션으로 두 화면을 묶어 둔다.
  3. 사용자는 외부 페이지에서 원하는 어떤 결제 수단으로든 결제를 끝낸다.
  4. 결제가 끝나면 채팅 안의 MCP 앱이 자동으로 갱신된다. 뒤에서 통신이 오가며 주문 상태를 전달하기 때문이다.

데모에서 본 것 12:10

이번 데모는 Claude에서 돌렸다. 판매자의 MCP 앱이 커넥터로 뜨고, 사용자가 상품을 골라 결제를 누르자 외부 링크가 열렸다. 거기서 결제를 마치자 Claude 안의 앱 화면이 스스로 바뀌었다.

얻는 것완전한 통제화면, 결제 수단, 흐름을 판매자가 모두 정한다. 특정 에이전트에 묶이지 않는다.

핵심 정리

  1. PayPal 엔터프라이즈 결제는 Braintree의 새 이름이다. 대기업 결제를 처리한다.
  2. 에이전트 결제를 받는 길은 셋이다. ChatGPT 인스턴트 체크아웃, Google AI 모드, MCP 앱 + 외부 결제 페이지.
  3. ChatGPT는 에이전트 커머스 프로토콜, Google은 유니버설 커머스 프로토콜을 쓴다. 발표자가 보기에 두 규격은 거의 같다.
  4. MCP 앱은 MCP 서버에 UI를 담은 것이다. ChatGPT에서는 앱, Claude에서는 커넥터라 부른다.
  5. ChatGPT 길의 흐름은 의도 → 탐색 → 결제 시작 → 토큰화 → 완료와 청구다.
  6. 토큰화는 카드 번호를 돌려 써도 안전한 토큰으로 바꾸는 것이다. 호스트가 맡고, 판매자는 토큰만 받는다.
  7. 토큰은 판매자, 최대 금액, 통화, 만료로 제한되고 거래에 출처가 붙는다.
  8. Google 길은 UI가 없다. well-known JSON과 결제 완료 엔드포인트만 세운다. 토큰화는 Google Pay가 한다.
  9. 세 번째 길은 통제를 얻고 마찰을 치른다. 엘리시테이션이 퍼지면 마찰이 줄 수 있다.
  10. 어느 길이든 판매자가 받는 토큰은 평소 쓰던 것과 같다. 정산, 환불, 지불 거절은 기존 그대로다.
10

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1Braintree와 PayPal 엔터프라이즈 결제의 관계는?
같은 것이다. Braintree가 PayPal 엔터프라이즈 결제로 이름을 바꿨다. 대기업의 결제 처리를 맡는다.
Q2발표에서 말한 세 가지 길은?
ChatGPT 인스턴트 체크아웃, Google AI 모드 결제, MCP 앱에서 외부 결제 페이지로 넘기기.
Q3에이전트 커머스 프로토콜과 유니버설 커머스 프로토콜은 각각 누가 만들었고, 서로 얼마나 다른가?
에이전트 커머스 프로토콜은 OpenAI, 유니버설 커머스 프로토콜은 Google과 파트너들이 만들었다. 발표자에 따르면 규격이 거의 똑같다.
Q4MCP 앱은 MCP 서버와 무엇이 다른가?
MCP 서버에 HTML과 JavaScript로 만든 UI가 함께 들어 있다. 에이전트가 그 UI를 채팅 안에 띄운다. ChatGPT에서는 앱, Claude에서는 커넥터라고 부른다.
Q5ChatGPT 인스턴트 체크아웃에서 토큰화는 누가 하나?
호스트인 ChatGPT가 한다. 카드 정보를 PayPal 결제에 보내고 토큰을 돌려받는다. 판매자는 이 과정에 관여하지 않고 토큰만 받는다.
Q6토큰화가 왜 필요한가?
실제 카드 번호 대신 토큰을 돌려 쓰면, 토큰이 여러 곳을 거쳐도 카드 정보 보안 규정인 PCI 범위가 넓어지지 않는다.
Q7인스턴트 체크아웃을 붙이려면 판매자가 코드를 넣는 두 곳은?
MCP 앱 위젯 안에서 결제 화면을 띄우는 JavaScript, 그리고 MCP 서버에서 토큰을 받는 결제 완료 도구.
Q8토큰에 걸린 네 가지 제한은?
특정 판매자에게서만, 최대 금액까지만, 정해진 통화로만, 만료 전까지만 쓸 수 있다. 거래에는 출처도 붙는다.
Q9Google AI 모드 길이 ChatGPT 길과 가장 다른 점은?
판매자가 UI를 만들지 않는다. well-known JSON과 결제 완료 엔드포인트만 세운다. 토큰화는 Google Pay가 맡는다.
Q10세 번째 길의 장점과 단점은?
장점은 어떤 에이전트에서나 쓸 수 있고 화면과 결제 수단을 판매자가 모두 통제한다는 것. 단점은 결제가 채팅 밖 외부 페이지에서 이뤄져 마찰이 조금 더 크다는 것.
Q11엘리시테이션은 무엇이고 지금 왜 쓰지 못하나?
MCP 앱에서 서버가 사용자에게 추가 입력이나 확인을 요청하는 새 기능이다. 외부 검증을 더 매끄럽게 할 수 있지만, 발표 시점에는 주요 에이전트 대부분이 아직 지원하지 않는다.
Q12어느 길로 오든 판매자 입장에서 같은 것은?
마지막에 받는 토큰이 평소 처리하던 토큰과 같다. 정산, 환불, 지불 거절, 규정 준수도 기존 방식 그대로다.

용어뜻

유니버설 커머스 프로토콜Universal Commerce Protocol, UCP. Google과 파트너들이 만든 규격. Google AI 모드에 쓰인다
MCPModel Context Protocol. AI 에이전트가 외부 도구를 부르는 표준 규약
MCP 앱MCP 서버에 HTML과 JavaScript로 만든 UI를 함께 담은 것. 에이전트가 채팅 안에 띄운다
커넥터Connector. Claude에서 MCP 앱을 부르는 이름
인스턴트 체크아웃Instant Checkout. ChatGPT 대화 안에서 바로 구매를 끝내는 기능
호스트Host. MCP 앱을 띄우는 에이전트 쪽. 여기서는 ChatGPT나 Claude
토큰화Tokenization. 실제 카드 번호를 돌려 써도 안전한 토큰으로 바꾸는 것
PCI 범위카드 정보를 다루는 시스템에 적용되는 보안 규정의 적용 범위. 카드 번호를 만지는 곳이 늘수록 넓어진다
정산Settlement. 결제된 돈이 실제로 판매자 계좌로 들어오는 과정
지불 거절Chargeback. 카드 소유자가 거래에 이의를 제기해 결제가 취소되는 것
체크아웃 세션Checkout session. 한 번의 구매 과정을 나타내는 개체. Google 길에서는 판매자에 속한다
well-known JSON정해진 주소에 두는 공개 설정 파일. 여기서는 결제 처리사와 판매자 ID 등을 적는다
엔드포인트Endpoint. 외부에서 호출할 수 있는 서버 주소
엘리시테이션Elicitation. MCP에서 서버가 사용자에게 추가 입력이나 확인을 요청하는 기능
iframe웹 페이지 안에 다른 페이지를 끼워 넣는 HTML 요소
