작은 모델이 큰 모델을 이긴 방법

Snorkel AI와 UC 버클리 연구팀은 40억 파라미터 모델을 500달러 미만으로 강화학습시켜, 금융 질의응답에서 같은 계열의 2,350억 파라미터 모델을 앞질렀다. 승부를 가른 건 크기가 아니라 잘 만든 데이터와 단순한 훈련 설계였다.

원본 영상: Small Models, Big Results: Training a Finance Agent for Under $500 발표: Charles Dickens (Snorkel AI 연구 과학자)

영어 발표의 자동 자막을 바탕으로 한글로 정리했다. 수치는 모두 발표자가 인용한 것이고 원 출처를 따로 확인하지는 않았다. 자막에서 뭉개진 이름은 확실한 것만 알려진 이름으로 고쳤다. 확실하지 않은 이름은 들린 대로 적고 (추정)을 붙였다. mm:ss는 영상 위치다.

3분 요약
  1. Qwen3 4B 모델을 금융 질의응답으로 강화학습시키자 정답률이 약 60%가 됐다. 같은 계열 235B 모델은 51%였다.
  2. 훈련 비용은 500달러 미만이었다. 컴퓨팅에 약 420달러, 채점 모델 API에 약 40달러를 썼다.
  3. 데이터는 미국 상장사 연차 보고서에서 뽑은 SQL 표로 만들었다. 표마다 질문 하나를 만들고 세 겹으로 검증했다.
  4. 큰 모델도 같은 실수를 반복했다. 없는 표를 지어내고, 맥락을 데이터로 넘치게 하고, 실패한 방법을 되풀이했다.
  5. 표 하나짜리 쉬운 문제로만 훈련했는데 표 여러 개를 엮는 문제도 좋아졌다. 일반 도구 호출 능력도 떨어지지 않았다.
  6. 비교 실험에서는 늘 단순한 쪽이 이겼다. 쉬운 데이터만 쓴 쪽, 맞았나 틀렸나만 보는 보상이 가장 효과가 컸다.
  7. 발표자의 결론: 병목은 추론 깊이가 아니라 도구를 제대로 쓰는 습관이었다. 도메인을 잘 반영한 데이터가 있으면 작은 모델로 충분하다.
01

발표의 세 가지 주장 00:30

발표자는 결론부터 꺼낸다. 이번 결과는 모의 금융 환경에서 나왔다. 그래도 다른 분야에 가져갈 교훈이 있다고 본다.

  1. 기업 업무에서는 믿을 수 있는가와 전문화가 모델 크기보다 중요할 수 있다.
  2. 그러려면 목표 도메인과 실제 업무 분포를 그대로 반영한 질 좋은 데이터가 있어야 한다.
  3. 그러면 작은 모델이 최신 대형 모델과 같은 수준을 훨씬 적은 비용으로 낸다.

누가 만들었나 01:00

Snorkel AI는 스스로를 프런티어 AI 데이터 연구소라고 소개한다. 하는 일은 세 갈래다.

이번 연구는 UC 버클리 Sky Computing Lab과 함께 했다. 02:30 결과 모델의 이름은 rLLM-FinQA-4B다.

발표자는 데이터와 평가 환경을 파는 Snorkel AI 소속이다. "좋은 데이터가 모델 크기를 이긴다"는 주장은 회사 사업과 바로 닿아 있으니 감안해 읽자.

발표자는 이 대목을 "두 모델 이야기"라고 부른다. 발표자 이름과 같은 소설가 찰스 디킨스의 『두 도시 이야기』를 빗댄 말이다. 한쪽은 큰 범용 모델, 다른 쪽은 작은 전문 모델이다.

금융 회사가 "이 에이전트는 추론을 얼마나 잘하나"라고 물을 때 실제로 묻는 건 세 가지다.

  • 복잡한 스키마, 오래된 API, 쌓인 기술 부채가 있는 우리 시스템 안에서 일할 수 있나?
  • 길고 현실적인 작업에서 오류가 쌓이지 않고 믿을 만한가?

03

FinQA 데이터 만들기 04:50

FinQA는 Snorkel이 만든 금융 질의응답 데이터다. 훈련용 데이터와 평가용 벤치마크를 같은 방식으로 만들었다. 단계는 셋이다.

단계한 일
1. 표 뽑기 05:00미국 증권거래위원회(SEC) 공시 시스템 EDGAR에서 10-K 보고서를 가져왔다. 10-K는 상장사가 매년 내야 하는 연차 보고서다. Qwen3 30B 모델로 이 보고서에서 SQL 표 약 6,900개를 만들었다.
2. 질문 만들기 05:30표 하나에서 질문-답 쌍 하나를 만들었다. 금융 전문가와 함께 만든 질문 분류 체계taxonomy를 맥락으로 줬다. 나중에 검증에 쓸 메타데이터도 함께 만들었다.
3. 세 겹 검증 06:00① 프로그램 검사: 메타데이터의 출처 기록, 표 이름, 열 이름을 대조해 없는 표나 열을 지어내지 않았는지 본다. ② 독립된 에이전트의 자동 리뷰. ③ 전문가가 직접 읽고 질문과 답이 현실적이고 맞는지 확인한다.

결과물은 계획, 도구 호출, 추론이 모두 필요한 현실적인 질문이다. 06:30 답은 하나로 정해지고 확인할 수 있다. 이 성질 덕분에 뒤에 나오는 "맞았나 틀렸나" 채점이 가능하다.

분할문항 수쓰임
훈련4,000강화학습에 쓴다
검증500훈련 중 상태를 확인한다
보류 벤치마크290훈련에 쓰지 않고 최종 평가에만 쓴다

나눌 때 규칙이 하나 있었다. 같은 회사의 데이터가 두 분할에 겹치지 않게 했다. 모델이 특정 회사의 표를 외워서 맞히는 일을 막기 위해서다.

세 분할을 더하면 4,790개다. 표는 약 6,900개였으니 2,000개 넘게 빠졌다. 검증에서 걸러졌는지는 발표에서 설명하지 않았다.

04

큰 모델도 반복하는 실수 07:10

이 데이터로 최신 모델들을 돌려 보니 같은 실패가 되풀이됐다. 발표자는 이를 실력이 아니라 규율의 빈틈으로 본다.

스키마 환각 · schema hallucination

있지도 않은 표나 열이 있다고 가정하고 쿼리를 짠다.

원인 추정: 사전학습 때 비슷한 데이터를 본 흔적일 수 있다고 발표자는 본다.

맥락 넘침 · context flooding

계획 없이 짠 쿼리로 자기 맥락을 데이터로 가득 채운다. 예를 들면 SELECT *로 표 전체를 불러온다.

역설: 쿼리가 성공할수록 맥락 한도를 넘길 위험이 커진다.

오류 회복 실패 · poor recovery

Qwen3 235B는 오류가 나면 오류 메시지를 읽고 방법을 바꾸지 않았다. 실패한 방법을 그대로 다시 시도했다.

결과: 긴 작업에서 오류가 쌓인다. 금융 회사가 가장 걱정하는 바로 그 문제다.

이 실수는 금융에만 있지 않다. 07:50 보험 심사insurance underwriting 환경에서도 같은 실패가 나왔다고 한다. 몇 주 전 CAIS(추정) 학회에서 발표된 연구다.

05

훈련 도구: rLLM 08:10

훈련에는 rLLM을 썼다. Sky Computing Lab의 공동 연구자들이 만든 에이전트 강화학습 프레임워크다. 발표자가 꼽은 특징은 이렇다.

  • 어떤 에이전트 프레임워크와도 함께 쓸 수 있다.
  • 데코레이터decorator 하나를 붙이는 방식이라 기존 코드를 거의 고치지 않는다.
  • 명령줄CLI 중심으로 쓴다.
  • 이번 금융 사례 말고 수학 추론에서도 성능을 올린 적이 있다.
  • 강화학습 알고리즘이 여러 개 들어 있다. GRPO, REINFORCE, RLOO(추정) 등이고, 직접 바꿔 쓸 수 있다.
  • 여러 학습 백엔드를 지원한다.

자막에서 알고리즘 이름이 뭉개졌다. GRPO는 분명하고, 나머지 두 이름은 들린 소리로 추정한 것이다.

07

결과: 4B가 235B를 넘었다 10:20

핵심 질문은 이것이다. 전문 도구와 훈련을 갖춘 4B 모델이 훨씬 큰 같은 계열 모델과 겨룰 수 있나? 발표자의 답은 "그렇다"다.

학습 전 4B 모델과 비교하면 정확도가 두 배 넘게 올랐다. 학습 전 점수는 발표에서 따로 말하지 않았다. "두 배 넘게"라는 말로 미루어 30% 아래였다고 볼 수 있다.

읽을 때 주의 발표자도 이 결과가 모의 금융 환경에 한정된다고 밝혔다. 4B 모델은 벤치마크와 같은 방식으로 만든 훈련 데이터로 학습했다. 235B 모델을 이 데이터로 추가 학습했다는 언급은 없다. 그러니 "작은 모델이 더 똑똑하다"가 아니라 "제 업무에 맞춰 훈련한 작은 모델이 훈련하지 않은 큰 모델을 넘었다"로 읽는 게 맞다.
08

더 어려운 문제, 더 넓은 도구 10:50

당연히 의문이 생긴다. 표 하나짜리 질문에서 배운 게 더 어려운 문제에도 통할까?

표 여러 개를 엮는 문제 11:00

이를 확인하려고 FinQA 추론 데이터를 썼다. 앞의 FinQA를 발전시킨 것이다. 질문 하나에 표 2~5개가 얽혀 있다. 순서대로 결정하고 계획해야 풀린다. 분할은 훈련 약 1,000개, 검증 120개, 벤치마크 80개다.

결과는 이렇다. 표 하나짜리 쉬운 데이터로만 훈련했는데 이 문제에서도 점수가 올랐다. 다중 표 예시를 따로 가르칠 필요가 없었다. 도구를 쓰는 규율이 그대로 옮겨 갔다.

일반 도구 호출 능력 12:00

다음 의문은 전문화가 다른 능력을 깎지 않았냐는 것이다. 일반 도구 호출 능력을 재는 BFCLBerkeley Function Calling Leaderboard로 확인했다.

  • 전체 정확도는 조금 올랐다.
  • 여러 차례 주고받는 대화multi-turn와 메모리 항목도 소폭 올랐다.

금융에 맞춘 강화학습이 일반적인 도구 사용 능력을 해치지 않았다.

다중 표 문제와 BFCL의 구체적인 점수는 발표 자막에 나오지 않는다.

09

쉬운 데이터가 이겼다 12:30

무엇이 성능을 끌어올렸는지 가려내려고 비교 실험ablation을 했다. 훈련 데이터를 섞는 방법을 세 가지로 바꿔 봤다.

훈련 데이터구성결과
단일 표만FinQA(표 하나짜리 문제)만 쓴다가장 크게 올랐다
단일 + 다중 표두 데이터를 섞어 쓴다덜 올랐다
커리큘럼단일 표로 시작해 다중 표로 넘어간다덜 올랐다

발표자도 놀랐다고 했다. 이 결과가 앞의 일반화를 설명해 준다.

병목은 추론의 깊이가 아니었다. 도구 사용이었다. 기본기를 익히면 모델은 그 기술을 스스로 조합한다.발표자의 설명을 옮김 13:00

모델이 실제로 틀리던 곳은 도구를 쓰는 단계였다. 그 단계를 믿을 만하게 만들자 어려운 문제도 풀렸다.

세 방식의 구체적인 점수와, 아래 두 방식 사이의 순위는 발표에서 말하지 않았다.

10

단순한 보상이 이겼다 13:20

다음 질문은 보상이다. 중간 단계를 칭찬해 주면 더 빨리 배울까? 이건 커리큘럼과 다른 질문이다. 커리큘럼은 무엇을 먼저 가르칠지 정하고, 보상은 무엇을 칭찬할지 정한다.

보상 방식무엇을 보나
이진 보상최종 답이 맞았나 하나만 본다 (가장 크게 올랐다)
중간 단계 보상표에 제대로 접근했나, 쿼리가 완성됐나 같은 과정도 점수에 넣는다
루브릭전문가와 함께 만든 채점표. 여러 항목에 가중치를 둬 잘게 점수를 매긴다. 가장 공들인 방식이다

보상 설계에 공을 들였지만 결과는 같았다. 단순한 쪽이 나았다. 맞았나 틀렸나 하나만 보는 보상이 가장 큰 향상을 냈다.

보상 쪽 결과가 왜 그렇게 나왔는지는 발표에서 따로 설명하지 않았다.

기업 에이전트 설계도 14:00

Snorkel은 이 연구를 기업용 에이전트 설계도로 정리하고 있다. 요점은 이렇다.

  • 목표 업무와 결과를 잘 반영한 데이터가 있으면, 작은 모델도 강화학습으로 훈련할 수 있다.
  • 전문 업무에서는 이 방식이 배포 비용 면에서 더 유리하다.
  • 발표자는 의료, 법률, 보험에서도 같은 결과를 반복해 얻었다고 했다.

축묻는 것

출력 복잡도일상 업무에서 나오는 다양한 결과물을 다루는가. 지금 평가는 대부분 텍스트 결과물에 머문다.

발표자는 출력 복잡도가 아직 덜 연구됐다고 본다. 새 벤치마크가 나오고는 있지만, 이런 상황에서 더 엄격한 평가를 만드는 건 큰 기회라고 했다.

핵심 정리

  1. Qwen3 4B를 금융 질의응답으로 강화학습시키자 정답률이 두 배 넘게 올라 약 60%가 됐다. Qwen3 235B는 51%였다.
  2. 훈련 비용은 약 460달러다. 컴퓨팅 약 420달러, 채점 API 약 40달러, H100 8장.
  3. 금융 회사가 원하는 건 믿을 수 있음이다. 복잡한 시스템 안에서 일하고, 오류가 쌓이지 않고, 감사할 수 있어야 한다.
  4. 데이터: 10-K 보고서 → SQL 표 → 표마다 질문 하나 → 세 겹 검증.
  5. 훈련과 평가 데이터를 회사 단위로 나눠, 외워서 맞히는 일을 막았다.
  6. 큰 모델도 없는 표를 지어내고, 맥락을 넘치게 하고, 실패를 되풀이한다.
  7. 표 하나짜리 데이터로만 훈련해도 다중 표 문제가 좋아졌다. 일반 도구 호출 능력도 깎이지 않았다.
  8. 데이터 비교 실험에서 쉬운 데이터만 쓴 쪽이 가장 많이 올랐다. 병목은 추론 깊이가 아니라 도구 사용이었다.
  9. 보상 비교 실험에서도 맞았나 틀렸나 하나가 정교한 루브릭보다 나았다.
  10. 에이전트 평가의 세 축은 환경 복잡도, 자율 지평, 출력 복잡도다. 결과는 모의 환경 한정이고 회사 이해관계도 감안해야 한다.

점검 퀴즈

답을 먼저 떠올린 뒤 눌러서 확인한다.

Q1비교한 두 모델과 각각의 점수는?
강화학습한 Qwen3 4B(rLLM-FinQA-4B)가 약 60%, Qwen3 235B가 51%다. 보류 벤치마크 290문항에서 한 번에 맞힌 비율(pass@1)이다.
Q2"500달러 미만" 훈련 비용은 어떻게 나뉘나?
컴퓨팅 약 420달러, 채점 모델 API 약 40달러다. H100 8장으로 동시 환경 약 1,000개를 돌렸다.
Q3금융 회사가 "추론을 잘하나"라고 물을 때 실제로 묻는 세 가지는?
우리 시스템(복잡한 스키마, 오래된 API, 기술 부채) 안에서 일할 수 있나. 긴 작업에서 오류가 쌓이지 않나. 한 일을 감사할 수 있나.
Q4FinQA 데이터의 세 겹 검증은 무엇인가?
메타데이터로 표와 열 이름을 대조하는 프로그램 검사, 독립 에이전트의 자동 리뷰, 전문가의 직접 검토.
Q5데이터를 나눌 때 지킨 규칙과 그 이유는?
같은 회사가 훈련, 검증, 벤치마크 중 두 곳에 겹치지 않게 했다. 모델이 특정 회사의 표를 외워 점수가 부풀지 않게 하려는 것이다.
Q6큰 모델도 반복한 실패 세 가지는?
스키마 환각(없는 표나 열을 가정), 맥락 넘침(SELECT *처럼 데이터를 마구 불러옴), 오류 회복 실패(오류 메시지를 무시하고 같은 방법을 반복).
Q7보상은 어떻게 매겼나?
최종 답이 맞았는지만 보는 이진 보상이다. GPT-5 nano가 미리 정한 정답과 비교해 판정했다.
Q8표 하나짜리 데이터로만 훈련했는데 다중 표 문제가 좋아진 이유를 발표자는 어떻게 설명하나?
병목은 추론 깊이가 아니라 도구 사용이었다. 도구를 쓰는 기본기를 익히면 모델이 그 기술을 조합해 어려운 문제도 푼다.
Q9금융 전문화 훈련 뒤 일반 도구 호출 능력은 어떻게 됐나?
BFCL에서 전체 정확도가 조금 올랐고, 멀티턴과 메모리 항목도 소폭 올랐다. 전문화가 일반 능력을 해치지 않았다.
Q10데이터 혼합 실험과 보상 실험의 공통된 결론은?
단순한 쪽이 이겼다. 쉬운 단일 표 데이터만 쓴 쪽, 이진 보상만 쓴 쪽이 가장 많이 올랐다.
Q11발표자가 제안한 에이전트 평가의 세 축은?
환경 복잡도, 자율 지평(실제로 맡길 길이의 작업을 혼자 잘 해내나), 출력 복잡도(텍스트 말고 다양한 결과물을 다루나).
Q12이 결과를 "작은 모델이 큰 모델보다 낫다"로 일반화하면 안 되는 이유는?
모의 금융 환경 한정 결과다. 4B는 벤치마크와 같은 방식의 데이터로 훈련했고, 235B를 추가 학습했다는 언급은 없다. 발표자 회사가 데이터 사업을 한다는 점도 감안해야 한다.

용어 정리

용어뜻
파라미터Parameter. 모델이 학습으로 정하는 숫자. 4B는 40억 개, 235B는 2,350억 개다
강화학습Reinforcement Learning(RL). 모델이 직접 시도하고 결과에 따라 보상을 받으며 나아지는 학습 방식
pass@1문제를 한 번만 풀게 했을 때 맞힌 비율
10-K미국 상장사가 증권거래위원회(SEC)에 매년 내야 하는 연차 보고서
EDGARSEC의 기업 공시 검색 시스템
스키마Schema. 데이터베이스에 어떤 표와 열이 있는지 정한 구조
보류 벤치마크Held-out benchmark. 훈련에 쓰지 않고 최종 평가용으로 떼어 둔 문제
스키마 환각Schema hallucination. 없는 표나 열이 있다고 가정하는 실수
맥락 넘침Context flooding. 쿼리 결과를 너무 많이 불러와 모델의 맥락 창을 채워 버리는 실수
ReActReason + Act. 생각하고, 도구를 부르고, 결과를 보고, 다시 생각하기를 반복하는 에이전트 방식
궤적Trajectory. 에이전트가 문제를 푸는 동안 한 생각, 도구 호출, 결과를 순서대로 기록한 것
GRPOGroup Relative Policy Optimization. 같은 문제에 답을 여러 개 만들어, 그 무리 안에서 상대적으로 잘한 답을 강화하는 강화학습 알고리즘
이진 보상Binary reward. 맞으면 보상, 틀리면 없음. 두 값만 있는 보상
LLM 채점LLM-as-judge. 다른 언어 모델에게 답이 맞는지 판정을 맡기는 방식. 정답을 함께 주면 참조 기반 평가다
비교 실험Ablation. 요소를 하나씩 바꾸거나 빼서 무엇이 효과를 냈는지 가려내는 실험
커리큘럼Curriculum. 쉬운 문제부터 어려운 문제 순으로 가르치는 훈련 순서
루브릭Rubric. 여러 항목에 가중치를 둔 채점표
BFCLBerkeley Function Calling Leaderboard. 모델의 일반적인 도구(함수) 호출 능력을 재는 벤치마크
데코레이터Decorator. 기존 함수에 표시 하나를 붙여 기능을 더하는 코드 작성 방식
H100NVIDIA의 데이터센터용 GPU. 모델 훈련에 많이 쓴다
자율 지평Autonomy horizon. 에이전트가 사람 개입 없이 이어서 해내는 작업의 길이
